1.2 연구 목표 (Research Objective)

이 논문은 알고리즘이 아니라 데이터셋(벤치마크) 을 기여로 하는 연구다. 핵심 목표는 실외 Vision-and-Language Navigation(VLN)의 비현실적 평가 관행을 깨는 것이다.

기존 실외 VLN 데이터셋(Touchdown, map2seq, 그리고 대부분의 street-view 기반 벤치마크)은 도시를 고정된 이산 위상 그래프(discrete topological graph) 로 추상화한다. 에이전트는 노드(파노라마 촬영 지점) 사이를 "순간이동(teleport)"하듯 옮겨 다니며, 각 노드에서 이웃 노드 중 하나를 고르는 것이 곧 "행동"이다. 이 추상화에는 두 가지 치명적 괴리가 있다:

  1. 연속성의 부재(no continuous actions): 실제 로봇은 그래프 간선을 순간이동하지 않는다. 연속적인 조향/속도 제어로 주행하며, 노드 사이의 모든 중간 지점에서 지각·판단·회복을 수행해야 한다. 이산 그래프는 이 "중간의 어려움"을 통째로 지워버린다.
  2. 동역학(dynamics)의 부재: 실제 도시는 정적이지 않다. 차량, 보행자, 자전거가 끊임없이 움직이며 에이전트의 경로를 방해한다. 고정 그래프는 이 예측 불가능한 동적 요소를 담지 못한다.

DaViNCi(Dynamic Vision-and-Language Navigation in Continuous Environment)는 연속 행동(continuous actions)과 동적 요소(dynamic elements)를 동시에 도입한 최초의 실외 VLN 데이터셋을 표방한다. 저자들의 핵심 주장은 실험적으로 뒷받침된다: 동일한 SOTA VLN 모델을 DaViNCi에서 평가하면 이산 환경에서도 성공률이 기존 데이터셋 대비 10%p 이상 하락하고, 연속 환경에서는 하락 폭이 더 커진다. 즉, 기존 벤치마크의 높은 점수는 문제를 쉽게 만든 추상화의 산물이었음을 정량적으로 폭로한다.

연구 질문을 한 문장으로 요약하면:

"실외 VLN 에이전트가 이산 그래프의 순간이동이 아니라 연속 제어로 움직이고, 정적 배경이 아니라 움직이는 차량·보행자를 마주해야 할 때, 현재의 SOTA는 실제로 얼마나 잘하는가? 그리고 그 격차를 측정할 표준 벤치마크는 무엇인가?"

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

(C1) 이산 위상 그래프의 sim-to-real 괴리. Touchdown류 데이터셋은 Google Street View 파노라마를 노드로 삼는다. 에이전트의 상태 공간은 유한한 노드 집합이고, 행동 공간은 "현재 노드에서 이웃 노드 선택"이다. 이 설정에서 에이전트는:

  • 노드와 노드 사이 구간의 지각을 전혀 요구받지 않는다(그 구간이 통째로 없음).
  • 조향 각도, 속도, 정지 타이밍 같은 연속 제어 변수를 다루지 않는다.
  • 결과적으로 시뮬레이터에서 학습된 정책이 실제 연속 제어 로봇으로 전이될 때 심각한 성능 붕괴를 겪는다.

(C2) 정적 환경 가정. 기존 벤치마크는 경로 상의 장애물·교통 참여자가 고정되어 있거나 아예 없다. 실제 도시 주행에서 가장 어려운 부분 — 앞차의 급정거, 무단횡단 보행자, 좌회전 차량과의 상호작용 — 이 평가에서 완전히 빠져 있다.

(C3) 연속 환경에서의 지시 그라운딩 난이도 증가. 이산 그래프에서는 "다음 교차로에서 좌회전"이 "좌회전 간선 선택"이라는 단일 이산 결정으로 환원된다. 연속 환경에서는 같은 지시가 (a) 언제 좌회전을 시작할지, (b) 어느 각도로 조향할지, (c) 언제 정지 신호를 낼지의 연속적·시계열적 판단으로 분해된다. 행동 입도(action granularity) 가 성능에 미치는 영향은 이산 벤치마크로는 측정조차 불가능하다.

(C4) 표준화된 대규모 실외 연속 데이터의 부재. 실차 주행 로그로 연속 VLN 데이터를 만들면 수집 비용이 폭발하고, 동적 요소를 통제·재현할 수 없어 벤치마크로서 재현성이 무너진다. 시뮬레이션이 필요하지만, 자율주행용 고충실도 시뮬레이터(CARLA 등)를 VLN 데이터 생성에 맞게 재목적화하는 파이프라인은 표준화되어 있지 않다.

2.2 핵심 해결책

DaViNCi는 CARLA 시뮬레이터를 VLN 데이터 팩토리로 재목적화하여 위 도전과제를 정면 돌파한다. 해결책의 골격은 네 가지다:

  1. 연속 궤적 샘플링: CARLA에서 자율주행 차량(ego)이 교통 없는 환경을 자유 주행하며, 1초 간격으로 (x,y,z, yaw, pitch, roll)을 연속 기록 → 이산 노드가 아닌 연속 궤적을 원천 데이터로 확보.
  2. 2단계 언어 지시 생성: (Stage 1) 궤적의 기하로부터 좌/우회전 등 방향 이벤트를 벡터 외적으로 자동 추출 → (Stage 2) 1인칭 주행 영상을 멀티모달 LLM(Tongyi Qwen3-VL-Plus)에 넣어 자연어 지시 캡션 생성, 이때 Stage 1이 추출한 방향과 일치하도록 프롬프트로 강제.
  3. 연속/이산 이중 평가 프로토콜: 같은 궤적을 이산 그래프로도 변환해 동일 모델을 이산·연속 두 설정에서 평가 → 추상화가 감춘 난이도 격차를 직접 정량화.
  4. 동적 요소 주입 및 통제: CARLA의 트래픽 매니저로 차량/보행자/자전거를 개수 단위로 스폰 → 동적 요소 수를 변수로 통제하며 성능 열화를 측정.

이 네 요소가 결합되어, DaViNCi는 단순한 데이터 덤프가 아니라 연속성·동역학·입도라는 세 축을 독립적으로 조절하며 실외 VLN의 난이도를 해부하는 실험 장치가 된다.

2.3 기존 실외 VLN 데이터셋 대비 위치 (Positioning)

실외 VLN 벤치마크 계보에서 DaViNCi의 좌표를 명확히 하기 위해 대표 선행과 대조한다:

데이터셋 환경 원천 행동 표현 동적 요소 지시 생성
Touchdown (CVPR2019) Google Street View 이산 노드 그래프 없음(정적) 사람 주석
map2seq / StreetLearn 계열 Street View 이산 그래프 없음 템플릿/사람
CityWalker (CVPR2025) 실사 웹 보행영상 연속(VO 라벨) 비통제(실영상 내재) 약한 목표점
DaViNCi (본 논문) CARLA 시뮬 연속+이산 이중 통제 스폰(개수 변수) 기하앵커 LLM 캡션

이 표가 드러내는 DaViNCi의 고유 셀은 "동적 요소를 개수 단위로 통제 가능" 하면서 동시에 "연속·이산을 같은 궤적에서 이중 평가" 한다는 조합이다. CityWalker는 연속·실사·동적을 얻었지만 동적 요소가 실영상에 내재되어 통제·재현이 불가능하다(같은 장면을 보행자 수만 바꿔 재평가할 수 없음). Touchdown은 실사이지만 이산·정적이다. DaViNCi는 시각 사실성을 일부 희생(시뮬)하는 대신, 동적 밀도·행동 입도·연속성을 독립 변수로 완전 통제하는 실험적 재현성을 얻었다. 이것이 벤치마크로서의 핵심 차별점이다.

3. 핵심 방법론 (Core Methods)

데이터셋 논문이므로 "방법론"은 데이터 생성 파이프라인과 평가 프로토콜이다. 아래에서 파이프라인을 단계별로 분해한다.

3.1 CARLA 기반 연속 궤적 수집 (Continuous Trajectory Sampling)

CARLA(Car Learning to Act)는 원래 자율주행 시스템의 개발·학습·검증을 위한 오픈소스 시뮬레이터다. DaViNCi는 이 엔진을 VLN 궤적 생성기로 사용한다.

수집 절차:

CARLA Town 로드
   │
   ▼
ego 차량 스폰 (교통 없는 clean 환경)
   │
   ▼
자유 주행(free navigation) — 도로망을 따라 자율 주행
   │
   ▼
1초 고정 샘플링 간격으로 상태 기록:
   • 위치: (x, y, z)
   • 자세: (yaw, pitch, roll)
   • 도로 위상: road ID, lane ID
   │
   ▼
JSON 궤적 파일 저장

각 궤적은 위상 정보(road ID, lane ID)와 연속 기하(좌표·오일러각)를 함께 담는다. 이 이중 표현이 핵심인데, 위상 정보는 나중에 이산 그래프 버전을 만드는 데 쓰이고, 연속 기하는 연속 환경 평가의 기준 경로(reference path)가 된다. 즉 하나의 원천에서 이산·연속 두 벤치마크를 동시에 파생시킬 수 있다.

6개 맵(Town) 구성 — 지형·밀도의 다양성을 위해 CARLA 기본 타운 6종을 사용:

Town 성격 대표 요소
Town01 시골(단순) 저층 건물, 단순 도로
Town02 시골(복잡) 조밀·복잡한 도로 구조
Town03 고저차 있는 타운 로터리, 터널, 5거리 교차로
Town04 고속도로 산악 도로, 다차선
Town05 도심 고층 건물, 고가도로
Town10 번화가(주 수집지) 박물관·쇼핑몰·지하철역

Town10을 주 수집지로 삼은 것은, 건물·랜드마크 밀도가 높아 언어 지시의 참조 대상(reference landmark)이 풍부하기 때문으로 보인다. 반면 Town01/02 같은 시골 맵은 랜드마크가 희소해 순수 방향 지시(turn-by-turn) 중심이 된다. 이 다양성이 벤치마크의 일반화 측정력을 높인다.

규모: 6개 맵에 걸쳐 총 6,933 궤적. Touchdown(약 9,300 경로)과 같은 자릿수로, 실외 연속 VLN 데이터셋으로는 최초 규모다.

3.2 2단계 자연어 지시 생성 (Two-Stage Instruction Generation)

연속 궤적을 사람이 이해할 자연어 내비게이션 지시로 변환하는 것이 파이프라인의 지적 핵심이다. 순진하게 LLM에 "이 영상을 설명해"라고 하면 방향(좌/우회전)이 실제 궤적과 어긋나는 환각(hallucination) 이 발생한다. DaViNCi는 이를 기하 우선, 언어 나중(geometry-first, language-second) 의 2단계로 억제한다.

Stage 1 — 기하적 방향 이벤트 추출 (수식):

궤적을 세그먼트로 나누고, 인접 세그먼트의 방향 벡터 외적 부호로 좌/우회전을 판정한다.

연속 좌표열: P = {p_0, p_1, ..., p_N},  p_i = (x_i, y_i)

세그먼트 방향 벡터:
   v_i = p_{i+1} - p_i          # i번째 진행 방향

세그먼트 경계(junction) j에서의 회전 판정:
   cross_j = v_{j-1}.x * v_j.y  -  v_{j-1}.y * v_j.x     # 2D 외적(스칼라)

   if cross_j >  τ :  turn = "left"      # 반시계
   if cross_j < -τ :  turn = "right"     # 시계
   else            :  turn = "straight"  # 임계 τ 이내면 직진

여기서 τ는 미세한 조향 흔들림을 직진으로 흡수하는 임계값이다. 이렇게 추출된 방향 이벤트 시퀀스(예: [straight, left, straight, right, arrive])는 궤적 기하로부터 결정론적으로 얻어지므로 LLM 환각의 영향을 받지 않는다.

Stage 2 — 멀티모달 LLM 캡셔닝(제약 하):

1인칭 주행 영상 프레임과 Stage 1의 방향 시퀀스를 함께 Tongyi Qwen3-VL-Plus 멀티모달 API에 입력하고, 커스텀 프롬프트로 "생성되는 자연어 지시의 회전 방향이 Stage 1 시퀀스와 반드시 일치해야 한다"는 제약을 건다.

Prompt(개념):
  "다음은 1인칭 주행 영상이다. 그리고 검증된 방향 시퀀스는 [S,L,S,R,arrive]이다.
   이 영상을 보고 랜드마크(건물/간판/지형)를 참조하는 자연어 내비게이션 지시를
   작성하되, 언급되는 좌/우회전은 반드시 위 시퀀스를 따를 것."
   →
LLM 출력(예):
  "직진하다가 박물관이 보이는 교차로에서 좌회전하고,
   쇼핑몰을 지나 다음 교차로에서 우회전한 뒤 지하철역 앞에 도착하라."

이 설계의 장점:

  • 랜드마크 그라운딩: 시각(LLM)이 실제 건물·간판을 참조하므로 지시가 street-view의 시각 단서와 연결된다.
  • 방향 정합성 보장: 언어의 방향이 기하로 앵커링되어, 지시-궤적 불일치라는 라벨 노이즈를 원천 차단.
  • 확장성: API 기반이므로 6,933 궤적 전체에 자동 적용 가능(사람 주석 병목 제거).

이는 CityWalker가 Visual Odometry로 action label을 자동 생성해 VLM 프롬프트 비용을 없앤 것과 대비되는 상보적 전략이다. CityWalker는 "행동 라벨"을 기하로 자동화했고, DaViNCi는 "언어 라벨"을 기하로 앵커링했다.

3.3 이산-연속 이중 프로토콜 (Discrete↔Continuous Dual Protocol)

DaViNCi의 실험적 무기는 동일 궤적을 이산·연속 두 방식으로 평가하는 것이다.

                    ┌──────────────────────────┐
  원천 연속 궤적 ───▶│ (A) 이산 그래프로 변환    │──▶ 기존 방식 평가(순간이동)
   (JSON, 위상+기하) │     road/lane ID 노드화   │
                    └──────────────────────────┘
                    ┌──────────────────────────┐
                    │ (B) 연속 환경 그대로 유지 │──▶ 연속 행동 평가(조향/속도/정지)
                    │     CARLA 물리 롤아웃      │
                    └──────────────────────────┘

같은 지시·같은 목적지에 대해 (A)와 (B)의 성공률 차이를 재면, "추상화가 감춘 난이도"를 순수 분리해서 측정할 수 있다. 저자들의 결과(§5)는 이 격차가 상당함을 보인다: 이산에서도 기존 데이터셋 대비 10%p 이상 하락하고, 연속으로 가면 하락이 더 심해진다.

3.4 동적 요소 주입 (Dynamic Element Injection)

CARLA의 Traffic Manager를 사용해 차량·보행자·자전거를 개수 단위로 통제하며 스폰한다. 동적 요소 수를 0, 소수, 다수로 바꿔가며 같은 궤적을 평가하면, 성능이 동적 밀도에 따라 어떻게 열화되는지의 곡선(dose-response) 을 얻는다. 이는 정적 벤치마크에서는 존재할 수 없는 축으로, DaViNCi가 "동적"을 이름에 넣은 근거다.

3.5 행동 입도 스윕 (Action Granularity Sweep)

연속 환경에서는 에이전트가 한 스텝에 얼마나 멀리 움직이는지(예: 5m vs 12m)가 성능에 직접 영향을 준다. 입도가 크면(12m) 결정 횟수는 줄지만 지시-행동 정렬이 거칠어지고, 입도가 작으면(5m) 세밀하지만 장기 크레딧 할당이 어려워진다. DaViNCi는 입도를 변수로 스윕하여 이 트레이드오프를 정량화한다(§5.3의 Table 4).

형식적으로, 입도 g가 주어지면 연속 궤적 P를 재이산화(re-discretization)한 유효 결정 시퀀스의 길이는 대략:

K(g) ≈ L_path / g          # L_path: 궤적 총 길이

로 스케일한다. 지시가 참조하는 방향 이벤트 수 M(좌/우회전 등)은 g와 무관하게 고정되므로, 유효 "신호 대 결정 비율"은 M / K(g) ≈ M·g / L_path가 된다. g가 커질수록 이 비율은 커져(결정당 정보 밀도↑) 크레딧 할당은 쉬워지지만, 각 결정이 커버하는 물리 거리가 길어져 한 번의 오조향이 곧바로 큰 경로 이탈로 이어진다. 반대로 g가 작으면 개별 오차는 작지만 K(g)가 커져 장기 의존성 학습 부담이 증가한다. Table 4가 비단조(최적점 존재) 경향을 보이는 것은 이 상충의 자연스러운 귀결이다.

3.6 라벨링 철학: 기하 앵커링의 두 얼굴 (Geometry-Anchored Labeling)

DaViNCi 파이프라인을 한 단계 추상화하면, "라벨 노이즈를 기하로 제거한다" 는 단일 원칙으로 수렴한다. VLN 데이터셋의 두 라벨 — (i) 행동 라벨(어디로 움직였나)과 (ii) 언어 라벨(무엇을 지시했나) — 은 전통적으로 서로 다른 출처(자동 vs 사람/LLM)에서 와서 정합이 깨지기 쉽다. DaViNCi는 두 라벨을 같은 연속 궤적 기하에 앵커링한다:

                    연속 궤적 기하 P (단일 진실원천)
                   /                              \
     [외적 방향 이벤트]                      [1인칭 렌더 프레임]
       S/L/R 시퀀스  ── 제약(constraint) ──▶  Qwen3-VL 캡션
            │                                        │
            └──────────  방향 정합 보장  ────────────┘

이 구조의 이론적 함의는 라벨 정합이 설계상 보장(by construction) 된다는 점이다. LLM이 아무리 환각을 일으켜도, 방향 시퀀스라는 하드 제약이 좌/우회전 정합을 강제하므로, "좌회전하라고 했는데 실제로는 우회전하는 궤적" 같은 치명적 라벨 오류가 원천적으로 생성되지 않는다. 사람 검수로 이런 오류를 사후 제거하는 대신, 생성 단계에서 봉쇄한다는 점에서 확장성(6,933 궤적 자동)과 품질을 동시에 얻는다. 다만 이 앵커링은 "이산 방향 이벤트" 수준에서만 작동하므로, 곡률·속도 같은 연속 속성의 정합은 보장하지 못한다(§8.2 한계 참조).

5. 실험 결과 및 성능 (Experimental Results)

5.1 데이터셋 (Datasets)

  • DaViNCi(본 논문): CARLA 6 Towns, 6,933 궤적, 연속+동적. 이산/연속 이중 평가.
  • 비교 기준: 기존 이산 실외 VLN 데이터셋(Touchdown 계열)에서의 동일 모델 성능(성공률)을 참조점으로 사용.

5.2 평가 지표 (Evaluation Metrics)

실외 VLN 표준 지표를 사용:

  • SR (Success Rate): 목적지 도착 성공률(허용 반경 내 도달).
  • SPL (Success weighted by Path Length): 경로 효율을 반영한 성공률. SPL = (1/N) Σ S_i · ℓ_i / max(p_i, ℓ_i) (S: 성공여부, ℓ: 최단경로길이, p: 실제이동길이).
  • 연속 설정 부가 변수: stop 행동 유무(에이전트가 스스로 정지를 선언하는지), 행동 입도(5m/12m), 동적 요소 개수.

5.3 정량적 결과 (Quantitative Results)

논문 프로젝트 페이지가 제시하는 결과표 구조는 다음과 같다(구체 수치는 본문 표에 준함, 여기서는 구조와 경향을 정리):

Table 2 — 이산 환경 결과 (4개 모델). DaViNCi를 이산 그래프로 변환해 기존 데이터셋과 동일 프로토콜로 평가. 핵심 발견: 동일 SOTA 모델이 DaViNCi(이산)에서 기존 데이터셋 대비 성공률 10%p 이상 하락. 즉 데이터 자체(맵 다양성·궤적 구성)만으로도 기존 벤치마크가 과대평가되어 있었음을 시사.

Table 3 — 연속 환경 결과 (DaViNCi, stop 행동 유/무). 연속 설정에서 성능이 이산 대비 추가 하락. stop 행동을 명시적으로 부여하는지가 성능에 유의한 영향을 미침 — 에이전트가 "언제 도착했는가"를 스스로 판단하는 능력이 연속 VLN의 새로운 병목임을 드러냄.

Table 4 — 행동 입도별 성능 (5m vs 12m). 입도가 성능-정렬 트레이드오프를 만든다. 큰 입도(12m)는 결정 수를 줄이지만 지시 정렬이 거칠어지고, 작은 입도(5m)는 세밀하지만 장기 크레딧 할당 부담이 커짐. 최적 입도는 모델·맵에 의존.

Table 5 — 동적 요소 개수별 성능. 동적 요소가 늘수록 성공률이 단조 감소하는 dose-response 경향. 정적 벤치마크에서는 볼 수 없던 열화 곡선으로, "동적 강건성"이라는 새 평가 축을 제공.

경향 요약 (정성):

축 조작 성능 방향
데이터셋 기존 → DaViNCi(이산) SR −10%p 이상
행동표현 이산 → 연속 SR 추가 하락(더 큼)
stop 행동 무 → 유 유의한 변화(도착판단 병목 노출)
입도 5m ↔ 12m 비단조(트레이드오프, 최적점 존재)
동적밀도 0 → 다수 SR 단조 감소

결과의 해석 — 세 층위의 난이도 분해. DaViNCi 실험의 진가는 성능 하락을 세 층위로 귀속(attribution) 시킨다는 데 있다:

  1. 데이터 층위(Table 2, 이산-이산 비교): DaViNCi를 이산 그래프로 변환해도 기존 데이터셋보다 어렵다. 이는 행동 표현과 무관한 순수 데이터 난이도(맵 다양성, 궤적 길이 분포, 랜드마크 밀도) 기여분이다. −10%p의 상당 부분이 여기서 온다.
  2. 표현 층위(Table 2→3, 이산→연속): 같은 DaViNCi를 연속으로 평가하면 추가 하락한다. 이 증분이 연속 행동 자체가 부과하는 난이도로, 이산 벤치마크가 통째로 감춰온 부분이다.
  3. 환경 층위(Table 5, 동적 밀도): 연속 위에 동적 요소를 더하면 또 하락한다. 이는 동역학 강건성의 결핍을 노출한다.

이 삼분해가 방법론적으로 중요한 이유는, 후속 연구자가 자기 모델의 실패를 "데이터가 어려운가 / 연속 제어를 못하나 / 동적 회피를 못하나"로 진단적으로 분리할 수 있게 하기 때문이다. 단일 리더보드 점수만 제공하는 데이터셋과 질적으로 구별되는 지점이다.

stop 행동의 재발견. Table 3에서 stop 행동 유무가 유의한 차이를 낸다는 사실은 미묘하지만 중요하다. 이산 그래프에서 "도착"은 목적지 노드에 놓이면 자동 판정되므로, 에이전트는 언제 멈출지를 학습할 필요가 없었다. 연속 환경에서는 목적지 반경 내에서 스스로 정지를 선언해야 하며, 너무 일찍/늦게 멈추면 실패한다. 즉 연속화는 "도착 판단(stopping/termination)"이라는, 실내 VLN에서는 잘 다뤄졌으나 실외 이산 벤치마크에서는 사라졌던 능력을 다시 필수로 되살린다. DaViNCi가 이를 변수로 노출한 것은 실외 VLN 평가의 사각지대를 정확히 짚은 설계다.

5.4 리얼월드 실험 (Real-world Experiments)

DaViNCi는 순수 시뮬레이션(CARLA) 기반이며 실차/실로봇 실험은 포함하지 않는다. 다만 연구의 명시적 동기가 "이산 그래프의 sim-to-real 괴리 해소"이므로, CARLA의 연속 물리와 동적 트래픽을 통해 실세계에 한 걸음 더 가까운 시뮬레이션(sim-to-real gap 축소) 을 지향한다. 실로봇 배치는 후속 과제로 남는다.

5.5 베이스라인 (Baselines)

세 종의 실외 VLN SOTA를 평가:

  • VELMA: LLM 기반 에이전트. 궤적을 언어적으로 표현하고 CLIP으로 랜드마크를 검출해 다음 행동을 결정.
  • FLAME: 스트리트뷰 서술 + 경로 요약을 결합한 3단계 적응 알고리즘.
  • Mem4Nav: octree voxel 인덱싱 + 시맨틱 위상 그래프의 계층적 공간 메모리 시스템.

세 방법 모두 원래 이산 벤치마크에서 우수했으나, DaViNCi의 연속·동적 설정에서 일제히 성능이 하락 — 벤치마크의 변별력을 입증.

6. 핵심 기여점 (Key Contributions)

  1. 최초의 연속+동적 실외 VLN 데이터셋. 연속 행동과 동적 요소를 동시에 도입한 실외 VLN 벤치마크는 DaViNCi가 처음이다. 기존 outdoor VLN이 이산·정적 그래프에 갇혀 있던 근본 한계를 정면으로 겨냥.

  2. 이산-연속 이중 평가 프로토콜. 하나의 연속 궤적에서 이산 그래프와 연속 환경을 모두 파생시켜, 추상화가 감춘 난이도(10%p+)를 순수 분리 측정. 이는 벤치마크 방법론 자체의 기여다.

  3. 기하 앵커링 2단계 지시 생성 파이프라인. 외적 기반 방향 추출(Stage 1)로 LLM 캡셔닝(Stage 2)을 제약해, 6,933 궤적 규모에서 지시-궤적 정합성을 자동 보장. 사람 주석 병목 없이 확장 가능한 라벨링.

  4. 난이도 축의 해부. 행동 입도(Table 4)와 동적 밀도(Table 5)를 독립 변수로 스윕해, 실외 VLN 성능이 어떤 요인에 얼마나 민감한지의 정량적 감도 분석을 제공. 특히 연속 설정에서 stop(도착 판단) 능력을 새로운 병목으로 부각.

  5. 공개 아티팩트. 데이터셋을 즉시 다운로드 가능하게 공개하고 프로젝트 페이지를 유지 — 후속 연구가 곧바로 재현·확장 가능.

7. 구현 상세 (Implementation Details)

  • 시뮬레이터: CARLA (자율주행용 오픈소스 엔진).
  • 맵: Town01/02/03/04/05/10 (시골고속도로도심 스펙트럼), 주 수집지 Town10.
  • 샘플링: ego 자유주행, 1초 고정 간격 상태 기록.
  • 궤적 저장 스키마(JSON): road ID, lane ID, (x, y, z), (yaw, pitch, roll).
  • 규모: 6,933 궤적 / 6 맵.
  • 지시 생성 LLM: Tongyi Qwen3-VL-Plus 멀티모달 API + 커스텀 프롬프트(방향 제약).
  • 방향 추출: 세그먼트 방향 벡터의 2D 외적 부호 + 임계 τ(미세 조향 흡수).
  • 행동 입도: 5m / 12m 비교(Table 4).
  • 동적 요소: CARLA Traffic Manager로 차량/보행자/자전거를 개수 통제 스폰.
  • 평가 지표: SR, SPL; 연속 설정에서 stop 행동 유무 변수화.
  • 베이스라인: VELMA, FLAME, Mem4Nav.

수식(방향 판정) 재확인:

v_i    = p_{i+1} - p_i
cross  = v_prev.x * v_cur.y - v_prev.y * v_cur.x
sign(cross) > 0 → left,  < 0 → right,  |cross| ≤ τ → straight

8. 고급 주제 (Advanced Topics)

8.1 확장성 (Scalability)

파이프라인이 전적으로 시뮬레이션+API 기반이므로 수집 비용이 사실상 GPU/API 시간에 비례한다. 새 CARLA 타운을 추가하거나 궤적 밀도를 높이면 데이터셋을 손쉽게 키울 수 있다. 사람 주석이 방향 정합성 검증에서 배제되므로 병목이 없다.

8.2 한계점 (Limitations)

  • 시뮬레이션 도메인 갭: CARLA는 실사보다 텍스처·조명·보행자 거동이 단순하다. DaViNCi가 "이산→연속" 갭은 좁히지만 "시뮬→실사" 갭은 여전히 남는다. 실로봇 검증 부재가 가장 큰 약점.
  • 지시 다양성의 상한: 지시가 LLM 캡션이므로 어휘·문체 다양성이 Qwen3-VL-Plus의 분포에 종속. 사람 지시 특유의 모호성·구어체·오류가 과소 표현될 수 있음.
  • 방향 추출의 이산성: Stage 1이 좌/우/직진의 거친 이벤트만 추출하므로, "완만한 커브를 따라가라" 같은 연속적 곡률 지시는 약하게 표현될 수 있음.
  • 동적 요소의 상호작용 라벨 부재: 동적 요소는 밀도로만 통제되며, "앞차를 추월하라"처럼 동적 개체를 지시가 직접 참조하지는 않음 — 상호작용 그라운딩은 미래 과제.
  • 코드(에이전트/평가) 미공개: 데이터셋은 공개되었으나 평가 파이프라인 코드가 웹페이지 저장소에만 있어, 표(Table 2–5) 재현에는 저자 프로토콜 문서 의존.

8.3 향후 방향 (Future Directions)

  • 실로봇/실차 전이 검증: CARLA 학습 정책을 실차 또는 사족 로봇으로 전이해 sim-to-real 격차 실측.
  • 동적 개체 참조 지시: "빨간 차 뒤를 따라가다 버스가 서면 우회전" 같은 동적-그라운딩 지시로 확장.
  • 연속 곡률 지시: 곡률·속도 프로파일을 포함한 연속 언어 지시로 표현력 강화.
  • 폐루프 학습 벤치마크: 현재는 주로 평가용. RL/IL 학습을 위한 표준 학습 스플릿·리더보드 정착.

9. 비교 분석 (Comparative Analysis)

DaViNCi는 실외 VLN 트랙에 속하므로, 같은 트랙의 실외/도시 항해 선행 리뷰들과 비교한다. 가장 인접한 선행은 CityWalker: Learning Embodied Urban Navigation from Web-Scale Videos(CVPR 2025), WalkWithMe(맵-프리 실외 소셜 내비게이션), Route2Step(VLN 진행도-실행 분해)이다.

9.2 장단점 분석

DaViNCi의 강점:

  • 문제 정의의 정확성: "이산 그래프가 실외 VLN을 과대평가한다"는 가설을 이중 프로토콜로 직접 반증 가능하게 설계했다. CityWalker가 "더 좋은 정책"을, Route2Step이 "더 좋은 감독 구조"를 제안했다면, DaViNCi는 "우리가 무엇을 측정하는가"를 교정한다 — 벤치마크 층위의 기여로, 파급 범위가 넓다.
  • 라벨 정합성의 공학적 우수함: 기하 앵커링 2단계 지시 생성은 CityWalker의 VO 자동 라벨링과 철학이 같다(사람 주석 제거, 기하로 앵커링). CityWalker는 행동을, DaViNCi는 언어를 자동·정합 라벨링했다는 점에서 상보적.
  • 다축 감도 분석: 입도·동적밀도·stop을 독립 변수로 분해한 것은 단일 점수만 보고하는 대다수 데이터셋 논문보다 진단력이 높다.

DaViNCi의 약점:

  • 실로봇 부재: CityWalker는 Unitree Go1로 실세계 도시 항해를 실증했다. DaViNCi는 sim-to-real을 동기로 내세우지만 정작 실기 검증이 없어, "연속·동적이 실사에서도 그만큼 어렵다"는 주장이 시뮬 내부 증거에 머문다.
  • 실사 도메인 갭: CityWalker의 데이터는 실사 영상이라 텍스처·보행자 거동이 진짜다. DaViNCi는 CARLA 렌더라 시각 사실성이 낮고, 이것이 VELMA/FLAME 같은 CLIP·VLM 기반 방법의 성능 하락 일부를 시뮬 아티팩트로 오귀속할 위험이 있다.
  • 언어 다양성 종속: WalkWithMe가 다루는 "사람의 추상적·구어체 지시"의 난해함이, LLM 캡션으로 생성된 DaViNCi 지시에는 덜 반영된다. 실제 사용자 지시의 모호성 축이 약하다.

9.3 실적용 가능성 평가

  • 연구 인프라로서: 매우 높음. 데이터셋이 공개되어 있고, 이산·연속 이중 평가라는 표준 프로토콜을 제공하므로, 실외 VLN 연구자가 자기 모델의 sim-to-real robustness를 표준적으로 스트레스 테스트하는 데 즉시 유용하다.
  • 로봇 배치로서: 간접적. DaViNCi로 학습/평가한 정책을 실차·실로봇에 올리려면 CityWalker류의 실사 데이터·실기 파이프라인과 결합해야 한다. DaViNCi는 "실사 학습 전 시뮬 스트레스 테스트" 단계에 적합.
  • 결합 유망성: CityWalker(실사 정책) × DaViNCi(통제 가능한 연속·동적 평가) 조합이 가장 강력하다. 실사 영상으로 스케일 학습하고, CARLA에서 동적 밀도·입도를 통제하며 실패 모드를 해부하는 워크플로가 자연스럽다.

9.4 연구 방향성 평가

DaViNCi는 실외 VLN을 "모델 경쟁"에서 "평가 현실성"으로 재프레이밍하는 흐름에 선다. Route2Step이 실내 VLN에서 "감독 구조를 나눠 오류 귀속을 개선"했다면, DaViNCi는 실외에서 "평가 설정을 현실화해 성능 착시를 제거"한다 — 층위는 다르지만 둘 다 "무엇을 측정/감독하는가"의 재검토라는 공통 정신을 공유한다. 데이터셋 논문으로서 파급력은 후속 연구가 이 벤치마크를 표준 채택하는지에 달려 있으며, 즉시 다운로드 가능한 공개·이중 프로토콜의 명료함은 채택 장벽을 낮춘다.

11. 결론 (Conclusion)

혁신성. DaViNCi의 진짜 기여는 새 모델이 아니라 새 자(尺) 다. 실외 VLN 커뮤니티가 오랫동안 당연시해온 이산 위상 그래프 추상화가, 실은 문제를 상당히 쉽게 만들어 성능을 과대평가해왔음을 이중(이산↔연속) 프로토콜로 정량 폭로한다(이산에서도 −10%p, 연속에서 더 큰 하락). 여기에 동적 요소를 개수 단위로 통제하고 행동 입도를 스윕하는 다축 감도 분석을 얹어, 실외 VLN 난이도를 처음으로 성분 분해했다. 기하 앵커링 2단계 지시 생성은 6,933 궤적 규모에서 지시-궤적 정합을 사람 주석 없이 보장하는 견고한 공학이다.

실용적 의의. 데이터셋이 즉시 다운로드 가능하고 이중 평가 프로토콜이 명료해, 연구자가 자기 정책의 sim-to-real robustness를 표준적으로 스트레스 테스트할 인프라로 바로 쓸 수 있다. 특히 CityWalker류 실사 정책 학습과 결합하면 "실사 스케일 학습 + CARLA 통제 평가"의 강력한 워크플로가 된다.

향후 연구 방향. 최우선은 실로봇/실차 전이 검증으로 sim-to-real 주장을 실측하는 것이다. 이어 (a) 동적 개체를 직접 참조하는 상호작용 지시, (b) 곡률·속도를 포함한 연속 언어 지시, (c) 폐루프 학습용 표준 스플릿·리더보드 정착이 벤치마크의 수명을 좌우할 것이다. 시뮬 도메인 갭과 언어 다양성 종속(Qwen 분포)이 남은 약점이지만, "평가 현실성"이라는 올바른 질문을 던졌다는 점에서 DaViNCi는 실외 VLN 벤치마크 계보에서 의미 있는 이정표다.
