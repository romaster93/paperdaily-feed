1.2 연구 목표 (Research Objective)

StreamVLN은 연속 비주얼 스트림을 실시간으로 처리하면서 언어 지시에 따라 저지연(low-latency)으로 행동을 생성하는 VLN 프레임워크다. 핵심 문제 의식은 다음과 같다:

"실세계 VLN 에이전트는 끊임없이 들어오는 비디오 프레임을
 (1) 세밀하게 이해하고(fine-grained visual understanding),
 (2) 장기간의 과거 맥락을 기억하며(long-context modeling),
 (3) 그러면서도 매 스텝 빠르게 행동을 출력해야 한다(low latency).
 그러나 이 셋은 서로 충돌하는 트레이드오프 관계에 있다."

기존 Video-LLM 기반 VLN(NaVid, NaVILA)은 매 스텝 전체 과거 프레임을 다시 처리하거나(연산 폭발), 고정 개수 프레임으로 다운샘플(맥락 손실)하는 양극단 사이에서 타협해 왔다. StreamVLN은 SlowFast 컨텍스트 모델링이라는 단일 설계로 이 세 요구를 동시에 만족시키는 것을 목표로 한다:

  • Fast-streaming dialogue context — 최근 대화 턴의 KV 캐시를 재사용해 매 스텝의 디코딩을 빠르게(0.27s/4액션) 유지.
  • Slow-updating memory context — 3D-aware 토큰 프루닝으로 과거 관측을 소수의 메모리 토큰으로 압축, 길이에 무관한 바운드된 컨텍스트 크기를 보장.

기여의 핵심은 "정확도를 거의 희생하지 않으면서 추론 비용과 메모리를 시퀀스 길이에 무관하게 상수로 묶는다"는 점이며, 이를 VLN-CE(R2R-CE, RxR-CE)에서 SOTA로 입증하고 Unitree Go2 사족보행 로봇에 실제 배포한다.

[StreamVLN의 한 줄 핵심]

기존: 정확도 ↔ 속도 ↔ 메모리 = 셋 중 둘만 선택 가능
StreamVLN: KV재사용(속도) + voxel 프루닝(메모리) → 정확도 유지하며 셋 다 달성

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 스트리밍 입력의 연산 폭발 (Quadratic Blow-up)

VLN-CE에서 한 에피소드는 평균 수십~수백 스텝이며, 각 스텝마다 비디오 프레임이 추가된다. Transformer의 self-attention은 시퀀스 길이에 대해 O(L²)이므로, 단순히 모든 프레임을 누적하면 다음 문제가 발생한다:

[Naive full-context VLM-VLN의 비용 폭발]

스텝 t에서 누적 토큰 수 ≈ t × (프레임당 비전 토큰 수)

예: 프레임당 196 토큰, 100 스텝 →
    프리필 토큰 ≈ 100 × 196 ≈ 19.6K 토큰
    self-attention 비용 ∝ (19.6K)² → 메모리·연산 폭발
    KV 캐시 ∝ 토큰 수 → 길이에 비례해 선형 증가 (GB 단위)

결과: 장기 에피소드에서 (a) OOM, (b) 스텝당 레이턴시가 점점 증가
      → 실시간 제어(≥1Hz) 불가

B. 다운샘플링의 맥락 손실

반대로 NaVid 류는 비디오를 고정 개수 프레임으로 균일 샘플링하여 비용을 묶지만, 이는 세밀한 시각 정보(좁은 통로, 작은 표지물)와 최근 행동 이력을 잃는다. 특히 "방금 지나친 문"이나 "직전에 회전한 방향" 같은 단기 맥락이 사라지면 행동 일관성이 깨진다.

C. KV 캐시 재사용과 컨텍스트 압축의 양립 불가

레이턴시를 줄이는 표준 기법은 KV 캐시 재사용이다. 그러나 일반적인 토큰 프루닝(예: 평균 풀링, 토큰 병합)은 이전에 계산된 키-값을 변경하므로, 캐시를 무효화시켜 재사용을 불가능하게 만든다. 즉 "압축(메모리 절감)"과 "캐시 재사용(속도)"이 충돌한다.

[기존 압축 기법의 캐시 충돌]

일반 토큰 병합/풀링:
  토큰 A, B를 평균 → 새 토큰 C 생성
  → A, B의 기존 KV는 무효 → 재계산 필요 → 캐시 재사용 불가

StreamVLN이 풀어야 할 제약:
  "이미 계산된 KV를 건드리지 않고(=재사용 유지)
   동시에 토큰 수를 줄이는(=메모리 절감)" 프루닝이 필요

D. 행동 표현의 토큰 효율

VLM이 자연어로 행동을 풀어 쓰면("move forward 25 centimeters and turn left") 토큰 수가 많아 디코딩이 느려진다. 반대로 너무 흔한 단어를 행동 토큰으로 쓰면 일반 텍스트 생성과 의미가 섞여 혼동된다. 저지연을 위해서는 최소 토큰으로 명확히 구분되는 행동 표현이 필요하다.

2.2 핵심 해결책

StreamVLN의 세 가지 핵심 혁신:

[StreamVLN의 혁신 요소 3가지]

혁신 1: Fast-Streaming Dialogue Context (슬라이딩 윈도우 + KV 재사용)
  최근 N=8 대화 턴만 활성 윈도우로 유지
  윈도우 내 관측 토큰의 KV는 그대로 재사용(=비-관측 토큰만 폐기)
  → 매 스텝 디코딩 레이턴시를 상수로 유지

혁신 2: Slow-Updating Memory Context (Voxel 기반 3D-aware 프루닝)
  윈도우를 벗어난 과거 관측을 메모리 토큰 {M_0,...,M_j}로 압축
  3D 공간 중복 토큰을 "최신 관측만 남기는" 방식으로 제거
  → 이미 계산된 KV를 변경하지 않아 캐시 재사용과 양립

혁신 3: 효율적 행동 표현 + 멀티소스 Co-Training
  소수 토큰의 심볼릭 행동 표현(0.27s/4액션)
  Oracle VLN + DAgger + VideoQA + MMC4 혼합으로 일반 능력 유지

3. 핵심 방법론 (Core Methods)

3.1 SlowFast 컨텍스트 모델링의 형식화 (Formalization)

VLN을 인터리빙된 비전-언어-행동 시퀀스로 본다. 스텝 i의 대화(dialogue) 단위는 관측-행동 쌍 d_i = (o_i, a_i)이며, 전체 입력은 o_1 a_1 o_2 a_2 ... o_{i-1} a_{i-1} 형태로 누적된다. 여기서 o_i는 그 스텝의 비주얼 토큰(들), a_i는 행동 토큰이다.

StreamVLN은 이 시퀀스를 두 갈래의 컨텍스트로 분해한다:

[SlowFast 컨텍스트 분해 — 디코더 입력 수식]

윈도우 정의 (Fast):
  W_j = [ o_{i-N+1} a_{i-N+1} ... o_i a_i ]
  N   = 슬라이딩 윈도우 크기 (= 8 대화 턴)
  → 가장 최근 N개 대화 턴만 활성 컨텍스트로 유지

행동 생성:
  a_i^{W_{j+1}} = Decoder( o_i,
                          { M_0, M_1, ..., M_j },          ← Slow (메모리)
                          { k_{i-N+1} v_{i-N+1}, ...,      ← Fast (KV 캐시)
                            k_{i-1}    v_{i-1}    } )

기호:
  M_0..M_j  = 윈도우를 벗어난 과거를 압축한 "메모리 토큰" 집합 (느리게 갱신)
  k_* v_*   = 활성 윈도우 내 최근 대화의 키-값 캐시 (빠르게 재사용)
  Decoder   = LLaVA-Video(Qwen2-7B) 디코더

핵심 트릭 — 윈도우 전이 시 무엇을 버리는가: 윈도우가 다음으로 슬라이딩할 때, StreamVLN은 가장 오래된 대화 턴에서 프롬프트·행동 토큰 등 비-관측(non-observation) 토큰의 KV는 폐기하고, 관측(observation) 토큰의 KV만 남겨 메모리 토큰으로 압축한다. 이렇게 하면 활성 윈도우의 KV 캐시는 다음 스텝에서도 그대로 재사용되어 프리필을 반복하지 않는다.

[윈도우 슬라이딩과 메모리 누적]

윈도우 W_0:  [o1 a1 ... o8 a8]            활성 KV 캐시 보유
   ↓ 전이                              비-관측 토큰 폐기, 관측 → M_0
윈도우 W_1:  [o9 a9 ... o16 a16]          + 메모리 {M_0}
   ↓ 전이
윈도우 W_2:  [o17 a17 ... o24 a24]        + 메모리 {M_0, M_1}
   ↓ ...
                                         메모리는 voxel 프루닝으로 압축돼
                                         "선형 증가"가 아닌 "상수에 수렴"

이 설계의 의의는 레이턴시-맥락의 분리(decoupling)다. Fast 경로는 최근 맥락을 KV 재사용으로 빠르게 처리하고(상수 레이턴시), Slow 경로는 먼 과거를 압축 메모리로 보존(상수 메모리)한다.

3.2 Voxel 기반 3D-Aware 토큰 프루닝 (Algorithm 1)

메모리 토큰 M_j를 생성하는 핵심은 공간적으로 중복된 비전 토큰을 제거하는 voxel-based pruning이다. 에이전트가 같은 장소를 여러 프레임에 걸쳐 보면, 그 영역의 토큰은 거의 동일한 3D 위치를 가리킨다 — 즉 시간이 다를 뿐 공간적으로 중복이다.

[Voxel-Based Spatial Pruning — 알고리즘 단계]

입력: 비디오 스트림의 2D 패치 토큰 + 대응 depth
출력: 프루닝 마스크 M ∈ {0,1}^{T×H×W}

단계 1) Back-projection (2D → 3D)
  각 패치 토큰 (t, y, x)를 depth d 로 3D 점으로 역투영:
    z_3d = d
    x_3d = (x - c_x) · d / f_x      (pinhole 카메라 모델)
    y_3d = (y - c_y) · d / f_y
  → 모든 프레임의 토큰이 "공유 3D 공간"에 배치됨

단계 2) Voxelization (3D 이산화)
  균일 voxel 그리드로 3D 점들을 이산화:
    voxel_id = floor( (x_3d, y_3d, z_3d) / voxel_size )
  → 시간에 걸쳐 같은 공간 영역이 같은 voxel_id로 묶임

단계 3) Selection rule (최신 관측만 보존)
  "주어진 시간 구간(duration) 안에서 서로 다른 프레임의
   여러 토큰이 같은 voxel에 투영되면, 가장 최근 관측의 토큰만 남긴다."
  → 공간 중복 제거. ★ 핵심: 기존 토큰을 '병합·변형'하지 않고
     '선택적으로 보존'하므로 이미 계산된 KV가 그대로 유효 → 캐시 재사용 양립

단계 4) Threshold filtering (프레임 단위 하한)
  각 타임프레임 t에서, 프루닝 후 남은 토큰 수가 θ·H·W 미만이면
  그 프레임 전체를 폐기(정보량이 너무 적은 프레임 제거).
  θ = 프레임 유지 임계 비율

왜 단순 풀링이 아니라 voxel 선택인가 — 2.1.C에서 본 충돌을 푸는 것이 정확히 이 지점이다. 평균 풀링/토큰 병합은 새 토큰을 만들어 KV를 무효화하지만, voxel pruning은 기존 토큰 중 일부를 그대로 고르는(masking) 연산이므로 보존된 토큰의 키-값이 변하지 않는다. 따라서 "메모리 절감"과 "KV 캐시 재사용"을 동시에 달성한다.

# voxel_based_pruning 의사코드 (논문 Algorithm 1 기반 재구성)
def voxel_based_pruning(patch_tokens, depths, K, fx, fy, cx, cy,
                        voxel_size, theta):
    T, H, W = patch_tokens.shape[:3]
    keep = np.zeros((T, H, W), dtype=bool)
    latest_in_voxel = {}                 # voxel_id -> (t, y, x)

    # 1~3) back-project, voxelize, keep only most-recent per voxel
    for t in range(T):
        for y in range(H):
            for x in range(W):
                d = depths[t, y, x]
                if d <= 0:               # invalid depth
                    continue
                z = d
                X = (x - cx) * d / fx
                Y = (y - cy) * d / fy
                vid = (int(X // voxel_size),
                       int(Y // voxel_size),
                       int(z // voxel_size))
                prev = latest_in_voxel.get(vid)
                if prev is None or prev[0] < t:     # this frame is newer
                    if prev is not None:
                        keep[prev] = False          # drop older duplicate
                    latest_in_voxel[vid] = (t, y, x)
                    keep[t, y, x] = True

    # 4) per-frame threshold: drop frames that became too sparse
    min_tokens = int(theta * H * W)
    for t in range(T):
        if keep[t].sum() < min_tokens:
            keep[t] = False              # discard whole frame

    return keep      # KV of surviving tokens unchanged -> cache reusable

이 프루닝은 입력 토큰의 약 20%를 제거하면서도 성능을 떨어뜨리기는커녕 오히려 향상시킨다(5.3 참조: +1.2% SR, +1.0% SPL) — 중복·잡음 토큰을 걸러내 신호 대 잡음비를 높이는 효과로 해석된다.

3.3 효율적 행동 표현 (Action Token Design)

StreamVLN은 행동을 소수의 심볼릭 토큰으로 표현한다. 자연어 서술(예: "move forward 25cm, turn left")은 정확도는 약간 높지만 23 토큰을 디코딩해야 해 1.00s가 걸린다. 반면 forward/left/right/stop을 텍스트 토큰으로 쓰거나 심볼(↑←→ 등)을 쓰면 단 4 토큰으로 0.27s에 4개 행동을 생성한다. 논문은 이 트레이드오프를 정량 비교하여(5.3의 행동 토큰 ablation) 심볼릭 표현을 채택, 실시간성을 확보한다.

[행동 표현별 트레이드오프]

표현                         토큰수   생성시간   R2R SR
--------------------------- ------- --------- -------
텍스트(forward/left/...)      4       0.27s     44.4%
자연어("move forward 25cm")   23      1.00s     47.2%
심볼릭(↑ ← → ⊥)  ★채택        4       0.27s     45.5%

→ 자연어 대비 정확도 -1.7%p이지만 속도 3.7배 (1.00s → 0.27s)
   심볼릭이 텍스트보다 +1.1%p (모호성 감소 효과)

3.4 멀티소스 Co-Training 데이터 레시피

VLN 능력과 일반 시각-언어 능력을 동시에 유지하기 위해 4종 데이터를 혼합한다:

데이터 소스 규모 목적
Oracle VLN (MP3D: R2R, R2R-EnvDrop, RxR) 450K 내비게이션 SFT(전문가 경로)
ScaleVLN (HM3D subset) 300K 장면 다양성 확대
DAgger 교정 궤적 (Habitat 최단경로 전문가) 240K 분포 이동 완화, 오류 복구
VideoQA (LLaVA-Video-178K + ScanQA) 248K 비디오·3D QA 일반 능력 유지
MMC4 인터리브 이미지-텍스트 230K VLM의 인터리빙 이해력 유지

DAgger의 역할: Oracle 경로만 학습하면 실제 롤아웃에서 분포 밖 상태에 빠졌을 때 복구하지 못한다(compounding error). DAgger는 초기 모델이 직접 굴린 궤적을 수집하고 최단경로 전문가로 정답 라벨을 붙여, "경로 이탈 → 복귀" 패턴을 명시적으로 학습시킨다.

4.1 데이터 흐름 설명

  1. 관측 인코딩: 매 스텝 RGB(-D) 프레임을 비전 인코더로 패치 토큰화한다.

  3. Slow 경로: 윈도우를 벗어난 과거 관측은 voxel pruning으로 압축돼 메모리 토큰 {M_0..M_j}로 누적. 메모리는 길이에 비례해 늘지 않고 상수에 수렴.

  5. 실행: 시뮬레이터(Habitat) 또는 실로봇(Go2)에서 액션 실행 → 다음 프레임 획득 → 반복.

6. 핵심 기여점 (Key Contributions)

기여 1: SlowFast 컨텍스트 모델링 (저지연 + 저메모리 동시 달성)

VLM 기반 VLN에서 "정확도-속도-메모리"의 삼중 트레이드오프를 단일 설계로 동시에 푸는 최초급 프레임워크다. Fast 경로(KV 재사용)와 Slow 경로(메모리 압축)를 분리해, 시퀀스 길이에 무관한 상수 추론 비용을 보장한다.

기여 2: KV 재사용과 양립하는 Voxel 기반 3D-Aware 프루닝

일반 토큰 병합/풀링이 KV를 무효화해 캐시 재사용과 충돌하는 문제를, "토큰을 변형하지 않고 선택적으로 보존"하는 voxel pruning으로 해결한다. ~20% 토큰을 제거하고도 SR/SPL이 향상되는 것을 정량 입증(+1.2/+1.0%p).

기여 3: VLN-CE SOTA + 추가 센서 없는 효율성

단안 RGB만으로 R2R-CE 56.9% SR / 51.9% SPL, RxR-CE 52.9% SR / 46.0% SPL을 달성. Depth+Odometry를 쓰는 ETPNav와 SPL·nDTW에서 동급 이상의 효율을 보여 저비용 플랫폼 배포 가능성을 입증.

기여 4: 실시간 실로봇 배포 + 코드/체크포인트 전면 공개

Unitree Go2에서 0.27s 추론 레이턴시로 실시간 동작을 실증하고, GitHub(OpenRobotLab/StreamVLN)에 학습/평가 스크립트와 벤치마크·실로봇 체크포인트 2종을 공개해 재현성을 확보했다.

8. 고급 주제 (Advanced Topics)

8.1 왜 "긴 컨텍스트가 더 나쁜가" — Lost-in-the-Middle 관점

Table 4에서 "전체 과거(all)" 컨텍스트가 압축 메모리(8×196)보다 SR이 5.5%p 낮은(40.0 vs 45.5) 현상은 LLM의 lost-in-the-middle 및 attention dilution으로 설명된다.

[긴 컨텍스트의 역설]

토큰 수 L 증가 → softmax attention이 더 많은 키에 분산
  → 정작 결정적인 "최근 관측·핵심 표지물"의 가중치 희석
  → 잡음 토큰(중복 프레임)이 신호를 묻음

StreamVLN의 답:
  Fast(최근 N턴 풀 디테일) + Slow(과거는 voxel로 압축)
  → 결정적 정보엔 충분한 attention, 과거엔 요약만
  → "all" 대비 +5.5%p SR

이는 단순히 "메모리를 아낀다"를 넘어, 압축이 성능을 끌어올린다는 점에서 효율성과 정확성이 같은 방향을 가리키는 드문 사례다.

[효율-정확도가 충돌하지 않는 두 지점]

지점 A — Voxel 프루닝 (5.3 Table 5):
  토큰 -20%   →   SR +1.2%p, SPL +1.0%p
  (메모리 절감이 곧 잡음 제거)

지점 B — 메모리 압축 vs all (8.1 Table 4):
  메모리 8×196(압축)  SR 45.5
  전체 history(all)   SR 40.0
  → 압축이 +5.5%p (attention 희석 회피)

결론: StreamVLN에서 "덜 본다"는 것이 "더 잘 본다"가 되는
      구조적 이유는, 제거되는 토큰이 대부분
      (a) 공간적으로 중복되거나 (b) attention을 분산시키는
      잡음이기 때문. 이것이 단순 다운샘플링과 결정적으로 다르다.

8.2 확장성 분석

더 강력한 백본으로의 확장: 현재 LLaVA-Video(Qwen2-7B) 기반이지만, SlowFast/voxel 프루닝은 백본에 독립적인 컨텍스트 관리 레이어이므로 Qwen2.5-VL, InternVL 등 더 강한 Video-LLM에 그대로 이식 가능하다.

연속 행동으로의 확장: 현재 심볼릭 이산 행동(forward/turn/stop)은 실시간성에 유리하나, 가변 속도·각도 같은 연속 제어는 불가능하다. 행동 헤드를 회귀형 또는 확산 정책(diffusion policy)으로 교체하면 부드러운 제어가 가능할 것이다.

다른 스트리밍 태스크로의 일반화: SlowFast 컨텍스트는 VLN에 국한되지 않는다. 스트리밍 비디오 QA, 긴 영상 요약, 실시간 로봇 조작 등 "연속 입력 + 저지연 출력"이 필요한 어떤 멀티모달 태스크에도 적용 가능한 일반적 패턴이다.

8.3 한계점 (Limitations)

[StreamVLN의 한계]

한계 1: Depth 의존성
  Voxel 프루닝의 back-projection이 depth를 요구.
  실험은 RGB-D(D455)를 사용 — 순수 단안 RGB만으로는
  monocular depth 추정 오차가 voxel 분류에 누적될 수 있음.
  (벤치마크 표기는 S.RGB이나 프루닝 단계엔 depth가 들어감)

한계 2: 실로봇 정량 평가 부족
  Workspace/Mall/Outdoor 등은 정성적 시연 위주.
  환경별 SR, 반복 횟수, 실패 모드 분류 부재.

한계 3: 이산 행동의 표현력
  고정 프리미티브(forward/turn/stop)만 지원.
  "45도만 회전" 같은 정밀 정량 명령·연속 제어 불가.

한계 4: 윈도우/메모리 하이퍼파라미터의 환경 의존성
  N=8, 8×196 메모리, voxel_size, θ 등이 MP3D 환경에서
  튜닝됨. 더 길거나 복잡한 실외 에피소드에서의 최적값은 미검증.

8.4 향후 연구 방향

[향후 방향]

방향 1: depth-free voxel 프루닝
  학습된 monocular depth(DepthAnything 등) 또는
  암묵적 3D 표현으로 RGB-D 의존 제거

방향 2: 적응적 윈도우/메모리
  에피소드 복잡도에 따라 N, 메모리 크기를 동적 조정

방향 3: 연속 행동 + 동적 장애물
  확산 정책 행동 헤드 + 움직이는 사람/물체 회피

방향 4: 실로봇 대규모 정량 벤치마크
  실세계 SR·실패 모드·sim-to-real gap의 체계적 측정

9. 비교 분석 (Comparative Analysis)

비교 대상은 같은 VLN 트랙에서 토픽이 가장 가까운 선행 리뷰 논문들이다: NaVILA(Video-LLM/VLA 기반 VLN의 직접 비교 베이스라인), AwareVLN(같은 단안-RGB VLN-CE의 최신 SOTA, 추론 증강 접근), 그리고 센서 기반 SOTA인 ETPNav.

9.2 장단점 분석

StreamVLN의 장점:

  1. 추론 효율 1위: 0.27s/4액션의 레이턴시는 비교 군에서 가장 빠르다. AwareVLN(~1 FPS)·NaVILA(full history 재처리)보다 실시간성에서 앞선다.
  2. 상수 메모리: SlowFast로 시퀀스 길이에 무관한 메모리를 보장 — 장기 에피소드에서 NaVILA류의 선형 증가 문제를 회피.
  3. 압축이 성능을 높이는 설계: voxel 프루닝이 ~20% 토큰을 줄이면서 SR을 +1.2%p 올리는 점은 다른 방법에 없는 우아함.
  4. SPL·nDTW 효율 우위: 단안 RGB만으로 ETPNav(추가 센서)와 SPL/nDTW 동급 이상.

StreamVLN의 단점:

  1. 절대 정확도는 AwareVLN에 뒤짐: R2R SR 56.9% vs AwareVLN 65.4%, RxR SR 52.9% vs 67.6%. AwareVLN의 선택적 구조 추론이 더 높은 절대 성능을 낸다.
  2. 추론 능력 부재: StreamVLN은 효율 중심으로, AwareVLN처럼 "진행도·계획"을 명시적으로 추론하지 않는다 → 설명 가능성·경로 이탈 자가 교정에서 열세.
  3. Depth 의존: voxel 프루닝이 depth back-projection을 요구해, 진정한 순수 단안 RGB는 아니다.
  4. 이산 행동 한계: 연속 제어 불가.

NaVILA 대비: StreamVLN은 NaVILA(SR 54.0%)를 R2R에서 +2.9%p 능가하면서도 레이턴시를 크게 단축. 단 NaVILA의 저수준 보행 정책(legged locomotion 분리)은 StreamVLN에 없다 — StreamVLN은 Go2의 내장 보행 컨트롤러에 심볼릭 명령을 보낸다.

AwareVLN 대비: 두 논문은 상호보완적이다. AwareVLN은 정확도·설명 가능성(선택적 자기인식 추론)을, StreamVLN은 효율·실시간성(SlowFast 컨텍스트)을 극대화한다. 흥미로운 통합 방향은 StreamVLN의 SlowFast 백본 위에 AwareVLN의 Key-Node 기반 선택적 추론을 얹어 "빠르면서 설명 가능한" VLN을 만드는 것이다.

ETPNav 대비: ETPNav는 Depth+Odometry로 BEV/토폴로지 맵을 사전 구성해 강한 공간 추론을 한다. StreamVLN은 그런 명시적 맵 없이도 SPL·nDTW에서 동급 효율을 내며, 센서 요구가 낮아 배포 비용이 적다.

9.3 실적용 가능성 평가

[배포 적합성]

추천 환경:    실내 모바일/사족 로봇의 실시간 지시 추종
추천 플랫폼:  RGB-D 카메라 탑재 로봇 + RTX 4090급 원격/엣지 GPU
강점:         0.27s 추론 → 실시간 루프 성립, 상수 메모리 → 장기 운용
주의:         실로봇 정량 신뢰도(>95%) 미검증, depth 신뢰도 의존,
              동적 장애물·연속 제어 시나리오는 추가 검증 필요

StreamVLN의 가장 큰 실용적 가치는 레이턴시와 메모리가 에피소드 길이에 따라 발산하지 않는다는 점이다. 이는 장시간 배회·순찰형 로봇에서 NaVILA류가 겪는 메모리 폭발/지연 증가를 구조적으로 제거한다. 다만 배송·안내 로봇이 요구하는 >95% 신뢰도를 위해선 실로봇 정량 평가와 failure-mode 분석이 선행되어야 한다.

9.4 연구 방향성 평가

StreamVLN은 VLN 연구에서 "효율적 컨텍스트 관리"라는 축을 선명하게 세웠다. AwareVLN이 "어떻게 더 똑똑하게 추론할 것인가"를 밀었다면, StreamVLN은 "어떻게 무한 스트림을 상수 비용으로 처리할 것인가"를 답한다. 두 축은 직교(orthogonal)하므로, 향후 VLN은 이 둘의 결합 — 효율적 백본 위의 선택적 추론 — 으로 수렴할 가능성이 높다. SlowFast 컨텍스트와 KV-재사용형 프루닝은 VLN을 넘어 모든 스트리밍 멀티모달 에이전트의 표준 빌딩블록이 될 잠재력이 있다.

11. 결론 (Conclusion)

혁신성 평가

StreamVLN은 VLM 기반 VLN의 고질적 삼중 트레이드오프(정확도-속도-메모리)를 단일하고 우아한 설계로 해소한 수작이다. 핵심은 두 가지다. 첫째, SlowFast 컨텍스트 분해 — 최근 맥락은 KV 캐시 재사용으로 빠르게(Fast), 먼 과거는 압축 메모리로 가볍게(Slow) 처리해 추론 비용과 메모리를 시퀀스 길이에 무관한 상수로 묶는다. 둘째, Voxel 기반 3D-aware 토큰 프루닝 — 토큰을 변형하지 않고 공간 중복만 선택적으로 제거하여 KV 재사용과 메모리 절감을 양립시키며, ~20% 토큰을 줄이고도 성능을 끌어올리는 드문 결과를 보인다.

실용적 의의

단안 RGB만으로 R2R-CE 56.9% SR / 51.9% SPL, RxR-CE 52.9% SR / 46.0% SPL을 달성하며, 추가 센서(Depth+Odometry)를 쓰는 ETPNav와 SPL·nDTW에서 동급 이상의 효율을 보인다. 무엇보다 0.27s/4액션의 추론 레이턴시로 Unitree Go2에 실제 배포되어 실시간 제어 루프가 성립함을 실증했다. 코드와 두 종의 체크포인트가 공개되어 재현성도 확보됐다. 장기 에피소드에서 메모리·지연이 발산하지 않는 상수 비용 특성은 순찰·배회형 실로봇에 특히 가치가 크다.

향후 연구 방향

가장 중요한 과제는 (1) depth 의존을 줄인 순수 단안 voxel 프루닝, (2) 실로봇의 정량 신뢰도·failure-mode 측정, (3) 연속 행동·동적 장애물 처리다. 또한 AwareVLN류의 선택적 자기인식 추론을 SlowFast 백본 위에 결합하면 "빠르면서 설명 가능한" 차세대 VLN으로 발전할 여지가 크다.
