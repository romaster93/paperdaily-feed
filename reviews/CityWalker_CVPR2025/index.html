Abstract 요약

동적 도시 환경에서의 embodied 네비게이션은 spatial reasoning과 common-sense norm 준수를 요구하는 어려운 문제다. 기존 시각 내비게이션 방법들은 지도 없는 환경에서 성능이 제한적이어서, 배송 로봇 같은 자율주행체의 배포에 장애가 된다.

CityWalker: 2,000+ 시간의 웹 수집 도시 보행 및 주행 비디오로 학습한 확장 가능한 데이터 기반 접근법

핵심 기여:

  1. Visual Odometry (VO)를 이용한 자동 action label 생성 → VLM prompting 비용 제거
  2. 대규모 데이터 확장성 (2000시간 처리 가능)
  3. Cross-domain, cross-embodiment 일반화 (걷기 비디오 + 주행 비디오)
  4. 실세계 검증: Unitree Go1 사족 로봇으로 복잡한 도시 환경 네비게이션

결과:

  • 실세계 네비게이션 성공률: 기존 SOTA (ViNT) 대비 +15-30%p 향상
  • 오프라인 평가: 모든 critical scenarios에서 향상 (Turn, Crossing, Detour, Proximity, Crowd)
  • 데이터 스케일링 효과: 1000시간 학습 후 fine-tuned 기존 방법 능가

섹션별 상세 분석

I. Introduction & Motivation

도시 네비게이션의 고유 도전:

실내 시뮬레이션 (Habitat) → Near-perfect
    vs
실제 도시 환경 → Multiple unsolved problems:
├─ 보행자 상호작용 (dense pedestrians)
├─ 신호등 준수 (traffic rules)
├─ 갑작스러운 장애물 (sudden obstacles)
├─ 날씨 다양성 (rain, fog, night)
└─ Common-sense norms (sidewalk usage, social distance)

기존 방법의 한계:

  • Simulation-only RL: Static environments, sim-to-real transfer 취약
  • Limited expert data: Teleoperation은 비용이 크고 diversity 낮음
  • End-to-end learning: 상황별 처리 불가능 (hallucination, adversarial cases)

CityWalker의 직관:

인간의 도시 보행 비디오는 이미 모든 critical scenario를 포함하고 있다. 문제는 action label을 대규모로 얻는 것 → VO 기반 자동 labeling으로 해결

II. Method

A. 핵심 혁신 1: VO 기반 자동 Action Labeling

문제: 2000시간 비디오 × VLM prompting = 비현실적 비용

  • GPT-4 Vision 가격: ~0.1 USD per image
  • 30fps × 2000시간 = 2.16억 frames → $21.6M (불가능)

해결책: Visual Odometry (DPVO) 활용

입력: 도시 보행 비디오
    ↓
DPVO (Deep Patch Visual Odometry)
    ↓
카메라 포즈 추출 (상대 pose estimation)
    ↓
연속된 frame 간의 relative displacement
    ↓
Action label (2D Euclidean coordinates)
    ↓
Normalize by average step length
    ↓
Action labels (자동 생성, 비용 0)

VO의 특성 활용:

  • 약점: Global accumulation error (drift)
  • 강점: Short-window relative pose (5-frame window에서는 정확)

스케일 정규화 (crucial innovation):

Problem: VO scale ambiguity
- 걷기 비디오 1초 = 1.4m 실제 이동
- 주행 비디오 1초 = 8m 실제 이동
- VO는 모두 같은 스케일로 출력 (incorrect)

Solution: 각 trajectory 내 평균 step length로 정규화
- 결과: robot-agnostic action space
- 배포 시: Robot-specific step length로 denormalize

결과:

  • Zero-shot으로 walking → quadruped transfer 가능
  • Cross-domain: driving + walking 혼합 학습 가능

B. 핵심 혁신 2: Critical Scenario Definition

기존 평가: 모든 timestep을 동등하게 취급 → 문제: Forward movement에서는 작은 오류가 중요하지 않음

CityWalker: Critical scenarios 식별

Turn (8.2% data):
├─ 정의: φ_action > 20°
├─ 중요도: High (방향 결정)
├─ 실패 원인: 예측 orientation 오류
└─ 데이터: 제한적

Crossing (4.1% data):
├─ 정의: Traffic light 감지 + confidence > 0.5
├─ 중요도: Critical (safety)
├─ 실패 원인: 신호 무시, 타이밍 오류
└─ 현황: 현재 모델도 부분적으로만 학습

Detour (3.2% data):
├─ 정의: |φ_action - φ_target| > 45°
├─ 중요도: High (경로 효율)
├─ 실패 원인: Obstacle avoidance 미스
└─ 개선: Fine-tuning으로 +3.5° improvement

Proximity (5.1% data):
├─ 정의: Largest person bbox > 25% image area
├─ 중요도: Medium (social navigation)
├─ 실패 원인: 개인 공간 침해
└─ 현황: 거의 미검증

Crowd (2.3% data):
├─ 정의: ≥5 people detected
├─ 중요도: High (complex interaction)
├─ 현황: 가장 어려운 시나리오
└─ 성공률: 50% (가장 낮음)

평가 지표 혁신: Scenario-weighted average

기존: Mean over all timesteps
      → 95% forward movement에 의해 지배됨

제안: Mean over critical scenarios only
      → 각 scenario 동등 가중
      → 실제 실패 원인 드러남

C. 핵심 혁신 3: 새로운 평가 지표 (AOE, MAOE)

기존 L2 거리의 문제:

Figure 3의 예:
- 빨강: L2 error 작음, 하지만 방향 크게 벗남 (target으로부터 멀어짐)
- 초록: L2 error 크지만, 방향 정확 (target으로 접근)

실제 네비게이션에서: 초록이 성공, 빨강이 실패

제안: Average Orientation Error (AOE)

AOE(k) = (1/n) Σ_i arccos( <a_i^k, a_i> / (||a_i^k|| ||a_i||) )
       = 예측 action과 ground truth action 간의 평균 각도

이점:
├─ 실제 네비게이션 성공 기준과 일치
├─ L2는 complementary metric으로 사용
└─ Robust to scale variance

Maximum Average Orientation Error (MAOE):

MAOE = (1/n) Σ_i max_k θ_ik
     = 각 sample의 worst-case (5-step 중 가장 큰 오류)

이유: 단순 평균은 underestimate
- 예: [5°, 5°, 5°, 50°, 5°] → avg=14°지만 peak 50°가 실패 원인
- MAOE는 이 worst case를 포착

D. 네트워크 아키텍처

Input:
├─ RGB observations: [o_{t-5}, ..., o_t] (frozen DINOv2 encoder)
├─ Past positions: [p_{t-5}, ..., p_t] (trainable coordinate encoder)
└─ Target waypoint: w_t (coordinate encoder)

Transformer encoder:
├─ Past observation tokens (from DINOv2)
├─ Past position embeddings
├─ Target position embedding
└─ Process through self-attention + FFN

Feature hallucination branch (auxiliary):
├─ Transformer output tokens
├─ MSE loss against future frame embeddings
├─ Guides transformer to predict informative future tokens
└─ Effect on zero-shot: negative (domain gap), fine-tuning: positive

Action head:
├─ Decode transformer output → action waypoints (k=5 future steps)
└─ Each action: (Δx, Δy) in Euclidean space

Arrival head:
├─ Binary classification
├─ Predicts if agent reached goal
└─ Used to control waypoint sequencing

설계 선택의 근거:

  • DINOv2 frozen: Pre-trained vision knowledge 유지, trainable resource 절감
  • Coordinate encoder trainable: Spatial information processing 최적화
  • Transformer over CNN: Temporal dependency modeling, long-horizon prediction
  • k=5 past, 5 future: Trade-off between context and prediction horizon

E. 손실 함수 (Multi-task learning)

L_total = ω_l1 * L_l1 + ω_ori * L_ori + ω_arr * L_arr + ω_feat * L_feat

L_l1 = Mean absolute error
     = (1/k) Σ ||a_i - â_i||_1
     ∈ 기본적인 magnitude supervision

L_ori = Orientation loss (핵심)
      = -(1/k) Σ <â_i, a_i> / (||â_i|| ||a_i||)
      = Negative cosine similarity
      = Direction을 명시적으로 감독

L_arr = Binary cross-entropy
      = Arrival status 예측 감독

L_feat = MSE between transformer tokens and future DINOv2 features
       = Feature hallucination (auxiliary task)
       = 예측 tokens이 미래 관찰과 일치하도록

Weight selection:
├─ 각 loss가 유사한 magnitude 갖도록 설정
├─ ω_ori = 5.0 (방향이 중요)
└─ ω_l1 = 1.0, ω_arr = 1.0, ω_feat = 0-1.0

III. 실험 설계 및 결과

A. 데이터

Training data:

  • Web source: YouTube 도시 보행/주행 비디오
  • Scale: 2000+ hours (약 250만 프레임)
  • Diversity: 다양한 지역, 날씨, 시간대
  • Processing: DPVO + 정규화 (완전 자동)

Expert evaluation data (실제 로봇):

  • Robot: Unitree Go1 (12 DOF quadruped)
  • Sensors: RGB webcam, Livox Mid-360 LiDAR
  • Ground truth: LiDAR-SLAM (정확한 odometry)
  • Collection: 뉴욕시 여러 지역
    • Fine-tuning: 6 hours
    • Testing: 9 hours (offline evaluation)
  • Total: 15 hours

Test scenarios (실세계 deployment):

  • Target distance: 50-100m (실용적 거리)
  • Success criterion: 5m 이내 도착 예측
  • Robot adaptation: PD controller for velocity commands
  • Trial counts: Forward 8-14 trials, Left turn 8-14 trials, Right turn 8-14 trials

E. Feature Hallucination의 이중성

현상: Zero-shot에서 feature hallucination loss가 해롭다

Feature hallucination 포함: MAOE 16.1°
Feature hallucination 제외: MAOE 15.8°

차이: -0.3° (zero-shot에서 disadvantage)

원인 분석:

Feature hallucination loss의 목적:
├─ Transformer이 future tokens을 예측
└─ 이 tokens이 실제 future DINOv2 features와 유사하도록

문제 (zero-shot):
├─ Human walking과 quadruped의 embodiment gap
├─ Human perspective → quadruped의 movement 다름
└─ Future feature 예측이 실제 로봇 navigation과 불일치
└─ 결과: Hallucination loss가 misleading signal 제공

장점 (fine-tuning):
├─ Expert data로 조정 (6h)
├─ Embodiment alignment 개선
└─ 결과: +0.5° 개선

Table 7 해석:

  • 2000h walking + feature hallucination: 더 낮은 training loss
  • But zero-shot test에서는 성능 안 좋음 → overfitting to human motion
  • Fine-tuning 후 회복 → domain adaptation effect

결론: Feature hallucination은 domain-adaptive auxiliary task

  • In-domain (fine-tuning): 도움
  • Out-of-domain (zero-shot): 해로움
  • Trade-off 최적화 필요

  • 각 loss는 complementary information 제공
  • L1: magnitude supervision
  • Orientation: direction supervision
  • Feature: semantic understanding
  • 합치면 synergistic effect (1.80° improvement)

1. data/vo_pipeline.py (Action label 생성)

class VOLabelGenerator:
    """Visual odometry를 이용한 자동 action labeling"""
    
    def __init__(self, model_path='DPVO_weights'):
        self.vo = DPVO()  # 학습된 DPVO 모델 로드
    
    def process_video(self, video_path):
        """
        비디오 → 정규화된 actions
        
        Pipeline:
        1. 비디오 로드
        2. Frame 추출 (30fps)
        3. DPVO 처리 → 상대 poses
        4. Scale 정규화 (average step length 이용)
        5. Actions 저장
        """
        frames = extract_frames(video_path, fps=30)
        poses = self.vo.estimate_poses(frames)  # [T, 6] (trans+rot)
        
        # Global drift 제거 (window=5)
        actions = []
        for i in range(len(poses)-1):
            if i < 5:  # Short window
                # Relative pose만 사용 (global error 무시)
                delta_pose = poses[i+1] - poses[i]
                actions.append(delta_pose[:2])  # (Δx, Δy)
        
        # Scale normalization
        step_lengths = [np.linalg.norm(a) for a in actions]
        avg_step = np.mean(step_lengths)
        normalized_actions = [a / avg_step for a in actions]
        
        return normalized_actions

핵심 통찰:

  • Global DPVO error (drift) → 5-frame short window로 회피
  • Scale 정규화 → embodiment-agnostic
  • Parallelizable → 2000h processing 가능

class NavigationTransformer(nn.Module):
    """Multimodal embodied navigation for urban environments"""
    
    def __init__(self, 
                 vision_dim=768,      # DINOv2 dim
                 coord_dim=64,        # Coordinate embedding dim
                 n_layers=4,
                 n_heads=8,
                 max_history=5):
        super().__init__()
        
        self.vision_backbone = DINOv2()  # Frozen
        self.coord_encoder = CoordinateEncoder(coord_dim)
        self.transformer = TransformerEncoder(...)
        self.action_head = ActionHead(hidden_dim, out_dim=2)  # (Δx, Δy)
        self.arrival_head = ArrivalHead(hidden_dim)  # binary
        self.feature_hallucination = FeatureHallucination(...)
    
    def forward(self, 
                observations,      # [B, K, 3, H, W]
                positions,         # [B, K, 2]
                target,            # [B, 2]
                future_frames=None):  # Optional for hallucination loss
        
        # Encode vision
        vision_features = self.vision_backbone(observations)  # [B, K, 768]
        
        # Encode coordinates
        coord_features = self.coord_encoder(positions, target)  # [B, K, 64]
        
        # Combine
        combined = torch.cat([vision_features, coord_features], dim=-1)  # [B, K, 832]
        
        # Transformer
        transformer_output = self.transformer(combined)  # [B, K, 832]
        
        # Action prediction (K future steps)
        actions = self.action_head(transformer_output)  # [B, 5, 2]
        
        # Arrival prediction
        arrival = self.arrival_head(transformer_output[-1])  # [B, 1]
        
        # Feature hallucination (auxiliary)
        if future_frames is not None:
            future_features = self.vision_backbone(future_frames)  # [B, 5, 768]
            hallucination_loss = MSE(transformer_output[:, :, :768], future_features)
        else:
            hallucination_loss = 0
        
        return actions, arrival, hallucination_loss

설계 결정:

  • DINOv2 frozen: Pre-trained knowledge 유지, parameter 적음
  • Coordinate encoder trainable: Spatial context 최적화
  • Feature hallucination optional: Zero-shot에서 disable 가능

3. training/losses.py (손실 함수)

def orientation_loss(predicted, target):
    """Negative cosine similarity between action vectors
    
    Args:
        predicted: [B, K, 2]
        target: [B, K, 2]
    
    Returns:
        loss: scalar
    """
    # Normalize to unit vectors
    pred_norm = torch.nn.functional.normalize(predicted, dim=-1)
    target_norm = torch.nn.functional.normalize(target, dim=-1)
    
    # Cosine similarity
    cos_sim = torch.sum(pred_norm * target_norm, dim=-1)  # [B, K]
    
    # Negative cosine (to minimize)
    loss = -torch.mean(cos_sim)
    
    return loss

def combined_loss(actions_pred, actions_gt, arrival_pred, arrival_gt, 
                  future_features_pred=None, future_features_gt=None,
                  weights={'l1': 1.0, 'ori': 5.0, 'arr': 1.0, 'feat': 0.5}):
    
    # L1 loss for magnitude
    l1_loss = torch.nn.functional.l1_loss(actions_pred, actions_gt)
    
    # Orientation loss for direction
    ori_loss = orientation_loss(actions_pred, actions_gt)
    
    # Arrival loss (binary)
    arr_loss = torch.nn.functional.binary_cross_entropy(arrival_pred, arrival_gt)
    
    # Feature hallucination loss (optional)
    feat_loss = 0
    if future_features_pred is not None:
        feat_loss = torch.nn.functional.mse_loss(future_features_pred, future_features_gt)
    
    # Weighted combination
    total_loss = (weights['l1'] * l1_loss + 
                  weights['ori'] * ori_loss + 
                  weights['arr'] * arr_loss + 
                  weights['feat'] * feat_loss)
    
    return total_loss, {'l1': l1_loss, 'ori': ori_loss, 'arr': arr_loss, 'feat': feat_loss}

핵심: Orientation loss가 direction을 명시적으로 감독

4. deployment/controller.py (실세계 제어)

class Go1Controller:
    """Unitree Go1 제어 인터페이스"""
    
    def __init__(self, model_path):
        self.model = NavigationTransformer.load(model_path)
        self.robot = unitree_sdk.Go1()  # Robot 연결
        self.step_length = 0.15  # m (정규화 역변환)
    
    def predict_action(self, observation, position, target):
        """모델로부터 action 예측"""
        with torch.no_grad():
            actions, arrival, _ = self.model(
                obs=[observation],
                positions=[position],
                target=target
            )
        return actions[0], arrival[0]  # [5, 2], [1]
    
    def denormalize_action(self, action):
        """정규화된 action → 로봇 고유 step length로 복원"""
        return action * self.step_length  # [m]
    
    def execute_trajectory(self, actions):
        """5-step trajectory 실행"""
        for i, action in enumerate(actions):
            denorm = self.denormalize_action(action)  # [Δx, Δy]
            
            # Target velocity 계산
            distance = np.linalg.norm(denorm)
            duration = 0.5  # 각 step은 0.5초 (10Hz * 5 step)
            velocity = distance / duration
            direction = np.arctan2(denorm[1], denorm[0])
            
            # PD controller로 velocity command 생성
            cmd = {
                'vx': velocity * np.cos(direction),
                'vy': velocity * np.sin(direction),
                'omega': 0  # StraightLine
            }
            
            self.robot.send_command(cmd, duration=duration)
    
    def navigate_to_target(self, target_gps):
        """전체 네비게이션 루프"""
        while True:
            # 현재 위치, 관찰
            position = self.robot.get_gps()  # [lat, lon] → [x, y]
            observation = self.robot.get_rgb()  # [H, W, 3]
            
            # 예측
            actions, arrival = self.predict_action(
                observation, position, target_gps
            )
            
            # 실행
            self.execute_trajectory(actions)
            
            # 도착 확인
            if arrival > 0.5:  # Binary threshold
                distance = np.linalg.norm(position - target_gps)
                if distance < 5:  # 5m threshold
                    return SUCCESS
            
            # Timeout 체크
            if time.elapsed > 900s:
                return TIMEOUT

핵심: Action denormalization → robot-specific step length
