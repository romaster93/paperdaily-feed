1.2 연구 목표 (Research Objective)

이 연구는 "하나의 비전-언어 모델 가중치로, 서로 다른 항법(navigation) 태스크 패밀리를 모두 수행하는 내비게이션 파운데이션 모델을 만들 수 있는가" 라는 질문에 답한다.

기존 로봇 항법 연구는 태스크마다 별도 모델을 만든다: 자연어 지시 추종(VLN), 좌표 목표 도달(PointNav), 객체 목표 탐색(ObjectNav), 대상 추적(Tracking), 주행(Driving). 각각 데이터·아키텍처·평가가 분리되어 있어, 한 모델을 다른 태스크로 옮기면 성능이 무너진다. Qwen-RobotNav는 Qwen3-VL(2B/4B/8B) 라는 강력한 범용 VLM을 백본으로, 5개 태스크 패밀리를 단일 가중치(one set of weights)로 통합한다.

핵심 설계는 세 가지다:

  1. 파라미터화된 태스크 인터페이스(parameterized interface): 다섯 태스크를 공통 입출력 규격(언어 지시 + 관측 + 목표 유형 토큰)으로 통일해, 한 모델이 태스크별 분기 없이 처리.
  2. 웨이포인트 궤적 예측(waypoint trajectory prediction): 정책 출력으로 단일 행동이 아니라 8개 웨이포인트(2D 위치 + heading) 의 단기 궤적을 예측 — 4층 MLP 액션 헤드.
  3. 제어 가능한 관측 파라미터(controllable observation parameters): 시각 토큰 예산(visual token budget), 시간 감쇠(temporal decay), 카메라 가중치(camera weights)를 추론 시 조절 가능 → 연산-성능 trade-off를 배포 환경에 맞게 조정.

그 위에 agentic navigation system(VLM이 관측을 받아 웨이포인트를 내고, 실행·재관측을 반복하는 에이전트 루프)을 얹어, VLN-CE(R2R/RxR), ObjectNav(HM3Dv2), 추적(EVT-Bench), 주행(NAVSIM), 체화형 질의응답(EQA)에서 단일 모델로 SOTA급 성능을 달성한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

C1. 태스크 분절(fragmentation). VLN·PointNav·ObjectNav·Tracking·Driving은 목표 표현(자연어/좌표/객체명/대상/도로)·관측·보상이 모두 달라, 태스크별 전용 모델이 표준이었다. 통합 시 서로 다른 목표 유형을 한 인터페이스에 담는 것이 어렵다.

C2. 단일 행동 출력의 근시안성. 프레임마다 이산 행동(전진/회전) 하나만 내면 장기 일관성·부드러움이 떨어진다. 특히 연속 공간(VLN-CE)에서는 웨이포인트 수준의 단기 계획이 유리하다.

C3. 배포 환경의 연산 이질성. 온보드 컴퓨트는 천차만별이다. 고정된 시각 토큰 수·관측 윈도우는 어떤 로봇에선 과하고 어떤 로봇에선 부족하다. 추론 시 조절 가능해야 한다.

C4. 일반 VLM의 항법 접지(grounding) 부족. Qwen3-VL 같은 범용 VLM은 풍부한 시각-언어 지식을 갖지만, "공간을 이동하는 행동"으로 접지되어 있지 않다. 대규모 항법 데이터로 정렬해야 한다.

C5. 평가의 파편화. 태스크마다 벤치마크·지표가 달라(SR/SPL/PDMS/EQA 정확도 등) 단일 모델의 범용성을 입증하려면 다섯 영역을 모두 커버해야 한다.

2.2 핵심 해결책

  • C1 → 파라미터화된 태스크 인터페이스: 목표 유형을 토큰/파라미터로 표현해 한 모델이 5태스크를 분기 없이 처리.
  • C2 → 8-웨이포인트 궤적 예측(2D pos + heading) + 4층 MLP 헤드 → 단기 계획성·부드러움 확보.
  • C3 → 제어 가능 관측 파라미터(시각 토큰 예산·시간 감쇠·카메라 가중치)로 추론 시 연산-성능 조정.
  • C4 → Qwen3-VL 백본 + 15.6M 항법 샘플(85/15 분할)로 대규모 행동 접지.
  • C5 → VLN-CE(R2R/RxR)·ObjectNav(HM3Dv2)·Tracking(EVT-Bench)·Driving(NAVSIM)·EQA(HM-EQA/EXPRESS-Bench) 전 영역 평가.

3. 핵심 방법론 (Core Methods)

표기 (Notation)
  I_t            : 시각 관측(다중 카메라 RGB) at time t
  L              : 자연어 지시 / 목표 명세 (task-family에 따라 형태 상이)
  τ_type         : 태스크 유형 파라미터(VLN/PointNav/ObjNav/Track/Drive)
  Φ_obs          : 제어 가능 관측 파라미터 {token_budget, temporal_decay, cam_weights}
  W = {w_k}_{1..8}: 예측 웨이포인트 (각 w_k = [x_k, y_k, ψ_k], 2D 위치 + heading)
  f_VLM          : Qwen3-VL 백본 (2B / 4B / 8B)
  h_MLP          : 4층 MLP 액션 헤드

3.1 파라미터화된 태스크 인터페이스 (Parameterized Interface)

다섯 태스크를 하나의 입출력 규격으로 통일하는 것이 Qwen-RobotNav의 출발점이다. 각 태스크는 "목표를 어떻게 명세하는가"만 다르다:

태스크 패밀리        목표 명세(τ_type + L)                  공통 출력
─────────────────────────────────────────────────────────────────
VLN (지시 추종)      자연어 경로 지시("주방을 지나 …")   →  8 웨이포인트 W
PointNav            상대 좌표 목표 [Δx, Δy]            →  8 웨이포인트 W
ObjectNav           객체 카테고리("chair")            →  8 웨이포인트 W
Tracking            추적 대상(이미지/설명)             →  8 웨이포인트 W
Driving             주행 컨텍스트/네비 명령            →  8 웨이포인트 W

핵심은 출력을 8-웨이포인트 궤적으로 단일화하고, 입력에서 태스크 유형을 파라미터(τ_type)와 목표 명세 L로 표현한 점이다. 모델은 태스크별 헤드 분기 없이, 같은 백본+같은 헤드로 모든 태스크를 처리한다. 이는 "범용 VLM이 다양한 멀티모달 태스크를 프롬프트로 통합하던" 패러다임을 항법 행동 공간으로 확장한 것이다(C1 해소).

3.2 Qwen3-VL 백본 + 웨이포인트 액션 헤드 (Backbone & Action Head)

   다중 카메라 RGB I_t ┐
   언어 목표 L         ├─►  Qwen3-VL (2B/4B/8B)  ─► 멀티모달 토큰 임베딩 z_t
   태스크 유형 τ_type  ┘         (비전 인코더 + LLM)        │
                                                            ▼
                                          4층 MLP 액션 헤드 h_MLP
                                                            │
                                                            ▼
                              W = {[x_k, y_k, ψ_k]}_{k=1..8}  (8 웨이포인트)
  • 백본 f_VLM: Qwen3-VL을 2B/4B/8B 세 규모로 제공 — 온보드 컴퓨트에 맞춰 선택(C3 보완).
  • 액션 헤드 h_MLP: 백본의 멀티모달 임베딩을 받아 4층 MLP로 8개 웨이포인트(각 2D 위치 + heading)를 회귀. 단일 이산 행동이 아니라 단기 궤적을 예측하므로 부드럽고 장기 일관성이 좋다(C2 해소).
  • 웨이포인트 표현: 연속 공간 항법(VLN-CE)과 자연스럽게 맞물려, 별도 토폴로지 맵 없이 로컬 폴리시로 작동.
의사코드 (추론 1스텝)
  z = f_VLM(images=I_t, text=L, task=τ_type, obs_params=Φ_obs)
  W = h_MLP(z)                       # [8, 3] = 8개 (x,y,heading)
  next_action = controller.follow(W) # 웨이포인트 추종 컨트롤러
  execute(next_action); observe → I_{t+1}   # agentic loop 반복

3.3 제어 가능한 관측 파라미터 (Controllable Observation)

배포 환경의 연산 예산이 다르므로, 추론 시점에 관측 처리를 조절할 수 있게 했다(C3):

Φ_obs = {
  token_budget   : 시각 토큰 수 상한 (↑ 정확도/↑ 연산, ↓ 경량/↓ 정확도)
  temporal_decay : 과거 프레임 가중 감쇠율 (최근 관측에 집중 vs 장기 맥락)
  cam_weights    : 다중 카메라별 가중치 (전방 중심 vs 전방위 균형)
}
  • token_budget: 비전 토큰 예산을 줄이면 연산↓·지연↓, 늘리면 세밀한 장면 이해↑. 같은 가중치로 재학습 없이 경량/고성능 모드 전환.
  • temporal_decay: 과거 프레임의 영향력을 지수 감쇠 — 빠른 동적 환경에선 최근에 집중, 장기 지시 추종(RxR)에선 맥락 유지.
  • cam_weights: 다중 카메라(전/측/후)의 상대 중요도 — 주행은 전방 강조, 탐색은 전방위 균형.

이 세 다이얼은 하나의 학습된 가중치를 다양한 하드웨어·태스크에 맞춰 적응시키는 추론-시 제어 노브로, "한 모델, 여러 배포 프로파일"을 가능케 한다.

3.4 대규모 항법 데이터 정렬 (Navigation Grounding)

범용 Qwen3-VL을 항법 행동으로 접지하기 위해 약 15.6M 샘플을 사용하고 85/15(train/val) 로 분할한다(C4). 데이터는 다섯 태스크 패밀리를 아우르며, 각 샘플은 (관측, 목표 명세, 웨이포인트 궤적 정답) 형태로 통일된 인터페이스에 맞춰진다. 대규모·다태스크 혼합 학습이 태스크 간 양의 전이(positive transfer) 를 유도해, 단일 가중치가 다섯 영역에서 모두 강하게 작동하도록 한다.

3.5 Agentic Navigation System

Qwen-RobotNav는 단발 예측이 아니라 에이전트 루프로 작동한다:

   ┌──────────────────────────────────────────────┐
   │  관측 I_t ─► VLM+헤드 ─► 8 웨이포인트 W       │
   │                  │                            │
   │     웨이포인트 추종 컨트롤러로 일부 실행       │
   │                  │                            │
   │     실행 후 재관측 I_{t+1} ─────────────┐     │
   └──────────────────────────────────────┘ │     │
                  ▲                          │     │
                  └──────────(반복)──────────┘     │
                  목표 달성/종료 판단까지            │
   ────────────────────────────────────────────────

매 스텝 새 관측으로 웨이포인트를 갱신해 폐루프(closed-loop) 로 목표에 수렴한다. 이 agentic 구성이 장기 지시(RxR), 동적 추적(EVT), 객체 탐색(ObjectNav)에서 단발 예측보다 강건하다.

│  z_t ─► [Linear-ReLU]×4 ─► W = {[x_k,y_k,ψ_k]}_{k=1..8}  (8 웨이포인트)           │
└─────────────────────────────────────────────────────────────────────────────────┘
        │ W
        ▼
   웨이포인트 추종 컨트롤러 ─► 로봇 실행 ─(재관측)─► agentic loop (폐루프 수렴)
        │
        ▼
   평가: VLN-CE(R2R/RxR) · ObjectNav(HM3Dv2) · Tracking(EVT) · Driving(NAVSIM) · EQA

데이터 흐름 요약: (입력) 다중 카메라 + 목표 명세 + 태스크 유형 + 관측 파라미터 → (백본) Qwen3-VL 멀티모달 융합 → (헤드) 4층 MLP가 8-웨이포인트 궤적 예측 → (실행) 웨이포인트 추종 + 재관측 agentic loop → 다섯 태스크 통합 평가. 태스크별 분기가 없는 단일 가중치 경로가 핵심이다.

5. 실험 결과 및 성능 (Experimental Results)

5.1 데이터셋 (Datasets)

  • 학습: 약 15.6M 항법 샘플, 85/15 train/val 분할, 5 태스크 패밀리 혼합.
  • 평가 벤치마크:
    • VLN-CE: R2R, RxR (연속 공간 자연어 지시 추종)
    • ObjectNav: HM3Dv2 (객체 목표 탐색)
    • Tracking: EVT-Bench (대상 추적)
    • Driving: NAVSIM (주행, PDMS 지표)
    • EQA(체화형 질의응답): HM-EQA, EXPRESS-Bench

  • VLN/ObjectNav: Success Rate(SR) 중심(연속 공간 도달 성공률).

6. 핵심 기여점 (Key Contributions)

  1. 항법 파운데이션 모델. Qwen3-VL 백본 위에 5개 태스크 패밀리(VLN/PointNav/ObjectNav/Tracking/Driving)를 단일 가중치로 통합 — 항법의 "범용 모델" 패러다임 제시.
  2. 파라미터화된 태스크 인터페이스. 목표 유형을 파라미터/토큰으로 표현해 태스크별 분기 없이 한 모델이 다섯 영역을 처리.

  4. 제어 가능한 관측 파라미터. 시각 토큰 예산·시간 감쇠·카메라 가중치를 추론 시 조절 → 재학습 없이 연산-성능 적응(2B/4B/8B 규모와 결합).
  5. 광범위 SOTA급 검증. VLN-CE RxR 76.5%/R2R 72.1%, ObjectNav HM3Dv2 75.6%, EVT 90.0%, NAVSIM 91.4 PDMS, EQA 3종 SOTA.

8. 고급 주제 (Advanced Topics)

8.1 왜 "웨이포인트 궤적"인가

이산 행동(전진/회전) 출력은 (a) 프레임 단위 근시안, (b) 부드럽지 못한 모션, (c) 연속 공간(VLN-CE)과의 부정합 문제가 있다. 8-웨이포인트는 단기 계획(short-horizon plan) 을 한 번에 내어 컨트롤러가 부드럽게 추종하게 하고, agentic loop가 매 스텝 갱신하므로 계획성과 반응성을 동시에 얻는다. 이는 최근 VLN 연구가 토폴로지 맵·웨이포인트 예측기로 수렴해 온 흐름과 일치한다.

8.2 한계점 (Limitations)

  • 코드 미공개: 재현성 제약. 2차 매체의 "GitHub 동봉" 주장과 달리 공개 저장소 미확인.
  • 실로봇 통계 불충분(발췌 범위): 벤치마크 중심 검증. 실배포 일반화(센서 노이즈·도메인 갭)는 추가 입증 필요.
  • "Driving" 포함의 범위 논쟁: 주행은 본 리뷰 트랙(VLN)의 핵심이 아니다. 단, Qwen-RobotNav는 자연어 지시 추종 VLN(R2R/RxR)을 1차 태스크로 두고 주행을 5개 중 1개로 포함하므로 VLN 트랙으로 분류하되, AD 전용 논문과는 구분한다.
  • 추론 비용: 8B 백본은 강력하나 온보드 실시간엔 부담 — token_budget/2B 모드로 완화하나 정확도-지연 trade-off 존재.

8.3 향후 방향

  • 단일 가중치의 태스크 간 전이 분석(어떤 태스크가 서로 도움/방해되는가).
  • 실로봇 대규모 배포 + 도메인 적응(sim-to-real).
  • 관측 노브의 자동 스케줄링(상황 인식형 token_budget 조절).

9. 비교 분석 (Comparative Analysis)

비교 대상은 같은 VLN 트랙에서 "단일 모델로 다중 항법을 통합" 또는 "VLN SOTA" 주제가 가장 가까운 선행 리뷰 세 편을 선정했다(인덱스 우선 선별 후 정독):

  • FloVerse: Floor Plan-Guided Multi-Modal Navigation — PointNav/ObjectNav/ImageNav를 단일 가중치로 통합(디퓨전).
  • NavWAM: A Navigation World Action Model for Goal-Conditioned Visual Navigation — 통합 세계-행동 모델(image-goal).
  • AwareVLN: Reasoning with Self-awareness for Vision-Language Navigation — R2R/RxR SOTA(자연어 지시 추종 정점).

9.2 장단점 분석

  • 장점: ① 통합 범위가 가장 넓다 — FloVerse(3 태스크, 자연어 지시 없음)·NavWAM(image-goal 단일)·AwareVLN(VLN 전용)과 달리, 자연어 지시 VLN을 포함해 5 태스크를 한 가중치로 처리. ② VLN-CE 성능이 AwareVLN을 상회(R2R 72.1 vs 65.4, RxR 76.5 vs 67.6 — 벤치/세팅 차이 감안 필요하나 수치상 우위). ③ 추론-시 관측 노브는 세 비교 논문에 없는 배포 친화적 차별점. ④ 범용 VLM(Qwen3-VL) 백본의 강력한 사전지식 활용.
  • 단점: ① 코드 미공개 — AwareVLN(공개)·NavWAM(예정) 대비 재현성 열위. ② 실로봇 검증 발췌 부족 — NavWAM은 실세계 79.2%를 명시하는데 본 모델은 벤치 중심. ③ "Driving 포함"이 트랙 순수성 측면에서 모호 — 단 VLN(R2R/RxR)을 1차로 두므로 VLN 분류는 타당. ④ 파운데이션 모델 특성상 8B는 온보드 부담.

9.3 실적용 가능성 평가

  • 강점: 단일 가중치 다태스크 → 배포·유지보수 단순화. 2B/4B/8B + 관측 노브로 하드웨어 적응. Qwen 생태계(공개 VLM)와의 정합성으로 후속 파인튜닝 용이성 기대.
  • 제약: 코드 미공개로 즉시 도입 불가. 실로봇 도메인 갭·실시간성(8B) 검증이 실배포의 관건. token_budget 축소 시 정확도 저하 폭은 공개 데이터 부족.

9.4 연구 방향성 평가

Qwen-RobotNav는 VLN 연구를 "태스크별 전용 모델"에서 "범용 항법 파운데이션 모델" 로 이동시키는 방향 제시다. AwareVLN류의 정교한 VLN 추론을 이런 파운데이션 백본에 결합하거나, NavWAM류의 세계모델 예측을 웨이포인트 예측에 더하면, "통합 + 추론 + 예측"의 차세대 통합점이 된다. FloVerse의 구조 사전(평면도) 도 관측 파라미터의 한 형태로 흡수 가능하다.

11. 결론 (Conclusion)

Qwen-RobotNav는 "하나의 비전-언어 모델 가중치로 다섯 항법 태스크 패밀리를 모두 수행한다" 는 야심을, 파라미터화된 태스크 인터페이스·8-웨이포인트 궤적 예측·제어 가능 관측 파라미터·대규모(15.6M) 항법 정렬·agentic 루프로 구체화한 항법 파운데이션 모델이다. VLN-CE(R2R 72.1/RxR 76.5)·ObjectNav(75.6)·Tracking(90.0)·Driving(91.4 PDMS)·EQA(3종 SOTA)에서 단일 가중치로 강력한 성능을 보였다.

혁신성: 태스크별 전용 모델 관행을 깨고 범용 VLM 백본 + 통일 인터페이스로 항법을 "파운데이션 모델화"한 점, 그리고 추론-시 관측 노브로 배포를 적응시킨 점이 신선하다. 실용적 의의: 단일 가중치·다규모·관측 제어가 배포/유지보수를 단순화하며, 공개 Qwen 생태계와의 정합성이 후속 활용을 돕는다. 한계: 코드 미공개(2차 매체 주장과 달리 공개 저장소 미확인)로 재현성이 제약되고, 실로봇 검증·실시간성(8B)·도메인 갭이 후속 과제다. 향후: AwareVLN류 정교한 VLN 추론·NavWAM류 세계모델 예측과의 결합, 실로봇 대규모 배포, 관측 노브의 자동 스케줄링이 자연스러운 확장 방향이다.

        camera_weights=obs_params.camera_weights,    # 카메라별 가중
    )
    waypoints = mlp(z)        # [8, 3] = 8 × (x, y, heading)
    return waypoints          # agentic loop가 일부 실행 후 재호출

부록 F. agentic loop의 폐루프 동작 상세

초기화: t=0, 목표 명세 L, 태스크 유형 τ_type, 관측 파라미터 Φ_obs
반복:
  1) 관측 수집 I_t (다중 카메라 RGB; temporal buffer에 push, decay 적용)
  2) z_t = f_VLM(I_{0..t}, L, τ_type, Φ_obs)     # 과거 맥락 포함(감쇠 가중)
  3) W = h_MLP(z_t)                               # 8 웨이포인트
  4) 컨트롤러가 W의 앞부분 추종 → 일부 실행(receding-horizon 스타일)
  5) 종료 판정: 목표 도달/포기/시간초과 ? → break
  6) t ← t+1, goto 1
출력: 궤적(누적 실행) + (EQA의 경우) 탐색 후 답변

이 구조는 모델 예측 제어(MPC)의 receding-horizon 사고와 닮았다. 8-웨이포인트라는 단기 계획을 예측하되 앞부분만 실행하고 재계획하므로, (a) 예측 오차 누적을 매 스텝 보정하고, (b) 동적 환경(추적·주행)에 반응적이며, (c) 장기 지시(RxR)에서도 맥락 버퍼와 결합해 일관성을 유지한다. 단발 예측 대비 폐루프의 강건성이 EVT(90.0%)·ObjectNav(75.6%) 같은 탐색·추적 태스크에서 두드러진다.

부록 G. 태스크 간 전이(transfer)의 가설적 해석

혼합 학습(15.6M, 5 태스크) 시 기대되는 상호작용
  PointNav  → VLN     : 기하적 목표 도달 능력 = 지시의 공간 접지 토대
  ObjectNav → VLN     : 객체 인식·탐색 = "주방으로 가" 같은 의미 항법 지원
  Tracking  → Driving : 동적 대상 추종 = 주행의 선행차 추종과 공유
  Driving   → 전반     : 연속 고속 모션의 부드러운 웨이포인트 사전(prior)
  VLN       → ObjectNav: 언어 의미 지식 = 객체 카테고리 이해 강화
주의: 음의 전이(예: 주행의 직진 편향이 실내 탐색의 회전성을 약화)도
      이론상 가능 → 단일 가중치 통합의 핵심 리스크이자 향후 분석 과제.

파운데이션 모델의 가치는 양의 전이에 있다. Qwen-RobotNav가 다섯 영역에서 동시에 강하다는 사실은, 통일 인터페이스 하의 혼합 학습이 (적어도 평가 분포에서는) 태스크 간 시너지를 만들어냄을 시사한다. 다만 어떤 태스크 쌍이 서로 돕고 방해하는지에 대한 ablation은 (코드·세부 미공개로) 본 리뷰 범위에서 확인 불가하며, 통합 항법 연구의 중요한 후속 주제다.

VLN-CE(연속 환경)에서의 적합성
  - 토폴로지 그래프/이산 노드에 의존하지 않음 → 임의 연속 위치 표현

  - 프레임 단위 결정 → 근시안·지터, 긴 지시에서 누적 오차↑

부록 J. VLN 트랙 내 위치와 분류 근거

이 논문을 VLN 트랙으로 분류한 근거
  ✅ 1차 태스크에 자연어 지시 추종(VLN-CE R2R/RxR) 포함, 핵심 성능 지표로 보고
  ✅ ObjectNav·Tracking 등도 "언어/의미 목표 기반 항법"으로 VLN 인접
  ⚠ Driving(주행)을 5개 중 1개로 포함하나, AD 전용 논문이 아님
     → CLAUDE.md 제외 기준(자율주행 전용)을 위반하지 않음:
        자연어 항법(VLN)이 주(主)이고 주행은 통합 범위의 일부
판정: VLN 파운데이션 모델 — 자연어-접지 항법이 중심이므로 VLN 트랙 적합.
대비) VLA/매니퓰레이션/그래스핑 요소 없음 → 제외 대상 아님.

위 분류는 본 코퍼스의 카테고리 게이트를 엄격히 적용한 결과다. Qwen-RobotNav는 행동(action) 을 내지만, 그 행동이 항법 웨이포인트(이동)이지 매니퓰레이션/그래스핑이 아니며, 자연어 지시 추종(VLN-CE)을 1차 평가로 보고하므로 VLN 트랙에 정확히 부합한다. "Driving 포함" 때문에 자율주행 논문으로 오인하지 않도록, 본 리뷰는 VLN을 중심 축으로 분석했다.

부록 K. 파운데이션 모델 관점에서의 의의와 risk

의의 (왜 "파운데이션 모델"인가)
  - 단일 가중치 × 5 태스크 × 3 규모 × 추론-시 노브
    → 한 번 학습한 자산을 다양한 로봇/태스크/하드웨어로 재사용
  - 범용 VLM(Qwen3-VL)의 시각-언어 사전지식을 항법으로 전이
    → 데이터 효율·일반화의 토대(zero/few-shot 잠재력)
  - 통일 인터페이스 → 새 태스크 추가가 "새 목표 명세 형식" 정의로 환원

risk (단일 모델 통합의 그림자)
  - 음의 전이: 태스크 간 간섭으로 특정 영역 성능 저하 가능
  - 안전성: 단일 정책의 실패 모드가 모든 태스크에 전파될 위험
  - 평가-배포 갭: 벤치 SOTA ≠ 실로봇 강건성(도메인/센서 노이즈)
  - 재현성: 코드·데이터·세부 미공개 시 커뮤니티 검증 제약(현 상태)

Qwen-RobotNav의 학술적 무게중심은 "VLN을 포함한 항법을 파운데이션 모델 패러다임으로 옮긴" 데 있다. 이는 NLP·비전에서 입증된 "대규모 사전학습 → 다태스크 일반화" 공식을 로봇 항법에 적용하려는 시도이며, 다섯 영역의 동시 SOTA급 성능이 그 가능성을 뒷받침한다. 다만 파운데이션 모델 특유의 리스크(음의 전이, 단일 실패 모드 전파, 평가-배포 갭)와 현 시점의 재현성 제약(코드 미공개)은, 본 모델을 실배포 가능한 제품이라기보다 방향을 증명한 연구로 읽게 한다.

  - temporal_decay: 높음 (최근 프레임 집중, 메모리 절약)
  - cam_weights: 전방 강조
  → 지연 우선, 단순 환경/단거리 지시에 적합

시나리오 2: 고성능 서버-인-더-루프(정밀 우선)
  - 백본: Qwen3-VL 8B
  - token_budget: 높음 (세밀 장면 이해)
  - temporal_decay: 낮음 (장기 맥락 유지 → 긴 RxR 지시)
  - cam_weights: 전방위 균형 (탐색/객체 항법)
  → 정확도 우선, 복잡한 자연어 지시·탐색에 적합

시나리오 3: 동적 추적/주행(반응성 우선)
  - 백본: 4B (균형)
  - temporal_decay: 높음 (빠른 대상 변화 추종)
  - cam_weights: 전방 + 측방 (추적 대상 시야 유지)
  → EVT/NAVSIM류 동적 태스크에 적합

이처럼 하나의 학습 자산이 재학습 없이 세 배포 프로파일로 분기한다는 점이, Qwen-RobotNav가 단순한 벤치마크 모델을 넘어 실배포를 의식한 파운데이션 모델임을 보여준다. 향후 이 노브들을 상황 인식형으로 자동 스케줄링한다면(예: 속도·장면 복잡도에 따라 token_budget 동적 조절), 효율-성능 곡선을 더 끌어올릴 수 있다.
