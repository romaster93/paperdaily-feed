1.2 연구 목표 (Research Objective)

로봇의 많은 실용 과제 — 이중팔 폐연쇄(closed-chain) 협조 조작, 휴머노이드 전신(whole-body) 균형 유지, 물체를 일정 자세로 들고 이동하기 — 는 구성공간(configuration space) 전체가 아니라 등식 제약으로 정의되는 저차원 다양체(constraint manifold) ℳ = {q | h(q) = 0} 위에서만 실현 가능하다. 이런 제약 모션계획(constrained motion planning) 은 샘플링 기반 계획기(RRT 계열)의 고전적 난제다. 무작위로 뽑은 샘플이 다양체 위에 놓일 확률이 0이기 때문에, 전통적 접근은 "앰비언트(ambient) 구성공간에서 조향(steering)한 뒤 다양체로 투영(projection)"하는 2단계 절차를 쓴다. 그러나 이 방식은 (1) 조향 방향이 다양체의 국소 기하와 어긋나 투영 후 큰 보정이 생기고, (2) 매 확장(extension)마다 값비싼 투영을 반복하며, (3) 차원(n)과 공차원(codimension m = n − d)이 커질수록 투영 실패·수렴 지연이 급격히 악화된다.

최근 GPU 병렬 샘플링 계획기(cpRRTC, pRRTC 계열)가 수백~수천 개의 CUDA 블록으로 트리를 동시 확장해 비제약 모션계획을 밀리초 단위로 끌어내렸지만, 제약 모션계획에서는 여전히 "앰비언트 조향+투영"의 구조적 비효율을 그대로 안고 있어 고차원·고공차원에서 성능이 무너진다.

PATACON 은 이 문제를 정면으로 공략한다. 핵심 통찰은 "앰비언트 공간에서 조향하고 투영하지 말고, 처음부터 다양체의 접공간(tangent space) 안에서 탐색하라" 이다. 제약 함수 h와 그 야코비안 Jh(q)로부터 각 노드에서 접공간의 영공간(null-space) 기저 N(q)를 구하면, 다양체의 국소 기하가 이미 알려져 있다. PATACON은 이 접공간 기하를 양방향 RRT-Connect의 두 단계(샘플링·에지 투영)에 직접 녹여 넣어, (1) Tangent-Guided Sampling (TGS) — 접공간 안에서 샘플·최근접 노드를 선택하고, (2) Tangent-Guided Multi-Edge Projection (TGMP) — 한 번의 접공간 구성 비용으로 여러 개의 연속 후보 에지를 동시에 생성·투영한다. 전체 파이프라인을 GPU SIMT 3계층 병렬성(블록=접공간/최근접탐색, 협력 스레드 그룹=다중 에지 검증) 위에 올려, 이중팔·휴머노이드 과제에서 차원과 공차원이 커질수록 기존 GPU 제약 계획기(cpRRTC) 대비 최대 11.25배 가속을 달성한다.

트랙 판정: PATACON의 평가 플랫폼은 매니퓰레이터(Franka)·이동 매니퓰레이터(FFW-SG2)·휴머노이드(Unitree G1)이지만, 논문의 기여는 그래스핑·조작 스킬이 아니라 제약 다양체 위의 샘플링 기반 모션계획 알고리즘 자체다. 이는 본 코퍼스의 PAAMP(#227, 부족구동 볼록 모션계획), Constraint Manifold Charts IFT(#282, 제약다양체 차트 계획), MR.POP(#303, GPU 다중로봇 모션계획), CMG-RRT(크리티컬 다양체 유도 RRT) 선례와 동일한 "매니퓰레이터 플랫폼이나 기여가 모션계획 → Planner in-scope" 규칙에 정확히 들어맞는다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

제약 모션계획의 본질적 난제. n-차원 구성공간 𝒞 안에서, m개의 미분가능 등식 제약 h: 𝒞 → ℝᵐ (예: 양팔이 같은 물체를 쥐어 상대 변환이 고정되는 폐연쇄 제약, 발바닥 접촉·CoM 제약)을 만족하는 실현가능 집합은 d = n − m 차원의 다양체 ℳ = {q | h(q) = 0}에 불과하다. 𝒞의 측도(measure) 관점에서 ℳ는 측도 0 집합이므로, 균일 무작위 샘플 q_rand는 확률 1로 ℳ 위에 있지 않다. 따라서 샘플링 기반 계획기는 샘플을 다양체로 되돌리는 보정 절차가 반드시 필요하다.

기존 "조향 후 투영(steer-then-project)"의 3가지 병목:

  1. 기하 불일치로 인한 큰 투영 보정. cpRRTC 등은 먼저 앰비언트 𝒞에서 q_near → q_rand 방향으로 직선 조향한 뒤 결과를 뉴턴/경사하강 투영으로 ℳ에 되돌린다. 조향 방향은 다양체의 국소 접평면을 전혀 반영하지 않으므로, 투영이 샘플을 크게 끌어당겨야 하고 — 그만큼 실제 전진(progress)이 줄어든다. 고공차원일수록 접평면과 앰비언트 방향의 괴리가 커져 보정량이 폭증한다.

  2. 반복되는 값비싼 투영. 매 확장 스텝마다, 그리고 에지를 여러 웨이포인트로 이산화할 때마다 투영을 호출한다. 투영 자체가 야코비안 계산·선형 풀이의 반복이라 비싸며, 트리가 커질수록 전체 계획 시간의 지배 요인이 된다.

  3. 차원·공차원 스케일링 붕괴. 투영 수렴 반경과 성공률은 차원이 올라가면 급격히 나빠진다. 특히 휴머노이드처럼 n=35, 공차원 m이 18~20에 이르면(G1 BK+FT/CoM, BK+OR+FT/CoM), 앰비언트 조향+투영은 투영 실패·수렴 지연이 누적돼 계획시간이 수백 ms로 치솟는다.

GPU 병렬 계획기의 미완성 부분. cpRRTC/pRRTC는 수백 개 CUDA 블록으로 트리 확장을 병렬화해 비제약 계획을 밀리초로 가속했지만, 제약 계획에서는 "앰비언트 조향+투영" 구조를 그대로 병렬화했을 뿐이라 위 3가지 병목이 GPU 상에서도 그대로 재현된다. 즉, 병렬 하드웨어가 아무리 빨라도 알고리즘의 단위 작업(앰비언트 조향+큰 투영)이 비효율적이면 고차원에서 이득이 사라진다.

2.2 핵심 해결책

PATACON은 "접공간을 계획의 1차 시민으로 승격(tangent space as a first-class citizen)"한다. 각 노드 q_r에서 제약 야코비안 Jh(q_r)의 영공간 직교기저 N(q_r) ∈ ℝ^{n×d}를 구하면, 접공간 𝒯_r = {q_r + N(q_r)c | c ∈ ℝᵈ}과 접공간 투영자 P_{𝒯_r} = N(q_r)N(q_r)ᵀ가 즉시 확보된다. 이 국소 기하를 두 축에 녹인다:

  • TGS (Tangent-Guided Sampling): 샘플링·최근접 탐색을 접공간 좌표 q̄(저차원 d-표현)에서 수행한다. 샘플이 다양체 접평면에 정렬되므로, 이어지는 투영 보정이 작아지고 전진이 직접적이다. 또한 역행(backtracking)을 접공간 변위 투영 부호로 감지·방지한다.

  • TGMP (Tangent-Guided Multi-Edge Projection): 한 번의 샘플·최근접 질의로 접선 방향 u를 따라 K개의 연속 후보 에지 q̄_k = q̄_near + kξu를 생성하고, 이를 협력 스레드 그룹에 분산해 동시 검증한다. 접공간 구성이라는 고정 오버헤드를 K개 에지가 공유(amortize)하므로, 확장당 유효 처리량이 K배로 늘어난다.

  • GPU SIMT 3계층 병렬성: N_blk=512 블록이 트리별 접공간 뱅크에서 준비된 접공간을 동적 선택 → 블록 내 스레드로 거리 평가·리덕션 최근접 탐색 → TGMP 다중 에지를 협력 스레드 그룹으로 분산 검증. 양방향(start/goal 트리) RRT-Connect 구조 위에서 돈다.

결과적으로 PATACON은 저차원·저공차원(Franka OR 2D, Dual Franka 6D/8D)에서는 cpRRTC와 대등하면서, 차원·공차원이 커질수록 상대 이득이 커지는 스케일링 특성을 보인다 — FFW-SG2 고정 BK+OR(8D)에서 최대 11.25배.

3. 핵심 방법론 (Core Methods)

3.1 접공간·접공간 투영자 (Tangent Space & Projector)

PATACON의 모든 연산의 기반은 제약 다양체의 국소 선형 근사다. 미분가능 등식 제약 h: 𝒞 → ℝᵐ (full row rank m 가정)이 주어지면:

제약 다양체:
    ℳ = { q ∈ 𝒞 | h(q) = 0 }

구성 q에서의 접공간 (tangent space):
    T_q ℳ = { v ∈ ℝ^n | Jh(q) v = 0 }

    여기서 Jh(q) = ∂h(q)/∂q ∈ ℝ^{m×n} 는 제약 야코비안.
    full row rank m 이면 다양체 차원 d = n − m.

접공간은 야코비안의 영공간(null space) 이다. 이 영공간의 직교정규 기저 N(q) ∈ ℝ^{n×d}는 다음을 만족한다:

    Jh(q) N(q) = 0          (영공간 조건)
    N(q)ᵀ N(q) = I_d        (직교정규)

N(q)는 보통 Jh(q)의 SVD 또는 QR 분해에서 영공간 블록으로 얻는다. 이로부터 접공간 표현과 접공간 투영자가 정의된다:

접공간(국소 좌표계로 매개화):
    𝒯_r = { q_r + N(q_r) c | c ∈ ℝ^d }

    → q_r 를 원점으로, N(q_r) 열을 축으로 하는 d-차원 평면.
    → c 가 접공간 좌표(저차원 d-벡터).

접공간 투영자 (tangent-space projector):
    P_{𝒯_r} = N(q_r) N(q_r)ᵀ   ∈ ℝ^{n×n}

    → 임의의 앰비언트 벡터를 접평면 성분으로 사영(제약 위반 방향 성분 제거).
    → 멱등(P² = P), 대칭(Pᵀ = P).

핵심 차별점을 명확히 하자. cpRRTC는 앰비언트 변위 (q_rand − q_near)를 그대로 조향 방향으로 쓴 뒤 큰 투영으로 되돌린다. PATACON은 변위를 먼저 P_{𝒯_r}로 접평면에 사영하거나(연결 단계) 아예 접공간 좌표 c 안에서 샘플링(확장 단계)하므로, 제약 위반 방향 성분이 처음부터 제거된다. 투영은 이제 "다양체의 미세한 곡률로 인한 2차 오차"만 보정하면 되므로 훨씬 작고 빠르다.

3.2 Tangent-Guided Sampling (TGS)

TGS는 "어디서 샘플하고 어느 노드에서 확장할지" 를 접공간 기하로 결정한다. 핵심은 최근접 탐색을 앰비언트 n-차원 유클리드 거리가 아니라 접공간 저차원 표현 q̄ 에서 수행하는 것이다.

GPU 블록-접공간 뱅크 동적 선택. 각 트리(start/goal)는 지금까지 생성된 노드들의 접공간 정보를 담은 공유 뱅크를 GPU 전역 메모리에 유지한다. 각 CUDA 블록은 매 반복에서 뱅크로부터 준비된(ready) 접공간을 동적으로 선택한다. 이렇게 블록마다 서로 다른 접공간을 맡아 트리의 여러 영역을 동시 확장한다.

접공간 좌표 최근접 탐색. 선택된 접공간 𝒯_r 안에서 확장 기준 노드는 다음으로 정해진다:

    q_near = argmin_{ q_i ∈ V(T_grow, r) }  dist( q̄_i , q̄_rand )

    - q̄_i   : 노드 q_i 의 접공간(국소) 표현
    - q̄_rand : 접공간 안에서 뽑은 무작위 샘플의 표현
    - V(T_grow, r) : 성장 중인 트리에서 접공간 r 과 연관된 노드 집합

이 최근접 탐색은 블록 내 스레드들이 각자 거리를 평가(thread-level distance evaluation)하고 블록 수준 리덕션(block-level reduction) 으로 최솟값을 모아 완료한다 — GPU에 최적화된 병렬 패턴이다.

역행 방지 (backtracking prevention). 접공간 안에서 무작정 전진하면 부모 노드 방향으로 되돌아가는 낭비가 생긴다. PATACON은 부모 q_p와 현재 q_r의 변위를 새 접공간으로 투영해 전진 방향 d_r을 정하고, 내적이 음수(즉 부모 쪽으로 향함)이면 샘플 변위를 반전시킨다:

    d_r ← P_{𝒯_r} ( q_r − q_p )        # 부모→현재 변위를 새 접평면에 사영
    if  ⟨ d_r , 샘플변위 ⟩ < 0 :
        샘플변위 ← − 샘플변위         # 역행이면 뒤집어 전진 보장

이로써 접공간 샘플이 항상 "트리가 자라던 방향"을 존중하며 확장된다.

3.3 Tangent-Guided Multi-Edge Projection (TGMP)

TGMP는 PATACON의 처리량 핵심이다. 한 번의 샘플·최근접 질의로 끝나지 말고, 그 접선 방향을 따라 여러 개의 연속 에지를 한꺼번에 만들어 동시에 검증하자는 것이다.

다중 후보 에지 생성. 정규화된 확장 변위 u = v_ext / ‖v_ext‖₂ 를 접선 방향으로 삼아, K개의 등간격 후보 구성을 생성한다:

    q̄_k = q̄_near + k ξ u ,     k = 1, …, K

    - ξ   : 확장 스텝 크기 (extension step size, 기본 0.4)
    - u   : 정규화 접선 방향
    - K   : 이번 확장에서 만들 후보 수 (≤ K_max, 기본 4)

생성은 다음 중 하나가 걸리면 종료한다: (1) K_max개를 다 만들었거나, (2) 제약 잔차(constraint residual) 가 임계를 넘어 접선 선형 근사가 더 이상 유효하지 않을 때.

    제약 잔차:
        E_ℳ( q̄_k ) = ‖ h( q̄_k ) ‖₂

    종료 조건:
        k = K_max  또는  E_ℳ( q̄_k ) > ε_ℳ      (ε_ℳ 기본 0.1)

즉 접선 방향으로 조금씩 나아가다가, 다양체 곡률 때문에 잔차가 ε_ℳ를 초과하는 지점에서 멈춘다 — 선형 근사의 신뢰 구간을 자동으로 정하는 셈이다.

핵심 분할상환(amortization). 접공간 구성(야코비안 계산 → 영공간 기저 N → 접선 방향)은 확장당 한 번의 고정 비용이다. 기존 방식은 이 비용을 들여 에지 하나만 얻지만, TGMP는 같은 비용으로 K개의 연속 에지를 얻는다. 뒤이은 각 후보의 투영·충돌검사는 서로 다른 협력 스레드 그룹에 분산돼 병렬 실행된다:

┌──────────── 1회 접공간 구성 (고정 오버헤드) ───────────┐
│  Jh(q_near) → N(q_near) → 접선 방향 u                  │
└───────────────────────┬───────────────────────────────┘
                        │  TGMP: K개 후보 전개
        ┌───────────┬───┴───────┬───────────┐
        ▼           ▼           ▼           ▼
      q̄_1         q̄_2         q̄_3         q̄_4
    [스레드그룹1][스레드그룹2][스레드그룹3][스레드그룹4]  ← 동시 검증
     투영+충돌    투영+충돌    투영+충돌    투영+충돌
        │           │           │           │
    (에지 내부 웨이포인트 투영은 각 에지 안에서 순차)

주의: 서로 다른 에지는 서로 다른 스레드 그룹으로 병렬 검증되지만, 한 에지 내부의 웨이포인트 투영(G=16 해상도로 이산화한 중간점들)은 순차적으로 진행한다 — 앞 웨이포인트가 다양체에 투영돼야 다음 투영의 초기값이 되기 때문이다.

3.4 RRT-Connect 확장과 CONNECT 단계

PATACON의 전역 골격은 양방향 RRT-Connect다. 두 트리(start·goal)를 번갈아 성장시키며, EXTEND로 한 트리를 샘플 쪽으로 뻗고 CONNECT로 반대 트리의 최근접 노드까지 반복 확장해 연결을 시도한다.

EXTEND 단계. 선택된 접공간에서 TGS로 q_near를 고르고, TGMP로 접선 방향 다중 후보를 전개·투영·검증해 트리에 추가한다(위 3.2·3.3).

CONNECT 단계 — 목표지향 접공간 투영. 한 트리가 새 노드 q_new를 얻으면, 반대 트리의 가장 가까운 노드 q_tar를 향해 반복 확장한다. 이때 앰비언트 목표 변위를 현재 접공간에 사영해 접평면을 벗어나지 않는 연결 속도를 만든다:

    v_con = P_{𝒯_r} ( q_tar − q_cur )

    → (q_tar − q_cur) 앰비언트 변위에서 제약 위반 성분을 제거하고
      접평면 성분만 남겨 연결을 진행.

전진 보장(progress condition). CONNECT가 무한 루프에 빠지지 않도록, 모든 후보 에지는 목표까지 거리가 최소 ε_prog만큼 단조 감소해야 한다:

    dist( q_k , q_tar ) < dist( q_{k−1} , q_tar ) − ε_prog

연결 성공 판정. 현재 구성이 목표에 충분히 가까우면 두 트리가 연결됐다고 본다:

    dist( q_cur , q_tar ) ≤ ε_con          # 연결 근접 임계

CONNECT는 최대 J_max 반복까지 시도한다. 각 후보 에지는 (i) 투영 수렴, (ii) 관절 한계 만족, (iii) 충돌 없음을 모두 통과해야 유효하다.

전체 RRT-Connect 흐름 (의사코드):

TB-RRT-Connect (PATACON):
    T_a ← {q_start} ,  T_b ← {q_goal}
    접공간 뱅크 초기화: N(q_start), N(q_goal)
    repeat (N_blk=512 블록 병렬):
        q_rand ← 접공간에서 무작위 샘플 (TGS)
        # ── EXTEND(T_a) ──
        𝒯_r      ← 블록이 뱅크에서 동적 선택
        q_near   ← argmin_{q_i} dist(q̄_i, q̄_rand)      # 접공간 최근접
        방향 u   ← 역행방지 적용한 정규화 접선 변위
        {q̄_k}    ← q̄_near + kξu, k=1..K  (E_ℳ ≤ ε_ℳ)   # TGMP 다중에지
        {q_k}    ← 각 후보 투영+관절한계+충돌검사 (스레드그룹 병렬)
        유효 노드들을 T_a 에 추가, 접공간 뱅크 갱신
        # ── CONNECT(T_b → q_new) ──
        q_tar ← T_b 의 q_new 최근접 노드
        while dist(q_cur,q_tar) > ε_con and iter < J_max:
            v_con ← P_{𝒯_r}(q_tar − q_cur)
            전진조건 dist↓ε_prog 만족 에지만 추가
        if 연결 성공: 경로 추출 → (anytime 10s 예산 내 정제)
        swap(T_a, T_b)
    until 연결 or timeout(500s)

3.5 GPU SIMT 3계층 병렬성 (Parallelism Architecture)

PATACON은 위 알고리즘을 NVIDIA GPU의 SIMT 모델에 맞춰 3계층으로 병렬화한다 (Figure 2):

┌─ 계층 1: 블록 수준 (N_blk = 512 CUDA 블록) ─────────────────┐
│  각 블록이 트리별 공유 접공간 뱅크에서 "준비된" 접공간을      │
│  동적 선택 → 트리의 서로 다른 영역을 동시 확장               │
│  (start/goal 양방향 트리 동시 성장)                          │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌─ 계층 2: 블록 내 스레드 (최근접 탐색) ───────────────────────┐
│  블록 내 스레드들이 각 노드까지 접공간 거리 병렬 평가         │
│  → 블록 수준 리덕션으로 q_near 결정                           │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌─ 계층 3: 협력 스레드 그룹 (TGMP 다중 에지 검증) ─────────────┐
│  TGMP가 만든 K개 후보 에지를 서로 다른 스레드 그룹에 분산     │
│  → 투영·관절한계·충돌검사를 에지별 동시 실행                  │
│  (단, 한 에지 내부 웨이포인트 투영은 순차)                    │
└──────────────────────────────────────────────────────────────┘

메모리 레이아웃. 접공간 뱅크는 GPU 전역 메모리에 유지되며, 각 트리 노드는 다음을 저장한다:

    노드 i 저장 내용:
      - q_i          : 다양체로 투영된 (실현가능) 구성
      - parent(i)    : 부모 노드 인덱스
      - τ(q_i)       : 연관된 접공간 식별자 (어느 접공간에서 생성됐나)
      - q̄_i          : 접공간 국소 표현 (저차원 d-벡터)

이 설계로 (1) 블록들이 락(lock) 경합 없이 서로 다른 접공간을 맡고, (2) 최근접 탐색이 저차원 q̄로 수행돼 거리 계산 비용이 줄며, (3) TGMP 다중 에지가 하드웨어 점유율(occupancy)을 높인다. 즉 cpRRTC가 "앰비언트 조향+투영을 병렬화"한 데 비해, PATACON은 "접공간 기하 연산을 GPU 병렬 패턴(리덕션·스레드그룹 분산)에 맞게 재설계"한 것이 성능 비결이다.

3.6 Anytime 최적화 (선택적 정제)

연결에 성공하면 PATACON은 남은 예산(기본 10초) 동안 경로 비용을 낮추는 anytime 정제를 수행한다. 상대 비용 절감률로 정량화한다:

    R_cost = ( C_init − C*(T_AO) ) / C_init × 100   [%]

    - C_init     : 최초 발견 경로 비용
    - C*(T_AO)   : anytime 최적화 후 최선 경로 비용

이는 PATACON이 "먼저 빠르게 실현가능 해를 찾고, 시간이 허락하면 품질을 끌어올리는" anytime 특성을 가짐을 보인다. (DFT*#237·AnytimeGTMP#232의 anytime 철학과 같은 결.)

Dual Franka 6D/8D에서도 거의 대등(0.83×, 0.95×). 그러나 공차원이 커지고 제약이 복잡해질수록 역전된다: FFW-SG2 고정 BK+OR(8D)에서 cpRRTC는 291.96ms로 폭증하지만 PATACON은 25.94ms에 머물러 11.25배 빠르다. 이동 FFW-SG2(1.96×)·G1 20D(1.58×)에서도 일관된 이득. 즉 PATACON의 가치는 "접공간 유도가 앰비언트 조향+투영의 고차원 붕괴를 막는다"는 것이며, 바로 이중팔·휴머노이드 같은 실제로 어려운 고공차원 제약 과제에서 빛난다.

TGS 단독은 접공간 샘플·최근접의 추가 오버헤드만 지불하고 다중 에지 분할상환 이득을 못 받으며, TGMP 단독은 앰비언트 조향 방향에 다중 에지를 깔아봤자 투영 보정이 커 효율이 안 난다. 두 기법을 결합해야 "접공간 정렬 샘플(TGS) × 그 정렬 방향을 따른 다중 에지 분할상환(TGMP)"의 시너지로 152.95ms까지 떨어진다. 이는 PATACON 설계가 임의 조합이 아니라 상호보완적으로 공동 설계됐음을 입증한다.

5.4 리얼월드·시뮬레이션 실험 (Real-world / Simulation)

본 논문의 평가는 시뮬레이션(물리·운동학 시뮬) 중심이며, 실물 로봇 하드웨어 배포 실험은 보고되지 않았다(향후 과제로 남김). 대신 실제 로봇 모델(Franka Panda, FFW-SG2, Unitree G1)의 정확한 URDF·관절 한계·충돌 지오메트리를 사용해 이중팔 폐연쇄·휴머노이드 전신 균형이라는 현실적으로 어려운 제약 설정을 다룬다는 점이 실용적 강점이다. 코드 저장소에는 네 로봇 백엔드(Franka, G1, FFW-SG2, IGRIS-C)와 벤치마크·평가 프론트엔드(single_mbm, evaluate_mbm)가 포함돼 재현 가능하다.

6. 핵심 기여점 (Key Contributions)

  1. 접공간을 계획의 1차 시민으로 — 패러다임 전환. "앰비언트 조향 후 투영"이 아니라 "접공간 안에서 직접 탐색"하는 TB-RRT-Connect를 제안. 제약 야코비안의 영공간 기저로 국소 다양체 기하를 명시적으로 활용해 투영 보정을 근본적으로 줄인다.

  2. Tangent-Guided Sampling (TGS). 접공간 저차원 좌표에서 샘플·최근접 탐색을 수행하고 역행을 부호 검사로 방지. 블록이 접공간 뱅크에서 동적 선택하는 GPU 친화적 구조.

  3. Tangent-Guided Multi-Edge Projection (TGMP). 한 번의 접공간 구성 비용으로 K개 연속 후보 에지를 생성·동시 검증해 고정 오버헤드를 분할상환. 제약 잔차 E_ℳ ≤ ε_ℳ로 선형 근사 신뢰 구간을 자동 결정.

  4. GPU SIMT 3계층 병렬성. 블록(접공간/양방향 트리) → 스레드(리덕션 최근접) → 협력 스레드 그룹(다중 에지 검증)의 계층적 병렬 설계로 접공간 연산을 하드웨어에 정합.

  5. 고공차원 스케일링 입증. 차원·공차원이 커질수록 cpRRTC 대비 이득이 커지는 특성을 이중팔(최대 11.25×)·휴머노이드(최대 1.58×) 과제에서 실증. 절제 연구로 TGS·TGMP의 상호보완적 시너지 입증.

  6. 공개 코드 (재현성). Apache-2.0 라이선스로 C++/CUDA 구현을 공개(gahyun0425/cpRRTC_TB-RRT), 네 로봇 백엔드·벤치마크·테스트 포함.

8. 고급 주제 (Advanced Topics)

확장성 (Scalability). PATACON의 설계 철학은 "단위 작업을 저차원 접공간에 가두어 차원 증가에 둔감하게 만든다"이다. 실제로 가속비가 차원·공차원과 함께 증가(8D에서 11.25×)하는 것은 이 철학이 성립함을 보인다. N_blk=512 블록·RTX 5090의 대규모 병렬성이 TGMP 다중 에지와 결합해 하드웨어 점유율을 높게 유지한다.

한계점 (Limitations).

  • 극저차원 오버헤드. Franka OR(2D)처럼 쉬운 문제에서는 접공간 뱅크 관리·영공간 분해 오버헤드가 상대적으로 커 cpRRTC보다 느리다(0.32×). PATACON은 "어려운 고공차원" 전용 도구에 가깝다.
  • 분산 증가. G1 20D에서 PATACON 표준편차(±44.29ms)가 cpRRTC(±19.47ms)보다 크다 — 접공간 동적 선택·다중 에지 종료(E_ℳ) 조건이 실행 간 변동을 키운다. 실시간 보장이 중요한 상황에서는 worst-case 특성을 더 봐야 한다.
  • 실물 하드웨어 미검증. 시뮬레이션·정확한 URDF 기반이나 실로봇 배포 실험은 없다. 센서 노이즈·동역학 오차 하 강건성은 미지수.
  • 등식 제약 가정. h(q)=0 등식·full row rank 가정에 기댄다. 부등식 제약(관절 한계는 검사로 처리하나)·불연속 접촉 전환 등은 직접 다루지 않는다.

향후 방향.

  • 실물 이중팔·휴머노이드 배포 및 동적 재계획(이동 장애물)으로의 확장.
  • 접공간 유도를 다른 GPU 계획기(MR.POP류 dRRT 다중로봇, PAAMP류 볼록 행동집합)에 이식해 "접공간+집합값 노드" 결합.
  • 부등식 제약·접촉 모드 전환을 포함한 하이브리드 제약 다양체로 일반화.

PAAMP(Trusted Polytopic Action Sets for Fast Planning in Underactuated Systems) 대비. 두 논문은 "제약·동역학 때문에 앰비언트 조향이 비효율적"이라는 같은 문제의식에서 출발하지만 처방이 다르다. PAAMP는 명목궤적 주변을 국소 아핀좌표로 잡아 충돌·제어 제약을 선형화하고, 신뢰영역을 IRIS-ZO로 볼록 내부근사한 다면체 행동집합(PAS)을 노드로 삼는다("단일 상태 → 도달가능 집합"). PATACON은 접공간(영공간)을 좌표계로 삼아 그 안에서 샘플·확장한다("단일 상태 → 접평면 위 탐색"). 공통점은 "국소 선형 구조를 노드/탐색 단위에 녹인다"이고, 차이는 PAAMP가 부족구동 동역학(제어 가능성)을, PATACON이 운동학 등식 제약 다양체(폐연쇄·균형)를 겨냥한다는 점이다. 둘은 직교·상보적이다: PATACON의 접공간 샘플링을 PAAMP의 볼록 행동집합 노드와 결합(접평면 위에서 도달가능 폴리토프 구성)하면 "기하 제약 + 동역학"을 함께 다루는 하이브리드가 가능하다.

Constraint Manifold Charts IFT(Planning along Differentiable Charts of Constraint Manifolds with General-Purpose IK Solvers) 대비. 가장 개념적으로 가깝다. 둘 다 "제약 다양체를 최소좌표로 매개화해 앰비언트 투영 부담을 줄인다". 그러나 접근이 대칭적으로 반대다. IFT 논문은 해석적 IK 솔버(IKFast/EAIK)를 블랙박스로 써서 다양체를 미분가능 차트 φ:𝒴→ℳ로 매개화하고, 역함수 정리로 FK 야코비안만으로 그래디언트를 조립한다 — "IK가 이미 다양체를 알고 있으니 그걸 좌표로 쓰자". PATACON은 제약 야코비안의 영공간으로 접평면을 수치적으로 구성한다 — "제약 함수의 미분으로 국소 좌표를 만들자". IFT 논문은 CPU 드롭인(IrisNp2/Trajopt/TOPPRA 재사용)에 최적화된 반면, PATACON은 GPU 병렬 RRT-Connect에 특화됐다. 전자는 궤적최적화·볼록계획과의 결합을, 후자는 대규모 샘플링 병렬성을 노린다. PATACON의 11.25× 가속은 "GPU에서 접공간을 병렬 패턴으로 재설계"한 데서 오고, IFT의 강점은 "임의 IK 솔버 무수정 재사용 + 해석적 정확도(Jacobian 오차 1e-13)"에 있다.

MR.POP(Multi-Robot Parallel Optimizing Planner) 대비. 둘 다 GPU SIMT 3계층 병렬 샘플링 계획기이며 CoMMALab 계열 cpRRTC/pRRTC 생태계를 공유한다(PATACON 저장소명 cpRRTC_TB-RRT가 직접 계승을 명시). 차이는 문제 축이다. MR.POP은 다중로봇의 결합 구성공간을 dRRT 텐서곱 복합 로드맵 + AO-x로 거의확실 점근최적(a.s.a.o.) 다루는 데 집중하고, 제약 다양체는 주 관심이 아니다. PATACON은 단일(혹은 폐연쇄 결합) 로봇의 제약 다양체를 접공간으로 효율화한다. 두 논문은 같은 GPU 병렬 뼈대 위에서 서로 다른 "어려움"(다중로봇 조합 폭발 vs 제약 다양체 투영 붕괴)을 공략하므로, 원리적으로 결합 가능하다(다중로봇 + 각 로봇 제약을 접공간으로).

CMG-RRT(Critical-Manifold-Guided RRT) 대비. 둘 다 "다양체 기하로 샘플링을 유도"하지만 대상 다양체가 다르다. CMG-RRT는 크리티컬 다양체(좁은 통로·접촉 다양체)를 SDF 세분화로 찾아 샘플을 그쪽으로 편향시키는 — 조립/퍼즐 같은 좁은 통로 집중 전략이다. PATACON은 제약(등식) 다양체 위에서 전역적으로 탐색하는 — 폐연쇄·균형 제약 전역 포괄 전략이다. "집중(CMG-RRT) vs 포괄(PATACON)"의 대비이며, CMG-RRT는 CPU, PATACON은 GPU라 병렬화 축도 다르다.

9.2 장단점 분석

장점:

  • 고공차원 제약 과제(이중팔·휴머노이드)에서 cpRRTC 대비 큰 실질 이득(최대 11.25×)이 증가 추세로 입증 — 실제 어려운 문제에서 가치.
  • TGS·TGMP의 상호보완 시너지가 절제로 명확히 입증(단독은 오히려 느림 → 공동설계 증거).
  • Apache-2.0 공개 코드 + 네 로봇 백엔드 + 벤치마크/테스트로 재현성 우수.
  • 100% 성공률(모든 평가 조합)로 완전성 측면 안정.

단점:

  • 극저차원에서 오버헤드로 역전(cpRRTC가 더 빠름) — 범용 기본 계획기로는 부적합.
  • 실행 간 분산 증가(G1 ±44ms) — 실시간 경성 보장에 불리할 수 있음.
  • 실물 하드웨어 미검증 — sim-to-real 강건성 미지수.
  • ICRA 2027 투고 상태(미확정) — 피어리뷰 검증 전.

9.3 실적용 가능성 평가

이중팔 협조 조작·휴머노이드 전신 동작은 산업·서비스 로봇의 핵심 수요다. PATACON은 바로 이 "고DOF·고공차원 제약"에서 밀리초~수십 ms 계획을 달성하므로, GPU가 탑재된 온보드/엣지 플랫폼에서 온라인 제약 재계획에 실용적이다. 코드가 cpRRTC 생태계·표준 URDF를 따르고 Apache-2.0라 기존 파이프라인 통합 장벽이 낮다. 다만 (1) 실물 센싱/동역학 오차 하 검증, (2) 분산(worst-case) 특성 보강, (3) 동적 장애물 재계획 확장이 실배포 전 과제다.

9.4 연구 방향성 평가

PATACON은 "접공간을 계획 단위에 녹이기"라는 아이디어를 GPU 병렬 샘플링에 성공적으로 이식했다는 점에서 참신하다. PAAMP(아핀좌표 행동집합)·IFT(해석 IK 차트)가 각각 CPU 볼록계획·드롭인 솔버 방향으로 제약 다양체를 다룬 것과 대칭적으로, PATACON은 GPU 대규모 병렬 방향을 채웠다. 중복 아이디어라기보다 "제약 다양체 모션계획을 GPU로 끌어올린 빈칸"을 메운 것이며, MR.POP(다중로봇)·PAAMP(부족구동)와의 결합 가능성이 후속 연구 공간을 넓게 연다.

11. 결론 (Conclusion)

PATACON 은 제약 모션계획의 오랜 병목인 "앰비언트 조향 후 투영"의 고차원 붕괴를, 접공간(제약 야코비안 영공간)을 계획의 1차 시민으로 승격함으로써 근본적으로 공략한다. 두 핵심 기법 — 접공간 안에서 샘플·최근접을 수행하는 TGS, 한 번의 접공간 구성으로 다중 연속 에지를 생성·동시 검증해 오버헤드를 분할상환하는 TGMP — 를 GPU SIMT 3계층 병렬성 위에 올려, 이중팔 폐연쇄·휴머노이드 전신 같은 실제로 어려운 고공차원 제약 과제에서 기존 GPU 제약 계획기 cpRRTC 대비 최대 11.25배 가속을 100% 성공률로 달성했다. 절제 연구는 두 기법이 단독이 아니라 결합해야 이득이 난다는 점(공동설계의 증거)을 명확히 보였다.

혁신성 측면에서 PATACON은 PAAMP(국소 아핀좌표 볼록 행동집합)·Constraint Manifold Charts IFT(해석 IK 미분가능 차트)·MR.POP(GPU 다중로봇 dRRT)·CMG-RRT(크리티컬 다양체 유도)가 각각 메운 조각들 사이의 "제약 다양체 모션계획을 GPU 대규모 병렬로" 라는 빈칸을 채웠다. 실용적 의의는 GPU 탑재 플랫폼에서 이중팔·휴머노이드의 온라인 제약 재계획을 수십 ms로 가능케 한다는 점이며, Apache-2.0 공개 코드가 재현성과 생태계 통합을 뒷받침한다. 향후 실물 하드웨어 검증, worst-case 분산 보강, 동적 장애물 재계획 확장, 그리고 PAAMP(부족구동)·MR.POP(다중로봇)과의 결합이 유망한 연구 방향이다.
