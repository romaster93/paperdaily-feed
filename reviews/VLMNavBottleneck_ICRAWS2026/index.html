1.2 연구 목표 (Research Objective)

본 논문은 VLM(Vision-Language Model)과 LLM(Large Language Model)의 결합으로 구동되는 제로샷 Vision-Language Navigation(Zero-Shot VLN) 시스템에서, 3D 장면 인식(3D scene understanding) 능력이 내비게이션 성공률에 미치는 영향을 체계적으로 분석한다.

핵심 문제 의식:

[제로샷 VLN 파이프라인의 구조적 문제]

기존 VLM-LLM 기반 제로샷 VLN 시스템:
  시각 입력 → [3D 인식 모델] → 장면 표현 → [LLM 플래너] → 행동

인식 단계의 오해:
  "더 정확한 3D 인식 = 더 높은 내비게이션 성공률"
                     ↓ 이 논문의 핵심 반론
  "인식 정확도는 특정 임계점 이상에서 성공률 향상에 
   거의 기여하지 않는다 (Perception Saturation)"

핵심 질문:
  1. 3D 인식의 어떤 측면이 내비게이션에 실제로 중요한가?
  2. 현재 3D 인식 모델들은 어디서 내비게이션을 실패시키는가?
  3. 최적 VLN을 위한 인식 시스템 설계 원칙은 무엇인가?

이 논문은 "인식(perception)이 좋아지면 내비게이션도 좋아진다"는 단순 가정을 깨뜨리고, 인식 포화 현상(Perception Saturation Phenomenon)을 발견하며, 실제 내비게이션에 중요한 인식 특성이 무엇인지를 실험적으로 규명한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 3D 인식 모델과 내비게이션 요구사항의 불일치

현재 3D 인식 모델들은 픽셀 수준 정확도를 최우선으로 학습하지만, VLN은 전혀 다른 특성을 요구한다:

[인식 모델 최적화 목표 vs. VLN 요구사항]

3D 인식 모델 최적화:
  ✓ 모든 객체의 높은 분할 정확도 (AP, IoU 최대화)
  ✓ 픽셀 단위의 경계 정확도
  ✓ 다수의 객체 클래스 인식 (ScanNet200: 200개 클래스)
  ✓ 배경 포함 완전한 장면 분할

VLN이 실제로 필요로 하는 것:
  ✓ 지시문에 등장하는 랜드마크 객체 인식 (~20개 핵심 클래스)
  ✓ 객체의 대략적 공간 위치와 방향 (정확한 형태 불필요)
  ✓ 실시간 처리 가능한 계산 복잡도
  ✓ 바운딩 박스의 가로세로 비율 정확성 (크기 왜곡 없는 공간 추론용)

핵심 불일치:
  인식 모델이 최적화하는 지표 ≠ VLN이 민감한 지표

이 불일치는 두 가지 구체적인 실패 모드를 만든다:

실패 모드 1 — Slow LLM Planner에서의 오탐지(False Positive):

3D 인식 모델이 200개 클래스 중 관련 없는 객체들을 
다수 탐지 → 위상 지도(topological map)에 노이즈 증가
→ LLM이 관련 없는 객체들을 랜드마크로 혼동
→ 잘못된 경로 결정

예시: "계단을 올라가 왼쪽 방으로"라는 지시에서
탐지된 320개 객체 중 내비게이션에 유용한 것: 12개
무관한 오탐지가 의사결정을 방해함

실패 모드 2 — Fast Reactive Navigator에서의 바운딩 박스 왜곡:

목표 객체(예: "문")의 바운딩 박스가 가로세로 비율 왜곡
→ 에이전트가 객체까지의 실제 거리/방향을 잘못 추정
→ 충돌하거나 목표에 도달하지 못함

특히 문, 복도 입구 같은 가로 길쭉한 구조물에서 심각:
탐지: 정사각형 BB → 실제: 세로 길쭉한 문 (4:1 비율)
추정 통과 경로: 중심점 기준 → 실제 통과 가능 경로: 양측 기준

B. 계산 자원과 실시간 요구사항 충돌

[3D 인식 모델의 계산 비용 vs. VLN 실시간 요구]

ESAM (Efficient Segment Anything Model) 계열:
  - 단일 뷰포인트에서 40프레임 360° 스캔 처리 필요
  - 전체 파이프라인: 수 초 ~ 수십 초
  
VLN 실시간 요구사항:
  - 각 의사결정 단계: 1-2초 이내 (R2R: 최대 500스텝 이동)
  - 계산 지연이 늘어날수록 전체 내비게이션 시간 급증

실용적 딜레마:
  정확한 인식 → 높은 계산 비용 → 느린 내비게이션
  빠른 인식 → 낮은 정확도 → 낮은 내비게이션 성공률

2.2 핵심 해결책

이 논문은 해결책을 직접 제안하기보다, 문제의 본질을 정밀하게 분석하여 설계 원칙을 도출한다. 구체적으로:

  1. 통계적 성공률 상한(SR upper bound) 도출: 이상적인 인식 조건에서 각 플래너가 달성할 수 있는 최대 성공률을 수학적으로 계산
  2. 인식 품질 파라미터화: 탐지율(ρ_ret)과 바운딩 박스 IoU(φ_iou)를 변수로 SR과의 관계 규명
  3. 핵심 설계 원칙 제시: 정밀도보다 커버리지 핵심 어휘(navigation-critical vocabulary)가 중요함을 실험으로 증명

3. 핵심 방법론 (Core Methods)

3.1 시스템 기반: SFCo-Nav 프레임워크 분석

이 논문의 분석 대상은 SFCo-Nav 아키텍처로, Slow/Fast 이중 플래너 구조를 채택한다:

[SFCo-Nav 전체 파이프라인]

입력: 자연어 지시 I, 현재 시각 관측 {v_1, ..., v_T}
      ↓
[3D 인식 단계 — ESAM]
  • 40프레임 360° 회전 스캔
  • 객체 분할 + 3D 위치 추정
  • ScanNet200 어휘 → R2R 카테고리 매핑
      ↓
      ├──→ [Slow LLM Planner]          ├──→ [Fast Reactive Navigator]
      │      • 위상적 장면 그래프         │      • 공간 좌표 + BB
      │      • GPT-4o 추론              │      • 반사적 행동 결정
      │      • 전역 경로 계획            │      • 지역 장애물 회피
      │      • 높은 지연, 높은 정확성     │      • 낮은 지연, 즉각 반응
      └──────────────┬─────────────────┘
                     ↓
              최종 내비게이션 행동

두 플래너는 인식 결과를 다르게 활용하므로, 인식 품질에 대한 민감도도 다르다.

3.2 인식 품질 파라미터화 (Perception Quality Parameterization)

3.2.1 이상적 관측 (Ideal Observation)

시점 v에서의 이상적 관측은 N개 객체의 완전 정보:

O_gt^v = {o_1, o_2, ..., o_N}

각 객체 o_i:
  - semantic label: l_i ∈ L (정확한 카테고리)
  - bounding box: b_{i,gt}^v (이상적 위치/크기)
  - 3D position: pos_i (공간 좌표)

3.2.2 Slow Planner용 탐지율 (Retention Ratio) ρ_ret

Slow LLM Planner는 위상적 시간-객체 이분 그래프(Temporal-Object Bipartite Graph) G를 구성한다:

G = (T, V_obj, E)

T: 궤적 상의 시간 노드들 {t_1, ..., t_K}
V_obj: 탐지된 의미론적 객체들
E: 간선 집합, (t, o) ∈ E ↔ 시간 t에 객체 o가 관측됨

그래프 무결성 점수 (Graph Integrity Score):
  S_match = λ·S_edge + (1-λ)·S_obj

  S_obj  = |V_obj^deg ∩ V_obj^ideal| / |V_obj^ideal|
         = 탐지된 관련 객체 수 / 전체 관련 객체 수 (객체 재현율)
         
  S_edge = |E_deg ∩ E_ideal| / |E_ideal|  
         = 올바른 시간-객체 연결 수 / 전체 이상적 연결 수 (시간-의미 간선 점수)
         
  λ = 0.5 (균등 가중치)

탐지율 파라미터:

O_slow^v = {o_1, ..., o_K},  K = floor(ρ_ret · N)

포함 규칙 (중첩 부분집합 속성):
  ρ_1 < ρ_2 ⟹ O(ρ_1) ⊂ O(ρ_2)
  
  즉, ρ_ret가 높을수록 더 많은 객체가 포함되며
  낮은 ρ_ret의 부분집합이 항상 유지됨

이 중첩 속성은 실험의 일관성을 보장한다: 낮은 품질의 탐지 결과가 높은 품질 결과의 부분집합이 되도록 강제함.

3.2.3 Fast Navigator용 바운딩 박스 IoU (φ_iou)

Fast Reactive Navigator는 객체의 공간 좌표와 BB를 직접 활용한다. BB 품질은 φ_iou로 파라미터화:

노이즈 BB 생성 방법:
  b_noise의 중심점: c_noise = c_ideal + Δ
  제약 조건: IoU(b_noise, b_ideal) = φ_iou

  φ_iou = 0: 완전히 다른 위치/크기의 BB
  φ_iou = 1: 이상적인 BB (완벽한 위치/크기)
  실제 ESAM: φ_iou ≈ 0.063 ~ 0.567

3.3 기술 기반 스킬 (Skill-Based Navigation)

Fast Navigator는 두 가지 기하학적 스킬로 목표에 접근한다:

3.3.1 접근 스킬 (Approach Skill) — 고체 표면용

탁자, 의자, 카운터 등 고체 물체에 접근할 때:

목표 위치 계산:
  p_target = c_noise - u · (r_coll + δ_safe)

  c_noise: 노이즈가 포함된 객체 중심
  u = (c_noise - pos_agent) / ||c_noise - pos_agent||
    : 에이전트에서 객체로의 단위 벡터
  r_coll: BB 치수에서 계산된 충돌 반경
  δ_safe: 안전 여유 버퍼

직관: 에이전트는 객체 앞 안전 거리에 정지

3.3.2 통과 스킬 (Through Skill) — 문/통로용

문, 복도 입구 등 통과 가능한 구조물을 위해:

통과 축 결정:
  j = argmin_i(s_i)    // 가장 얇은 차원 = 통과 축
  n = R[:, j]          // 통과 방향의 법선 벡터

목표 위치 계산:
  p_target = c_noise + sgn(u·n) · n · (0.5·s_j + δ_pass)

  s_j: BB의 j번째 차원 크기
  δ_pass: 통과 후 여유 거리
  sgn(u·n): 에이전트가 어느 쪽에서 통과할지 결정

직관: 에이전트는 구조물 반대편으로 이동하여 통과 완료

3.3.3 뷰포인트 선택

목표 위치 계산 후:

v* = argmin_{v ∈ V_nav} || p_target - pos(v) ||

V_nav: 내비게이션 가능한 뷰포인트 집합
v*: 목표에 가장 가까운 뷰포인트 선택

3.4 ESAM (Efficient Segment Anything Model) 훈련 분석

ESAM은 ScanNet200 데이터셋에서 훈련되며, 이 논문에서는 5개 변형을 비교한다:

[ESAM 훈련 변형 비교]

┌──────────┬──────────┬──────────┬──────────┬───────┬───────┬───────┬─────┐
│ 변형     │ SV Iter  │ MV Iter  │ 총 Iter  │ IoU   │ AP@25 │ AP@50 │ AP  │
├──────────┼──────────┼──────────┼──────────┼───────┼───────┼───────┼─────┤
│ Minimal  │    300   │    0     │    300   │  6.3  │  6.2  │  4.1  │ 2.1 │
│ Light    │    600   │    0     │    600   │ 12.5  │ 11.0  │  6.0  │ 2.8 │
│ Medium   │  80.1k   │    0     │  80.1k   │ 46.1  │ 48.2  │ 32.3  │18.6 │
│ Heavy    │  80.1k   │  38.5k   │ 118.6k   │ 56.7  │ 66.4  │ 51.7  │34.3 │
│ 20-class │  80.1k   │  38.5k   │ 118.6k   │  —    │ 75.6  │ 60.1  │41.6 │
└──────────┴──────────┴──────────┴──────────┴───────┴───────┴───────┴─────┘

SV: Single-View (단일 뷰 훈련)
MV: Multi-View (멀티뷰 훈련 — 장거리 관계 학습)
20-class: 내비게이션 핵심 20개 클래스만 사용

주목할 점:
  20-class 변형이 200-class Heavy 대비 AP에서 앞섬
  → 내비게이션 핵심 어휘만 학습해도 충분함을 시사

5.1 데이터셋 (Datasets)

  • R2R (Room-to-Room): 실내 내비게이션 표준 벤치마크

5.2 평가 지표 (Evaluation Metrics)

SR (Success Rate): 목표 지점 3m 이내 도달 성공률

SPL (Success Path Length): 경로 효율성 가중 성공률
  SPL = SR × (최단경로 / 실제경로)

6. 핵심 기여점 (Key Contributions)

6.1 인식 포화 현상 발견 (Perception Saturation Phenomenon)

[인식 포화 현상의 수학적 이해]

이상적 상황에서의 SR-ρ_ret 관계 (Slow Planner):
  ρ_ret: 0.20 → 0.80 (4배 증가)
  SR:    41.0 → 44.3 (약 8% 향상)
  
  한계 효용 체감:
  Δ(SR) / Δ(ρ_ret) = (44.3-41.0) / (0.80-0.20) ≈ 5.5%p/unit
  
  이는 내비게이션 성공률이 인식 정확도의 준선형 함수가 아님을 의미:
  SR ≈ f(ρ_ret) where f'(ρ_ret) → 0 as ρ_ret → 1.0

실제 함의:
  3D 인식 모델 개선에 막대한 자원 투자 → 내비게이션 성능 미미한 향상
  대신: 내비게이션 특화 인식 최적화가 더 효율적

6.2 플래너별 인식 실패 원인 특정

Slow LLM Planner 실패 원인:

주요 원인: False Positive 과다
  현상: ρ_ret 증가 시 관련 없는 객체도 함께 증가
  결과: 그래프 노이즈 → LLM 혼란 → 잘못된 경로 결정

수치:
  이상 조건에서 ρ_ret=0.80: SR 44.3%
  실제 ESAM ρ_ret=0.756: SR 33.7% (-10.6%p)
  
  격차 원인: 실제 탐지에서는 관련 없는 객체가 다수 포함됨
  → ρ_ret는 높지만 S_match (그래프 무결성)은 낮음

Fast Reactive Navigator 실패 원인:

주요 원인: 바운딩 박스 가로세로 비율 왜곡
  현상: ESAM의 BB가 실제 객체 형태를 정확히 반영하지 못함
  특히 문/통로: 세로 길쭉한 구조물을 정사각형 BB로 탐지

  구체적 문제:
  실제 문 크기: 0.9m × 2.1m (가로:세로 = 1:2.3)
  ESAM 탐지 BB: 1.5m × 1.5m (정사각형 - 왜곡)
  
  결과:
  - p_target 위치 오계산 → 잘못된 통과 경로
  - 충돌 또는 목표 미달

비단조적 SR-φ_iou 관계 설명:
  중간 φ_iou(0.20-0.60): BB 중심은 맞지만 형태 왜곡
  극단적 φ_iou(≈0.05): 완전히 엉뚱한 위치 → 우연히 다른 경로 발견
  높은 φ_iou(≈0.80): 형태도 맞고 위치도 맞음 → 성능 회복

6.3 내비게이션 특화 어휘 충분성 증명

[20-class vs. 200-class 실험의 의미]

증명한 것:
  ① 내비게이션 성공에 필요한 핵심 어휘 = ~20개 클래스
  ② 200개 클래스 학습 → 불필요한 클래스의 false positive 증가
  ③ 어휘 축소 → 핵심 클래스 정밀도 향상 (AP@25: 66.4 → 75.6)

설계 원칙 도출:
  "VLN을 위한 3D 인식 모델은 범용 분할 정확도보다
   내비게이션 핵심 어휘의 정밀한 바운딩 박스 추정을 최적화해야 한다"

6.4 통계적 SR 상한 프레임워크

[상한 도출 방법론의 가치]

기존 VLN 연구의 한계:
  실제 시스템 성능 측정 → 어느 요소가 병목인지 불명확

본 논문의 기여:
  이상적 인식 + 실제 인식 비교:
    격차 → 인식 병목 정량화
  인식 포화 상한 식별:
    상한 자체가 낮으면 → 인식 이외 요소(LLM 추론 등)가 병목

예: Slow Planner 이상적 상한 ~44% SR
  현재 최고 성능 제로샷 VLN(no LLM): ~35%
  → 추론 병목이 더 큼 (인식 완벽해도 44%에 그침)
  
이 프레임워크는 미래 연구의 최적화 방향을 제시

8. 고급 주제 (Advanced Topics)

8.1 인식 포화 현상의 이론적 배경

[왜 인식 포화가 발생하는가?]

VLN의 의사결정 구조:
  내비게이션 성공 여부는 연속적이 아닌 이진적 (도달/미달)
  
  핵심 변수: 정확한 랜드마크 N개 인식 여부
  N=5 랜드마크 기반 경로:
    ρ_ret = 0.20 (2/5 인식): 1/5 성공 경로만 완성 가능 → SR ≈ 20%
    ρ_ret = 0.80 (4/5 인식): 4/5 성공 경로 완성 가능 → SR ≈ 80%
    ... 이상적인 경우
    
  현실에서 포화가 발생하는 이유:
  1. LLM 자체 추론 오류 (~15% 기여)
  2. 대체 경로 발견 가능성 (랜드마크 일부 누락 시에도 성공)
  3. 잘못된 랜드마크를 활용한 우연한 성공
  4. False positive가 실제 성공을 방해하는 상쇄 효과

8.2 비단조적 SR-φ_iou 관계 설명

[Fast Navigator에서 φ_iou ≈ 0.20-0.60이 최악인 이유]

φ_iou 범위별 BB 왜곡 특성:
  φ_iou ≈ 0.05: BB 완전 엉뚱 → 에이전트가 다른 전략 채택
  φ_iou ≈ 0.20-0.60: BB 중심 근처, 형태 심각 왜곡
    → "반쯤 맞는" 정보가 가장 위험한 오도
    → 특히 BB 가로세로 비율 반전 시 (가로→세로 혼동)
    → Through Skill이 잘못된 축으로 통과 시도
  φ_iou ≈ 0.80+: BB 형태도 맞고 위치도 맞음 → 정상 동작

교훈:
  "부정확한 정보 일부가 아예 없는 것보다 더 위험할 수 있다"
  → Semi-reliable information can be more harmful than no information

8.3 실용적 설계 가이드라인

[이 연구에서 도출된 3D 인식 시스템 설계 원칙]

원칙 1: 어휘 최적화 (Vocabulary Optimization)
  ❌ 범용 분할 (ScanNet200 200개 클래스 전부)
  ✓ 내비게이션 특화 어휘 (~20개 핵심 클래스)
  이유: 핵심 클래스 정밀도 향상 + false positive 감소

원칙 2: 바운딩 박스 형태 정확성 (BB Shape Accuracy)
  ❌ 중심점만 정확한 BB (높은 center IoU, 낮은 aspect ratio 정확성)
  ✓ 가로세로 비율이 정확한 BB
  이유: Through Skill이 BB 형태에 민감

원칙 3: 인식 정확도보다 실시간성 (Realtime over Accuracy)
  인식 포화 임계점 이상에서는 정확도 향상 ≈ 성능 향상 없음
  → 더 빠른 인식 모델이 더 유용할 수 있음

원칙 4: False Positive 관리 (FP Control)
  recall 최대화보다 precision 최적화
  → 관련 없는 객체 탐지를 줄이는 것이 우선

11. 결론 (Conclusion)

혁신성 평가

이 논문의 가장 중요한 공헌은 인식 포화 현상(Perception Saturation Phenomenon)의 발견이다. 이 발견은 VLN 연구 커뮤니티에서 당연시해온 "더 좋은 인식 = 더 좋은 내비게이션"이라는 가정을 실험적으로 반박한다.

[논문의 핵심 메시지 요약]

3D 인식 품질 ↑ (ρ_ret: 0.2 → 0.8)
              ↓
VLN 성공률 ↑ 폭: 고작 3.3%p (이상적 조건에서도)
              ↓
결론: 인식 병목은 "정밀도"가 아닌 "적절성"의 문제

진짜 병목:
  Slow Planner: False Positive (불필요한 객체 탐지)
  Fast Navigator: BB 가로세로 비율 왜곡 (형태 정확성 부재)
  
해결 방향:
  범용 분할 최적화 → 내비게이션 특화 최적화

실용적 의의

이 논문은 VLN 시스템 설계자들에게 명확한 우선순위를 제공한다:

  1. 어휘 최적화가 정밀도 최적화보다 우선: 200개 클래스에서 20개 핵심 클래스로의 전환이 더 효과적
  2. BB 형태 정확성이 위치 정확성만큼 중요: 특히 문/통로 같은 비등방성 구조물에서
  3. 실시간 경량 인식이 정밀 인식보다 유용할 수 있음: 인식 포화 임계점 이상에서

향후 연구 방향

단기 과제:
  1. 내비게이션 핵심 어휘 자동 발견 알고리즘
  2. BB 형태-인식 공동 손실 함수 설계
  3. 분석 결과를 실세계 로봇으로 검증

중기 과제:
  4. 여러 VLM-LLM VLN 아키텍처로 일반화 검증
  5. 동적 환경에서의 인식 포화 분석

장기 과제:
  6. 내비게이션과 인식의 엔드-투-엔드 공동 최적화
  7. 인식 포화 임계점의 이론적 규명

총평: 방법 제안 논문이 아닌 분석 논문임에도 불구하고, 발견한 인식 포화 현상은 VLN 분야 전체의 연구 방향에 영향을 줄 수 있는 중요한 기여다. ICRA 워크숍 구두 발표 채택은 이 가치를 인정받은 것이다. 다만 코드와 실세계 검증이 없어 실용적 영향은 제한적이며, 후속 연구의 활성화가 이 논문의 진정한 가치를 결정할 것이다.

부록 A: Zero-Shot VLN 패러다임 심층 분석

A.1 Zero-Shot VLN의 진화

[Zero-Shot VLN 패러다임의 역사적 변화]

1세대 (2020-2022): 규칙 기반 탐색
  - 미리 구축된 지도 + A* 탐색
  - 한계: 미지 환경 불가, 지도 구축 비용

2세대 (2022-2024): 단일 VLM 활용
  - CLIPNav, OpenNav: CLIP 특징 + 탐욕 탐색
  - 한계: 복잡한 지시 처리 어려움, 전역 계획 없음

3세대 (2024-현재): VLM-LLM 이중 모델
  - VLM: 시각 처리 + 3D 장면 이해
  - LLM: 자연어 추론 + 전역 경로 계획
  - SFCo-Nav, Three-Step Nav, CA-Nav 등
  - 현재 최고 성능이지만 새로운 병목 발생:
    "어떤 인식이 어떻게 LLM 추론에 영향하는가?"
    → 본 논문이 이 질문에 처음으로 체계적 답변

A.2 SFCo-Nav 프레임워크와의 관계

[SFCo-Nav: 분석 대상 시스템의 세부 설계]

SFCo-Nav (Slow-Fast Cooperative Navigation):
  설계 원칙: 인간의 이중 처리 이론에서 영감
  - 시스템 1 (빠름/자동): Fast Reactive Navigator
    → 직관적, 즉각적 반응, 낮은 인지 부하
  - 시스템 2 (느림/분석적): Slow LLM Planner
    → 신중한 추론, 높은 인지 부하, 전략적 결정

두 시스템의 협력:
  - Slow: 전역 목표와 방향 제시
  - Fast: 지역 장애물 회피와 즉각 이동
  - 상호 보완적 구조

VLN에 적용:
  Slow (LLM + 위상 그래프): "두 번째 문을 지나 왼쪽" 같은 전략
  Fast (기하학 + 목표 추적): "현재 보이는 문을 통해 이동" 같은 전술

인식 모델(ESAM)의 역할:
  두 시스템 모두에 입력을 제공하지만
  각각 다른 측면(탐지율 vs. BB 형태)에 민감

A.3 인식 포화의 정보 이론적 해석

[인식 포화의 정보 이론적 배경]

내비게이션 성공에 필요한 정보량:
  I_nav = H(목표 위치) - H(목표 위치 | 탐지된 랜드마크)

랜드마크 수 N과 상호 정보의 관계:
  N=0: I_nav = 0 (랜드마크 없음 → 탐색만 가능)
  N=1: I_nav = 큰 증가 (첫 번째 랜드마크의 정보 가치 최대)
  N=5: I_nav ≈ 최대치의 80% (대부분의 정보 확보)
  N=20: I_nav ≈ 최대치의 95%+
  N=200: I_nav ≈ 최대치와 거의 동일

직관: 
  내비게이션에 필요한 핵심 정보는 20개 랜드마크로 거의 포화
  추가 200개 클래스는 정보 이론적으로 거의 기여 없음
  오히려 false positive로 인한 정보 오염 증가

이것이 인식 포화의 정보 이론적 기반임

A.4 타 VLN 벤치마크로의 일반화 가능성

[R2R 이외 VLN 벤치마크에서의 예상 결과]

RxR (Room-Across-Room):
  - 더 긴 지시문, 더 많은 랜드마크 참조
  - 예상: 인식 포화가 더 늦게 발생 (더 많은 랜드마크 필요)
  - 어휘 크기: 30-40개 핵심 클래스로 충분할 것으로 예상

REVERIE (Remote Embodied Referring Expression):
  - 객체 지시 + 내비게이션 결합
  - 예상: 객체 탐지 정밀도에 더 민감
  - False Positive의 영향: 더 클 것으로 예상

NavBench (실외 내비게이션):
  - 도시 환경, 다른 어휘 (신호등, 건물, 차량)
  - 예상: 다른 핵심 어휘 필요, 포화점 다를 것

연속 VLN (R2R-CE, VLNBERT):
  - 연속 행동 공간 → Fast Navigator 역할 더 큼
  - BB 형태 정확성에 더 민감할 것으로 예상

A.5 향후 인식 모델 설계를 위한 상세 가이드라인

[VLN 최적화 3D 인식 모델 설계 원칙]

원칙 1: Navigation-Vocabulary-First 설계
  현재 접근: ImageNet/ScanNet200 사전학습 → VLN 파인튜닝
  권장 접근: VLN 핵심 어휘 우선 학습 → 범용 어휘 선택적 추가
  
  구현 방법:
    Step 1: R2R/RxR 지시문에서 랜드마크 어휘 마이닝
    Step 2: 핵심 어휘 (~20개)로 먼저 학습
    Step 3: 성능 포화 확인 후 선택적 어휘 확장

원칙 2: Aspect-Ratio-Aware 바운딩 박스 회귀
  현재 손실: L_bbox = Σ ||b_pred - b_gt||² (MSE)
  권장 손실: L_bbox = α·L_center + β·L_AR + γ·L_size
    L_AR = |AR_pred - AR_gt|² (가로세로 비율 손실)
    β >> γ: 비율 정확성 우선
  
  특히 문, 창문, 복도 같은 비등방성 객체에서 β 가중치 증가

원칙 3: 내비게이션 평가 기반 능동 학습
  현재: 인식 지표(AP, IoU) 최대화
  권장: VLN 시뮬레이터와 연결된 보상 신호로 인식 모델 조정
    R_perception = ΔSR_VLN (인식 개선에 따른 VLN SR 변화)
    → 이 보상으로 DRL 또는 RLHF 스타일 최적화

원칙 4: Computation-Aware 인식 스케줄링
  포화점 발견: ρ_ret ≈ 0.40-0.60에서 SR 거의 최대
  활용: 계산 자원에 따라 탐지 깊이 조절
    자원 여유: ρ_ret = 0.60 (더 많은 탐지)
    자원 부족: ρ_ret = 0.40 (빠른 처리, 성능 거의 동일)

A.6 이 연구가 VLN 평가 패러다임에 주는 함의

[VLN 벤치마킹의 재고]

현재 VLN 평가 방식의 한계:
  SR, SPL만으로는 어느 요소가 병목인지 불명확
  "더 높은 SR = 더 좋은 시스템"이지만 왜 좋은지 모름

이 논문이 제안하는 새로운 평가 프레임워크:
  1. 인식 한계 SR (Perception-Limited SR):
     이상적 인식 조건에서의 SR 측정
     → 시스템의 최대 잠재력

  2. 실제 인식 SR (Actual-Perception SR):
     실제 인식 모델 사용 시 SR
     → 현재 성능

  3. 인식 병목 지수 (Perception Bottleneck Index):
     PBI = (이상 SR - 실제 SR) / 이상 SR
     PBI ≈ 0: 인식 병목 없음 (다른 요소가 제한)
     PBI ≈ 1: 인식이 주요 병목

  4. 추론 병목 지수 (Reasoning Bottleneck Index):
     RBI = (이론 최대 SR - 이상 SR) / 이론 최대 SR
