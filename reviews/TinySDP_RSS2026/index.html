1.2 연구 목표 (Research Objective)

TinySDP는 임베디드 마이크로컨트롤러 위에서 비볼록(nonconvex) 기하학적 장애물 제약을 가진 MPC(Model Predictive Control) 문제를 실시간으로 해결하는 최초의 반정치 프로그래밍(SDP) 솔버이다.

핵심 문제 의식:

[임베디드 로봇 MPC의 딜레마]

로봇 경로 계획의 현실적 요구:
  ✓ 비볼록 장애물 회피 (원형, 타원형, 비볼록 공간)
  ✓ 실시간 제어 (25-100 Hz)
  ✓ 임베디드 하드웨어 (소형 마이크로컨트롤러, 수백 KB RAM)
  ✓ 공식적 안전 보장 (충돌 없음 인증)

기존 접근법의 한계:
  ┌─────────────────────────────────────────────────────┐
  │ 방법            │ 비볼록 │ 실시간 │ 임베디드 │ 보장  │
  │────────────────│───────│───────│─────────│──────│
  │ 선형화(LIN)     │ ❌     │ ✓     │ ✓       │ ❌   │
  │ CBF(Control    │ △     │ ✓     │ ✓       │ △   │
  │  Barrier Func) │       │       │         │      │
  │ 일반 SDP        │ ✓     │ ❌     │ ❌       │ ✓   │
  │ GPU MPC        │ ✓     │ ✓     │ ❌       │ △   │
  │ TinySDP        │ ✓     │ ✓     │ ✓       │ ✓   │
  └─────────────────────────────────────────────────────┘

TinySDP의 핵심 아이디어:
  비볼록 원거리 유지 제약(keep-out constraint)을
  볼록 반정치 제약(PSD constraint)으로 리프팅하고,
  이를 캐시된 리카티 기반 ADMM 솔버에 통합하여
  168 MHz STM32 마이크로컨트롤러에서 25 Hz 실시간 실행

결과적으로 TinySDP는 기존 최고 대비 73% 짧은 경로, 15배 정밀한 목표 도달, Crazyflie 2.1 쿼드로터에서의 실시간 실증을 달성한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 비볼록 장애물 제약의 계산적 어려움

[핵심 MPC 문제의 비볼록성]

기본 궤적 최적화:
  minimize:   ℓ_f(x_N) + Σ_{k=0}^{N-1} ℓ(x_k, u_k)
  
  subject to:
    x_{k+1} = A x_k + B u_k        (선형 동역학)
    u_k ∈ U, x_k ∈ X               (볼록 입출력 제약)
    ||p_k - c_j||²_2 ≥ r_j²        (비볼록 장애물 회피)

마지막 제약의 문제:
  ||p_k - c_j||²_2 ≥ r_j²는 비볼록 집합을 정의
  → 이 집합의 여집합(장애물 내부)이 볼록
  → 표준 볼록 최적화 도구로 직접 처리 불가
  → 선형화하면: 지역 근사 → 해가 장애물과 충돌 가능
  → 비선형 솔버: 계산 비용 매우 높음, 임베디드 불가

B. 기존 방법들의 한계

선형화 기반 방법 (TinyMPC-LIN):

방법: 장애물 주변에 보수적 안전 여유 추가 후 선형 근사
한계: 안전 여유를 매우 크게 설정해야 안전 보장 가능
  → TinyMPC-LIN: Crazyflie (폭 ~100mm) 대비 3.1m 안전 여유 필요!
  → 실제 공간 활용 극히 비효율적, 좁은 공간 통과 불가
  → 경로 길이: TinySDP 대비 최대 73% 더 긺

Control Barrier Functions (RPCBF):

방법: CBF를 이용한 안전 제약 소프트 적용
장점: 임베디드 구현 가능, 볼록 문제 유지
단점:
  1. 튜닝 파라미터에 민감 (안전-성능 트레이드오프)
  2. 형식적 보장 약함 (tight CBF는 미래 단계 무시)
  3. TinySDP 대비 경로 길이 31-73% 더 긺
  4. 목표 도달 정밀도 4-15배 낮음

일반 SDP 솔버 (CVXPY, Mosek):

방법: 정확한 SDP 리프팅 → 강력한 볼록 솔버로 해결
장점: 최적해, 공식적 보장 가능
한계:
  1. 계산 시간: 초 단위 (실시간 25Hz 불가)
  2. 메모리: MB 단위 (임베디드 수백 KB 불가)
  3. 동적 메모리 할당 → 임베디드 호환 불가

C. 임베디드 실시간 요구사항

[Crazyflie 2.1 하드웨어 제약]

프로세서: STM32F405 @ 168 MHz (ARM Cortex-M4)
메모리: 192 KB SRAM, 1 MB Flash
제어 주기: 40 ms (25 Hz MPC)
저수준 PID: 500 Hz

요구사항:
  MPC 솔버: 40 ms 이내 완료
  메모리: 정적 할당 (dynamic alloc 불가)
  플래시: ~1 MB 이내

2.2 핵심 해결책

[TinySDP의 3가지 핵심 아이디어]

1. Moment Matrix Lifting (모멘트 행렬 리프팅):
   비볼록 제약 → 볼록 PSD 제약으로 변환
   (Lasserre/Shor 릴렉세이션 적용)

2. Per-Stage PSD Projection in ADMM:
   각 시간 단계별 소형 행렬(3×3 또는 4×4)의 PSD 투영
   → 소규모 고유값 분해만 필요 → 임베디드 적합

3. Cached Riccati + A Posteriori Certificate:
   오프라인 리카티 재귀 캐시 → 온라인 계산 최소화
   사후 rank-1 인증서로 실제 안전 보장 검증

3. 핵심 방법론 (Core Methods)

3.1 반정치 리프팅 (Semidefinite Lifting)

3.1.1 2차 변수 리프팅

비볼록 장애물 제약을 볼록화하기 위해 2차 변수들을 리프팅:

원래 변수:
  x_k ∈ ℝ^{n_x}: 상태 벡터 (위치, 속도, 자세 등)
  u_k ∈ ℝ^{n_u}: 제어 입력

리프팅된 2차 변수:
  X_k   = x_k x_k^T ∈ ℝ^{n_x × n_x}   (상태 외적)
  XU_k  = x_k u_k^T ∈ ℝ^{n_x × n_u}   (상태-입력 교차적)
  UU_k  = u_k u_k^T ∈ ℝ^{n_u × n_u}   (입력 외적)

단계별 모멘트 행렬:
      ┌     1     x_k^T    u_k^T  ┐
  M_k = │   x_k     X_k      XU_k  │ ∈ S^{1+n_x+n_u}
      └   u_k     XU_k^T   UU_k  ┘

볼록 릴렉세이션: M_k ⪰ 0 (PSD 제약)
→ 비볼록 QCQP → 볼록 SDP 릴렉세이션

3.1.2 Kronecker 곱을 이용한 리프팅 동역학

리프팅 변수들도 선형 동역학을 만족하도록:

리프팅 상태 벡터: x̄_k = [x_k; vec(X_k)] (x_k와 X_k의 연결)
리프팅 입력 벡터: ū_k = [u_k; vec(XU_k); vec(UU_k)]

리프팅 동역학:
  x̄_{k+1} = Ā x̄_k + B̄ ū_k

  Ā = [ A,       0    ]
      [ 0,    A ⊗ A   ]

  B̄ = [ B,       0,        0,      0      ]
      [ 0,  B ⊗ A,  A ⊗ B,  B ⊗ B  ]

  ⊗: Kronecker 곱 연산자

직관: 원래 선형 동역학 (x_{k+1} = Ax_k + Bu_k)에서
  X_{k+1} = x_{k+1}x_{k+1}^T = (Ax_k + Bu_k)(Ax_k + Bu_k)^T
           = A X_k A^T + A XU_k B^T + B XU_k^T A^T + B UU_k B^T
  이 관계를 Kronecker 곱으로 표현

3.1.3 리프팅된 장애물 제약

위치 블록 추출 행렬 C_p 를 이용:

위치 블록 추출:
  X_k^{(p)} := C_p X_k C_p^T ∈ ℝ^{2×2}
  (X_k에서 위치 차원만 추출하는 선형 연산)

리프팅된 장애물 제약 (리프팅 변수에서 선형!):
  trace(X_k^{(p)}) - 2 c_j^T p_k + ||c_j||²_2 ≥ r_j²

  원래의 비볼록: ||p_k - c_j||²_2 = p_k^T p_k - 2c_j^T p_k + c_j^T c_j
  → p_k^T p_k = trace(p_k p_k^T) = trace(X_k^{(p)})로 대체
  → 리프팅 변수에서 선형!

단, rank(M_k) = 1 일 때만 exact (X_k = x_k x_k^T)
  릴렉세이션에서는 rank(M_k) ≥ 1 가능
  → a posteriori 인증서로 실제 안전성 검증

3.2 ADMM 솔버 — 3단계 반복 (Algorithm 1)

TinySDP의 핵심 온라인 알고리즘은 ADMM(Alternating Direction Method of Multipliers)의 3단계 반복:

3.2.1 ADMM 문제 분할

원래 문제:
  min Σ ℓ(x̄_k, ū_k)
  s.t. Ā x̄ + B̄ ū = 0 (동역학)
       M_k(x̄_k, ū_k) ⪰ 0 (PSD 제약)

ADMM 분할 (보조 변수 S_k 도입):
  이중 분해:
  변수 1: (x̄, ū) — 비용 함수 + 동역학에 대응
  변수 2: S_k — PSD 제약에 대응
  
  연결 제약: M_k(x̄_k, ū_k) = S_k (S_k가 PSD여야 함)
  
증강 라그랑지안:
  L_ρ = Σ[ℓ_k + (ρ_psd/2)||M_k - S_k + H_k||²_F]
  H_k: 이중 변수 (스케일된 라그랑지 승수)

3.2.2 Step 1 — 원시 업데이트 (Primal Update)

(x̄, ū)^+ = argmin_{x̄, ū} Σ ℓ̃_k(x̄_k, ū_k; S_k, H_k)

여기서 ℓ̃_k = ℓ_k + (ρ_psd/2)||M_k - S_k + H_k||²_F의
             M_k 관련 항을 전개하면 2차 함수 형태

핵심: PSD 증강 항이 원시 비용에 선형/2차 항을 추가
  q̃_k = q_k + linear terms from PSD penalty
  r̃_k = r_k + linear terms from PSD penalty
  
→ 수정된 비용을 가진 표준 LQR 문제 형태
→ 캐시된 리카티로 해결

3.2.3 Step 2 — PSD 원뿔 투영 (PSD Cone Projection)

S_k^+ = Π_{S^p_+}( M_k(x̄_k^+, ū_k^+) + H_k )

PSD 원뿔 투영 계산:
  임의 대칭 행렬 Y에 대해:
  고유값 분해: Y = V diag(λ_1, ..., λ_p) V^T
  PSD 투영: Π_{S^p_+}(Y) = V diag(max(λ_1,0), ..., max(λ_p,0)) V^T

핵심 장점:
  행렬 크기: 3×3 (2D 플래닝) 또는 4×4 (3D 플래닝)
  → 고유값 분해 비용 극히 낮음 (3×3: 해석적 공식 가능)
  → 임베디드 실시간 실행 가능

일반 SDP 솔버와의 차이:
  일반: 전체 시간 지평선에 걸친 대형 행렬 PSD 제약
  TinySDP: 각 시간 단계별 소형 행렬 PSD 제약
  → 계산 복잡도 O(N·n³) → O(N·p³) where p = 3 or 4

3.2.4 Step 3 — 이중 변수 업데이트 (Dual Update)

H_k^+ = H_k + γ_psd · (M_k(x̄_k^+, ū_k^+) - S_k^+)

γ_psd ∈ (0, 2): 언더-릴렉세이션 파라미터 (안정성 조절)
  γ_psd = 1.0: 표준 ADMM
  γ_psd < 1.0: 더 보수적, 수렴 안정성 향상

직관: PSD 제약 위반량에 비례한 이중 변수 업데이트
  M_k ≠ S_k: 제약 위반 → H_k 증가 → 다음 반복에서 보정

3.3 캐시된 리카티 재귀 (Cached Riccati Recursion)

ADMM의 원시 업데이트(Step 1)를 효율적으로 해결하는 핵심 기법:

3.3.1 오프라인 계산 (한 번만 수행)

[오프라인 리카티 방정식 풀기]

무한 지평선 리카티 방정식:
  P_∞ = Q + A^T P_∞ A - A^T P_∞ B (R + B^T P_∞ B)^{-1} B^T P_∞ A

피드백 이득 행렬:
  K_∞ = (R + B^T P_∞ B)^{-1} B^T P_∞ A

보조 행렬 캐시:
  C₁ = (R + B^T P_∞ B)^{-1}    (역행렬, 한 번만 계산)
  C₂ = (A - B K_∞)^T            (폐루프 전이 행렬 전치)

→ 이 모든 행렬을 오프라인에서 계산하여 플래시에 저장

3.3.2 온라인 계산 (매 제어 주기마다)

[온라인 역방향 재귀 (Backward Pass)]
k = N, N-1, ..., 0

  d_k = C₁ (B^T p_{k+1} + r̃_k)       (이득 벡터)
  p_k = q̃_k + C₂ p_{k+1} - K_∞^T r̃_k  (가중 비용-투-고 함수)

[온라인 순방향 롤아웃 (Forward Rollout)]
k = 0, 1, ..., N-1

  u_k = -K_∞ x_k - d_k                (최적 제어 입력)
  x_{k+1} = A x_k + B u_k             (상태 전파)

핵심 장점:
  C₁, C₂, K_∞: 오프라인 캐시 → 온라인에서 행렬 역변환 불필요
  온라인 연산: 주로 행렬-벡터 곱 (O(n²N))
  → 일반 LQR 솔버 대비 대폭 빠름

3.4 사후 rank-1 안전 인증서 (A Posteriori Safety Certificate)

릴렉세이션이므로 해가 실제 제약을 만족하는지 사후 검증이 필요:

3.4.1 트레이스 갭 (Trace Gap)

Δ_k := trace(X_k^{(p)}) - ||p_k||²_2

  정확한 rank-1 해: X_k^{(p)} = p_k p_k^T → trace = ||p_k||²_2 → Δ_k = 0
  릴렉세이션 해: rank(M_k) > 1 가능 → Δ_k > 0

Δ_k: 릴렉세이션의 "타이트니스(tightness)" 측정값
  Δ_k ≈ 0: 릴렉세이션이 tight → 실제 비볼록 문제의 근사 해
  Δ_k >> 0: 릴렉세이션이 느슨함 → 추가 검증 필요

3.4.2 리프팅된 장애물 여유 (Lifted Obstacle Margin)

η_{k,j} := trace(X_k^{(p)}) - 2 c_j^T p_k + ||c_j||²_2 - r_j²

  η_{k,j} ≥ 0: 리프팅된 제약 만족
  η_{k,j}^{min} := min_j η_{k,j}

3.4.3 인증 조건 (Certification Condition)

실제 기하학적 여유:
  δ_{k,j} := ||p_k - c_j||²_2 - r_j² (실제 장애물까지의 여유)

항등식:
  δ_{k,j} = η_{k,j} - Δ_k

인증서 (안전 보장 조건):
  η_k^{min} ≥ 0  AND  |Δ_k| ≤ η_k^{min}
  
  → 이 조건 만족 시: δ_{k,j} = η_{k,j} - Δ_k ≥ η_k^{min} - Δ_k ≥ 0
  → 모든 j에 대해 실제 충돌 없음 보장!

실패 시 안전 모드:
  Algorithm 2: 인증서 실패 시 호버링(제자리 정지)으로 대체
  → 폴백 정책을 통한 하드 안전 보장

4. 시스템 아키텍처 (System Architecture)

4.1 오프라인 단계

[오프라인 전처리 파이프라인 (Algorithm 1, Lines 1-5)]

입력: 시스템 행렬 A, B
      비용 행렬 Q, R, Q_f
      위치 추출 행렬 C_p

1. Kronecker 확장:
   리프팅 동역학 Ā, B̄ 구성
   (A⊗A, B⊗A, A⊗B, B⊗B 계산)

2. 리프팅 비용 행렬 구성:
   Q̄, R̄ (C_p를 통한 위치 블록 투영)

3. 무한 지평선 리카티 방정식 풀기:
   P_∞, K_∞ 계산

4. 보조 캐시 행렬 계산:
   C₁ = (R + B^T P_∞ B)^{-1}
   C₂ = (A - B K_∞)^T

5. 캐시 C = {K_∞, P_∞, C₁, C₂, ...} → 플래시 저장

출력: 플래시에 저장된 캐시 C

4.2 온라인 MPC 루프

[온라인 제어 루프 (25 Hz @ Crazyflie)]

매 제어 주기 (40 ms):
입력: 현재 상태 x_k, 장애물 집합 O_k

┌─────────────────────────────────────────────────────────┐
│                  ADMM 반복 (5회)                          │
│                                                          │
│  Step 1: 원시 업데이트 (Primal Update)                    │
│  ┌─────────────────────────────────────────────┐        │
│  │ S_k, H_k → 수정된 비용 계수 q̃, r̃ 계산      │        │
│  │ 역방향 리카티 재귀 (캐시 C 활용)             │        │
│  │ 순방향 롤아웃 → 상태/입력 궤적              │        │
│  └─────────────────────────────────────────────┘        │
│                                                          │
│  Step 2: PSD 원뿔 투영 (PSD Projection)                  │
│  ┌─────────────────────────────────────────────┐        │
│  │ 각 k에 대해 M_k 형성                        │        │
│  │ Y = M_k + H_k                              │        │
│  │ 고유값 분해 Y = V diag(λ) V^T (3×3 또는 4×4)│        │
│  │ S_k = V diag(max(λ,0)) V^T                 │        │
│  └─────────────────────────────────────────────┘        │
│                                                          │
│  Step 3: 이중 업데이트 (Dual Update)                     │
│  ┌─────────────────────────────────────────────┐        │
│  │ H_k += γ_psd · (M_k - S_k)                 │        │
│  └─────────────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────┘

수렴 또는 최대 반복 후:
→ 현재 상태에 대한 제어 입력 u_0 추출
→ 저수준 PID 트래커에 전달 (500 Hz)

사후 안전 모니터링 (Algorithm 2):
→ 인증서 Δ_k ≤ η_k^{min} 확인
→ 실패 시: 호버링 폴백 활성화

6. 핵심 기여점 (Key Contributions)

6.1 최초의 임베디드 SDP 솔버

[혁신성: 임베디드 SDP의 장벽 돌파]

기존 SDP 솔버들:
  MOSEK, SeDuMi: 서버급 CPU, GB 메모리 필요
  CVXPY: Python, 동적 메모리 할당 → 임베디드 불가
  SDPA: 정적 크기 가정하지만 여전히 큰 메모리

TinySDP의 혁신:
  ① 단계별 소형 행렬 분해 (3×3, 4×4만)
  ② 전적 정적 메모리 할당
  ③ 캐시된 리카티로 온라인 행렬 역변환 제거
  ④ C++ 헤더-온리 라이브러리 → 이식성 극대화

결과: 192 KB SRAM에서 25 Hz 실시간 SDP 기반 MPC
  → 세계 최초 임베디드 실시간 SDP

6.2 사후 rank-1 기하학적 인증서

[안전 보장의 혁신성]

기존 릴렉세이션 기반 방법들의 문제:
  SDP 릴렉세이션 해 ≠ 원래 비볼록 문제의 해 (일반적으로)
  → 릴렉세이션 해가 실제 충돌할 수 있음 → 신뢰 불가

TinySDP의 사후 인증서:
  Δ_k ≤ η_k^{min} 조건을 매 제어 단계 후 확인
  → 이 조건 만족 시: 기하학적으로 충돌 없음 수학적 보장
  → 위반 시: 보수적 폴백으로 전환 → 하드 안전 보장

하드웨어 검증:
  5회 실시험에서 Δ_k ≈ 0 유지 → 인증서 항상 유효
  → 실제 비선형 동역학에서도 rank-1 근사 유지됨 확인

7.3 핵심 알고리즘 복잡도

[오프라인 단계 복잡도]
  리카티 방정식: O(n_x³ × 반복 횟수) — 한 번만
  Kronecker 확장: O(n_x² × n_u²) — 한 번만

[온라인 단계 복잡도 (매 제어 주기)]

    원시 업데이트: O(N × (n_x + n_u)²) — 리카티 재귀
    PSD 투영: O(N × p³) where p = 3 (3×3 고유값 분해)
    이중 업데이트: O(N × p²)
  
  전체 (5 ADMM 반복):
    ≈ 5 × [O(N × n_x²) + O(N × 27)] 
    실측: 14.842 ms @ 168 MHz → 25 Hz 달성

8. 고급 주제 (Advanced Topics)

8.1 릴렉세이션 타이트니스의 실제 의미

[왜 실제에서 rank-1 해를 얻는가?]

이론적으로:
  SDP 릴렉세이션이 항상 rank-1 해를 보장하지는 않음
  → 특히 많은 장애물, 좁은 통로에서 느슨해질 수 있음

실제에서 rank-1이 유지되는 이유 (추측):
  1. ADMM이 수렴할 때 자연스럽게 rank-1 방향으로 정규화
  2. 물리적으로 의미 있는 궤적 공간이 rank-1 솔루션과 일치
  3. 작은 모멘트 행렬(3×3)에서는 릴렉세이션이 상대적으로 tight

하드웨어에서 확인:
  5회 시험에서 Δ_k ≈ 0 → 완전한 rank-1 유지
  → 현재 테스트 조건에서 릴렉세이션이 exact하게 작동
  → 더 복잡한 장애물 환경에서는 미보장

8.2 한계점 분석

[TinySDP의 한계]

1. 재귀적 실현 가능성 없음 (No Recursive Feasibility):
   현재 타임스텝 인증만 가능, 전체 지평선 보장 없음
   → 인증 실패 시 폴백으로 대처하지만, 폴백이 항상 안전한지 미보장

2. 3D 임베디드 배포:
   4×4 모멘트 행렬의 고유값 분해가 더 비쌈
   → 현재 Crazyflie STM32에서 3D 실시간 미검증
   (3D 시뮬레이션만)

3. 빠르게 이동하는 장애물:
   25 Hz MPC + 장애물 추적 지연 → 매우 빠른 장애물 처리 한계
   폴백(호버링)이 충돌을 막을 수 있는 속도의 상한 존재

4. 다수 장애물 확장성:
   장애물 수 증가 시 η_{k,j}^{min} 계산 비용 증가
   → 현재 소수 장애물 시나리오에서만 검증

5. 비선형 동역학:
   현재 선형 동역학 가정
   → 복잡한 비선형 시스템(6족 보행 등)에는 추가 선형화 필요

8.3 TinyMPC와의 기술적 관계

[TinySDP가 TinyMPC를 확장한 방식]

TinyMPC (기존):
  임베디드 실시간 MPC, 캐시된 리카티 솔버
  장애물 처리: 선형화 (TinyMPC-LIN)
  → 큰 안전 여유 필요

TinySDP (본 논문):
  TinyMPC의 캐시된 리카티 구조 유지
  + SDP 리프팅으로 비볼록 장애물 처리
  + ADMM의 PSD 투영 스텝 추가
  + 사후 rank-1 인증서 추가

핵심 통찰:
  "TinyMPC의 빠른 리카티 솔버 + SDP의 정확한 볼록화"의 결합이
  임베디드 실시간 SDP를 가능하게 함
  → 각 방법의 장점만 취하는 혁신적 결합

8.4 실용적 배포 시나리오

[TinySDP가 실용적으로 적합한 시나리오]

최적 적용 영역:
  ① 소형 자율 드론 (Crazyflie급)
     - 건물 내부 정밀 검사
     - 좁은 통로 탐색 (창고, 파이프, 터널)

  ② 소형 지상 로봇
     - 밀집된 가구 환경 탐색
     - 사람 사이를 누비는 서비스 로봇

  ③ 엣지 AI 제약 환경

11. 결론 (Conclusion)

혁신성 평가

TinySDP는 로봇 경로 계획 분야에서 오랫동안 불가능하다고 여겨졌던 영역을 개척한다: 손바닥 크기의 마이크로컨트롤러 위에서 정확한 비볼록 장애물 회피를 실시간으로 실현하는 것.

[TinySDP의 핵심 돌파구]

기존의 딜레마:
  정확한 비볼록 처리 ↔ 실시간 임베디드
  (둘 중 하나만 가능했던 10년)

TinySDP의 해답:
  ① SDP 리프팅: 비볼록 → 볼록 변환 (수학적 정확성 유지)
  ② 단계별 소형 행렬: 대형 SDP → N개 3×3 고유값 분해 (계산 분해)
  ③ 캐시된 리카티: 오프라인 전처리 → 온라인 최소화 (시간 절감)
  ④ 사후 인증서: 릴렉세이션 → 실제 안전 보장 (신뢰성 유지)

결과: 168 MHz, 192 KB SRAM에서 25 Hz 비볼록 MPC
  → 73% 짧은 경로, 15배 정밀한 목표 도달

실용적 의의

이 논문이 열어주는 가능성:

  1. 소형 드론의 정밀 임무: 좁은 공간(파이프, 잔해, 밀집 창고)에서 기존 불가능했던 임무 수행 가능

  2. 안전-크리티컬 임베디드 시스템: 공식적 안전 인증서가 필요한 의료 로봇, 물류 드론에 적용 가능

  3. 엣지 AI 트렌드와의 정렬: 오프보드 계산 없는 자율 소형 로봇 실현

  4. 오픈소스 기여: MIT 라이선스 C++ 라이브러리로 즉시 활용 가능

향후 연구 방향

단기 과제:
  1. 3D 임베디드 배포 최적화 (4×4 → 더 빠른 고유값 분해)
  2. 재귀적 실현 가능성 추가 (미래 안전 집합 사전 계산)
  3. 더 많은 로봇 플랫폼 검증 (지상 로봇, 다른 드론)

중기 과제:
  4. 비선형 동역학 지원 (순차 선형화 + SDP 반복)
  5. 다수 동적 장애물 실시간 처리
  6. 복잡한 비볼록 기하 (다면체 장애물)

장기 과제:
  7. "임베디드 인증 제어" 체계적 이론화
  8. 실세계 복잡 임무 (자율 구조, 정밀 배달) 배포

총평: RSS 2026 채택, 코드 공개, 실세계 Crazyflie 검증, 명확한 수학적 기여의 결합으로 TinySDP는 임베디드 로봇 제어 분야에서 2026년 가장 중요한 기여 중 하나로 평가할 수 있다. 특히 소형 자율 시스템의 실용화를 가속할 수 있는 즉각적인 실용성이 돋보인다.

부록 A: SDP 리프팅 이론 심층 분석

A.1 Lasserre Hierarchy와의 관계

[TinySDP가 사용하는 이론적 배경]

Lasserre Hierarchy (2001):
  비볼록 다항식 최적화 문제를 SDP 릴렉세이션 계층으로 해결
  
  Level 1 (Shor's Relaxation):
    min c^T x s.t. g_i(x) ≥ 0
    → 변수 X = xx^T를 도입하여 선형화
    → 1차 모멘트 행렬 M_1 ⪰ 0
    → TinySDP가 사용하는 수준
  
  Level 2:
    2차 모멘트 행렬 M_2 ⪰ 0
    → 더 tight한 릴렉세이션, 더 큰 행렬
    
TinySDP의 선택:
  Level 1 릴렉세이션 → 3×3 또는 4×4 행렬
  → 임베디드에서 실시간 가능
  → 실제에서 tight(rank-1)하게 수렴 확인
  
향후 방향:
  레벨 선택을 적응적으로: 단순 환경 → Level 1, 복잡 환경 → Level 2
  (하지만 Level 2는 현재 임베디드에서 실시간 불가)

A.2 ADMM 수렴 분석

[TinySDP ADMM의 수렴 조건]

일반 ADMM 수렴 조건:
  (1) 목적 함수 f(x): 볼록, 폐집합에서 최솟값 존재
  (2) 제약 집합 g(z): 볼록 (PSD 원뿔은 볼록) ✓
  (3) 증강 라그랑지안 파라미터 ρ > 0

TinySDP에서의 특수성:
  원시 업데이트가 리카티 기반으로 해결됨
  → 캐시된 리카티가 항상 feasible solution을 반환하므로
     Step 1이 항상 well-defined

실제 수렴 속도:
  5 ADMM 반복에서 실용적 수렴 달성
  → 반복 횟수 대 계산 비용 트레이드오프:
    1 반복: 빠르지만 부정확
    10 반복: 더 정확하지만 14.842 ms 초과 가능
    5 반복: 25 Hz 예산 내 실용적 품질 달성

수렴 가속 기법 (미래 연구):
  - 모멘텀 ADMM (과감쇠 업데이트)
  - 적응적 ρ 스케줄링
  - 웜 스타트 (이전 해를 초기값으로 사용)

A.3 3D 확장의 계산 비용 분석

[2D vs. 3D 모멘트 행렬 비교]

2D 플래닝 (현재 Crazyflie 구현):
  리프팅 변수: [1, p_x, p_y] → 3차원
  모멘트 행렬: 3×3
  고유값 분해: O(27) — 해석적 공식 가능
  
3D 플래닝 (미래 목표):
  리프팅 변수: [1, p_x, p_y, p_z] → 4차원
  모멘트 행렬: 4×4
  고유값 분해: O(64) — 수치적 방법 필요
  
계산 비용 증가 분석 (추정):
  3×3 분해: ~0.1 μs @ 168 MHz
  4×4 분해: ~0.5 μs @ 168 MHz
  
  전체 MPC (N=20 스텝, 5 ADMM 반복):
  2D: ~14.842 ms (검증됨)
  3D: ~15-16 ms (예상) — 여전히 40 ms 예산 내 가능할 것

A.4 MPC 지평선 길이와 안전의 관계

[N=20 지평선 선택의 근거와 한계]

지평선 N의 역할:
  N이 길수록: 더 장기적 계획, 더 효율적 궤적
  N이 짧을수록: 계산 빠름, 하지만 근시안적

N=20 선택:
  제어 주기: 40 ms
  총 예측 지평선: 20 × 40ms = 800 ms (0.8초 앞 예측)
  
  Crazyflie 평균 속도 ~0.5 m/s:
  800 ms × 0.5 m/s = 0.4 m 앞 계획
  
  U자형 장애물 탈출에 충분:
  → 17.95 m 총 경로에서 0.4 m 예측은 부족해 보이지만
  → MPC의 receding horizon 특성으로 반복 최적화 → 가능

더 긴 지평선의 잠재적 이점:
  N=50: 더 직접적인 경로, 글로벌 최적에 가까움
  비용: 계산 시간 2.5배 증가 → 25 Hz 위협
  
트레이드오프 규명:
  미래 연구: 적응적 지평선 (장애물 없으면 N 감소, 복잡하면 N 증가)
