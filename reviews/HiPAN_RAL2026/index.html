1.2 연구 목표 (Research Objective)

HiPAN은 사족보행 로봇(quadruped robot)이 비정형 3D 환경(unstructured 3D environments)에서 자율적으로 목표 지점까지 안전하게 내비게이션할 수 있도록 하는 계층적 자세-적응형 내비게이션 시스템이다.

기존 내비게이션 연구들이 주로 평탄한 실내 환경이나 휠 기반 로봇을 대상으로 설계된 것과 달리, HiPAN은 사족보행 로봇 고유의 기구학적 자유도—특히 몸체 높이(body height)와 피치 각도(pitch angle)를 동적으로 제어하는 능력—를 내비게이션 정책 자체에 통합함으로써, 다음과 같은 도전적 시나리오를 해결하고자 한다:

  1. 높이 제약 통로 (Height-constrained passages): 테이블 아래, 낮은 문틀, 제한된 수직 공간을 갖는 구조물을 몸을 낮추어(ducking) 통과하는 능력
  2. 막힌 골목 탈출 (Dead-end escape): 반응형(reactive) 플래너로는 해결 불가능한 U자형 막힌 공간에서의 후진(backtracking) 및 재탐색
  3. 복잡한 다중 방 탐색 (Complex multi-room navigation): 좁은 복도, 문, 계단식 장애물이 결합된 복합 환경에서의 장거리 목표 도달
  4. 실외 비정형 지형 (Outdoor unstructured terrain): 직사광선, 불균일 경사 지면, 새로운 장애물(자전거, 교통 콘 등) 조건에서의 강건한 작동

이를 위해 HiPAN은 계층적 정책 구조(hierarchical policy architecture)를 채택하여, 고수준 내비게이션 의사결정(어디로, 어떤 자세로 가야 하는가)과 저수준 운동 제어(관절을 어떻게 움직일 것인가)를 분리하며, 경로 안내 커리큘럼 학습(Path-Guided Curriculum Learning, PGCL)을 통해 점진적으로 복잡한 내비게이션 능력을 습득한다. 또한 교사-학생 증류(Teacher-Student Distillation with DAgger)를 통해 훈련 시 특권 정보를 활용하되, 배포 시에는 온보드 깊이 카메라만으로도 작동 가능한 학생 정책을 생성한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

도전과제 1: 사족보행 로봇의 자세 자유도 활용 부재

휠 기반 로봇과 달리 사족보행 로봇은 몸체를 낮추거나 피치를 조절하여 높이 제약 공간을 통과할 수 있는 고유한 능력을 갖는다. 그러나 기존 내비게이션 연구들은 이 자유도를 내비게이션 정책에서 명시적으로 제어하지 않았다. 기존 사족보행 내비게이션 파이프라인은 일반적으로:

[고수준 경로 계획기] → 목표점(waypoint) 전송 → [저수준 운동 제어기]
                                                  (자세는 고정/자율 관리)

이 구조에서 저수준 제어기는 단순히 속도 명령을 추종하며, 몸체 자세는 내비게이션 맥락과 독립적으로 관리된다. 결과적으로 테이블 아래와 같은 높이 제약 공간에서는 충돌이 발생하거나 경로를 포기해야 한다.

도전과제 2: 반응형 플래너의 국소 최소값(Local Minima) 문제

DWA(Dynamic Window Approach), 포텐셜 필드(Potential Field), 기타 반응형 장애물 회피 방법들은 현재 센서 데이터에만 기반하여 즉각적인 회피 행동을 생성한다. 이러한 방법들은:

  • U자형 장애물이나 막힌 골목에서 빠져나오지 못하는 국소 최소값 문제를 가진다
  • 뒤로 물러나는(backtracking) 전략적 행동을 학습하지 못한다
  • 현재 상태만 보고 판단하므로, 장기적 계획(long-horizon planning)이 불가능하다

수학적으로, 포텐셜 필드 기반 방법의 합력은:

F_total = F_attractive(goal) + F_repulsive(obstacles)

막힌 골목 상황:
  F_attractive: 목표 방향을 향해 전진 유도
  F_repulsive: 양 측벽에서 밀어냄 (서로 상쇄)
  → F_total ≈ 0 at dead-end vertex (국소 최소값에 수렴)

도전과제 3: SLAM/매핑 파이프라인의 누적 오차

기존 내비게이션 시스템들은 대부분 명시적 지도 구축(explicit map building)에 의존한다:

센서 데이터 → [SLAM] → 환경 지도 → [경로 계획기] → 로봇 명령

그러나 이 접근법은:

  • SLAM 알고리즘의 누적 포즈 오차(accumulated pose error)가 경로 계획 실패로 이어짐
  • 동적 환경에서 지도가 빠르게 부정확해짐
  • 계산 자원이 제한된 온보드 컴퓨터에서 실시간 SLAM + 경로 계획의 높은 연산 부담
  • 좁고 복잡한 3D 환경에서 정밀한 포인트 클라우드 정합(point cloud registration) 실패 위험

도전과제 4: 시뮬레이션-현실 격차(Sim-to-Real Gap)

강화학습 기반 내비게이션 정책을 시뮬레이션에서 훈련하면 물리 파라미터(질량, 마찰 계수, 모터 특성)의 차이로 인해 실제 로봇에서의 성능이 크게 저하된다. 이 격차를 해소하기 위한 도메인 랜덤화(domain randomization)만으로는 복잡한 지형에서의 자세 제어에 충분하지 않다.

도전과제 5: 커리큘럼 설계의 어려움

장거리, 복잡한 내비게이션 정책을 직접 훈련하면 희소 보상(sparse reward) 문제가 발생한다. 환경이 복잡해질수록 에이전트가 우연히 목표에 도달할 확률이 극히 낮아져 학습이 수렴하지 않는다.

2.2 핵심 해결책

HiPAN의 핵심 해결책은 다음 네 가지 기술적 구성 요소의 시너지이다:

문제 HiPAN의 해결책
자세 자유도 미활용 고수준 정책이 속도 명령과 함께 몸체 높이·피치 명령을 동시 생성
국소 최소값 후진(backtracking) 행동을 명시적으로 학습한 전략적 내비게이션 정책
SLAM 누적 오차 배포 시 지도 없이 깊이 카메라 직접 입력만 사용
Sim-to-Real 격차 도메인 파라미터 인코더 + 교사-학생 DAgger 증류
희소 보상/수렴 실패 경로 안내 커리큘럼 학습(PGCL)으로 점진적 복잡도 증가

3. 핵심 방법론 (Core Methods)

3.1 계층적 정책 구조 (Hierarchical Two-Level Policy Architecture)

HiPAN의 전체 구조는 두 개의 분리된 정책으로 이루어진다:

┌─────────────────────────────────────────────────────────┐
│                고수준 내비게이션 정책                     │
│         (High-Level Navigation Policy, π_nav)            │
│                                                          │
│  입력: 깊이 이미지, 목표 방향, 이전 행동                  │
│  출력: [v_x, ω_z, h_body, θ_pitch]                      │
│        (선속도, 각속도, 몸체높이, 피치각)                 │
└────────────────────────┬────────────────────────────────┘
                         │ 속도 + 자세 명령
                         ▼
┌─────────────────────────────────────────────────────────┐
│             저수준 자세-적응형 운동 제어기                 │
│      (Low-Level Posture-Adaptive Locomotion Controller)   │
│                                                          │
│  입력: 속도 명령, 자세 명령, 관절 상태, IMU 데이터        │
│  출력: 각 관절 토크/위치 명령 (12-DOF)                   │
└─────────────────────────────────────────────────────────┘

이 분리의 핵심적 통찰(key insight)은 다음과 같다:

"어디로 갈 것인가(WHERE)"와 "몸을 어떻게 구성할 것인가(HOW)"를 동일한 정책 레벨에서 결정한다.

기존 계층적 로봇 내비게이션에서는 고수준 정책이 웨이포인트(waypoint)나 속도 명령만 생성하고, 저수준 제어기가 자세를 자율적으로 관리했다. HiPAN은 이를 혁신하여 자세 명령(posture command)을 고수준 내비게이션 정책의 출력 공간에 명시적으로 포함시킨다.

행동 공간의 정의:

고수준 정책 행동 a_nav ∈ R^4:
  a_nav = [v_x, ω_z, h_body, θ_pitch]
  
  v_x     : 전진 속도 (선속도, m/s)
  ω_z     : 회전 속도 (각속도, rad/s)
  h_body  : 몸체 목표 높이 (m, 기본 높이 대비 오프셋)
  θ_pitch : 몸체 목표 피치 각도 (rad)

관찰 공간:

고수준 정책 관찰 o_nav:
  o_nav = [I_depth, φ_goal, a_prev, enc_domain]
  
  I_depth   : 정면 깊이 카메라 이미지 (H × W)
  φ_goal    : 목표까지의 상대 방향각 (rad)
  a_prev    : 이전 타임스텝의 행동 벡터
  enc_domain: 도메인 파라미터 인코더 출력

3.2 자세-적응형 운동 제어기 (Posture-Adaptive Locomotion Controller)

저수준 제어기는 고수준 정책에서 전달받은 속도 및 자세 명령을 추종하면서 실제 관절을 제어한다. 이 제어기는 교사(teacher) 단계에서 특권 도메인 파라미터(privileged domain parameters)를 활용하여 훈련된다.

특권 정보 (Privileged Information)

훈련 중 교사 제어기는 시뮬레이터에서만 접근 가능한 정보를 추가 입력으로 받는다:

특권 도메인 파라미터 p_priv:
  - 로봇 전체 질량 (m_total)
  - 각 관절 마찰 계수 (μ_joint[12])
  - 모터 강성/감쇠 계수 (k_p, k_d)
  - 지면 마찰 계수 (μ_ground)
  - 페이로드 위치 및 질량 (x_payload, m_payload)
  - 관절 가동 범위 오프셋 (δ_joint_limit)

PPO 기반 교사 정책 학습

운동 제어기 교사 정책은 PPO(Proximal Policy Optimization)로 훈련된다:

보상 함수 r_locomotion:

r_total = w_vel · r_velocity_tracking
        + w_pos · r_posture_tracking
        + w_smooth · r_action_smoothness
        + w_safe · r_safety
        - w_energy · r_energy_penalty

r_velocity_tracking = exp(-||v_cmd - v_actual||^2 / σ_v)
r_posture_tracking  = exp(-|h_cmd - h_actual|^2 / σ_h)
                    × exp(-|θ_cmd - θ_actual|^2 / σ_θ)
r_action_smoothness = -||a_t - a_{t-1}||^2
r_safety            = -I(collision) - I(fall_detected)
r_energy_penalty    = ||τ · q_dot||  (토크 × 관절 속도)

여기서 I(·)는 지시 함수(indicator function), τ는 관절 토크 벡터, q_dot은 관절 속도 벡터이다.

몸체 높이 및 피치 제어 메커니즘

사족보행 로봇의 역기구학(inverse kinematics)을 이용하여 목표 몸체 높이와 피치를 달성하는 관절 각도를 계산한다:

목표 발 위치 계산 (예: 오른쪽 앞발 RF):
  
  기본 발 위치: p_foot_default = [x_d, y_d, -h_default]
  
  높이 오프셋 적용:
    p_foot_adj = [x_d, y_d, -(h_default + Δh)]
  
  피치 회전 적용:
    R_pitch = [[cos(θ), 0, sin(θ)],
               [     0, 1,      0],
               [-sin(θ), 0, cos(θ)]]
    p_foot_final = R_pitch · p_foot_adj
  
  역기구학으로 관절 각도 계산:
    q_target = IK(p_foot_final, hip_position)

"덕킹(ducking)" 동작의 경우:

낮은 천장 감지 시나리오:
  
  깊이 이미지에서 천장까지의 거리: d_ceiling ≈ 0.4m
  현재 몸체 높이: h_current = 0.5m
  
  고수준 정책 출력: h_cmd = -0.15m (15cm 낮추기)
  
  저수준 제어기:
    → 4개 발을 동시에 목표 높이 달성을 위해 조정
    → 정적 보행(static gait)으로 안정성 유지
    → 이동하면서 점진적 높이 변화 실행

3.3 경로 안내 커리큘럼 학습 (Path-Guided Curriculum Learning, PGCL)

PGCL은 HiPAN의 훈련 안정성과 복잡한 환경에서의 수렴을 보장하는 핵심 메커니즘이다.

커리큘럼 단계 설계

커리큘럼 진행 단계:

단계 1 (Stage 1): 단거리 반응형 회피
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  환경 복잡도: 낮음 (단일 장애물, 짧은 경로)
  내비게이션 지평선: 짧음 (2~3m)
  교사 서브목표 수: 1~2개
  학습 목표: 기본 장애물 회피, 즉각 반응

단계 2 (Stage 2): 중거리 전략적 내비게이션

  내비게이션 지평선: 중간 (5~10m)
  교사 서브목표 수: 3~5개

  교사 서브목표 수: 5개 이상

  환경 복잡도: 최고 (불균일 지형, 새로운 장애물 클래스)
  내비게이션 지평선: 가변적
  학습 목표: 일반화, 강건성

경로 안내 메커니즘

커리큘럼의 핵심은 교사 정책이 학생 정책에게 서브목표(subgoal)를 제공하는 구조이다:

훈련 시 경로 안내:

  1. 환경 내 최적 경로 P* = {p_0, p_1, ..., p_N} 사전 계산
     (시뮬레이터 내 특권 맵 사용, A* 또는 RRT* 기반)
  
  2. 에이전트 현재 위치 p_t에서 가장 가까운 경로 점 찾기:
     p_nearest = argmin_{p_k ∈ P*} ||p_t - p_k||
  
  3. 서브목표 제공:
     p_subgoal = p_{nearest + K}  (K 스텝 앞의 경로 점)
  
  4. 교사 내비게이션 정책:
     a_teacher = π_teacher(o_t, p_subgoal, map_privileged)
  
  5. 학생 정책이 교사 행동을 모방하도록 학습:
     L_imitation = ||a_student - a_teacher||^2

희소 보상 문제 해결

경로 안내 없이 복잡한 환경에서 학습하면:

희소 보상 상황 (PGCL 없이):
  에피소드 길이: T = 1000 스텝
  성공 확률 (초기): p_success ≈ 0.001 (복잡한 다중 방)
  예상 성공 에피소드 수: 1/0.001 = 1000 에피소드마다 1번
  → 학습 신호 거의 없음 → 수렴 실패

PGCL 적용 후:
  단계 1에서 성공 확률: p_success ≈ 0.8 (단순 환경)
  점진적 복잡도 증가 → 각 단계에서 충분한 학습 신호 확보
  최종 복잡 환경 성공 확률: p_success > 0.7

3.4 교사-학생 증류 with DAgger (Teacher-Student Distillation)

교사 정책 (Teacher Policy)

교사 내비게이션 정책은 훈련 시에만 사용 가능한 특권 정보를 입력으로 받는다:

교사 정책 입력 o_teacher:
  o_teacher = [map_privileged,    # 완전한 환경 지도
               p_subgoal,         # 경로 기반 서브목표
               state_ground_truth, # 정확한 로봇 포즈
               p_priv]            # 도메인 파라미터

교사 정책 출력:
  a_teacher = π_teacher(o_teacher) = [v_x, ω_z, h_body, θ_pitch]

교사 정책은 강화학습으로 먼저 훈련된다:

교사 강화학습 (PPO):

  상태: s_t = o_teacher
  행동: a_t = π_teacher(s_t)
  보상: r_nav = w_goal · r_goal_reaching
              + w_path · r_path_following
              + w_posture · r_posture_adaptation
              - w_collision · r_collision_penalty
              + w_backtrack · r_backtracking_success
  
  r_goal_reaching    = exp(-||p_t - p_goal||^2 / σ_goal)
  r_path_following   = exp(-d(p_t, P*)^2 / σ_path)
  r_posture_adaptation = I(clearance_maintained)
  r_collision_penalty  = I(collision)
  r_backtracking_success = I(dead_end_escaped)

학생 정책 (Student Policy)

학생 정책은 배포 시 실제로 실행되며, 온보드 센서만 사용한다:

학생 정책 입력 o_student:
  o_student = [I_depth,         # 정면 깊이 카메라 이미지
               φ_goal,          # 목표까지의 상대 방향각
               a_prev,          # 이전 행동
               enc_domain(h_t)] # 도메인 파라미터 인코더 출력
              
  h_t: 역사적 관찰-행동 쌍으로부터 도메인 파라미터 추론

학생 정책의 인코더 구조:

학생 정책 아키텍처:

  ┌─────────────────────────────────────────────────┐
  │                학생 정책 네트워크                 │
  │                                                  │
  │  I_depth → [공간 인식 인코더]                    │
  │              (Spatial-Perception Encoder)         │
  │              CNN 기반, 3D 장애물 위치 추출         │
  │              → e_spatial ∈ R^d_s                  │
  │                                                  │
  │  h_t ──→ [도메인 파라미터 인코더]                 │
  │              (Domain-Parameter Encoder)           │
  │              LSTM/MLP 기반                        │
  │              → e_domain ∈ R^d_d                  │
  │                                                  │
  │  [e_spatial, e_domain, φ_goal, a_prev]            │
  │              ↓                                   │
  │         [MLP 정책 헤드]                           │
  │              ↓                                   │
  │  출력: a_student = [v_x, ω_z, h_body, θ_pitch]  │
  └─────────────────────────────────────────────────┘

DAgger (Dataset Aggregation) 학습

DAgger는 단순 행동 복제(behavior cloning)의 분포 이탈(distribution shift) 문제를 해결한다:

DAgger 알고리즘:

초기화: D = {} (데이터셋), π_0 = π_student_init

반복 i = 1, 2, ..., N:
  1. 현재 학생 정책 π_{i-1}로 환경에서 롤아웃 수행
     (학생 정책이 실제로 방문하는 상태 수집)
  
  2. 각 방문 상태 s_t에서 교사 행동 라벨링:
     a_label = π_teacher(s_t, privileged_info)
  
  3. 새 데이터를 기존 데이터셋에 추가:
     D = D ∪ {(s_t, a_label)}
  
  4. 전체 데이터셋 D로 학생 정책 재훈련:
     π_i = argmin_π E_{(s,a)~D} [||π(s) - a||^2]

핵심 장점:
  - 학생이 실제 방문하는 상태에서 교사 행동 학습
  - 분포 이탈로 인한 복합 오차(compounding error) 방지
  - 온보드 센서만으로도 교사 수준 성능 근접

단순 행동 복제 vs DAgger 비교:

행동 복제 (BC):
  훈련 데이터: 교사가 방문한 상태
  학생 상태 분포: 교사 분포와 다를 수 있음
  오차 누적: O(T^2) (에피소드 길이 T에 제곱 비례)

DAgger:
  훈련 데이터: 학생이 실제 방문한 상태
  상태 분포 불일치: 점진적으로 해소
  오차 누적: O(T) (선형 비례)

3.5 막힌 골목 탈출을 위한 후진 전략 (Backtracking for Dead-End Escape)

후진 행동은 HiPAN의 가장 특별한 능력 중 하나로, 반응형 플래너가 근본적으로 해결할 수 없는 문제를 학습된 정책으로 극복한다.

막힌 골목 인식

고수준 내비게이션 정책은 깊이 이미지를 통해 암묵적으로 막힌 골목 상황을 인식한다:

막힌 골목 시각적 특성 (깊이 이미지 관점):

전형적인 U자형 막힌 골목:
  ┌──────────────────────────────┐
  │                              │
  │  ████████████████████████   │ ← 정면 벽 (깊이값 작음)
  │  █                       █  │
  │  █      로봇 →             █  │ ← 양측 벽 (좌우 깊이값 작음)
  │  █                       █  │
  └──────────────────────────────┘

깊이 이미지 패턴:
  - 중앙 열: 작은 깊이값 (정면 벽)
  - 양쪽 열: 작은 깊이값 (측면 벽)
  - → 탈출구 없음 패턴 학습

후진 행동 학습

커리큘럼 학습의 후기 단계에서 막힌 골목 환경이 포함되어 후진 행동이 학습된다:

후진 보상 함수:

r_backtrack_success = +10.0  if dead_end_escaped (골목 탈출 성공)
r_time_penalty      = -0.01  per timestep (빠른 탈출 장려)
r_goal_progress     = +dist_progress_to_goal (목표 방향 진전)

학습된 행동 시퀀스:
  t=0: 골목 진입, 정면 벽 감지
  t=1~K: 후진 (v_x < 0) + 회전 시작
  t=K~M: 빠져나와 새 경로 탐색
  t=M~: 목표 방향으로 재탐색

수치적으로, 반응형 방법과 HiPAN의 차이:

DWA (Dynamic Window Approach) 막힌 골목:
  속도 샘플링 공간: {v_x: [0, v_max], ω_z: [-ω_max, ω_max]}
  목적 함수: 목표 방향 + 장애물 거리
  결과: 전진 불가 → 제자리 진동 (국소 최소값에 수렴)

HiPAN:
  학습된 정책: P(v_x < 0 | dead_end_signature) > 0.8
  결과: 후진 후 회전 → 탈출 경로 탐색 성공

3.6 명시적 지도 없는 배포 (Map-Free Deployment)

배포 시 HiPAN 학생 정책은 명시적 지도를 구축하거나 사용하지 않는다. 이는 다음과 같은 장점을 제공한다:

기존 SLAM + 경로 계획기 파이프라인:
  ┌──────────────────────────────────────────────────────────┐
  │ 깊이 카메라 → 포인트 클라우드 → [SLAM] → 환경 지도        │
  │                                    ↓                     │
  │                              [경로 계획기]                │
  │                                    ↓                     │
  │                           속도 명령 → 로봇                │
  └──────────────────────────────────────────────────────────┘
  문제: SLAM 오차 누적, 높은 계산 비용, 동적 환경 취약

HiPAN 배포 파이프라인:
  ┌──────────────────────────────────────────────────────────┐
  │ 깊이 카메라 이미지 → [학생 정책] → [v_x, ω_z, h, θ]     │
  │ 목표 방향          →    (직접)  → 속도+자세 명령          │
  └──────────────────────────────────────────────────────────┘
  장점: 누적 오차 없음, 낮은 계산 비용, 동적 환경 강건

깊이 이미지로부터 암묵적 공간 추론:

공간 인식 인코더(Spatial-Perception Encoder)는 단일 깊이 이미지로부터 3D 공간 구조를 암묵적으로 추론한다. CNN 기반 인코더는 다음을 학습한다:

공간 인식 인코더 학습 표현:
  - 통행 가능한 방향 (passable directions)
  - 장애물까지의 거리 및 방향
  - 상단 통과 가능성 (overhead clearance)
  - 측면 여유 공간 (lateral clearance)
  
  → 이를 통해 지도 없이도 국소적 공간 구조 파악

                      ↓ (반복)

  └──→ φ_goal (목표 방향각)

  └──→ MLP 정책 헤드

4.3 컴퓨팅 주기 분리

고수준 내비게이션 정책 (π_student): 10 Hz
  - 깊이 이미지 처리 (CNN 추론)
  - 목표 방향 업데이트
  - 속도 + 자세 명령 생성

저수준 운동 제어기: 50-100 Hz
  - 관절 상태 읽기
  - 목표 관절 각도 계산
  - 토크 명령 전송

계산 집약적인 비전 처리를 낮은 주파수에서 수행 가능하게 한다.

시뮬레이션 훈련 환경

5.2 평가 지표 (Evaluation Metrics)

평가 지표:

SR  (Success Rate, 성공률):
    = (목표 도달 에피소드 수) / (전체 에피소드 수) × 100%
    임계값: 목표 지점 0.5m 이내 도달 = 성공

NL  (Navigation Length, 내비게이션 경로 길이):
    = 에피소드 동안 로봇이 이동한 실제 경로 길이 (m)
    낮을수록 효율적 (최적 경로에 근접)

CR  (Collision Rate, 충돌률):
    = (충돌 발생 에피소드 수) / (전체 에피소드 수) × 100%
    낮을수록 안전한 내비게이션

SPL (Success weighted by Path Length):
    = SR × (최적 경로 길이) / max(실제 경로 길이, 최적 경로 길이)
    성공률과 경로 효율성을 동시에 평가

6. 핵심 기여점 (Key Contributions)

기여 1: 내비게이션-자세 통합 계층 구조

기존 패러다임:
  내비게이션 정책 → 속도 명령만 생성
  자세 제어 → 별도 모듈 (내비게이션과 분리)
  결과: 높이 제약 공간 통과 불가

HiPAN 패러다임:
  내비게이션 정책 → 속도 + 자세 명령 동시 생성
  자세 제어 → 내비게이션 맥락 반영
  결과: 높이 제약 공간 능동적 통과

이 기여는 사족보행 로봇의 형태적 자유도(morphological degrees of freedom)를 내비게이션 의사결정 루프 내에 명시적으로 통합한 최초의 체계적 접근으로 위치 지어질 수 있다.

기여 2: 경로 안내 커리큘럼 학습 (PGCL)

문제: 복잡한 환경에서의 장거리 내비게이션 직접 학습 → 수렴 실패
해결: 점진적 복잡도 증가 + 경로 서브목표 안내

PGCL의 기술적 혁신:
  1. 특권 정보(지도, 서브목표)를 교사 정책에만 제공
  2. 학생 정책은 교사 행동을 모방하며 암묵적 공간 추론 학습
  3. 커리큘럼 진행에 따라 안내 밀도(guidance density) 감소
  4. 최종적으로 순수 온보드 센서만으로 자율 내비게이션 가능

기여 3: 후진 전략 학습 (Backtracking via RL)

기존 방법들의 실패:
  반응형 플래너: 막힌 골목 탈출 불가 (수학적으로 증명됨)
  전통적 경로 계획기: 명시적 지도 필요, 실시간 재계획 비용 높음

HiPAN의 해결:
  강화학습으로 후진 행동을 내비게이션 정책에 내재화
  깊이 이미지에서 암묵적으로 막힌 골목 인식
  지도 없이도 탈출 가능

기여 4: 교사-학생 DAgger 증류

혁신점:
  - 교사: 특권 정보 활용, 최적에 가까운 행동 생성
  - 학생: 온보드 센서만 사용, 실제 배포 가능
  - DAgger: 분포 이탈 문제 해결, 안정적 수렴
  - 도메인 파라미터 인코더: 물리 특성 변화에 적응
  - 공간 인식 인코더: 3D 환경 구조 암묵적 추론

기여 5: 실세계 검증

4가지 실제 환경:
  - 다양한 실내 복합 장애물 환경
  - 막힌 골목 탈출이 필요한 환경
  - 높이 제약이 있는 다중 방 환경
  - 실외 비정형 지형 환경

사족보행 로봇 실제 실험으로 검증된 시스템
  → 시뮬레이션 전용 연구 대비 실용성 크게 향상

7. 구현 상세 (Implementation Details)

7.1 신경망 아키텍처

공간 인식 인코더 (Spatial-Perception Encoder):
  입력: 깊이 이미지 (H × W × 1)
  
  레이어 구성:
    Conv1: 32 필터, 8×8 커널, stride 4
    Conv2: 64 필터, 4×4 커널, stride 2
    Conv3: 64 필터, 3×3 커널, stride 1
    FC:    512 유닛
    출력: e_spatial ∈ R^256
  
  활성화: ReLU
  정규화: Layer Normalization

도메인 파라미터 인코더 (Domain-Parameter Encoder):
  입력: 이전 K 타임스텝의 [관찰, 행동] 쌍
        h_t = {(o_{t-K}, a_{t-K}), ..., (o_{t-1}, a_{t-1})}
  
  레이어 구성:
    LSTM: hidden_size=256, num_layers=2
    FC:   128 유닛
    출력: e_domain ∈ R^64
  
  이력 길이 K: 50 타임스텝 (약 5초, @10Hz)

MLP 정책 헤드:
  입력: [e_spatial(256), e_domain(64), φ_goal(1), a_prev(4)]
        총 325차원
  
  레이어 구성:
    FC1: 512 유닛, ReLU
    FC2: 256 유닛, ReLU
    FC3: 128 유닛, ReLU
    출력: 4차원 (v_x, ω_z, h_body, θ_pitch)
  
  출력 활성화:
    v_x:     tanh × v_max (최대 속도 제한)
    ω_z:     tanh × ω_max (최대 각속도 제한)
    h_body:  tanh × h_range (높이 변화 범위)
    θ_pitch: tanh × θ_max (최대 피치 각도)

  높이: 약 55cm (능동 높이 제어)
  특성: 연구용 플랫폼, 정밀한 상태 추정
  HiPAN 적용: 직접 적용 가능성 높음 (유사 DOF 구조)

Unitree A1/Go1:
  높이: 약 35cm (소형)
  특성: 저가, 경량
  HiPAN 적용: 소형 로봇의 좁은 공간 내비게이션에 특히 유리

확장 시 고려사항:
  - 각 플랫폼별 운동 파라미터 재캘리브레이션
  - 도메인 파라미터 인코더의 플랫폼 특화 훈련
  - 내비게이션 정책은 높은 전이 가능성 (센서 입력 동일)

더 복잡한 환경으로의 확장

현재 한계 및 미래 확장:

다층 건물 (Multi-floor):
  현재: 수평 내비게이션 중심
  확장 필요: 계단 등반 + 수직 이동 능력
  도전: 높이 제약을 넘어서는 3D 경로 계획

동적 장애물 (Dynamic Obstacles):
  현재: 정적 환경 가정 (실험 설정)
  확장: 움직이는 사람, 로봇과의 상호작용
  도전: 동적 장애물 예측 + 반응적 회피의 통합

장거리 내비게이션 (Long-range):
  현재: 수십 미터 규모
  확장: 수백 미터 이상의 장거리
  도전: 위상적 기억(topological memory) 통합 또는 분산 내비게이션

8.2 한계점 분석

한계 1: 목표 방향 의존성

현재 입력: φ_goal = 목표까지의 방향각
가정: 목표까지의 상대 방향을 항상 알 수 있음

현실적 문제:
  - GPS 불가 실내 환경에서 목표 방향 획득 어려움
  - 시각적 목표(visual goal)로 확장 필요
  - 비구조적 환경에서의 목표 인식 문제

완화책:
  - UWB(Ultra-Wideband) 신호 기반 목표 방향 추정
  - 시각적 목표 이미지 입력으로 확장 (Image-Goal Navigation)
  - 토폴로지 맵 기반 목표 방향 제공

한계 2: 코드 미공개

재현성 문제:
  - 학습 커리큘럼 세부 설정 검증 불가
  - 비교 실험의 독립적 재현 제한
  - 커뮤니티 기여 및 확장 어려움

향후 기대:
  - 저자들의 코드 공개 예정 여부 불명확
  - 학회 발표 후 코드 공개 관례에 따라 기대 가능

한계 3: 단일 카메라 의존

현재 입력: 전면 깊이 카메라 단일 이미지
한계:
  - 측면/후방 장애물 감지 불가
  - 시야각 제한으로 인한 근접 충돌 위험
  - 카메라 오염/차단 시 완전 실패

개선 방향:
  - 다중 카메라 융합 (전후좌우 깊이 카메라)
  - LiDAR 융합으로 360도 인식
  - 카메라 이상 감지 및 안전 정지 메커니즘

한계 4: 상태 정보의 제약

현재: φ_goal (방향각 단일 값)만 목표 정보로 사용
  → 거리 정보 없음
  → 목표까지의 경로 복잡도 정보 없음

개선:
  - 목표까지의 거리도 입력으로 추가
  - 다단계 서브목표 개수 조절 능력
  - 목표 유형 (장애물 회피, 높이 제약 등) 컨텍스트 추가

8.3 향후 연구 방향

방향 1: 온라인 적응 (Online Adaptation)
  - 배포 중 실시간으로 도메인 파라미터 업데이트
  - 새로운 환경 유형에 점진적 적응
  - 경험 기반 메모리 버퍼 활용

방향 2: 다중 로봇 내비게이션 (Multi-Robot)
  - 여러 HiPAN 에이전트의 협조적 내비게이션
  - 서로의 위치 정보 공유로 충돌 회피
  - 분산 탐색 및 지도 구축

방향 3: 시맨틱 내비게이션 (Semantic Navigation)
  - 자연어 목표 ("부엌으로 가")를 방향각으로 변환
  - 오브젝트 목표 내비게이션 (특정 객체까지 이동)
  - VLN (Vision-Language Navigation)과의 통합

방향 4: 경량화 및 엣지 배포
  - 모델 양자화(quantization)로 추론 속도 향상
  - 지식 증류(knowledge distillation)로 모델 크기 축소
  - 저전력 임베디드 프로세서에서의 실행

8.4 이론적 보장 분석

HiPAN은 학습 기반 방법이므로 전통적 알고리즘의 완전성(completeness)
또는 최적성(optimality) 보장을 제공하지 않는다.

보장 부재 항목:
  - 완전성: 경로가 존재해도 반드시 찾는다는 보장 없음
  - 최적성: 찾은 경로가 최단/최적이라는 보장 없음
  - 안전성: 모든 상황에서 충돌 없음을 보장하지 못함

실증적 강건성:
  - 다양한 실환경에서의 높은 성공률로 실용적 성능 입증
  - 도메인 랜덤화로 일정 수준의 분포 외 강건성 확보
  - 실패 모드가 상대적으로 예측 가능 (시야 밖 장애물 등)

안전 강화 방향:
  - 학습 기반 정책 + 규칙 기반 안전 필터 결합
  - Conformal prediction 기반 불확실성 정량화
  - 충돌 직전 긴급 정지 하드웨어 인터럽트

9.2 장단점 분석

HiPAN의 장점

장점 1: 사족보행 로봇 자세 자유도의 내비게이션 통합

IRRL, ViLiNT, AmelPred는 모두 사족보행 로봇의 고유한 형태적 자유도를 내비게이션 정책에서 활용하지 않는다. TRG-Planner는 사족보행 로봇을 대상으로 하지만 경로 계획기만을 제공하며, 자세 적응형 운동 제어기는 외부 모듈에 의존한다. HiPAN은 최초로 이 두 가지를 단일 계층 구조 내에서 통합하여, 높이 제약 공간 통과라는 실질적 능력을 부여한다.

장점 2: 막힌 골목 탈출의 명시적 학습

반응형 플래너(IRRL의 SFM 기반, DWA 등)는 수학적으로 국소 최소값 문제를 가지며 막힌 골목에서 탈출할 수 없다. TRG-Planner는 전역 경로 계획을 통해 막힌 골목을 사전에 회피하지만, 예상치 못한 동적 폐쇄 상황에는 취약하다. HiPAN은 후진 행동을 내재화하여 지도 없이도 막힌 골목을 탈출할 수 있다.

장점 3: 지도 없는 배포의 간결성

TRG-Planner는 포인트 클라우드 지도를 요구하므로 새로운 환경에서 먼저 지도 구축이 필요하다. ViLiNT도 환경 탐색을 위한 사전 정보를 필요로 한다. HiPAN은 깊이 카메라 하나만으로 즉시 새로운 환경에서 작동 가능하며, 이는 긴급 구조 또는 즉각 배포 시나리오에서 결정적 장점이다.

장점 4: 탁월한 훈련 안정성 (PGCL)

희소 보상 문제는 복잡한 내비게이션 학습의 가장 큰 장벽이다. 비교 대상 논문들 중 체계적인 커리큘럼 학습을 도입한 경우는 없으며, IRRL은 SFM 기반 사전 정책으로 이를 부분적으로 해결하고, AmelPred는 보조 표현 학습으로 샘플 효율을 높인다. HiPAN의 PGCL은 명시적으로 훈련 난이도를 단계적으로 증가시켜 수렴을 보장한다.

장점 5: 포괄적인 실세계 검증

4가지 서로 다른 실세계 환경 (복합 실내, 막힌 골목, 다중 방 높이 제약, 실외 비정형)에서의 검증은 비교 논문들 중 가장 광범위한 실험이다. IRRL은 소셜 내비게이션 특화, AmelPred는 드론 환경, TRG-Planner는 야외 비정형 지형에 집중된 것과 대비된다.

HiPAN의 단점 및 한계

단점 1: 코드 미공개

비교 대상 중 TRG-Planner가 코드와 프로젝트 페이지를 공개한 것과 달리, HiPAN은 코드를 공개하지 않았다. 이는 재현성과 커뮤니티 활용 측면에서 중대한 단점이다. 특히 복잡한 커리큘럼 설계와 DAgger 구현 세부사항의 독립적 검증이 불가능하다.

단점 2: 단일 방향 인식 한계

ViLiNT는 RGB + LiDAR 융합으로 360도 환경 인식을 제공하는 반면, HiPAN은 전면 깊이 카메라만 사용한다. 측면이나 후방에서 접근하는 위협 또는 장애물에 대응이 어려우며, 후진 중에는 특히 취약하다.

단점 3: 정적 환경 가정

IRRL은 소셜 내비게이션으로 동적 인간과의 상호작용을 명시적으로 다루는 반면, HiPAN의 실험은 주로 정적 장애물 환경에서 수행되었다. 실제 배포 환경에서 동적 장애물(움직이는 사람, 다른 로봇 등)에 대한 성능이 제한적일 수 있다.

단점 4: 목표 표현의 단순성

φ_goal(방향각)만을 목표 정보로 사용하는 것은 간단하지만, 거리 정보나 목표 이미지를 활용할 수 없는 제약이 있다. AmelPred가 오브젝트 목표 내비게이션을 지원하는 것과 대조된다.

단점 5: 훈련 비용

PGCL의 다단계 커리큘럼과 DAgger 반복 증류는 상당한 훈련 시간과 연산 자원을 요구한다. IRRL의 온라인 학습 접근법이 데이터 효율성 측면에서 유리할 수 있다.

9.3 실적용 가능성 평가

즉각 배포 가능성 (Short-term Deployment)

✅ 강점:
  - 깊이 카메라만으로 작동 (추가 인프라 불필요)
  - 실세계 4가지 시나리오에서 검증됨
  - 낮은 배포 연산 비용 (온보드 GPU 수준)
  - 새로운 환경에 즉각 투입 가능 (지도 구축 불필요)

⚠️ 주의사항:
  - 코드 미공개로 직접 활용 어려움
  - 목표 방향 제공 인프라 필요 (GPS, UWB 등)
  - 동적 장애물 환경에서의 성능 미검증
  - 사족보행 로봇 특화 (다른 플랫폼 전이 필요)

응용 시나리오 평가

1. 수색 구조 (Search & Rescue):
   적합도: ★★★★☆ (높음)
   이유: 비정형 환경 + 즉각 배포 + 높이 제약 통과
   제한: 코드 미공개, 동적 환경 검증 필요

2. 실내 서비스 로봇:
   적합도: ★★★☆☆ (중간)
   이유: 좁은 통로, 문 통과 능력
   제한: 사람과의 동적 상호작용 미검증

3. 산업 시설 점검:
   적합도: ★★★★☆ (높음)
   이유: 복잡한 실내 구조물, 높이 제약 공간 접근
   제한: 장시간 배터리, 통신 인프라 필요

4. 실외 물류/배달:
   적합도: ★★☆☆☆ (낮음)
   이유: 실외 실험 일부 있음
   제한: 대규모 개방 공간 내비게이션 미검증

TRG-Planner와의 실적용 비교

TRG-Planner:
  장점: 명시적 안전 경로 계획, 위험도 인식, 코드 공개
  단점: 지도 사전 구축 필요, 자세 적응 없음
  적합 시나리오: 사전 지도가 가능하고 체계적 탐색이 중요한 경우

HiPAN:
  장점: 즉각 배포, 자세 적응, 막힌 골목 탈출
  단점: 코드 미공개, 동적 환경 미검증
  적합 시나리오: 사전 지도가 없고 빠른 탐색이 필요한 경우

결론: 두 시스템은 상호 보완적 - TRG-Planner를 전역 계획기로,
      HiPAN을 로컬 내비게이션 정책으로 결합하는 것도 가능

9.4 연구 방향성 평가

기존 패러다임과의 비교

전통적 경로 계획 패러다임:
  [인식] → [지도 구축] → [전역 계획] → [로컬 제어]
  대표: TRG-Planner, SLAM + A* 등
  
  특징: 모듈식, 해석 가능, 수학적 보장 가능
  한계: 모듈 간 오차 누적, 실시간 재계획 비용

학습 기반 종단 내비게이션 패러다임:
  [센서] → [학습 정책] → [직접 제어]
  대표: 순수 RL 방법들
  
  특징: 단순, 빠른 추론
  한계: 해석 불가, 복잡한 환경에서 수렴 어려움

HiPAN 패러다임 (계층적 학습):
  [센서] → [고수준 학습 정책 (내비+자세)] → [저수준 학습 제어기]
  
  특징: 학습의 유연성 + 계층의 구조성 결합
  장점: 자세 적응 통합, 막힌 골목 탈출 학습
  한계: 훈련 복잡도, 보장 없음

트렌드 분석

2024-2026 로봇 내비게이션 연구 트렌드:

1. End-to-End 학습의 부상:
   - 전통적 SLAM + 계획기에서 학습 기반 방법으로 전환
   - HiPAN은 이 트렌드의 선두에 위치
   - 단, 완전 E2E보다 계층적 구조로 안정성 확보

2. Sim-to-Real 격차 해소:
   - 도메인 랜덤화 + 특권 학습이 표준화
   - HiPAN의 DAgger 접근이 효과적임을 실증
   - 향후 메타러닝 기반 빠른 적응이 연구 방향

3. 형태적 자유도 활용:
   - 소프트 로봇, 뱀형 로봇 등에서도 형태 적응 내비게이션 연구 증가
   - HiPAN의 사족보행 자세 적응은 이 방향의 선구적 사례
   - 향후 더 풍부한 형태 제어 (옆으로 걷기, 기어가기 등)로 확장 예상

4. 코드/데이터 공개 압력:
   - RA-L, ICRA 등 주요 학회에서 재현성 요구 강화
   - HiPAN의 코드 미공개는 역트렌드
   - 향후 공개 시 커뮤니티 영향력 크게 증가 예상

11. 결론 (Conclusion)

혁신성 평가

HiPAN은 사족보행 로봇 내비게이션 연구에서 근본적인 패러다임 전환을 제안한다. 기존 연구들이 "내비게이션 = 속도 명령 생성"으로 문제를 단순화했던 것과 달리, HiPAN은 "내비게이션 = 속도 + 자세 명령 통합 생성"으로 문제를 재정의한다. 이 단순해 보이는 관점의 전환이 테이블 아래 통과, 낮은 문틀 통과 등 기존 방법으로는 근본적으로 불가능했던 능력을 가능하게 한다는 점에서 혁신적이다.

계층적 구조(Hierarchical Architecture), 경로 안내 커리큘럼(PGCL), 교사-학생 DAgger 증류의 세 가지 핵심 기술의 조합은 단순히 기존 방법들의 조합이 아니라, 각각이 서로의 약점을 보완하는 시너지를 창출한다. 계층적 구조가 자세 적응을 가능하게 하고, PGCL이 복잡한 환경에서의 안정적 학습을 보장하며, DAgger가 시뮬레이션-현실 격차를 효과적으로 해소한다.

실용적 의의

4가지 실세계 환경에서의 검증은 HiPAN이 단순히 이론적 제안에 그치지 않고 실제 사족보행 로봇에서 작동함을 보여준다. 특히 코드나 지도 없이도 깊이 카메라 하나만으로 즉각 새로운 환경에 투입될 수 있는 능력은 수색 구조, 재난 대응, 산업 시설 점검 등 실용적 응용에서 결정적 이점을 제공한다.

KAIST SGVR Lab의 로봇 제어 및 학습 분야에서의 전문성이 집약된 이 연구는 RA-L이라는 로봇공학 최고 권위 저널에 게재됨으로써 학술적으로도 높은 평가를 받았다. 동료 연구자들이 이 연구를 기반으로 자세 적응 내비게이션을 더 복잡한 시나리오(계단, 동적 환경, 장거리 탐색)로 확장하는 후속 연구들이 예상된다.

향후 연구 방향

단기적으로는 코드 공개, 동적 환경 실험, 다중 카메라 확장이 이 연구의 즉각적인 발전 방향이다. 중기적으로는 온라인 적응, 다중 로봇 협조, 시맨틱 내비게이션과의 통합이 의미 있는 연구 주제가 될 것이다. 장기적으로는 HiPAN의 핵심 아이디어인 "형태적 자유도를 내비게이션 정책에 통합"하는 패러다임이 사족보행 로봇을 넘어 뱀형 로봇, 가변 형태 로봇 등 더 풍부한 형태적 자유도를 가진 시스템에 적용될 것으로 전망된다.

사족보행 로봇 내비게이션 분야에서 HiPAN은 "몸을 어떻게 구성할 것인가"를 내비게이션의 핵심 요소로 격상시킨 선구적 연구로 오래 기억될 것이다.
