1.2 연구 목표 (Research Objective)

WMNav는 Zero-shot Object Goal Navigation(ObjectNav) 문제를 VLM(Vision-Language Model)을 World Model에 통합하는 방식으로 해결하는 연구다. 에이전트는 학습(training) 없이 처음 보는(unseen) 실내 환경에서 자연어로 지정된 목표 객체(예: "bed", "toilet", "sofa")를 찾아 그 앞에 도달해야 한다.

핵심 연구 질문:

"VLM의 풍부한 상식(commonsense) 추론 능력을, '미래 환경 상태를 예측하는
 World Model'의 틀 안에 끼워 넣어, 학습 없이도(zero-shot) 비용이 큰 실제
 환경 상호작용(탐색 스텝)을 최소화하면서 목표 객체를 효율적으로 찾을 수 있는가?"

기존 zero-shot ObjectNav 접근법은 크게 두 갈래였고, 각각 한계를 가진다:

패러다임 대표 방법 한계
Frontier-based 의미 탐색 ESC, L3MVN, VLFM, SGM LLM/VLM이 "프런티어 점수"만 매기고 과거 관측의 기억(memory)을 구조적으로 누적하지 못함
End-to-end / map-less VLM ZSON, PixNav, PSL, TopV-Nav VLM의 직접 행동 예측이 거리·기하 추정에 약하고 hallucination이 누적됨

WMNav는 이 둘 사이에서, VLM이 예측한 "호기심 가치(curiosity value)"를 온라인 탑다운 맵에 누적하고, 그 맵을 World Model의 "예측된 미래 상태"로 사용하여 행동을 결정한다. HM3D와 MP3D 벤치마크에서 zero-shot SOTA를 갱신한다(HM3D +3.2% SR, MP3D +13.5% SR).

[World Model 관점에서의 WMNav 핵심 개념]

전통 World Model (RL/MBRL):
  학습된 동역학 모델 f(s_t, a_t) → s_{t+1} 예측 → 가상 롤아웃으로 계획
  문제: 학습 필요, ObjectNav의 의미론적 목표를 직접 모델링 어려움

WMNav의 World Model:
  VLM이 "이 방향으로 가면 목표가 있을 가능성"을 예측 → 미래 상태(목표 분포)
  Curiosity Value Map = 누적된 "예측 + 관측 갱신" 메모리 = belief state
  Subtask + GoalFlag = 예측과 실제 관측의 불일치를 보정하는 feedback(cost) 신호

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. VLM 직접 행동 예측의 거리/기하 약점

VLM은 "이 이미지에 침대로 가는 길이 보이는가?" 같은 의미론적 질문에는 강하지만, "몇 미터 직진해야 하는가, 어느 각도로 회전해야 하는가" 같은 정밀 기하 추정에는 약하다.

[VLM 직접 행동 예측의 실패 모드]

문제 1: 거리 추정 부정확
  "앞으로 2m 가라" → VLM은 단안 RGB에서 절대 거리를 모름
  → 목표를 지나치거나, 미달하여 정지 실패

문제 2: 좌표계 혼동
  "왼쪽으로 30도" → 에고센트릭/탑다운 좌표 변환 오류
  → 가능하지 않은(navigable하지 않은) 영역으로의 행동 제안

문제 3: 기억의 부재
  매 스텝 독립적으로 VLM을 호출 → "방금 저기엔 침대가 없었다"를 잊음
  → 같은 영역을 반복 탐색 (low SPL)

B. VLM Hallucination의 누적

VLM은 종종 존재하지 않는 객체를 "보인다"고 보고하거나, 잘못된 방향을 자신 있게 선택한다. 매 스텝의 결정을 독립적으로 신뢰하면 이 오류가 궤적 전체로 전파된다.

[Hallucination 누적 시나리오]

t=3: VLM "오른쪽 방에 침대가 보임 (점수 9)" — 실제로는 소파
t=4~8: 그 방으로 이동 — 침대 없음 — 그러나 다시 같은 곳을 의심
t=9: VLM이 또 다른 환각 → 다른 방으로
→ 탐색 예산(40 스텝) 소진, 실패

근본 원인: VLM의 단발성 출력을 검증/누적하는 메커니즘 부재

C. 비용이 큰 환경 상호작용

실로봇/시뮬레이터 모두에서 한 번의 이동·회전은 비용(시간, 에너지, 충돌 위험)이다. 무작정 탐색하면 효율(SPL)이 급락한다. World Model의 목적은 "실제로 가보기 전에 미래를 예측하여 불필요한 상호작용을 줄이는 것"이다.

2.2 핵심 해결책

WMNav의 세 가지 핵심 혁신:

[WMNav의 혁신 요소 3가지]

혁신 1: Curiosity Value Map (CVM) — VLM 예측의 온라인 누적 메모리
  PredictVLM이 각 방향의 목표 존재 가능성(0~10)을 예측
  → 탑다운 맵에 투영하여 min 연산으로 누적
  → "이미 확인했는데 없던 영역"을 0으로 고정 (반복 탐색 방지)

혁신 2: Subtask Decomposition — Hallucination 완화 feedback
  PlanVLM이 작업을 서브태스크 단위로 분해하고 GoalFlag를 출력
  → 예측(world model)과 관측(observation)의 불일치를 cost로 환원
  → 다음 VLM 프롬프트를 보정하는 feedback loop

혁신 3: Two-stage Action Proposer (TAP) — 탐색/정위 분리
  Stage 1(탐색): 넓게 sparse 샘플 + navigable 필터 + 거리 제약
  Stage 2(정위): 목표 감지 시 dense 샘플 + 거리 제약 해제 → 정밀 접근

3. 핵심 방법론 (Core Methods)

3.1 VLM 기반 상태 예측과 Curiosity Value Map (CVM)

WMNav의 심장은 Curiosity Value Map이다. 이것은 "각 위치에 목표 객체가 있을 호기심 가치"를 저장하는 탑다운(bird's-eye) 맵으로, World Model이 예측하는 "미래 환경 상태"의 역할을 한다.

3.1.1 방향별 점수 예측 (PredictVLM)

매 스텝, 에이전트는 6개 방향(30°, 90°, 150°, 210°, 270°, 330°)으로 회전하며 파노라마를 구성하고, PredictVLM에 입력하여 각 방향의 목표 존재 가능성 점수(0~10)를 얻는다.

[Eq. 1 — 방향별 호기심 점수 예측]

Score_t = PredictVLM(I_t^pan)

  I_t^pan : t 시점의 파노라마 이미지 (6개 뷰포인트)
  Score_t : 각 방향에 대한 점수 벡터, 각 원소 ∈ [0, 10]
            10 = 목표가 이 방향에 매우 있을 법함
             0 = 이 방향엔 목표가 거의 없음

해석: VLM은 상식 추론으로 "침대를 찾는다면 침실 쪽(문/복도)이
      유망하다"를 판단 → 의미론적 사전지식을 점수로 환산

3.1.2 에고센트릭 → 탑다운 투영

방향별 점수는 에고센트릭(로봇 중심)이므로, 깊이(depth)와 자세(pose) 정보를 이용해 글로벌 탑다운 좌표로 투영한다.

[Eq. 2 — 점수의 탑다운 투영]

M_t^nav = Projection(Score_t)

  Projection : depth + pose를 사용해 에고센트릭 점수를
               탑다운 격자(grid)의 픽셀 (u, v)로 사상
  M_t^nav    : 현재 스텝이 예측한 navigable 가치 맵

[투영 과정 ASCII]

  로봇 위치 (depth로 거리 추정)
        │
   ┌────┴────┐  각 방향 점수를
   │ 30° = 2 │  navigable 영역의
   │ 90° = 0 │  해당 픽셀에 기입
   │150° = 7 │ ───────────────►  탑다운 격자 M_t^nav
   │210° = 3 │   (장애물/미관측은
   │270° =10 │    별도 처리)
   │330° = 0 │
   └─────────┘

3.1.3 CVM 갱신 — min 연산 (핵심 식)

CVM은 매 스텝 새로 예측된 맵 M_t^nav와 기존 누적 맵 M_{t-1}^cv의 픽셀별 최소값으로 갱신된다.

[Eq. 3 — Curiosity Value Map 갱신 (핵심 혁신)]

M_t^cv(u, v) = min( M_{t-1}^cv(u, v),  M_t^nav(u, v) )

초기화:
  모든 픽셀 M_0^cv(u, v) = 10  (아직 아무것도 모름 → 최대 호기심)

갱신 규칙의 의미:
  ┌──────────────────────────────────────────────────────────┐
  │ 방문하여 목표가 없음을 확인한 영역  → 0으로 내려가 고정     │
  │ 아직 미탐색이지만 VLM이 유망하다고 본 영역 → 높은 값 유지   │
  │ min 연산 → "한 번 0이 된 곳은 다시 올라오지 않음"          │
  │            (이미 확인한 곳을 또 탐색하지 않게 하는 비가역성) │
  └──────────────────────────────────────────────────────────┘

설계 철학: min 연산은 "보수적(conservative) 기억"을 구현한다. 즉, "이미 가봤는데 없더라"라는 부정적 증거를 영구히 보존하여 반복 탐색을 막는다. 이것이 World Model의 belief state로 기능한다 — 에이전트는 이 맵을 보고 "어디로 가면 새 정보를 얻을 수 있는가"를 결정한다.

비판적 검토: min은 단조 감소만 가능하므로, 동적 환경(객체가 움직임)이나 초기 오판(잘못 0으로 만든 영역)에서 회복이 불가능하다. 정적 ObjectNav 벤치마크에서는 합리적이지만, 일반화에는 약점이다(§8 한계 참조).

3.2 Subtask Decomposition — Hallucination 완화 feedback

CVM이 "어디로"를 정한다면, Subtask Decomposition은 "지금 무엇을 하고 있는가"를 추적하여 hallucination을 완화한다. PlanVLM은 선택된 방향의 이미지와 직전 서브태스크를 받아, 새 서브태스크와 GoalFlag를 출력한다.

[Eq. 4 — 서브태스크 분해]

SubTask_t, GoalFlag_t = PlanVLM( I_t(ᾱ),  SubTask_{t-1} )

  I_t(ᾱ)        : 선택된 방향 ᾱ의 현재 이미지
  SubTask_{t-1} : 직전 서브태스크 (텍스트)
  SubTask_t     : 갱신된 서브태스크 (예: "복도를 따라 침실로 진입")
  GoalFlag_t    : 목표 객체 감지 여부 (boolean)

feedback(cost) 메커니즘:
  - World Model 예측(CVM)이 "여기 목표가 있을 것"이라 했는데
    실제 관측에서 GoalFlag=False면 → 불일치(cost)가 발생
  - 이 cost가 다음 PlanVLM/PredictVLM 프롬프트의 컨텍스트로 들어가
    "여기엔 없었다"는 정보를 반영 → hallucination 누적 차단

[서브태스크 진행 예시 — 침대 찾기]

t=2: SubTask = "거실에서 침실로 통하는 문/복도 탐색", GoalFlag=False
t=5: SubTask = "복도 끝 방으로 진입", GoalFlag=False
t=8: SubTask = "방 안에서 침대 위치 확인", GoalFlag=True  ← 예측-관측 일치
t=9: → Two-stage Stage 2(정위)로 전환

직관: 인간도 "지금 침실로 가는 중 → 방 안 → 침대 발견" 식으로 작업을 잘게 나누어 진행 상황을 점검한다. 서브태스크가 명시되면 VLM이 "이미 한 일"과 "다음 할 일"을 혼동하지 않는다.

3.3 Two-stage Action Proposer (TAP)

VLM의 거리 추정 약점을 보완하기 위해, 행동 제안을 탐색(Exploration) 과 정위(Goal-Approaching) 두 단계로 분리한다.

[Eq. 5 — 최종 행동 선택 (ReasonVLM)]

ā_t = ReasonVLM( SubTask_t,  Goal_t,  I_t^ann )

  I_t^ann : 후보 행동들이 극좌표 (r_t, θ_t)로 주석(annotation)된 이미지
  ā_t     : 선택된 행동 (어느 후보로 이동할지)
  ReasonVLM이 SubTask/GoalFlag를 컨텍스트로 받아 후보 중 하나 선택

[Two-stage Action Proposer 동작]

┌─────────────────── Stage 1: Exploration (GoalFlag=False) ──────────────────┐
│                                                                            │
│  1) K개 후보 행동을 일정 각도 간격으로 sparse 샘플링                        │
│  2) navigable area map으로 도달 불가 후보 제거                              │
│  3) 이미 탐색한(CVM=0) 영역 방향 후보 필터링                               │
│  4) 이동 거리 제약(max/min) 적용 → K' 후보                                  │
│  5) ReasonVLM이 K' 중 하나 선택 (넓게 멀리 → 빠른 탐색)                     │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
                                    │
                          GoalFlag=True 감지
                                    ▼
┌──────────────── Stage 2: Goal-Approaching (GoalFlag=True) ─────────────────┐
│                                                                            │
│  1) 목표 주변을 dense 샘플링 (촘촘한 후보)                                  │
│  2) 이동 거리 제약 제거 → 목표 바로 앞까지 접근 허용                        │
│  3) ReasonVLM이 정밀 위치로 이동 → 정확한 정지(stop)                        │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

[Eq. 6 — 정지 조건]

StopFlag = True   if  DistanceToGoal < d_thres   else  False
  d_thres = 1.0m   (에피소드 성공 판정 거리)

왜 두 단계인가?: 탐색 단계에서는 "멀리 빠르게" 이동해야 효율적이지만(sparse), 목표를 찾았을 땐 "가까이 정밀하게" 접근해야 성공한다(dense). 단일 정책으로는 이 둘을 동시에 만족하기 어렵다. 거리 제약을 단계별로 다르게 두어 VLM의 거리 약점을 우회한다.

3.4 전체 의사결정 루프 (Putting It Together)

[WMNav 한 스텝의 흐름]

(1) 6방향 파노라마 촬영 → PredictVLM → Score_t                  (Eq.1)
(2) depth+pose로 탑다운 투영 → M_t^nav                          (Eq.2)
(3) CVM 갱신 min(M_{t-1}^cv, M_t^nav) → M_t^cv                  (Eq.3)
(4) CVM 최댓값 방향 선택 → 그 방향 이미지를 PlanVLM에
      → SubTask_t, GoalFlag_t                                  (Eq.4)
(5) GoalFlag에 따라 TAP가 후보 행동 샘플 → ReasonVLM 선택 ā_t   (Eq.5)
(6) 목표 도달 시 StopFlag                                        (Eq.6)
(7) 다음 스텝으로 (최대 40 스텝)

4. 시스템 아키텍처 (System Architecture)

[WMNav 전체 파이프라인]

┌──────────────────────────────────────────────────────────────────────┐
│                          관측 (Observation)                            │
│   RGB-D 카메라 (640×480, FOV 79°, pitch -14°)  +  Pose (odometry)      │
│   6방향 회전 → 파노라마 I_t^pan                                         │
└───────────────────────────────┬──────────────────────────────────────┘
                                │
              ┌─────────────────▼─────────────────┐
              │   ① PredictVLM  (World Model 예측) │
              │   각 방향 목표 존재 점수 0~10       │  Eq.1
              └─────────────────┬─────────────────┘
                                │ Score_t
              ┌─────────────────▼─────────────────┐
              │   ② Projection  (depth + pose)     │  Eq.2
              │   에고센트릭 → 탑다운 M_t^nav        │
              └─────────────────┬─────────────────┘
                                │
              ┌─────────────────▼─────────────────┐
              │   ③ Curiosity Value Map (belief)   │  Eq.3
              │   M_t^cv = min(M_{t-1}^cv, M_t^nav) │
              │   ┌───────────────────────────┐    │
              │   │ 10 미탐색·유망            │    │
              │   │  5 부분 관측              │    │
              │   │  0 확인됨·목표없음(고정)   │    │
              │   └───────────────────────────┘    │
              └─────────────────┬─────────────────┘
                                │ argmax 방향 선택
              ┌─────────────────▼─────────────────┐
              │   ④ PlanVLM     (feedback/cost)    │  Eq.4
              │   SubTask_t, GoalFlag_t            │
              └─────────────────┬─────────────────┘
                                │
              ┌─────────────────▼─────────────────┐
              │   ⑤ Two-stage Action Proposer      │
              │   GoalFlag=False → Stage1(sparse)  │
              │   GoalFlag=True  → Stage2(dense)   │
              │       │                            │
              │       ▼ navigable 필터 + 거리제약  │
              │   ⑥ ReasonVLM → ā_t                │  Eq.5
              └─────────────────┬─────────────────┘
                                │
                  ┌─────────────▼─────────────┐
                  │  StopFlag (dist < 1.0m)?  │  Eq.6
                  │   Yes → 종료 / No → t+1    │
                  └───────────────────────────┘

4.1 데이터 흐름 설명

World Model 루프(예측 → 관측 → 보정):

  1. PredictVLM이 미래 상태(목표 분포)를 예측 → CVM에 누적
  2. 에이전트가 CVM에서 가장 유망한 방향으로 실제 이동(관측)
  3. PlanVLM의 GoalFlag로 예측-관측 일치 여부 판정
  4. 불일치(cost)는 CVM의 min 갱신과 다음 프롬프트 컨텍스트로 환류
  5. 이 폐루프가 hallucination 누적을 억제하고 탐색을 의미론적으로 유도

세 VLM 모듈의 역할 분담:

  • PredictVLM = World Model의 "예측기"(어디에 목표가 있을 것인가)
  • PlanVLM = 진행 추적 + feedback 생성기(지금 무엇을 하는가, 목표를 봤는가)
  • ReasonVLM = 행동 선택기(후보 중 어디로 갈 것인가)

세 모듈은 동일 백본 VLM(Gemini 1.5 Pro 등)을 서로 다른 프롬프트로 호출하는 구조다 — 별도 학습 가중치가 없는 zero-shot 파이프라인.

6. 핵심 기여점 (Key Contributions)

기여 1: VLM을 World Model로 통합한 zero-shot ObjectNav 프레임워크

WMNav는 VLM의 예측을 "미래 환경 상태(목표 분포)"로 해석하여 World Model의 belief state(CVM)로 누적하는 최초의 실용적 ObjectNav 프레임워크다. 학습된 동역학 모델 대신 VLM의 상식 추론을 예측기로 사용함으로써, MBRL의 학습 부담 없이 "미래 예측 기반 계획"의 이점을 zero-shot으로 취한다.

기여 2: Curiosity Value Map (CVM)

min 연산 기반의 단조 누적 메모리로, "이미 확인했으나 목표가 없던 영역"을 영구히 억제한다. 어블레이션에서 메모리 없음 대비 SR +3.7%p, SPL +9.1%p로 가장 큰 단일 기여 요소임이 입증됐다. 단순 Text-Image 메모리가 오히려 성능을 떨어뜨린 것과 대비되어, 기하 투영 + min 누적이라는 구조적 설계의 가치를 보여준다.

기여 3: Subtask Decomposition을 통한 hallucination 완화 feedback

예측(World Model)과 관측(GoalFlag)의 불일치를 cost로 환원하여 다음 VLM 호출을 보정하는 폐루프를 구성한다. 개별 SR 기여(+0.6%p)는 작지만, 진행 추적과 정지 판정의 안정성에 기여한다.

기여 4: Two-stage Action Proposer로 VLM의 거리 약점 우회

탐색(sparse) / 정위(dense)를 분리하고 거리 제약을 단계별로 달리하여, VLM이 약한 정밀 거리 추정 없이도 정확한 목표 접근을 달성한다(SR +2.1%p).

기여 5: 완전한 코드 공개 및 재현성

Habitat·vLLM·transformers 기반의 실제 동작 코드를 공개하고(Gemini/Qwen2.5-VL 양쪽 지원), 백본 VLM에 따른 성능 스펙트럼을 정량 보고하여 재현성과 확장성을 모두 확보했다.

7. 구현 상세 (Implementation Details)

7.1 파이프라인 설정

[zero-shot 파이프라인 — 학습 가중치 없음]

세 VLM 모듈(PredictVLM/PlanVLM/ReasonVLM)은 동일 백본을
서로 다른 프롬프트로 호출 → 별도 fine-tuning 불필요

PredictVLM 프롬프트  : 6방향 파노라마 + 목표 카테고리 → 방향별 0~10 점수
PlanVLM 프롬프트     : 선택 방향 이미지 + 직전 서브태스크 → 새 서브태스크 + GoalFlag
ReasonVLM 프롬프트   : 후보 행동 주석 이미지 + 서브태스크/GoalFlag → 행동 선택

7.2 맵 처리

[CVM 투영/갱신 관련 처리]

투영(Eq.2):
  - depth로 각 픽셀의 3D 위치 복원 → pose로 글로벌 좌표 변환
  - navigable area map과 교차하여 도달 가능 영역에만 점수 기입

갱신(Eq.3):
  - M_t^cv = element-wise min(M_{t-1}^cv, M_t^nav)
  - 미관측 영역은 초기값 10 유지 → 자연스러운 frontier 탐색 유도

행동 샘플링:
  - Stage1: 각도 균일 간격 K개 sparse, 거리 제약(max/min) 적용
  - Stage2: 목표 주변 dense, 거리 제약 해제

7.3 비용 관점(정성)

논문은 API 호출 횟수·금전 비용을 정량화하지 않는다. 매 스텝 최소 3회(Predict/Plan/Reason)의 VLM 호출이 발생하고, 6방향 파노라마 촬영을 위해 로봇이 정지·회전해야 하므로, 실제 필드 운영 비용과 지연(latency)은 미지수로 남는다.

8. 고급 주제 (Advanced Topics)

8.1 확장성 분석

백본 VLM 교체: WMNav는 학습 가중치가 없으므로 백본 VLM을 자유롭게 교체할 수 있다(코드가 Gemini/Qwen 둘 다 지원). 더 강한 VLM(GPT-4o, Gemini 2.5 등)으로 갈수록 성능이 단조 향상(Table 4)되므로, 모델 발전을 그대로 흡수한다. 반대로 말하면 알고리즘의 천장이 백본에 종속된다.

다른 임베디드 태스크로의 전이: CVM의 "예측 누적 belief map" 아이디어는 ObjectNav를 넘어 instruction-following(VLN), 다중 객체 탐색, 영역 커버리지 같은 태스크에도 적용 가능하다. 단, min 누적은 "찾을 대상이 정적이고 한 번 없으면 영구히 없다"는 가정에 의존하므로, 동적/다목표 태스크에는 합/평균/감쇠 누적으로의 변형이 필요하다.

8.2 한계점 (Limitations)

[WMNav의 핵심 한계]

한계 1: 실로봇 미검증 (Sim-to-Real 갭)
  모든 결과가 Habitat 시뮬레이터.
  - 완벽한 odometry/depth/collision 가정 → 실세계 노이즈로 깨짐
  - CVM 투영(Eq.2)이 pose drift·depth 노이즈에 직접 노출됨
  - 6방향 정지·회전 파노라마는 동적 환경/연속 이동에 부적합

한계 2: min 연산의 비가역성
  한 번 0이 된 픽셀은 회복 불가
  - 초기 오판(잘못된 0)이 영구 손해
  - 동적 환경(객체 이동)에서 outdated belief

한계 3: 백본 VLM 종속성
  Qwen2.5-VL-3B 29.7% vs Gemini 1.5 Pro 58.1% — 거의 2배 격차
  - 오프라인/엣지 배포 사실상 불가 (상용 API 의존)
  - API 지연·비용 미분석

한계 4: SR과 SPL의 트레이드오프
  TAP가 SR을 올리지만 SPL은 떨어뜨림 (dense 샘플의 미세 이동)
  - HM3D에서 SR이 SGM에 미달 (58.1% vs 60.2%)

8.3 향후 연구 방향

[향후 방향]

방향 1: 감쇠/적응 누적으로 CVM 일반화
  min → 시간 감쇠(decay) 또는 Bayesian update
  → 동적 환경·오판 회복 가능

방향 2: 오픈소스 VLM 강화 + 온디바이스화
  Qwen2.5-VL fine-tuning 또는 distillation
  → API 의존 탈피, 실시간 엣지 배포

방향 3: 실로봇 배포 + Sim-to-Real
  pose/depth 노이즈에 강건한 투영, 연속 행동 공간
  → 6방향 정지 파노라마 대신 스트리밍 관측

방향 4: 비용-인지 계획
  VLM 호출 횟수를 명시적 cost로 두어 호출 예산 최적화

9.2 장단점 분석

WMNav의 장점:

  1. Zero-shot: NavWM·WorldMAP·NavWAM이 모두 World Model을 학습해야 하는 것과 달리, WMNav는 백본 VLM을 그대로 사용한다. 새 환경·새 객체에 즉시 적용 가능하며 학습 데이터/연산이 불필요하다.
  2. 해석 가능한 belief: CVM은 픽셀별 0~10 점수로 "어디가 유망한가"를 직접 시각화·디버깅할 수 있다. 생성 WM(WorldMAP)의 잠재 표현보다 투명하다.
  3. 의미 사전지식 활용: VLM의 상식("침대→침실")을 점수로 환산 — 학습 기반 WM이 데이터에서 암묵적으로 익혀야 하는 것을 명시적으로 가져온다.
  4. 실제 동작 코드: 세 형제 대비 공개 코드의 완성도(Habitat 통합, Gemini/Qwen 양쪽)가 높아 재현성이 우수하다.

WMNav의 단점:

  1. 표현력 제한: CVM은 "목표 존재 가능성"이라는 스칼라 점수 맵일 뿐, WorldMAP처럼 미래 관측 프레임을 생성하거나 NavWAM처럼 행동-조건 상태 전이를 모델링하지 못한다 — World Model의 "예측" 깊이가 얕다.
  2. min 비가역성: NavWM/NavWAM의 학습된 동역학은 belief를 갱신·회복할 수 있으나, WMNav의 min은 단조 감소만 가능하다.
  3. 백본 종속: 학습이 없으므로 성능 천장이 백본 VLM에 묶인다(Qwen 3B에서 29.7%로 붕괴). 학습 기반 형제들은 백본이 약해도 태스크 적합 학습으로 보완한다.
  4. 실로봇 미검증: 세 형제와 마찬가지로 실로봇 결과가 없어, "World Model이 실세계 상호작용을 줄인다"는 주장이 시뮬레이션 밖에서 입증되지 않았다.

NavWM 대비: NavWM은 foresight-driven planning을 위해 통합 navigation World Model을 학습한다. WMNav는 같은 "미래 예측 기반 계획" 목표를 학습 없이 VLM 예측 누적으로 달성한다 — NavWM이 더 풍부한 잠재 동역학을, WMNav가 더 가벼운 zero-shot 배포성을 택한 상보적 관계다.

WorldMAP 대비: WorldMAP은 생성적 World Model로 미래 궤적/프레임을 부트스트랩하여 데이터를 늘린다. WMNav는 미래를 "이미지 생성"이 아니라 "점수 맵"으로 추상화한다 — WorldMAP의 생성 품질이 높으면 더 풍부하지만, WMNav는 생성 비용·hallucination 없이 가벼운 belief만 유지한다.

NavWAM 대비: NavWAM은 행동-조건(state, action → next state) World Action Model을 학습하여 goal-conditioned 내비를 푼다. WMNav의 belief는 행동-조건 전이를 명시적으로 모델링하지 않고, "현재 어디가 유망한가"만 누적한다 — 계획 지평(horizon)이 NavWAM보다 짧다.

9.4 연구 방향성 평가

WMNav는 "학습된 동역학 World Model"(NavWM/NavWAM/WorldMAP)과 "프런티어 의미 탐색"(VLFM/SGM/L3MVN) 사이의 제3의 길을 제시한다 — VLM 예측을 belief map으로 누적하는 학습-프리 World Model. 이 방향의 의의:

  1. 경량성: 학습 없이 World Model의 "예측 기반 계획" 이점을 취함.
  2. 모델 발전 흡수: 백본 VLM이 강해질수록 성능이 자동 향상(Table 4).
  3. 투명성: 해석 가능한 점수 맵으로 디버깅·신뢰성 확보.

중장기적으로, WMNav의 min-누적을 학습 가능한/감쇠 가능한 갱신으로 일반화하고 실로봇으로 옮기는 것이 핵심 과제다. NavWAM의 행동-조건 모델링이나 WorldMAP의 생성 예측과 결합하면, "zero-shot 의미 사전지식 + 학습된 정밀 동역학"의 하이브리드 World Model이 가능할 것이다.

11. 결론 (Conclusion)

혁신성 평가

WMNav는 VLM의 의미론적 예측을 World Model의 belief state로 통합한다는 명쾌한 아이디어로 zero-shot ObjectNav를 진전시킨 IROS 2025 Oral 논문이다. 핵심 기여인 Curiosity Value Map은 "VLM이 예측한 방향별 목표 가능성을 탑다운 맵에 min-누적"하여, 학습된 동역학 모델 없이도 "미래 예측 기반 효율 탐색"을 실현한다. 어블레이션이 보여주듯 성능의 주역은 이 belief map(메모리 없음 65.8% → CVM 69.5% SR, SPL +9.1%p)이며, Subtask Decomposition과 Two-stage Action Proposer가 보조한다.

실용적 의의

HM3D에서 SPL 31.2%(최고 효율), MP3D에서 SR 45.4%(SOTA, +13.5% 상대)를 학습 없이 달성한다는 것은, 강한 백본 VLM만 있으면 새 환경에 즉시 배포 가능한 의미론적 탐색 에이전트를 만들 수 있음을 보여준다. 코드가 실제로 공개(Gemini/Qwen 양쪽)되어 재현성과 확장성도 확보했다.

한계와 향후 방향

가장 큰 한계는 실로봇 미검증과 백본 VLM 종속이다. 모든 결과가 Habitat 시뮬레이터에서 나왔고, CVM의 핵심인 탑다운 투영(Eq.2)은 실세계 pose/depth 노이즈에 직접 노출된다. min 누적의 비가역성은 동적 환경·초기 오판에 취약하다. 향후 (1) 감쇠/Bayesian 갱신으로 CVM 일반화, (2) 오픈소스 VLM 강화로 온디바이스화, (3) 실로봇 Sim-to-Real, (4) VLM 호출 비용-인지 계획이 핵심 과제다.
