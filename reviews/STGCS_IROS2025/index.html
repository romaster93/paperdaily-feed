1.2 연구 목표 (Research Objective)

ST-GCS는 동적 장애물이 존재하는 환경에서의 시공간 시간-최적 모션 플래닝(spatiotemporal time-optimal motion planning) 과 그 자연스러운 확장인 다중로봇 모션 플래닝(Multi-Robot Motion Planning, MRMP) 을 하나의 통일된 틀로 푼다.

핵심 착안은 최근 각광받는 볼록집합 그래프(Graphs of Convex Sets, GCS) 프레임워크를 시간 축으로 확장하는 것이다. 기존 GCS(Marcucci et al.)는 공간을 충돌 없는 볼록 영역들의 그래프로 분해하고, "어느 볼록집합들을 어떤 순서로 통과하고 각 집합의 진입/이탈 상태를 어디로 둘 것인가"를 하나의 혼합정수 볼록계획(MICP)으로 푼다. 이 접근은 공간 플래닝에서 강력하지만, 동적 장애물과 다중로봇 상호작용을 시간 차원에서 다루는 데는 그대로 쓰기 어렵다 — 시간을 함께 다루면 그래프가 급격히 커지고, 단일 거대 MICP는 좁은 시공간 통로에서 확장성이 무너진다.

논문이 답하려는 질문:

  • 공간 볼록집합을 시간 축으로 밀어 올려(extrude) 시공간 볼록집합(space-time convex set)을 만들면, 동적 장애물과 다른 로봇의 궤적을 시공간 점유 영역(space-time occupancy) 으로 통일되게 표현할 수 있는가?
  • 시간-최적 궤적 계획을, 하나의 거대 MICP를 푸는 대신 경로-인덱스 최선우선 탐색(path-indexed best-first search) 으로 분해하면 좁은 통로에서 훨씬 빠르고 확장 가능한가?
  • 이 단일로봇 솔버를 우선순위 기반 계획(prioritized planning) + 우선순위 기반 탐색(PBS) 과 정확 볼록분해(Exact Convex Decomposition, ECD) 로 결합하면 최대 100대 규모 MRMP를 수 분 내에 풀 수 있는가?

한 줄 요약: "GCS를 시간으로 확장하고, 그 위에서 시간-최적 플래닝을 (거대 MICP가 아닌) 경로-인덱스 그래프 탐색으로 분해하며, 궤적 점유를 정확 볼록분해로 예약하여 동적 장애물·다중로봇을 통일 처리한다."

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

(C1) GCS의 비최적 부분구조(non-optimal substructure). 표준 그래프 최단경로(Dijkstra/A*)는 "부분경로의 최적성"을 전제로 한다 — 목표까지의 최적 경로의 어떤 접두부(prefix)도 그 자체로 최적이다. 그러나 GCS에서는 한 정점 v에 도달하는 비용이 그 정점에 이르기까지 사용한 전체 접두 경로(entire prefix path)에 의존한다. 왜냐하면 각 볼록집합 내부에서 진입/이탈 상태 (x_v, y_v)를 연속 최적화하는데, 그 최적값이 앞서 통과한 집합들의 상태에 연쇄적으로 얽히기 때문이다. 논문이 명시하듯 "the cost of a path depends on the entire prefix path used to reach that vertex." 따라서 정점 단위로 최단 비용을 저장하는 통상적 탐색은 최적성을 보장하지 못한다.

(C2) 시간 차원 추가로 인한 그래프 폭발. 공간만 다루던 GCS에 시간 축을 더하면 상태가 x = (p, t) ∈ ℝ^(m+1) 로 한 차원 커지고, 동적 장애물·다른 로봇의 궤적이 시공간에서 볼록 영역을 잘라내며 정점 수를 늘린다. 하나의 거대 MICP로 풀면 이진 변수가 폭증해 좁은 시공간 통로에서 솔버가 붕괴한다.

(C3) 동적 장애물·다중로봇의 통일 표현. 이동 장애물과 "이미 계획된 다른 로봇의 궤적"은 본질적으로 같은 것 — 시공간을 점유하는 스윕 볼륨(swept volume) 이다. 그러나 기존 방법은 이 둘을 별개 메커니즘으로 다루는 경우가 많다. 하나의 표현으로 통일하지 못하면 코드·이론이 이원화된다.

(C4) 다중로봇 결합의 지수 복잡도. N대 로봇을 결합 상태공간(joint configuration space)에서 동시에 풀면 차원이 N에 비례해 폭발한다. 좁은 병목(bottleneck)에서 로봇들이 서로 양보·교차해야 할 때 이 결합이 특히 어렵다.

(C5) 샘플링 기반 시공간 플래너의 좁은 통로 취약성. ST-RRT*, T-PRM 같은 샘플링 기반 시공간 플래너는 무작위 표본에 의존해, 좁은 시공간 회랑(narrow space-time corridor) — 예컨대 이동 장애물 사이의 짧은 시간창 — 에서 유효 표본을 거의 못 뽑아 성공률·품질이 저하된다.

2.2 핵심 해결책

ST-GCS의 해법은 "시공간 GCS + 경로-인덱스 탐색 + 정확 볼록분해 + 우선순위 다중로봇" 의 4중 결합이다:

┌──────────────────────────────────────────────────────────────────────┐
│ (1) ST-GCS 구성:  공간 볼록집합 X_v ⊂ ℝ^m 을 [0,tmax]로 밀어올려        │
│     시공간 볼록집합 X_v×[0,tmax] ⊂ ℝ^(m+1) 생성 (extrusion)            │
│              │                                                          │
│ (2) 경로-인덱스 최선우선 탐색(BFS):  정점이 아니라 "접두경로 π"로       │
│     탐색 노드를 인덱싱 → C1(비최적 부분구조) 정면 돌파.                 │
│     각 노드마다 경로-조건부 볼록계획(PathOptimize)으로 시간-최적 궤적. │
│              │                                                          │
│ (3) 지배 검사(δset/δstate/δpos) + 상한 가지치기 → 지수 탐색을 실용화.   │
│              │                                                          │
│ (4) ECD(정확 볼록분해):  동적 장애물/타 로봇 궤적의 시공간 스윕을        │
│     볼록집합에서 정확히 도려내 → C3(동적·다중로봇 통일 표현).           │
│              │                                                          │
│ (5) MRMP:  우선순위 계획(PP) + PBS로 로봇을 순차 배치, 각 로봇 궤적을    │
│     ECD로 예약 → 다음 로봇은 정적 장애물로 취급 → C4(지수결합) 회피.    │
│     윈도우 조정(windowed coordination)으로 100대까지 확장.             │
└──────────────────────────────────────────────────────────────────────┘
  • 경로-인덱스 탐색(C1 해결): 노드를 정점이 아니라 접두경로 전체로 인덱싱해, GCS의 비최적 부분구조를 우회하면서 ε-최적성을 증명한다.
  • 탐색 분해(C2, C5 해결): 하나의 거대 MICP 대신, 각 노드에서 작은 경로-조건부 볼록계획만 풀고 최선우선으로 확장 → 좁은 통로에서 MICP·샘플링 대비 수배~수십배 빠름.
  • ECD(C3 해결): 동적 장애물과 타 로봇 궤적을 모두 시공간 스윕으로 도려내 통일 처리.
  • 우선순위 + PBS + 윈도우(C4 해결): 결합 공간을 피하고 로봇을 순차·우선순위로 배치, 시간창 중첩 로봇만 조정 → 100대 수 분.

3. 핵심 방법론 (Core Methods)

3.1 배경: 공간 볼록집합 그래프(GCS)

먼저 논문의 토대인 공간 GCS를 정리한다. 볼록집합 그래프 G = (V, E, 𝒳) 에서:

각 정점 v ∈ V  ↔  볼록집합  X_v = { x | A_v x ⪯ b_v } ⊆ ℝ^m   (충돌 없는 영역)
각 간선 (u,v) ∈ E  ↔  두 집합이 겹침:  X_u ∩ X_v ≠ ∅
경로 π = ⟨v_1, v_2, ..., v_l⟩  ↔  연속 간선으로 이어진 정점열

공간 GCS 모션 플래닝(논문 식 1a–1e)은 시작→목표를 잇는 경로 π를 고르고, 각 집합 안에서 진입/이탈 상태 (x_v, y_v)를 함께 최적화하여 총비용을 최소화한다. 각 집합 내부는 직선(또는 저차 곡선)으로 연결되고, 집합이 충돌 없는 영역이므로 그 안의 궤적도 충돌 없다. 원래 GCS는 이를 하나의 혼합정수 볼록계획(MICP) 으로 통째로 풀거나 볼록완화 후 라운딩한다.

3.2 시공간 볼록집합 구성 (Space-Time Convex Sets)

ST-GCS의 첫 번째 핵심은 공간 집합을 시간 축으로 밀어 올리는(extrude) 것이다. 상태를 x = (p, t) 로 두어 위치 p ∈ ℝ^m 와 시간 t ∈ ℝ 를 결합, 시공간 ℝ^(m+1) 에서 작업한다.

논문 표현: "an ST-GCS can be initialized by extruding each given spatial collision-free convex set from time 0 to an arbitrarily large but finite time limit t_max." 즉 초기 시공간 집합은 공간 볼록집합을 [0, t_max] 구간의 시간 프리즘으로 세운 것이다:

공간 (2D)                     시공간 (2D+시간, 3D)
                                       t ↑  t_max ┌────────┐
   ┌──────┐                              │        │        │  ← 시간 프리즘
   │  X_v │   ── extrude [0,tmax] ─▶     │        │  X_v   │     (extruded set)
   └──────┘                              │        │        │
                                     t=0 └────────┴────────┘→ p

코드 근거 (mrmp/stgcs.py STGCS.from_env): 실제 구현이 정확히 이 extrusion을 수행한다.

@staticmethod
def from_env(env, t0=0, tmax=1e2, vlimit=1.0, dt=1e-6) -> STGCS:
    sets = [make_hpolytope(V) for V in env.C_Space]   # 공간 볼록영역(IRIS 등)
    dim = 1 + sets[0].ambient_dimension()             # +1 : 시간 차원 추가
    stgcs = STGCS(dim, t0=t0, tmax=tmax, vlimit=vlimit, dt=dt)
    for i, s in enumerate(sets):
        t_set = time_extruded(s, t0, tmax)            # ★ 공간집합을 [t0,tmax]로 시간 압출
        ...
        stgcs.add_vertex(t_set, Interval(t0, tmax), space_bounds)
    for u_name, v_name in combinations(stgcs.G.vertex_names, 2):
        stgcs.try_build_edge(u_name, v_name)          # 겹치는 시공간집합끼리 간선
    for obs in env.O_Dynamic:
        stgcs = obs.reserve(stgcs, env.robot_radius, True, True)  # ★ 동적장애물 예약(ECD)
    return stgcs
  • dim = 1 + ambient_dimension(): 공간 차원 m에 시간 1차원을 더해 m+1.
  • time_extruded(s, t0, tmax): 공간 폴리토프 s를 [t0, tmax] 시간으로 압출한 시공간 폴리토프.
  • 기본값 tmax=1e2(코드), vlimit=1.0 — 논문 실험은 t_max = 50 시간단위, 성분별 속도한계 1 단위/시간을 사용한다.

3.3 시간-최적 계획의 정식화 (Time-Optimal Formulation)

ST-GCS 상의 시간-최적 궤적은 총 경과시간의 최소화로 정의된다(논문 식 3a–3f):

minimize   c(τ) = Σ_{v∈π}  Δt_v                     (총 경과시간)
  변수:     경로 π 와 각 집합의 진입/이탈 상태 (x_v, y_v)
subject to
  (i)   π ∈ 𝒫(v_s, v_g; G)          경로는 시작→목표 유효경로
  (ii)  x_v, y_v ∈ X_v               진입/이탈이 시공간집합 내부
  (iii) x_v = y_u   (연속 간선 u→v)   집합 경계에서 상태 연속
  (iv)  Δt_v ≥ 0                     시간 단조증가(뒤로 못 감)
  (v)  -v_lim·Δt_v ⪯ Δp_v ⪯ v_lim·Δt_v   속도 한계 (성분별)

여기서 Δp_v = y_v.p − x_v.p, Δt_v = y_v.t − x_v.t 는 집합 v 안에서의 공간·시간 변위다. 각 집합 안에서는 균일속도의 조각별 선형(piecewise-linear) 궤적으로 통과한다. 조건 (v)는 속도가 v_lim을 넘지 않게 하는 볼록 제약이다.

코드 근거 (STGCS.__init__): 이 제약들이 Drake LinearConstraint로 정확히 인코딩되어 있다.

# 속도 한계:  -v_lim·Δt ⪯ Δp ⪯ v_lim·Δt  를 두 반평면으로
A_vmax = np.hstack([ np.eye(d-1),  vlimit*np.ones((d-1,1)), -np.eye(d-1), -vlimit*np.ones((d-1,1))])
A_vmin = np.hstack([-np.eye(d-1),  vlimit*np.ones((d-1,1)),  np.eye(d-1), -vlimit*np.ones((d-1,1))])
A_dt   = np.array([0]*(d-1) + [1] + [0]*(d-1) + [-1])     # 시간 단조: Δt ≥ dt(>0)
A_time = np.vstack([A_vmax, A_vmin, A_dt])
self.time_constraint = LinearConstraint(A_time, -inf, b_time)   # b_time[-1] = -dt
self.time_cost = L2NormCost(A_dt.reshape(1,-1), np.zeros(1))     # ★ 비용 = Δt (경과시간)
  • time_cost = L2NormCost(A_dt, 0): 비용이 시간 변위 Δt의 L2노름 = 경과시간. 즉 목적함수가 문자 그대로 "시간" 임을 코드가 증명한다.
  • A_dt 행: Δt ≥ dt(작은 양수 dt=1e-6)로 시간 단조성 강제.
  • 연속 제약(cont_constraint = LinearEqualityConstraint(A_cont, 0))은 간선 양단의 상태를 같게 묶는다(식 (iii)).

solve()가 반환 시 sol.cost = sol.itvl.duration 로 비용을 다시 시간 길이로 확정한다 — 목적이 시간-최적임을 이중으로 못박는다.

3.4 경로-인덱스 탐색 노드 (Path-Indexed Search Node)

이 논문의 이론적 심장은 C1(비최적 부분구조) 을 정면으로 다루는 경로-인덱스 탐색이다. 정점 단위로 최단 비용을 저장하면 GCS에서 최적성을 잃으므로, 탐색 노드를 접두경로 전체로 인덱싱한다.

정의 1 (경로-인덱스 노드): N = (π, v, τ, g, f)

N.π : 시작에서 여기까지의 접두경로(prefix path)
N.v : 현재(말단) 정점
N.τ : 접두경로 N.π 에 조건부인 최적 궤적 (경로-조건부 볼록계획의 해)
N.g = c(N.τ) : cost-to-come (여기까지의 최적 시간)
N.f = N.g + ε·h(N.π) : 탐색 우선순위 키 (A* 유사, ε는 가중치)

핵심은 N.τ가 경로 전체에 조건부인 최적 궤적이라는 점 — 정점만 보는 게 아니라 "이 접두경로로 왔을 때의 최적 통과"를 매 노드가 들고 있다. 이 덕에 부분경로의 최적성 가정 없이도 전역 최적성을 회복할 수 있다.

보조정리 1 (재방문 배제, Revisitation Exclusion): 조각별 선형 궤적 표현과 시간-비용 목적 하에서, "반복 정점이 없는 단축 경로 위에도 더 높지 않은 비용의 유효 궤적이 존재한다." 즉 정점을 반복하는(사이클) 경로는 결코 이득이 없으므로, 탐색을 단순경로(simple path, 사이클 없음) 로 제한해도 최적성을 잃지 않는다. 이는 탐색 공간을 유한(단순경로 집합)으로 만들어 종료를 보장한다.

3.5 최선우선 탐색 솔버 (Algorithm 1: BFS Solver)

경로-인덱스 노드 위에서 최선우선 탐색(Best-First Search)이 돈다:

자료구조:
  OPEN : 우선순위 큐 (키 = N.f = N.g + ε·h(N.π))
  S(v) : 정점 v 에 도달해 "채택된(살아남은)" 노드 집합 (지배검사용)

메인 루프:
  1. OPEN 에서 f 최소 노드 N 팝
  2. N.v == v_g (목표) 이면 → N.τ 반환 (완료)
  3. 아니면 인접 정점 w ∉ N.π 각각으로 확장:
       π' = N.π ⊕ w
       τ' = PathOptimize(π')       ← ★ 경로-조건부 볼록계획 풀기
       N' = (π', w, τ', c(τ'), c(τ')+ε·h(π'))
  4. 상한 가지치기: N'.f ≥ c_ub 이면 버림 (c_ub = 현재 최선 incumbent 비용)
  5. 지배 검사(δ): S(w) 의 어떤 채택 노드가 N' 을 지배하면 버림
  6. 살아남으면 OPEN·S(w) 에 삽입

        ┌─ OPEN (min-heap on f) ─┐
        │  N1(f=3.2) N2(f=3.5) …  │
        └───────────┬─────────────┘
                    │ pop min f
                    ▼
              N.v == v_g ?  ──yes──▶  return N.τ  (ε-최적)
                    │ no
                    ▼  각 인접 w ∉ N.π
        π' = N.π ⊕ w  →  τ' = PathOptimize(π')  (볼록계획, Drake+Mosek)
                    │
       상한가지치기 (f ≥ c_ub?)  →  버림
                    │
       지배검사 δ (S(w) 내 노드가 N' 지배?) → 버림
                    │ 통과
                    ▼
             OPEN ← N',   S(w) ← S(w) ∪ {N'}

상한 가지치기(Upper-Bound Pruning): incumbent 궤적 비용 c_ub 로 f ≥ c_ub 노드를 잘라낸다. 초기 incumbent τ_ub 는 보조 정점-인덱스 탐색(빠르지만 준최적)으로 미리 하나 얻어 둔다 — 좋은 상한이 있어야 가지치기가 강하게 작동한다.

정리 2 (ε-최적성 보장): 허용가능(admissible) 휴리스틱 h, 유효한 incumbent 쌍 (c_ub, τ_ub), 안전한 지배검사 하에서 알고리즘은 ε-최적 궤적을 반환한다. 특히 ε = 1 이면 비용-최적(정확 최적) 이다. 이것이 샘플링 기반(ST-RRT*는 점근적 최적, T-PRM은 무보장)과의 결정적 차별점 — 탐색이 유한 종료하며 최적성 보장을 갖는다.

3.6 지배 검사 (Dominance Checks) — 탐색을 실용화하는 열쇠

경로-인덱스 탐색은 원리상 지수적(단순경로 수)이다. 이를 실용화하는 것이 지배 검사 — "이미 더 나은(또는 최소한 대등한) 노드가 같은 정점에 있으면 새 노드를 버린다". 논문은 안전성-공격성 트레이드오프가 다른 세 가지를 제시한다.

먼저 전방 도달 원뿔(forward reachable cone) 을 정의한다. 상태 x = (p,t) 에서 속도한계 v_lim 로 앞으로 갈 수 있는 시공간 영역:

C(x) = { z ∈ ℝ^(m+1) |  z.t ≥ x.t,  -v_lim(z.t−x.t) ⪯ z.p−x.p ⪯ v_lim(z.t−x.t) }

즉 시간이 흐를수록 벌어지는 시공간 원뿔이다. "N'이 N을 지배한다"는 것은 대략 N'의 도달 원뿔이 N의 도달 원뿔을 덮는다(N이 갈 수 있는 곳은 N'도 간다) 는 뜻.

(1) δset (안전 집합-포함 검사): 노드 N이 u에서 v로 도달할 때의 도달집합 R_N = X_u ∩ X_v ∩ {x | x.t ≥ N.x.t} 의 모든 상태에 대해:

N' 이 N 을 지배  ⟺  ∀ x ∈ R_N,  C(x) ⊆ C(N'.x)

보조정리 3이 이 검사가 최적성을 보존함을 증명한다 — N-일관 궤적이 쓸 수 있는 어떤 상태든 N'이 도달함을 인증하므로 N을 안전히 버릴 수 있다.

(2) δstate (휴리스틱 도착-상태 검사): δset의 근사 — 증인 상태(witness state) 하나만 검사한다.

C(N.x) ⊆ C(N'.x)   (도착 상태 N.x 하나만 비교)

빠르지만 N.x가 단일 증인이라 휴리스틱적(가능 도착상태 전체가 아님).

(3) δpos (휴리스틱 위치기반 검사): 접두경로를 표본 공간위치에서 비교. X_v 내 표본 p 에 대해 J_p(N'.π) ≤ J_p(N.π) 인지 본다. 가장 공격적으로 가지치기하나 최적성 보장을 잃는다.

공격성 / 속도:    δset  <  δstate  <  δpos
최적성 보장:      δset(안전) | δstate(준-안전) | δpos(무보장, 최고속)

실험(§8.2.2): δset은 최적성 손실 없이 상당한 속도향상, δstate·δpos는 추가 속도향상을 주나 incumbent(준최적) 해를 반환할 수 있다.

3.7 허용가능 휴리스틱 (Admissible Heuristics)

모든 휴리스틱은 목표에서 0(h(⟨v_g⟩)=0)이며 접두경로 N.π 에서 목표까지 남은 최적비용의 하한(lower bound) 이다(A* 허용성).

h_mot (운동-전용):   속도한계 외 모든 제약 완화. 접두 인터페이스 I_N 에서
                     목표 p_g 까지 v_lim 만으로 가는 최소시간.  (가장 느슨)

h_tri (삼중항 완화): 말단집합 X_{N.v} 내부의 집합소속·운동 제약은 유지하되
                     집합 간 연속성 완화 → 독립 최적화.

h_tab (인터페이스-집합 비용표): 오프라인 사전계산 표. 인터페이스집합→말단집합
                     최소통과시간 저장. 온라인에서 목표위치를
                     ρ(Y,p_g)=min_{x∈Y}‖(p_g−x.p) ⊘ v_lim‖_∞ 로 반영.

h_max = max(h_mot, h_tri, h_tab)   ← 셋의 최댓값 (하한 중 가장 강한 안내)

실험(§8.2.1): h_max가 런타임에서 다른 셋을 지배하면서도 해 품질을 유지한다. 세 하한의 최댓값이 여전히 허용가능하면서 가장 타이트한 안내를 주기 때문이다.

3.8 정확 볼록분해 (Exact Convex Decomposition, ECD)

C3(동적·다중로봇 통일) 의 핵심 장치. 궤적 τ를 시간에 따라 진화하는 공간 점유로 보고, 그 시공간 스윕 볼륨 S(τ) ⊂ ℝ^(m+1) 를 기존 볼록집합에서 정확히 도려낸다. 도려낸 뒤에도 남은 영역이 볼록집합들로 유지되도록 세분(subdivide)한다. 이로써 "동적 장애물과 로봇 간 상호작용의 통일 처리(unified treatment)" 가 가능해진다.

3.9 다중로봇: 우선순위 계획 + PBS (Multi-Robot Planning)

C4(지수결합) 회피의 핵심. 결합 상태공간을 피하고 로봇을 순차·우선순위로 배치한다.

우선순위 계획(Prioritized Planning, PP):

for i in 1..N (우선순위 순):
    로봇 i 를 현재 ST-GCS 상에서 BFS 솔버로 계획      # 앞 로봇들은 이미 예약됨
    S(τ_i) = 로봇 i 궤적의 시공간 스윕 계산
    ST-GCS ← ECD(ST-GCS, S(τ_i))                    # ★ 궤적 예약 → 다음 로봇엔 정적 장애물

이 순차화가 다중로봇 상호작용을 후속 쿼리의 정적 장애물로 바꿔 결합 폭발을 피한다.

우선순위 기반 탐색(Priority-Based Search, PBS): PP는 고정 우선순위라 좁은 병목에서 실패(교착)할 수 있다. PBS는 우선순위 순서(constraint ordering) 자체를 탐색한다.

코드 근거 (mrmp/pbs.py): PBS가 우선순위를 방향그래프(DiGraph)로 들고, 충돌 시 분기한다.

class Node:
    def __init__(self, dg: nx.DiGraph):
        self.dg = dg            # 우선순위 부분순서 (i<j 간선 = i가 j보다 높음)
        self.sols = []          # 각 로봇의 현재 해

    def update_plans(self, parent, stgcs, idx, robot_radius, ...):
        # idx 및 그 하위(우선순위 낮은) 로봇만 재계획 (위상정렬 순)
        for j in nx.topological_sort(self.dg.subgraph(replan_list)):
            high_priority = list(self.dg.predecessors(j))
            if replan:
                stgcs_reserved = stgcs.copy()
                for k in high_priority:
                    stgcs_reserved = ecd_reserve(stgcs_reserved, self.sols[k].trajectory, 2*robot_radius)  # ★ 상위 로봇 궤적 ECD 예약
                sol = stgcs_reserved.solve(starts[j], goals[j], t0s[j], relaxation=True, ...)
                if not sol.is_success: return False
                self.sols[j] = sol

    def find_first_conflict(self, num_agents, robot_radius, tmin, tmax):
        for i, j in combinations(range(num_agents), 2):
            if collision_checking(self.sols[i].trajectory, self.sols[j].trajectory, ...):
                return i, j            # 첫 충돌쌍 반환 → 분기
        return None, None

    stgcs = STGCS.from_env(env=env, t0=0, tmax=tmax, vlimit=vlimit)
    ...
    Stack = [(None, root, None)]           # 깊이우선 스택(분기 트리)
    while Stack != []:
        parent, node, j = Stack.pop()
        if j is not None and not node.update_plans(parent, stgcs, j, ...):
            continue                        # 재계획 실패 → 이 분기 폐기
        i, j = node.find_first_conflict(...)
        if (i, j) == (None, None): return node.sols   # 충돌 없음 → 해
        for (a, b) in [(j, i), (i, j)]:     # 두 우선순위 방향으로 분기
            child = node.get_child(a, b)    # a<b 간선 추가 (DAG 유지 시)
            if child: Stack.append((node, child, b))
  • 분기 규칙: 첫 충돌쌍 (i,j) 에 대해 i<j 와 j<i 두 우선순위를 각각 시도(자식 노드) — CBS의 제약분기를 우선순위 분기로 바꾼 형태.
  • 부분 재계획: 우선순위가 바뀐 로봇과 그 하위만 재계획(replan_list), 상위는 그대로 → 효율적.
  • ECD 예약: 상위 로봇 궤적을 2*robot_radius 안전반경으로 도려낸 ST-GCS에서 하위 로봇을 계획.
  • 노드 순서 규칙(§7 Algorithm 3): 충돌 수·경로 길이·도착 시간을 종합해 우선순위를 휴리스틱 배정 → 확장 노드 수·런타임 감소(§8.2.3).

윈도우 조정(Windowed Coordination): 대규모(수십~100대)에서, 시간창이 겹치는 로봇만 조정 대상으로 좁힌다. 충돌이 집중된 구간으로 동적 윈도우를 조정해 결합 오버헤드를 크게 줄인다(§8.2.4) — 이것이 100대 규모를 분 단위로 푸는 열쇠다.

3.10 알고리즘 복잡도 (Complexity)

경로-조건부 볼록계획(각 노드):
  - 연속변수 수: 2m·l   (l개 집합의 진입/이탈 상태)
  - 볼록 원뿔계획 → 다항시간. Mosek이 m+1=3(2D+시간)을 효율 처리.

탐색 공간:
  - 그래프 G 상 모든 단순경로 → 최악 |V|에 지수적.
  - 상한 가지치기 + 지배검사(δ) 가 실제 탐색노드를 크게 축소.
  - 경로 길이는 합리적 볼록분해에서 통상 O(|V|).

MRMP:
  - 순차(PP): N개 독립 ST-GCS 쿼리 (로봇당 1회).
  - PBS: 우선순위 순서 트리 탐색 → 최악 지수적.
  - 윈도우 조정: 시간중첩 로봇쌍만 → 고차원 결합탐색 가지치기.

핵심 직관: 거대 MICP의 이진변수 지수 폭발을, 각 노드에서 작은 연속 볼록계획만 풀고 그래프 탐색이 조합을 담당하도록 분해했다. 지배검사·가지치기·휴리스틱이 지수 탐색을 실용 시간으로 눌러 준다.

        │
        ▼

데이터 흐름의 핵심: 공간분해(오프라인) → 시간압출(정점) → ECD(동적/타로봇 예약) → 경로-인덱스 탐색(단일로봇 최적) → 우선순위+PBS(다중로봇). ECD가 [2]와 [6]에서 동일하게 재사용되는 점이 "동적장애물 = 타로봇궤적"이라는 통일 표현의 구조적 증거다 — 코드에서도 from_env의 obs.reserve와 PBS의 ecd_reserve가 같은 mrmp/ecd.py:reserve를 부른다.

설계 미학 — "조합은 탐색이, 연속은 볼록계획이": 원래 GCS는 조합(어느 집합순서)과 연속(집합내 상태)을 하나의 MICP에 섞었다. ST-GCS는 이를 분리 — 조합은 경로-인덱스 그래프 탐색이, 연속은 경로-조건부 볼록계획이 담당한다. 이 분리가 좁은 통로에서의 확장성과 ε-최적성을 동시에 준다.

  • 샘플링 기반 대비 좁은 통로 우위: ST-RRT*·T-PRM은 좁은 시공간 회랑에서 유효 표본 부족으로 저조, ST-GCS는 볼록분해 구조를 활용해 5–50배 빠름.

6. 핵심 기여점 (Key Contributions)

  1. 시공간 볼록집합 그래프(ST-GCS). 공간 GCS를 시간축으로 압출해 시공간 볼록집합을 정의하고, 그 위에서 시간-최적 계획을 정식화. 코드(time_extruded, L2NormCost(Δt))가 정확히 이 압출·시간비용을 구현.

  2. 경로-인덱스 최선우선 탐색 + ε-최적성. GCS의 비최적 부분구조(C1)를 정면 돌파 — 노드를 접두경로로 인덱싱하고, 보조정리 1(재방문 배제)로 단순경로에 제한, 정리 2로 ε-최적성(ε=1이면 정확 최적) 을 증명. 하나의 거대 MICP를 작은 경로-조건부 볼록계획들의 그래프 탐색으로 분해.

  3. 안전·휴리스틱 지배검사 계열. 전방 도달원뿔 기반 δset(안전, 최적성 보존) 과 근사 δstate/δpos(공격적, 고속)로 지수 탐색을 실용화. 안전성 증명(보조정리 3) 포함.

  4. 정확 볼록분해(ECD)로 통일 표현. 궤적 스윕을 볼록집합에서 정확히 도려내 동적 장애물과 타 로봇 궤적을 하나의 메커니즘으로 처리. 코드에서 from_env와 PBS가 동일 ecd.reserve를 공유.

  5. 대규모 MRMP. 우선순위 계획 + PBS + 윈도우 조정으로 최대 100대를 수 분 내(100대 밀집 1.60분, 50대 병목 1.64분)에 해결.

  6. 완전 공개 오픈소스(검증됨). Drake+Mosek 기반 Python 구현, 세 환경·다수 로봇 데모·베이스라인(ST-RRT*, T-PRM) 포함(GPL-3.0). 코퍼스 다수 Planner 논문이 코드 미공개/예정인 것과 대조적으로 즉시 재현 가능.

7.3 구현상의 미묘함

  • 시간비용의 명시성: time_cost = L2NormCost(A_dt, 0) — 목적함수가 문자 그대로 시간 변위. solve()가 sol.cost = sol.itvl.duration으로 재확정. 시간-최적임을 코드가 이중 보증.
  • 속도한계의 볼록 인코딩: A_vmax/A_vmin이 -v_lim·Δt ⪯ Δp ⪯ v_lim·Δt를 두 반평면으로 표현 — 비볼록 없이 순수 선형제약이라 원뿔계획으로 다항시간 해결.
  • source/target 하이퍼 정점: build_source_vertex/build_target_vertex가 시작·(목표,tmax) 상태를 포함하는 정점을 동적으로 붙였다 떼며(solve 끝에서 remove_vertex) 원 그래프를 오염 없이 유지.
  • ECD의 AABB 1차 필터: 비싼 slice 전에 축정렬 경계상자 겹침(AABB)으로 후보 정점을 걸러 연산 절약.
  • relaxation vs optimal: 기본은 볼록완화+확률적 라운딩(빠름). relaxation=False면 정확 최단경로(느리지만 최적). ε-최적성은 후자 경로에 대응.
  • PBS 부분 재계획: 우선순위 변경 로봇과 그 하위만(nx.topological_sort(subgraph)) 재계획해 매 분기 비용을 억제.

7.4 실배치 관점의 관찰

  • 2D 시뮬 중심: 코드·실험이 2D(및 3D 그리기 지원)에 집중. 논문은 m+1=3(2D+시간)을 Mosek이 효율 처리한다고 명시하나, 고차원(3D 공간+시간=4D) 대규모 실험이나 실로봇 하드웨어 검증은 본 원고 범위에 두드러지지 않는다 — IROS 데모(iros_formation, iros_rearrange)가 있으나 물리 로봇 상세는 제한적.
  • Mosek 라이선스 의존: 기본 솔버가 상용 Mosek — 완전 오픈 재현엔 Mosek 학술 라이선스 또는 Drake-Gurodi 빌드 필요(순수 무료 스택은 추가 작업).

8. 고급 주제 (Advanced Topics)

8.1 확장성 (Scalability)

  • 단일로봇: 탐색 공간은 최악 |V|에 지수적이나, 상한 가지치기+지배검사가 실제 확장 노드를 크게 줄인다. 경로 길이는 합리적 볼록분해에서 O(|V|).
  • 다중로봇: 결합 공간을 피하는 순차화가 핵심. 100대 밀집 1.60분은 윈도우 조정 — 시간중첩 로봇만 결합 — 덕이다. 윈도우 없이는 결합 오버헤드가 로봇 수에 급증한다(§8.2.4 소거가 이를 증명).
  • 볼록집합 수 의존: ECD가 궤적을 도려낼수록 정점이 세분·증가한다. 로봇이 많아질수록 n_edges가 커지고(코드가 n_edges로 scaler를 키움) 각 쿼리가 무거워진다 — 이것이 확장의 실질 병목.

8.2 한계점 (Limitations)

  • (L1) 조각별 선형 궤적: 각 집합을 균일속도 직선으로 통과 → 동역학(가속도·저크·비홀로노믹) 미고려. 실 로봇의 관성·조향 제약이 있는 경우 후처리 평활화나 고차 GCS 확장이 필요. 논문의 "시간-최적"은 속도한계 하 기구학적(kinematic) 최적이지 동역학 최적이 아니다.
  • (L2) 2D 중심·실로봇 미검증: 실험이 2D 시뮬 중심. 고차원·물리 로봇 전이는 열린 문제.
  • (L3) MICP 대비 5–15% 품질 격차(완화 시): 기본 relaxation=True(라운딩)는 정확 최적이 아니라 5–15% 이내 준최적. 정확 최적(relaxation=False)은 느려진다 — 속도-최적성 트레이드오프.
  • (L4) 우선순위 계획의 불완전성: PP/PBS는 근본적으로 우선순위 기반이라 완전성(completeness)을 보장하지 않는다 — 어떤 좁은 병목은 어떤 우선순위로도 못 풀 수 있다(CBS의 완전성과 대비). 논문도 PBS가 CBS보다 빠르나 이론적 완전성은 다르다는 계보 위에 있다.
  • (L5) 볼록분해 품질 의존: 성능이 IRIS 등 공간 볼록분해 품질에 좌우. 분해가 파편적이면 그래프가 커지고 느려진다.
  • (L6) Mosek 의존: 완전 무료 재현에 상용 솔버 라이선스 부담.

8.3 향후 방향

  • 동역학(고차 GCS: 가속도·저크 제약, Bezier/다항 궤적) 통합으로 실 로봇 실행 가능성 강화.
  • 3D 공간(4D 시공간) 대규모·물리 로봇(드론 스웜, AGV 창고) 실증.
  • 우선순위 기반의 불완전성 보완 — CBS 계열과의 하이브리드(경계 있는 최적/완전성).
  • ECD 세분으로 인한 정점 증가 억제(병합·근사 볼록분해).
  • 온라인/재계획 설정(동적 장애물 실시간 관측 → 증분 ECD).

8.5 이론적 위치짓기

ST-GCS는 두 계보의 교차점이다: (i) GCS(Marcucci et al.) — 볼록최적화로 모션 플래닝을 푸는 흐름, (ii) 탐색 기반 다중로봇(MAPF/CBS/PBS) — 우선순위·충돌기반으로 결합 폭발을 피하는 흐름. 원래 GCS가 조합+연속을 하나의 MICP로 섞은 반면, ST-GCS는 "조합은 그래프 탐색이, 연속은 볼록계획이" 로 분리하고, 그 위에 시간축(시공간) 과 다중로봇(PBS+ECD) 을 얹었다. 특히 ECD가 "동적 장애물 = 타 로봇 궤적"이라는 통일 표현을 코드 수준에서 실현한 점이 개념적으로 우아하다.

9.2 장단점 분석

ST-GCS의 강점:

  1. 최적성 보장(ε-최적) — 셋 중 어느 것도 갖지 못한 특성. Enhanced Tube-RRT*는 RRT*의 점근적 최적성 + QP 국소최적이고, Visual-RRT·NeuPAN은 각각 국소탐색·학습으로 최적성 무보장이다. ST-GCS는 정리 2로 ε-최적(ε=1이면 정확 최적) 을 증명 — 좁은 통로에서 MICP 60–80% 대비 100% 성공은 이 보장의 실증이다.

  2. 시간을 1급 시민으로(시공간) — Visual-RRT는 정지 목표(시간 없음), Enhanced Tube-RRT*는 궤적 시간을 다루나 단일 시스템, NeuPAN은 반응형 실시간 회피다. ST-GCS만이 시공간 볼록집합으로 동적 장애물·타 로봇을 계획 단계에서 시공간 영역으로 미리 예약(ECD)한다 — 반응형이 아닌 계획적(proactive) 시공간 조정.

  3. 진짜 다중로봇 확장(100대) — Enhanced Tube-RRT*의 "다중 UAV"는 케이블로 묶인 하나의 강결합 시스템이고, Visual-RRT·NeuPAN은 단일 로봇이다. ST-GCS는 독립 100대를 PP+PBS+윈도우로 분 단위 조정 — MRMP 규모가 질적으로 다르다.

  4. 동적/타로봇 통일 표현(ECD) — 셋 모두에 없는, "이동장애물 = 타로봇궤적 = 시공간 스윕"의 단일 메커니즘.

ST-GCS의 약점:

  1. 동역학 미고려 — NeuPAN은 비홀로노믹 로봇의 실시간 제어까지 엔드-투-엔드로 다루고 다수 실로봇에서 검증했다. Enhanced Tube-RRT*는 QP 단계에서 케이블 장력·페이로드 동역학을 명시 제약으로 넣는다. ST-GCS는 조각별 선형·속도한계만 — 관성·조향·저크가 없어 실 로봇 실행엔 후처리가 필요.

  2. 실로봇 검증 부족 — NeuPAN이 모래상자·복도·주차장 등 다플랫폼 실증인 데 반해, ST-GCS는 2D 시뮬 중심.

  3. 우선순위 기반 불완전성 — MRMP가 우선순위 계획이라 완전성 무보장(CBS 대비). 어떤 병목은 못 풀 수 있다.

  4. 준최적(완화 시)·Mosek 의존 — 기본 라운딩은 5–15% 준최적, 정확 최적은 느림. 상용 솔버 의존.

9.3 실적용 가능성 평가

  • ST-GCS: 다수 로봇의 시공간 조정(창고 AGV, 교차로, 드론 스웜) 에 개념적으로 가장 강하다 — 시간을 1급으로 다루고 100대까지 확장. 단 (a) 동역학 후처리, (b) 실로봇 전이, (c) Mosek/Gurobi 라이선스, (d) 온라인 재계획 통합이 실배치 전제. 계획 계층(누가 언제 어디를 통과)엔 즉시 유용, 실행 계층(어떻게 부드럽게)엔 보완 필요.
  • Enhanced Tube-RRT*: 케이블-페이로드 협력 운반이라는 특정 강결합 시스템에 특화 — 범용 다중로봇엔 부적합하나 해당 도메인엔 동역학까지 포함.
  • Visual-RRT: 목표가 이미지로만 주어지는 특수 설정 — 데모 모방·생성목표에 유용하나 다중로봇·동적·시간엔 비대상.
  • NeuPAN: 지도없는 단일로봇 실시간 항법에 가장 실배치 성숙(다수 실로봇). 다만 다중로봇 계획적 시공간 조정은 비대상.

9.4 연구 방향성 평가

ST-GCS는 모션 플래닝의 무게중심을 "샘플링/학습 → 볼록최적화의 그래프 탐색 분해" 로, 그리고 "공간 → 시공간" 으로 옮긴다. 이는 세 비교 논문과 직교한다:

  • Enhanced Tube-RRT*(샘플링+QP)·Visual-RRT(샘플링+렌더)와는 샘플링 vs 볼록탐색 축에서 대립 — ST-GCS의 ε-최적·좁은통로 우위 vs 저들의 유연한 조향(임의 목표 표현·동역학).
  • NeuPAN(학습 E2E)과는 계획적 vs 반응형 축에서 상보 — ST-GCS의 시공간 계획을 상위층에, NeuPAN류 학습 제어를 하위 실행층에 얹는 계획-실행 이층 구조가 자연스러운 결합.

가장 유망한 융합: ST-GCS의 시공간 그래프 탐색(상위, ε-최적 다중로봇 조정) + 고차 GCS 또는 학습 제어(하위, 동역학 실행) — 계획적 최적성과 동역학 실행성을 동시에.

9.5 일반화 가능성

ST-GCS의 "시간압출 + 경로-인덱스 탐색 + ECD 예약" 레시피는 2D 항법에 국한되지 않는다. 어떤 볼록분해 가능 상태공간 + 시간 — 관절공간(매니퓰레이터의 시공간 회피), 3D 드론 스웜, 다차선 교통 — 에 이식 가능한 일반 패턴이다. 특히 ECD의 "궤적 = 시공간 스윕을 도려냄" 은 예약 기반 다중에이전트 조정 전반(시간창 예약, 활주로 스케줄링)에 재사용 가능한 원리다.

11. 결론 (Conclusion)

혁신성

ST-GCS의 핵심 혁신은 볼록집합 그래프(GCS)를 시간축으로 확장하고, 시간-최적 계획을 하나의 거대 MICP가 아니라 경로-인덱스 최선우선 탐색으로 분해한 것이다. GCS의 비최적 부분구조(부분경로 최적성 부재)를 접두경로 인덱싱으로 정면 돌파하고, 보조정리 1(재방문 배제)로 단순경로에 제한하며, 정리 2로 ε-최적성(ε=1이면 정확 최적) 을 증명한다. 전방 도달원뿔 기반 지배검사(안전 δset·고속 δstate/δpos)가 지수 탐색을 실용화하고, 정확 볼록분해(ECD)가 동적 장애물과 타 로봇 궤적을 하나의 시공간 스윕 예약으로 통일한다.

실용적 의의

이 통일 위에서 ST-GCS는 단일로봇 시공간 계획에서 MICP 60–80% 대비 100% 성공, MICP 대비 자릿수 빠른 속도에 5–15% 이내 품질, 샘플링 기반 대비 좁은 통로에서 5–50배 가속을 달성한다. 다중로봇에서는 우선순위 계획+PBS+윈도우 조정으로 최대 100대를 수 분(100대 밀집 1.60분, 50대 병목 1.64분)에 조정한다. 그리고 Drake+Mosek 기반 완전 오픈소스(세 환경·다수 로봇·ST-RRT*/T-PRM 베이스라인 포함, GPL-3.0)로 재현성이 코퍼스 Planner 논문 중 최상위 축이다.

향후 연구 방향

한계는 (i) 조각별 선형·속도한계만의 동역학 미고려, (ii) 2D 시뮬 중심·실로봇 미검증, (iii) 우선순위 기반의 불완전성, (iv) 완화 시 준최적·Mosek 의존, (v) ECD 세분에 따른 그래프 폭발에 있다. 따라서 고차 GCS(가속도·저크 제약)로 동역학 통합, 3D·물리 로봇 실증, CBS 하이브리드로 완전성 보완, 하위 학습 제어(NeuPAN류)와의 계획-실행 이층 결합이 자연스러운 다음 단계다.

종합 평가

ST-GCS는 "GCS를 시간으로 확장하면 무엇이 가능한가"라는 질문에, 경로-인덱스 탐색(ε-최적)·정확 볼록분해(통일 예약)·우선순위 다중로봇(100대 확장) 이라는 정연한 답을 내놓는다. 원래 GCS가 조합과 연속을 하나의 MICP에 섞어 좁은 통로에서 무너졌던 지점을, "조합은 그래프 탐색이, 연속은 볼록계획이" 로 분리해 100% 성공·자릿수 가속으로 돌파한 것이 본질적 기여다. 코퍼스 내 다른 Planner 논문들이 샘플링(Enhanced Tube-RRT*·Visual-RRT)이나 학습(NeuPAN)으로 유연한 조향·동역학·실로봇을 강점으로 갖는 반면, ST-GCS는 최적성 보장·시공간 1급 표현·대규모 다중로봇 조정이라는 상보적 축에서 독보적이다. 남은 빈칸 — 동역학과 실 로봇 전이 — 이 후속 연구의 명확한 표적이며, 그 위에 학습 제어를 얹는 계획-실행 이층 구조가 이 방법을 실배치로 잇는 가장 유망한 다리다. 완전 공개된 Drake 기반 구현은 이 모든 후속 연구를 즉시 재현·확장 가능하게 만든다.

본 리뷰는 PhD 수준 상세 분석이며, 논문 본문(arXiv HTML 2607.00444)의 수식·정리·실험 서술과 공개 코드(github.com/reso1/stgcs: mrmp/stgcs.py, mrmp/ecd.py, mrmp/pbs.py)의 실제 구현에 기반한다. 명시한 실험 수치(100%/60–80% 성공, 5–15% 품질, 5–50× 가속, 100대 1.60분/50대 1.64분)는 모두 논문 HTML에서 확인한 값이며, 표 셀 단위로 완전 추출되지 않은 환경별 개별 런타임은 논문이 명시한 범위·경향으로 서술했다(임의 수치 날조 없음).
