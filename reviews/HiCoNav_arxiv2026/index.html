1.2 연구 목표 (Research Objective)

HiCo-Nav는 Vision-and-Language Navigation(VLN) 시스템을 실세계 리소스 제한 로봇 플랫폼에 배포 가능하도록 만드는 것을 목표로 한다. 핵심 문제는 다음과 같다:

현재 VLN 시스템의 근본적 딜레마: 강력한 추론 능력(Strong Reasoning) vs. 실시간 실행 가능성(Real-Time Deployability) 사이의 트레이드오프

  • 경량 시스템 (VLFM, ApexNav 계열): 내장형 하드웨어에서 실시간 동작 가능하지만, 복잡한 자연어 지시 이해 및 장거리 의사결정 능력 부족
  • 고성능 시스템 (SG-Nav, UniGoal 계열): VLM/LLM을 매 스텝마다 호출하여 우수한 추론 능력을 보이지만, 스텝당 1~2초 이상 소요되어 실시간 로봇 제어 불가

HiCo-Nav는 이 딜레마를 계층적 비동기 아키텍처로 해결한다. 인지(Cognition)를 세 계층으로 분리하여 고빈도 반응적 제어와 심층 VLM 추론을 동시에 실현한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 멀티스케일 내비게이션 지능의 요구사항

실세계 VLN 로봇은 다음을 동시에 수행해야 한다:

[인지 스케일의 계층적 요구]

고빈도 계층 (10+ Hz):
├── LiDAR 기반 실시간 SLAM (위치 추정)
├── YOLO-World 객체 탐지
├── 장애물 회피 및 로컬 경로 계획
└── 모터 제어 명령 실행

중간 계층 (1~2Hz):
├── 인지 메모리 그래프(CMG) 업데이트
├── 프론티어 탐색 후보 점수 계산
└── 글로벌 탐색 순서 최적화

저빈도 계층 (0.1~0.5Hz):
├── VLM/LLM 기반 고수준 추론
├── 목표 객체 위치 추정
└── 자연어 지시 해석 및 서브태스크 분해

기존 시스템은 이 세 계층을 순차적(blocking)으로 처리하므로, 고빈도 반응성과 VLM 추론 중 하나를 포기해야 했다.

B. Greedy 탐색 전략의 한계

기존 프론티어 기반 탐색 전략은 매 스텝에서 가장 유망한 방향을 선택하는 greedy 전략을 사용한다. 이 방식의 문제점:

Greedy 탐색의 실패 패턴:
────────────────────────────────────────────

시나리오: 두 유망한 프론티어 A(높은 점수)와 B(중간 점수)가 반대 방향에 위치

Greedy:
Step 1: A 방향으로 이동 → A 탐색 완료 (목표 없음)
Step 2: B 방향으로 이동 → 왕복 이동 비용 발생
총 이동 거리 = d(start→A) + d(A→B)

최적 전략:
Step 1: B 방향으로 이동 (A 방향으로 이미 부분 탐색)
Step 2: 경로 최적화 → A 방향 계속 탐색
총 이동 거리 = d(start→B→A) (최적 경로)

이 문제는 탐색 순서 전체를 글로벌하게 최적화하는 Weighted Traveling Repairman Problem(WTRP) 공식화로 해결된다.

C. 리소스 제한 하드웨어에서의 배포 제약

논문에서 사용한 실세계 배포 플랫폼:

  • 플랫폼: Unitree 사족보행 로봇
  • 컴퓨팅: Jetson Orin NX (내장형 GPU)
  • 센서: Mid-360 LiDAR + RealSense D455 RGB-D 카메라
  • 추론: 온라인 Qwen3-Omni API 호출 (VLM 추론 오프로딩)

기존 SG-Nav(5.69초/스텝)나 UniGoal(2.98초/스텝)은 이 플랫폼에서 실시간 동작 불가능하다.

2.2 핵심 해결책

HiCo-Nav의 3단계 해결 전략:

해결책 1: 계층적 비동기 시스템 아키텍처
→ 인지/메모리/추론 계층을 분리하여 동시 병행 실행

해결책 2: 인지 메모리 그래프 (Cognitive Memory Graph, CMG)
→ 시각 앵커 + 객체 노드의 이분 그래프로 환경 표현
→ 최소 집합 커버 ILP로 컴팩트한 메모리 유지

해결책 3: Weighted Traveling Repairman Problem (WTRP) 공식화
→ 프론티어 탐색 순서를 글로벌 최적화 문제로 공식화
→ 기대 발견 시간 최소화 목표

3. 핵심 방법론 (Core Methods)

3.1 계층적 비동기 시스템 아키텍처 (Hierarchical Asynchronous Architecture)

HiCo-Nav의 핵심은 세 계층의 비동기 병행 처리 구조이다:

┌─────────────────────────────────────────────────────────────────┐
│                HiCo-Nav 시스템 아키텍처                           │
├───────────────┬─────────────────┬───────────────────────────────┤
│  Layer 1:     │  Layer 2:       │  Layer 3:                     │
│  Perception-  │  Memory         │  Reasoning                    │
│  Action       │  Construction   │  (VLM-based)                  │
│               │                 │                               │
│  10+ Hz       │  1~2 Hz         │  0.1~0.5 Hz                   │
│               │                 │                               │
│ ▸ FAST-LIO2   │ ▸ CMG 구성       │ ▸ Qwen3-Omni API 호출         │
│   (LiDAR SLAM)│ ▸ YOLO-World     │ ▸ 서브그래프 VLM 추론          │
│ ▸ YOLO-World  │   탐지 연동      │ ▸ 목표 위치 추정               │
│ ▸ Mobile-SAM  │ ▸ ILP 최적화     │ ▸ 지시문 분해                  │
│ ▸ A* 경로계획 │ ▸ WTRP 풀이      │                               │
│ ▸ 속도 명령   │                 │                               │
└───────────────┴─────────────────┴───────────────────────────────┘
         ↑                ↑                    ↑
    공유 전역 상태를 통한 비동기 통신 (Asynchronous Communication)

비동기 통신 메커니즘:

  • 각 계층은 독립적인 스레드에서 실행
  • Shared Global State: CMG, 프론티어 맵, 목표 추정 상태
  • Layer 1은 항상 최신 목표 위치를 참조하여 이동
  • Layer 3의 VLM 추론이 진행 중에도 Layer 1은 중단 없이 동작

구체적 구현:

# 비동기 시스템 구조 (의사코드)
class HiCoNav:
    def __init__(self):
        self.cmg = CognitiveMemoryGraph()
        self.shared_state = SharedGlobalState()
        
        # Layer 1: 10Hz 지각-행동 루프
        Thread(target=self.perception_action_loop).start()
        
        # Layer 2: 1-2Hz 메모리 구성 루프
        Thread(target=self.memory_construction_loop).start()
        
        # Layer 3: 비동기 VLM 추론 루프
        Thread(target=self.reasoning_loop).start()
    
    def perception_action_loop(self):
        while True:
            obs = self.get_observation()  # LiDAR + RGB-D
            self.cmg.update_objects(obs)  # 실시간 객체 검출
            goal = self.shared_state.current_goal
            self.execute_motion(goal)     # 중단 없는 이동
            time.sleep(0.1)  # 10Hz
    
    def reasoning_loop(self):
        while True:
            subgraphs = self.cmg.decompose()
            for sg in subgraphs:
                result = self.vlm_query(sg, self.instruction)
                if result.target_found:
                    self.shared_state.update_goal(result.location)
                    break

3.2 인지 메모리 그래프 (Cognitive Memory Graph, CMG)

CMG는 환경 정보를 구조화된 이분 그래프로 인코딩하는 핵심 메모리 표현이다.

그래프 정의:

CMG G = (V_a, V_o, E)

V_a: 시각 앵커(Visual Anchor) 집합
     - 각 앵커 a_i = {keyframe image, camera pose}
     - 환경의 "사진" 역할

V_o: 객체 노드(Object Node) 집합
     - 각 객체 o_j = {P_j (3D point cloud), f_j (CLIP feature)}
     - 탐지된 모든 시맨틱 객체 표현

E: 관찰 관계 엣지
   - (a_i, o_j) ∈ E: 앵커 a_i에서 객체 o_j가 관찰됨

앵커 선택 조건 (식 2):

앵커 선택 트리거:
(i)  새 객체 탐지됨: ∃ new object
(ii) 로봇 이동량 초과:
     ‖Δt‖ > δ_d  OR  Δθ > δ_θ

여기서:
- Δt: 마지막 앵커 대비 이동 거리
- Δθ: 마지막 앵커 대비 회전각
- δ_d = 0.5m (실험값), δ_θ = 30° (실험값)

객체 노드 표현:

# 객체 노드 구조
class ObjectNode:
    P_j: np.ndarray    # 3D 포인트 클라우드 (depth + pose)
    f_j: np.ndarray    # CLIP 특징 벡터 (512차원)
    
    def compute_similarity(self, other):
        # 기하학적 유사도 (3D IoU)
        s_g = compute_3d_iou(self.P_j, other.P_j)
        
        # 시맨틱 유사도 (CLIP 코사인 유사도)
        s_s = cosine_similarity(self.f_j, other.f_j)
        
        # 가중 결합 (식 4)
        return λ₁ * s_g + λ₂ * s_s

# 새 객체 병합 또는 신규 생성
def update_graph(self, new_object):
    best_match = max(existing_objects, key=new_object.compute_similarity)
    if best_match.similarity > threshold:
        best_match.merge(new_object)  # 기존 노드 업데이트
    else:
        graph.add_node(new_object)    # 새 노드 추가

그래프 최적화 (Memory Compaction):

CMG의 시각 앵커 수가 증가하면 VLM 입력이 과도해진다. 논문은 이를 Weighted Set Multicover Problem으로 공식화하여 최소 앵커 집합을 선택한다:

최적화 목표 (식 5-7):
────────────────────────────────────────────

최소화: Σ c_i * x_i
         a_i ∈ V_a

조건: Σ x_i ≥ r_j, ∀ o_j ∈ V_o
      a_i: (a_i, o_j) ∈ E

여기서:
x_i ∈ {0, 1}: 앵커 a_i 선택 여부 (이진 결정 변수)
c_i: 앵커 비용 (기본값=1, 품질 인코딩 가능)
r_j = min(r, |{a_i | (a_i, o_j) ∈ E}|): 객체 o_j의 최소 관찰 횟수

해법: Integer Linear Programming (ILP)
결과: 최소 앵커 집합으로 시맨틱 완전성 보장

이 공식화는 단순 휴리스틱 필터링 대비 명시적 시맨틱 커버리지 보장이 가능하다는 장점이 있다.

3.3 VLM 기반 심층 추론 모듈 (Deep Reasoning Module)

3.3.1 서브그래프 분해 (Subgraph Decomposition)

CMG를 VLM에 직접 입력할 수 없으므로, 우선순위 기반 서브그래프로 분해한다:

분해 과정:
────────────────────────────────────────────

1단계: 지시문 분해 (VLM 1회 호출)
   지시문 T → 목표 객체 집합 O_t + 관련 객체 집합 O_r
   예) "침실을 찾아가라" → O_t={침대}, O_r={베개, 협탁, 램프}

2단계: 우선순위 서브그래프 구성
   - 목표 객체 o_t ∈ O_t에 대해: G_t = (V_a_t, V_o_t, E_t)
     V_a_t = {a_i | (a_i, o_t) ∈ E}  ← o_t를 관찰한 앵커들
     V_o_t = {o_j | ∃a_i ∈ V_a_t, (a_i, o_j) ∈ E}  ← 동반 관찰 객체들

3단계: 나머지 서브그래프 우선순위 스코어
   S(G_k) = Σ s(o_i, T)          (식 11)
             o_i ∈ V_o_k
   s(o_i, T) = CLIP similarity(o_i, T)

처리 순서: G_t (목표 포함) → G_r (관련 포함) → 우선순위순 나머지

3.3.2 VLM 추론 루프

# VLM 추론 루프 (의사코드)
def reasoning_loop(instruction):
    subgraphs = cmg.decompose_by_priority(instruction)
    
    for sg in subgraphs:
        # Qwen3-Omni API 구조화 프롬프트 호출
        prompt = f"""
        Task: {instruction}
        
        Visual Anchors: [anchor images from subgraph]
        Scene Context: [object nodes with labels]
        
        Please:
        1. Determine if the target is visible in any anchor
        2. If found, identify the anchor and locate via bounding box
        3. Provide reasoning evidence
        """
        
        result = qwen3_omni_api(prompt, sg.images)
        
        if result.target_visible:
            target_location = result.bounding_box
            shared_state.update_goal(target_location)
            return  # 목표 발견 시 즉시 중단

# 추론은 별도 스레드에서 연속 실행 (Layer 1 차단 없음)

핵심 차별점: 기존 시스템은 매 스텝마다 VLM을 수동적으로(reactively) 호출하지만, HiCo-Nav는 CMG 메모리를 능동적으로(proactively) 쿼리하며 연속 추론한다.

3.4 Context-Aware 프론티어 탐색 (Context-Aware Frontier Exploration)

3.4.1 프론티어 유틸리티 추정

각 프론티어 f_i의 유틸리티 S(f_i)는 두 가지 상보적 정보원의 가중 합으로 계산된다 (식 12):

S(f_i) = λ₁ · S_struct(f_i) + λ₂ · S_vis(f_i)

S_struct: 탐색된 영역 내부의 구조적-시맨틱 신호
S_vis:    프론티어 너머 시각적 증거 (경계 밖)

구조적-시맨틱 점수 S_struct (식 13-15):

각 객체 o_j의 공간적 영향을 가우시안 함수로 모델링한다:

φ_j(p) = s̃_j · exp(-‖p - p_j‖² / 2σ_j²)

여기서:
s̃_j = s_j              (일반 객체)
s̃_j = γ · s_j > s_j   (관련 객체 o_j ∈ O_r인 경우, γ > 1 부스팅)
s_j  = CLIP similarity(o_j, T)   (태스크와의 시맨틱 유사도)
σ_j  = 객체 3D 바운딩박스 평균 크기 (공간 영향 반경)

S_struct(f_i) = Σ s̃_j · φ_j(p_i)
                o_j ∈ V_o

경계 밖 시각적 증거 S_vis (식 16):

프론티어는 미탐색 영역이지만, 해당 경계를 관찰한 시각 앵커의 이미지에는 경계 너머 정보가 부분적으로 포함되어 있다:

S_vis(f_i) = CLIP similarity(a_i, T)

여기서 a_i는 프론티어 f_i를 최초 관찰한 시각 앵커

3.4.2 Weighted Traveling Repairman Problem (WTRP)

WTRP는 가중 순서로 장소를 방문하는 문제로, 기대 발견 시간 최소화 목표를 가진다:

문제 정의:
F = {f_1, f_2, ..., f_n}: 후보 프론티어 집합
π = (π_0, π_1, ..., π_n): 방문 순서 (π_0: 현재 로봇 위치)

누적 이동 비용 (식 17):
C_i(π) = Σ M_{π_{j-1}, π_j}  (j=1 to i)

최적화 목표 (식 18):
min_π Σ W_{π_i} · C_i(π)
       i=1

여기서 W_{π_i}: 프론티어 π_i의 중요도 가중치

가중치 계산 (식 19):

# 지수적 재가중화 (온도 파라미터 β로 선명도 조절)
def compute_weight(utility_score, beta=3.0):
    normalized = (utility_score - min_score) / (max_score - min_score)
    return exp(beta * normalized) / exp(beta)

# β가 클수록 고유틸리티 프론티어 강조
# β가 작을수록 균형적 탐색

이동 비용 모델링 (식 20-24):

M_{k_r, k_s} = max{d(p_{k_r}, p_{k_s}) / v_max, |ξ_{k_r} - ξ_{k_s}| / ξ̇_max}

여기서:
d(·): 두 위치 간 유클리드 거리
v_max: 최대 선속도
ξ̇_max: 최대 각속도

현재 위치 → 후보 k 이동 비용 (추가 항):
M_{0,k} = t(0,k) + w_c · c_c(k) + w_f · c_s(k)

c_c(k) = cos⁻¹((p_k - p_0)⊤ v_0 / ‖...‖): 방향 일관성 페널티
c_s(k) = h_k / h_max: 미탐색 구역 크기 항 (작을수록 먼저 처리 권장)

WTRP 최적화는 LKH(Lin-Kernighan-Helsgott) 휴리스틱 솔버로 해결하여 효율적 방문 순서를 계산한다.

5.2 평가 지표 (Evaluation Metrics)

SR (Success Rate) = N_success / N_total

SPL (Success weighted by Path Length) = 
  1/N_total * Σ S_i * l_i^s / max(l_i^s, l_i^a)

S_i ∈ {0,1}: 에피소드 성공 여부
l_i^s: 최단 경로 거리
l_i^a: 실제 이동 경로 길이

SPL은 성공률과 경로 효율성을 동시에 측정 (높을수록 최단 경로에 가까운 성공)

6. 핵심 기여점 (Key Contributions)

6.1 계층적 비동기 시스템 아키텍처

기여 내용: VLN 시스템을 인지(10Hz), 메모리(1-2Hz), 추론(0.1-0.5Hz) 세 계층으로 분리하여 비동기 병행 실행 실현

왜 중요한가: 기존 시스템은 VLM 추론이 완료될 때까지 로봇이 대기해야 했다. HiCo-Nav는 추론 중에도 지각-행동 루프가 계속 실행되어 Stop-and-Go 현상 없이 연속 이동 가능.

기술적 혁신: 공유 전역 상태(Shared Global State)를 통한 비동기 계층 간 통신 설계. Layer 1은 항상 최신 목표 정보를 참조하지만, VLM 추론 결과가 업데이트될 때까지 기존 목표로 이동 계속.

6.2 인지 메모리 그래프 (CMG) 설계

기여 내용: 시각 앵커와 객체 노드의 이분 그래프 구조로 환경 정보를 컴팩트하게 인코딩

왜 중요한가: 기존 SG-Nav 방식의 3D 씬 그래프는 매 스텝마다 전체 그래프를 처리해야 하지만, CMG는 서브그래프 분해로 필요한 정보만 VLM에 제공.

기술적 혁신: ILP 기반 최소 집합 커버로 앵커 수 최소화하면서 시맨틱 완전성 보장. 단순 임계값 필터링 대비 명시적 최적화 보장.

6.3 WTRP 기반 글로벌 탐색 전략

기여 내용: 프론티어 탐색 문제를 Weighted Traveling Repairman Problem으로 공식화

왜 중요한가: 기존 greedy 전략은 최고 유틸리티 프론티어만 선택하여 비효율적 왕복 이동이 발생. WTRP는 이동 비용과 목표 발견 확률을 동시에 고려한 글로벌 최적 방문 순서 계산.

기술적 혁신: 목표 발견 기대 시간(Expected Time-to-Discovery) 최소화를 명시적 목표로 설정. LKH 솔버를 활용한 실시간 WTRP 해결.

6.4 실세계 로봇 배포 검증

기여 내용: Unitree 사족보행 로봇에서 음성 명령 기반 객체 탐색 성공

왜 중요한가: 대부분의 VLN 논문이 시뮬레이션에서만 검증되는 반면, HiCo-Nav는 실제 하드웨어 제약(Jetson Orin NX)에서 실시간 동작 입증.

8. 고급 주제 (Advanced Topics)

8.1 ILP 기반 메모리 압축의 이론적 토대

CMG 최적화의 Weighted Set Multicover Problem은 NP-hard이지만, 실제 CMG 크기(수십~수백 앵커)에서는 ILP가 실용적 시간 내에 해결된다. GUROBI 또는 CBC 솔버를 활용할 수 있으며, 근사 알고리즘도 사용 가능하다.

Weighted Set Multicover:
- 집합 S = V_a (앵커 집합)
- 원소 집합 U = V_o (객체 집합)
- 각 앵커 a_i가 커버하는 객체 집합 N(a_i)
- 목표: 최소 비용으로 모든 객체를 r회 이상 커버

근사 비율: O(log n) (greedy 근사)
실제 구현: ILP (최적해 보장)

8.2 WTRP와 TSP(Traveling Salesman Problem)의 관계

WTRP는 TSP의 가중 변형이다:

  • TSP: 모든 도시 방문 최소 비용 경로
  • TRP(Traveling Repairman Problem): 각 도시의 대기 시간(누적 이동 비용) 최소화
  • WTRP: TRP에 가중치 추가 → 중요 프론티어 우선 방문

내비게이션 맥락에서 WTRP의 해석:

  • 프론티어 가중치 W_i ∝ 목표 포함 확률
  • 비용 C_i(π) ∝ i번째 프론티어까지의 이동 시간
  • 목표: 기대 발견 시간 E[T_discover] 최소화

8.3 한계점 (Limitations)

  1. 다층 환경 처리 불가: 2D 탐색 맵 기반 → 다른 층(floor)의 목표 탐색 실패 (MP3D에서 13.9%, HM3D에서 18.5%가 이 경우)

  2. 소형 객체 탐지 제한: 로봇 진동으로 인한 이미지 블러, 소형 객체 3D 재구성 정밀도 부족 (소형 객체 성공률 65%)

  3. VLM API 의존성: 실세계 배포에서 Qwen3-Omni API 사용 → WiFi 연결 필요, 레이턴시 의존. 오프라인 또는 에지 배포에 제한.

  4. 최대 스텝 제한: 200 스텝으로 대형 환경에서 탐색 불완전 (MP3D 15.0%, HM3D 10.1% 실패 원인)

  5. 정적 환경 가정: 동적 장애물 처리 없음 (로컬 플래너 수준의 장애물 회피만 존재)

8.4 향후 연구 방향

  • 수직 탐색: 엘리베이터 사용 또는 3D 탐색 그래프로 다층 환경 처리
  • 에지 VLM: 경량 VLM(Qwen3-VL-1.5B 등) 온보드 배포
  • 동적 환경 적응: 이동 장애물 추적 + CMG 동적 업데이트
  • 멀티모달 언어 지시: 이미지+텍스트 복합 목표 처리

WMNav와의 상세 비교:

WMNav는 World Model을 통해 VLM의 예측을 내비게이션에 활용한다. HiCo-Nav가 WMNav를 능가하는 이유:

  1. 탐색 전략: WMNav는 greedy 프론티어 선택 → HiCo-Nav는 WTRP 글로벌 최적화
  2. 메모리 표현: WMNav는 Curiosity Value Map(2D 점수 맵) → HiCo-Nav는 CMG(3D 구조화된 그래프)
  3. 추론 효율: WMNav는 매 스텝 VLM 호출 → HiCo-Nav는 비동기 연속 추론

LiveVLN과의 상세 비교:

LiveVLN은 VLN의 Stop-and-Go 문제를 비동기 실행으로 해결한다. HiCo-Nav와 유사한 문제 인식이지만 접근법 차이:

  • LiveVLN: Training-Free, 기존 VLN 모델(NaviDa 등)을 런타임 계층에서 비동기화 → 모델 자체는 그대로
  • HiCo-Nav: 시스템 전체를 계층적으로 재설계 + CMG 메모리 + WTRP 탐색 통합 설계

HiCo-Nav가 더 포괄적인 시스템 설계이며, 시뮬레이션 벤치마크(Habitat)에서 검증된 반면 LiveVLN은 실세계 중심.

9.2 장단점 분석 (Pros and Cons)

장점:

  1. 실시간 배포 가능성: 기존 High-추론 시스템 중 유일하게 실시간 성능 달성
  2. 시뮬레이션-실세계 갭 최소화: 동일 아키텍처를 시뮬레이션과 실세계 모두에서 검증
  3. 확장 가능한 메모리: ILP 기반 메모리 압축으로 장시간 탐색에도 메모리 폭발 없음
  4. WTRP 기반 글로벌 최적화: 기대 발견 시간 직접 최소화

단점:

  1. VLM API 의존성: 오프라인 환경에서는 경량 모델 사용 필요 (성능 저하)
  2. 2D 맵 한계: 다층 건물 처리 불가
  3. 소형 객체 약점: 65% 성공률 → 실용적 응용에 제한
  4. ILP 계산 비용: 대규모 환경에서 최적화 시간 증가 가능성

11. 결론 (Conclusion)

HiCo-Nav는 VLN 시스템의 실세계 배포 가능성과 고수준 추론 능력의 딜레마를 계층적 비동기 아키텍처로 해결한 주목할 만한 연구이다.

혁신성 평가:

  • 인지 메모리 그래프(CMG)의 이분 그래프 표현과 ILP 기반 메모리 압축은 새로운 기여
  • WTRP를 VLN 탐색 문제에 적용한 것은 독창적
  • 비동기 3계층 시스템 아키텍처는 LiveVLN과 유사한 문제 의식 공유하나 더 포괄적

실용적 의의:

  • Unitree 사족보행 로봇에서 음성 명령 기반 실시간 객체 탐색 입증
  • 기존 High-추론 시스템 대비 26.5배(vs SG-Nav) 빠른 실행 속도
  • Jetson Orin NX 지원으로 저비용 하드웨어 배포 가능성 제시

향후 연구 방향:

  • 다층 건물 처리를 위한 3D 탐색 그래프 통합
  • 경량 온보드 VLM으로 API 의존성 제거
  • 동적 환경(이동 장애물)에 대한 CMG 실시간 업데이트
  • 실외 환경(GPS 활용)으로의 확장

현재 VLN 연구가 시뮬레이션 벤치마크 성능 경쟁에서 실세계 배포 가능성으로 패러다임이 전환되는 시점에서, HiCo-Nav는 이 방향을 선도하는 참조 아키텍처로서 중요한 의미를 가진다.

부록 A: CMG 수학적 상세 분석 (Appendix A: CMG Mathematical Details)

A.1 ILP 공식화의 완전 전개

Weighted Set Multicover Problem (WSMP)의 정확한 공식화:

[WSMP 정수 선형 프로그래밍 전개]

결정 변수:
  x_i ∈ {0,1}: 앵커 v_a^i가 활성화 앵커 집합 A에 포함되는지 여부

목적함수:
  최소화: Σ_i w_i * x_i   (선택된 앵커들의 총 가중치)

제약조건:
  (1) 포함 제약 (Coverage): 모든 객체 노드 v_o^j에 대해,
      Σ_{i: (v_a^i, v_o^j) ∈ E} x_i ≥ 1
      ← 모든 객체는 최소 1개의 활성 앵커에서 커버되어야 함

  (2) 기수 제약 (Cardinality): Σ_i x_i ≤ K
      ← 활성 앵커 수가 최대 K를 초과할 수 없음

  (3) 이진 제약 (Binary): x_i ∈ {0,1}

완화 버전 (LP relaxation):
  x_i ∈ [0,1] (연속 변수로 완화)
  → 근사 알고리즘 가능 (ln(n)+1 approximation ratio)

HiCo-Nav에서의 실제 구현:
  - Python-MIP 라이브러리 사용
  - CBC (Coin-or Branch and Cut) 솔버 활용
  - 일반적으로 <500ms 이내 해 도출

A.2 WTRP 수학적 배경

Weighted Traveling Repairman Problem (WTRP)의 이론적 배경:

[WTRP와 고전 TSP의 비교]

고전 TSP (Traveling Salesman Problem):
  목표: 최단 순회 경로 (총 이동 거리 최소화)
  성격: NP-hard, 2-approximation 알고리즘 존재

WTRP (Weighted Traveling Repairman Problem):
  목표: Σ_j p_j * t(visit j) 최소화 (기대 탐색 완료 시간)
  특징: 탐색 성공 확률을 "수리 필요도"로 모델링
  복잡도: TSP보다 어려운 NP-hard (Σ-P^2 완전)
  HiCo-Nav 근사: 탐욕적 휴리스틱 + 국소 교환 (O(n²))

핵심 차이:
  TSP는 "모든 노드 방문" 최적화 → 거리 중심
  WTRP는 "높은 확률 노드 우선" 최적화 → 기대 시간 중심
  
  → HiCo-Nav에서 목표 객체의 사전 분포를 활용한
    탐색 순서 최적화에 자연스럽게 부합
