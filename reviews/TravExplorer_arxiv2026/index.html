1.2 연구 목표 (Research Objective)

TravExplorer는 Zero-shot Object Navigation(ZSON) 문제를 다층(multi-floor) 실내 환경으로 확장하는 크로스 플로어 구현화 탐색 프레임워크다. 기존 대부분의 ZSON 시스템이 단층(single-floor) 평면 내비게이션을 가정하는 데 반해, 실제 건물은 계단, 층계참, 수직 중첩 공간 등을 포함한 복잡한 3차원 구조를 갖는다.

핵심 연구 질문:

"사전 지도 없이 미지의 다층 건물 환경에서,
 자연어(카테고리) 목표를 가진 사족 보행 로봇이
 어떻게 Zero-shot으로 목표 물체를 탐색할 수 있는가?"

이 문제를 해결하기 위해 TravExplorer는 세 가지 핵심 모듈을 통합한다:

  1. 3차원 통과 가능성 매핑(Traversability Mapping): 로봇이 실제로 이동할 수 있는 표면(바닥, 계단, 층계참)을 점유 공간과 분리
  2. 시야각 인식 능동 지각(FOV-Aware Active Perception): 계단 횡단 시 발생하는 사각지대를 자동으로 처리
  3. 계층적 계획(Hierarchical Planning): 목표 물체 가설, 탐색 프런티어, 계단 랜드마크를 통합한 우선순위 기반 탐색 순서 결정

실증 결과: HM3D+MP3D 4,195 에피소드 시뮬레이션에서 SOTA, Unitree Go2 실세계 50회 실험에서 64.0% 성공률 달성.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 2D 내비게이션의 구조적 한계

기존 ZSON 시스템의 대표적인 방법들(ESC, L3MVN, VLFM, SG-Nav, ApexNav)은 모두 단층 평면 그리드 맵이나 2D 시맨틱 맵을 기반으로 한다. 이 접근법은 단층 환경에서 잘 동작하지만, 다층 환경에서 다음과 같은 구조적 실패를 일으킨다:

[2D 내비게이션의 다층 환경 실패 모드]

실패 유형 1: 계단 표현 불가
  2D 점유 맵: 계단 → 장애물로 표현됨
  결과: 로봇이 계단에 근접 불가 → 다른 층 탐색 원천 차단

실패 유형 2: 수직 중첩 공간 충돌
  2D 투영: 층계참 + 아래층 바닥 → 동일 위치에 겹침
  결과: 빈 공간이 장애물로 잘못 표시 → 탐색 경로 차단

실패 유형 3: 프런티어의 3D 연결성 미확인
  2D 프런티어: 탐색 방향 제시는 하지만 3D 실현 가능성 미검사
  결과: 로봇이 도달 불가능한 가상의 프런티어를 향해 이동 시도

실패 유형 4: 계단 하강 시 사각지대 (blind spot)
  카메라 시야: 전방 고정 → 계단 첫 단이 보이지 않음
  결과: 계단 구조 미파악 → 3D 맵의 계단 연결성 누락

B. Zero-shot 크로스 플로어 내비게이션의 복잡성

난이도 요인 단층 ZSON 크로스 플로어 ZSON
탐색 공간 차원 2D (x, y) 3D (x, y, z)
이동 타입 평면 이동 평면 + 수직 횡단
지도 표현 평면 그리드 체적 복셀
목표 위치 불확실성 단층 내 어딘가 임의의 층
탐색 전략 프런티어 탐색 층별 순서 결정 포함
사각지대 처리 전방/측방만 위/아래 포함

C. 사족보행 로봇의 계단 이동 제약

일반 바퀴형 로봇과 달리 사족보행 로봇(예: Unitree Go2)은 계단 이동이 가능하다. 그러나 이는 추가적인 계획 복잡성을 야기한다:

[사족보행 로봇 계단 이동의 특수 제약]

기하학적 제약:
  - 발디딤 최소 면적: 계단 깊이 > 발 크기
  - 수직 장애물 한계: 계단 높이 ≤ 로봇 다리 길이/2
  - 경사도 한계: 최대 허용 경사도

동역학적 제약:
  - 계단 이동 시 속도 제한: v_max = 1.0 m/s (평지) → 감속
  - 균형 유지를 위한 가속도 제한: a_max = 0.25 m/s²

지각 제약:
  - LiDAR의 계단 스캔 음영(shadow): 계단 앞면 미스캔
  - RGB-D의 사각지대: 고정 시야각으로 계단 첫 단 미관측

2.2 핵심 해결책

TravExplorer의 4대 해결 원리:

[TravExplorer 설계 원리]

원리 1 — 통과 가능성 분리 (Traversability Decoupling):
  기존: 복셀 = 빈(free) | 점유(occupied)
  TravExplorer: 복셀 = 빈(free) | 점유(occupied) | 통과가능(traversable)
  효과: 계단·층계참이 장애물이 아닌 이동 표면으로 표현됨

원리 2 — 이중 레이어 매핑 (Dual-Layer Mapping):
  기하 모드: 기본 탐색 중 LiDAR 기반 점유 추적
  시맨틱 모드: 계단 감지 시 SAM3 세그멘테이션으로 전환
  효과: 계산 효율 + 계단 정확도 동시 달성

원리 3 — 능동 카메라 조정 (Active Perception):
  맹점 프런티어: 근거리 프런티어 접근 시 하향 카메라
  계단 하강 감지: 가상 지면 평면 아래 포인트 감지 시 하향
  효과: 계단 지오메트리 완전 관측 보장

원리 4 — 계층적 우선순위 계획 (Hierarchical Priority Planning):
  1순위: 목표 물체 가설 위치
  2순위: 탐색 프런티어
  3순위: 계단 랜드마크 (층간 이동 거점)
  효과: 목표 지향적 탐색 + 체계적 층간 이동

3. 핵심 방법론 (Core Methods)

3.1 적응형 통과 가능성 매핑 (Adaptive Traversability Mapping)

3.1.1 체적 맵 구조

TravExplorer는 체적 복셀 맵 V를 기반으로 동작한다. 각 복셀 v ∈ V는 다음 값을 가진다:

[복셀 상태 정의]

로그 오즈 점유 값 (log-odds occupancy):
  L(v) = log(p(v=occupied) / p(v=free))
  초기값: L(v) = 0 (불확실)
  업데이트: L(v) += l_hit or l_miss (Bayesian 갱신)

이진 점유 상태:
  O(v) = 1 if L(v) > τ_occ (점유됨)
  O(v) = 0 if L(v) < τ_free (빔)

통과 가능성 레이어:
  M_g(v): 기하학적 통과 가능성 (2D 레이캐스팅 기반)
  M_s(v): 시맨틱 통과 가능성 (SAM3 세그멘테이션 기반)

최종 통과 가능성 맵:
  M_trav = (M_g ∪ M_s) \ O_inf
  단, O_inf = 장애물 팽창(inflation)된 점유 공간

3.1.2 이중 모드 매핑

# TravExplorer 이중 모드 매핑 의사코드

class DualLayerMapper:
    def __init__(self):
        self.mode = "geometric"  # 초기 모드
        self.stair_count = 0
        self.N_enter = 5  # 시맨틱 모드 진입 임계값
        self.N_exit = 3   # 기하 모드 복귀 임계값
    
    def update(self, lidar_points, rgb_image, segmentation):
        if self.mode == "geometric":
            # 기하 모드: LiDAR 기반 빠른 점유 추적
            M_g = self.raycast_2d_traversability(lidar_points)
            
            # 계단 감지 시 모드 전환 카운터 증가
            if self.detect_stair(rgb_image):
                self.stair_count += 1
                if self.stair_count >= self.N_enter:
                    self.mode = "semantic"
                    self.stair_count = 0
            else:
                self.stair_count = 0
            
            return M_g
        
        else:  # semantic mode
            # 시맨틱 모드: SAM3 오픈-보캐뷸러리 세그멘테이션
            stair_mask = segmentation.query("staircase")
            M_s = self.project_to_voxels(stair_mask, lidar_points)
            
            # 계단 미감지 시 기하 모드 복귀
            if not self.detect_stair(rgb_image):
                self.non_stair_count += 1
                if self.non_stair_count >= self.N_exit:
                    self.mode = "geometric"
                    self.non_stair_count = 0
            
            return M_s
    
    def raycast_2d_traversability(self, points):
        """
        2D 레이캐스팅: 각 열(x, y)에 대해 최저 지지 표면 찾기
        지지 표면 = 로봇이 발을 딛을 수 있는 면
        
        - z_min: 해당 (x,y)에서 가장 낮은 점유 복셀 높이
        - 지지 표면 조건: z_min - epsilon < z < z_min + delta
        - 충분한 헤드룸: 지지 표면 위 K_h 복셀 레이어에 장애물 없음
        """
        M_g = {}
        for col in columns(points):
            z_min = min(z for (x,y,z) in col if occupied(x,y,z))
            if has_headroom(z_min, K_h):
                M_g[(x,y)] = traversable
        return M_g

3.1.3 증분식 장애물 팽창 (Incremental Obstacle Inflation)

표준 팽창 알고리즘은 맵 전체를 재처리하는 O(V) 비용이 발생한다. TravExplorer는 이방성(anisotropic) 팽창 커널과 증분식 업데이트로 이를 최적화한다:

[이방성 팽창 커널 설계]

XY 평면 팽창: 반경 r_xy (고정, 로봇 폭 기반)
Z 방향 팽창: 하향만 (downward-only), 반경 r_z

이방성 커널의 이유:
  - 위쪽 팽창이면 계단·층계참 표면 상의 로봇 발이 장애물로 잘못 표시됨
  - 아래 방향만 팽창하여 지지 표면 위의 공간을 보호

증분 업데이트:
  매 타임스텝 Δt에서 변경된 복셀만 처리:
  O_inf[t] = O_inf[t-1] ∪ inflate(ΔO_new) \ deflate(ΔO_removed)
  복잡도: O(n) where n = |변경된 복셀 수|
  (전체 재처리 O(V)에서 대폭 개선)

3.2 통과 가능한 프런티어 추출 (Traversable Frontier Extraction)

프런티어는 탐색된 공간과 미탐색 공간의 경계로, 탐색 방향을 결정하는 핵심 요소다. TravExplorer는 3D 통과 가능성 레이어에서 프런티어를 추출한다:

[TravExplorer 프런티어 추출 조건]

복셀 v가 통과 가능한 프런티어(traversable frontier)가 되는 조건:

조건 1 — 충분한 헤드룸:
  v의 위 K_h 레이어 내에 통과 가능 복셀이 없어야 함
  (바닥·계단 표면이지, 허공이 아님을 의미)

조건 2 — 경계 배치:
  v의 26-이웃(26-neighbor, 3D 인접) 중 적어도 하나가 미탐색(unknown)

조건 3 — 최소 클러스터 크기:
  프런티어 복셀들을 26-이웃 연결성으로 클러스터링
  소규모 클러스터(< 임계값 크기) 제거 → 노이즈 필터링

[증분 업데이트]
  맵 변경 시 영향받은 영역의 프런티어만 재계산:
  O(n_changed) 복잡도로 실시간성 유지

이 설계의 핵심은 "통과 가능"이라는 추가 조건이다. 기존의 2D 프런티어는 단순히 "탐색된 빈 공간과 미탐색 공간의 경계"를 의미했다. TravExplorer의 3D 프런티어는 로봇이 실제로 발을 디딜 수 있는 표면 위의 경계만 포함하므로, 도달 불가능한 허공의 프런티어가 자동으로 제거된다.

어블레이션 실험 결과:

  • 2D 프런티어만 사용 시: 크로스 플로어 성공률 0.4% (사실상 불가)
  • 3D 통과 가능 프런티어 사용 시: 48.7% 크로스 플로어 성공률

3.3 시야각 인식 능동 지각 (FOV-Aware Active Perception)

고정된 카메라 방향은 계단 환경에서 두 가지 사각지대를 생성한다. TravExplorer는 이를 자동으로 감지하고 카메라를 능동적으로 조정한다:

3.3.1 맹점 프런티어 처리 (Blind-Spot Frontier)

[맹점 프런티어 발생 원리]

카메라의 최소 관측 거리: d_blind (전방 근거리 미관측)
프런티어가 d_i < d_blind에 위치할 때:
  - 로봇이 프런티어에 근접해도 관측 불가
  - 계단 첫 단이 맹점에 들어오는 경우 발생

TravExplorer 처리:
  if d_i < d_blind:
    카메라 피치 = -α_down (하향 조정)
    → 근거리 지면/계단 관측 가능

3.3.2 계단 하강 감지 (Descent Stair Detection)

[계단 하강 사각지대 원리]

수평 고정 카메라로 하강 계단 접근 시:
  - 계단 윗 면만 보임, 아래 면/높이 미관측
  - 3D 복셀 맵에서 계단 하부 구조 누락

TravExplorer 감지 방법:
  가상 지면 평면(virtual ground plane) Π_vg 정의:
  - 현재 로봇 위치에서 수평 연장된 가상 바닥
  
  감지 조건:
  - Π_vg 아래로 N_down 개 이상의 LiDAR 포인트 관측됨
  → 로봇 전방에 하강 계단 존재 의심
  
  처리:
  if stair_descent_detected:
    카메라 피치 = -β_down (하향 조정)
    → 계단 전체 구조 관측

이 두 가지 능동 지각 메커니즘은 사전 학습 없이 순수 기하학적 규칙으로 동작하므로, 환경 일반화 능력을 유지하면서 계단 관측 완전성을 보장한다.

3.4 확률론적 인스턴스 맵 (Probabilistic Instance Map)

오픈-보캐뷸러리 세그멘테이션(SAM 3)으로 감지된 물체는 누적 증거를 통해 확률론적으로 추적된다:

[인스턴스 맵 업데이트 수식]

관측 t에서 감지된 물체 후보 집합:
  D_t = {d_1, d_2, ..., d_k} (각각 카테고리 + 3D 중심점 + 신뢰도)

기존 인스턴스 I_j와 새 감지 d_i의 연관:
  연관 조건: ||c_j - c_i||_3D < δ_asso (3D 중심점 거리 임계값)

인스턴스 J = {I_j} 두 종류:
  O_tar: 목표 물체 인스턴스 집합
  O_stair: 계단 랜드마크 인스턴스 집합

양성 증거 업데이트 (연관된 인스턴스):
  p_j ← p_j + (1 - p_j) × conf_i × w_fov
  
  단, w_fov: FOV 코사인 가중치 (정면 관측일수록 높은 가중치)
       conf_i: SAM3 신뢰도 점수

음성 증거 업데이트 (해당 위치를 지나쳤지만 미감지):
  p_j ← p_j × (1 - λ_decay) × (1 - conf_vis)
  
  단, conf_vis: 현재 시야에서 해당 인스턴스 위치 가시성

신규 인스턴스 생성:
  if no association found for d_i:
    I_new = {c = c_i, p = conf_i}
    O_tar or O_stair ← O_tar or O_stair ∪ {I_new}

3.5 공간 가치 맵 (Spatial Value Map, BLIP-2)

목표 카테고리 언어 지시를 공간적 탐색 가치로 변환한다:

[공간 가치 맵 구성]

입력: 목표 카테고리 텍스트 q (예: "chair", "sofa")
      각 타임스텝 t의 RGB 이미지 I_t

BLIP-2 이미지-텍스트 유사도:
  sim(I_t, q) = BLIP-2_score(I_t, q) ∈ [0, 1]

FOV 코사인 가중치:
  w_k = max(0, cos(θ_k)) where θ_k = 복셀 k와 카메라 광축의 각도
  (카메라 정면 방향에 가까울수록 높은 가중치)

공간 가치 업데이트:
  s_k[t+1] = s_k[t] + w_k × sim(I_t, q)  (누적 가치)
  r_k[t+1] = r_k[t] + w_k               (누적 신뢰도)

정규화된 공간 가치:
  V_k = s_k / (r_k + ε)  (평균 가치)

이 설계의 장점은 특정 물체 감지 모델 없이도 언어 조건부로 탐색 방향을 편향시킬 수 있다는 점이다. 예를 들어 "침대"를 찾을 때, 침실처럼 보이는 방향으로 탐색이 자연스럽게 유도된다.

3.6 계층적 탐색 계획 (Hierarchical Exploration Planning)

3.6.1 Open-ATSP 기반 목표-프런티어-계단 최적 방문 순서

[우선순위 체계]

렉시코그래픽(Lexicographic) 우선순위:
  P1: 목표 물체 가설 (O_tar에서 신뢰도 높은 인스턴스)
  P2: 탐색 프런티어 (미탐색 영역으로 이어지는 경계)
  P3: 계단 랜드마크 (O_stair, 층간 이동 거점)

비용 행렬 구성:
  C[i][j] = 3D 통과 가능 맵 위의 A* 경로 비용 + 인식 보너스
  
  인식 보너스:
    - 목표 물체 가설: -w_conf × p_j (신뢰도 비례 음수 비용)
    - 미탐색 정도: -w_frontier × frontier_density

LKH(Helsgott-Karp) 솔버:
  Open-ATSP(비대칭 외판원 문제) 풀이
  → 최적 방문 순서 계산
  
  Open-ATSP (vs. Closed-TSP):
    출발점 = 현재 로봇 위치
    도착점 = 임의 (귀환 없음)
    → 탐색 미션에 적합

3.6.2 발디딤 안내 3D 경로 탐색 (Foothold-Guided 3D Search)

일반 A*는 연속 공간의 최단 경로를 찾지만, 사족보행 로봇의 계단 이동에는 발디딤 가능 여부를 고려해야 한다:

[Foothold-Guided A* 설계]

이웃 공간 정의:
  표준 A*: 26-이웃 (3D 인접 복셀)
  TravExplorer: 발디딤 스케일 이웃 (foothold-scale neighborhood)
    - 사족보행 로봇의 보폭에 맞는 공간 단위로 이웃 정의
    - 각 이웃 위치에서 4발 발디딤 가능성 검사

비용 함수:
  g(v) = g(parent) + 이동 비용 + 발디딤 부적합 패널티
  h(v) = 유클리드 거리 to 목표 (admissible heuristic)

발디딤 적합성:
  foothold_ok(v) = all(p_foot in M_trav for p_foot in foothold_config(v))

3.6.3 실행-검토 루프 (Execute-Review Loop)

계획 실행 중 막힘(blockage)이 발생하면 재계획한다:

[막힘 감지 및 재계획]

정상 이동:
  실제 이동 거리 ≈ 예측 이동 거리
  → 계획 계속 실행

막힘 감지:
  실제 오도메트리 vs. 예측 포즈 비교
  if ||actual_pos - predicted_pos|| > δ_stuck:
    막힘 감지됨
    → 해당 프런티어/경로를 "차단됨"으로 표시
    → 다음 우선순위 목표로 전환

타임아웃 처리:
  if time_at_goal > T_timeout:
    → 해당 목표 인스턴스를 낮은 신뢰도로 재표시
    → 다음 목표로 전환

3.7 로컬 궤적 최적화 (Local Trajectory Optimization)

계층적 계획이 생성한 글로벌 경로를 로봇이 실행 가능한 부드러운 궤적으로 변환한다:

[큐빅 B-스플라인 궤적 최적화]

파라미터화:
  T(t) = B-spline(control_points, t) ∈ SE(3)

목적 함수:
  J_total = λ_s × J_s + λ_o × J_o + λ_f × J_f

  J_s (부드러움 비용, Smoothness):
    J_s = ∫ ||T''(t)||² dt  (가속도 최소화)

  J_o (장애물 비용, Obstacle):
    J_o = Σ max(0, r_safe - d(T(t), obstacles))²
    (안전 반경 r_safe 이내 장애물에 패널티)

  J_f (실현 가능성 비용, Feasibility):
    J_f = Σ max(0, ||v(t)|| - v_max)² + max(0, ||a(t)|| - a_max)²
    (속도·가속도 한계 초과 패널티)

  가중치: λ_s : λ_o : λ_f = 실험적으로 결정

수직 구속 기울기 투영 (Vertical-Constrained Gradient Projection):
  XY 평면 그래디언트: 표준 최적화 방향 적용
  Z 방향 그래디언트: 3D 경로 탐색이 결정한 높이 프로파일 유지
  → 계단 이동 시 Z 방향이 최적화로 인해 비현실적으로 변형되는 것 방지

6. 핵심 기여점 (Key Contributions)

기여 1: Zero-shot 크로스 플로어 ZSON의 최초 완전 실증

기존의 MFNP, ASCENT와 달리 TravExplorer는 다층 내비게이션을 단순히 시뮬레이션에 제한하지 않고 실세계 사족보행 로봇으로 50회 실험을 통해 검증했다. 특히 4개 서로 다른 환경(빌라, 아파트, 복층, 오피스)에서 64% SR을 달성한 것은 실용적 의의가 크다.

기여 2: 적응형 이중 모드 통과 가능성 매핑

기하학적 모드(속도 우선)와 시맨틱 모드(정확도 우선) 간의 자동 전환 메커니즘은 계산 효율과 계단 인식 정확도를 동시에 달성한다. 이방성 팽창 커널과 증분 업데이트의 조합으로 실시간 처리가 가능하다.

기여 3: FOV 인식 능동 지각의 규칙 기반 설계

학습 없이 순수 기하학적 규칙으로 카메라를 능동 제어하는 접근법은 새로운 환경에 즉시 적용 가능하며, 특정 로봇 플랫폼에 종속되지 않는다.

기여 4: Open-ATSP 기반 계층적 우선순위 계획

목표 물체 가설, 탐색 프런티어, 계단 랜드마크를 렉시코그래픽 우선순위로 통합하고 LKH 솔버로 최적 방문 순서를 결정하는 것은 체계적인 다층 탐색 전략의 수학적 형식화다.

기여 5: 수직 구속 로컬 궤적 최적화

표준 궤적 최적화를 그대로 적용하면 Z 방향 경로가 최적화 과정에서 왜곡된다. 수직 방향에 별도의 구속을 두어 계단 프로파일을 보존하는 것은 실세계 적용을 위한 실용적 기여다.

8. 고급 주제 (Advanced Topics)

8.1 다층 내비게이션의 계획 복잡성

단층 내비게이션은 2D 그래프에서의 최단 경로 문제로 환원되어 A* 등의 알고리즘으로 효율적으로 풀린다. 다층 내비게이션은 3D 그래프 + 수직 이동 추가로 계획 공간이 확장된다:

[계획 복잡성 비교]

단층 (N×N 그리드):
  상태 공간: O(N²)
  A* 복잡도: O(N² log N)

다층 (N×N×K 체적, K 층):
  상태 공간: O(N²K)
  3D A* 복잡도: O(N²K log(N²K))
  추가 복잡성:
    - 계단 연결성 검증: O(S)  (S = 계단 수)
    - ATSP 풀이: O(exp(L))  (L = 목표+프런티어+계단 수)
      (LKH의 경험적 성능은 훨씬 좋음)

TravExplorer는 실시간 계획을 위해 LKH의 근사 솔버를 사용하며, 이는 최적성을 약간 포기하는 대신 계산 시간을 다항식으로 제한한다.

8.2 시맨틱 오탐(False Positive)의 근본 원인

실패 분석에서 오탐이 22-26%를 차지하는 것은 오픈-보캐뷸러리 세그멘테이션(SAM3)의 한계를 반영한다:

[오탐 발생 시나리오]

시나리오 1: 시각적 유사성 오탐
  목표: "chair"
  오탐: 의자와 유사한 외관의 다른 가구 (예: 작은 테이블)
  
  원인: SAM3 + 이미지-텍스트 유사도는
        정밀한 물체 식별이 아닌 언어-시각 근사 유사도 기반

시나리오 2: 부분 관측 오탐
  목표: "bed"
  오탐: 소파의 일부가 침대로 잘못 식별
  
  원인: 제한된 시야각에서 물체 전체를 보지 못한 채 분류

시나리오 3: 인스턴스 중복
  같은 물체를 다른 각도에서 관측 → 두 개의 인스턴스로 분리
  원인: δ_asso 임계값보다 큰 시점 변화로 인한 중심점 불일치

8.3 스케일링 한계: 대규모 환경에서의 도전

빌라 환경(300 m², 2층)에서 AT = 203.0초는 다른 환경(46-102초) 대비 2-4배 길다. 이는 대규모 다층 환경에서 TravExplorer의 계획이 점차 비효율화되는 현상을 반영한다:

[대규모 환경 비효율화 원인]

원인 1: 프런티어 폭발
  환경 크기 ∝ 프런티어 수
  ATSP 풀이 시간 ∝ exp(프런티어 수)
  → 300 m² 환경에서 프런티어 수 급증

원인 2: 탐색 우회로 증가
  계단이 하나 막히면 다른 층 전체 탐색 불가
  다음 계단 탐색에 추가 이동 거리 발생

원인 3: 오탐 누적
  탐색 시간 ↑ → 방문 위치 ↑ → 오탐 누적 기회 ↑
  → 오탐 인스턴스에 시간 낭비

8.4 향후 연구 방향

[저자 제시 + 추가 제안]

저자 제시:
  - 일반 에이전트 프레임워크: 대형 VLM으로 고수준 추론/예측 통합
  - 미관측 영역 예측: 현재 관측을 기반으로 건물 구조 예측

추가 제안:

     환경 크기 추정치 기반 동적 스텝 할당

     여러 사족보행 로봇이 각 층을 분담 탐색
     (통신 대역폭 공유 비용 vs. 탐색 속도 향상)
  
  4. 온보드 컴퓨팅 강화:
     현재 마스터 의존도 감소 → 완전 자율 배포

9.1 기존 리뷰 논문과의 비교

비교 핵심 포인트:

  1. GNPFkCT vs. TravExplorer: GNPFkCT는 폐색, 위치 오차, 하이브리드 행동 공간을 다루는 POMDP 기반으로, 단일 물체 탐색의 불확실성 처리에 강점이 있다. TravExplorer는 다층 탐색이라는 구조적 문제를 해결한다. 두 방법은 상호 보완적이며, POMDP 의사결정을 TravExplorer에 통합하면 오탐 문제를 줄일 수 있을 것이다.

  2. SAGE vs. TravExplorer: SAGE는 학습 기반으로 시뮬레이션에서 얻은 추상 경험을 실세계에 전이하는 데 초점을 맞춘다. TravExplorer는 학습 없이 3D 기하학적 매핑으로 접근하여, 새로운 다층 환경에서 즉시 배포 가능하다는 장점이 있다. SAGE의 학습 기반 접근은 미래에 더 복잡한 환경(비정형 계단 등)에서 유리할 수 있다.

  3. ThreeStepNav vs. TravExplorer: ThreeStepNav는 3단계 계층 프롬프팅으로 Zero-shot VLN 지시 이해에 강점이 있지만 단층 환경에 제한된다. TravExplorer는 언어 이해보다 3D 공간 탐색에 집중한다. 장기적으로는 ThreeStepNav의 LLM 기반 의사결정과 TravExplorer의 3D 맵 구조를 통합하는 것이 이상적이다.

9.2 장단점 분석

장점 (Advantages):

1. 학습 불필요 (Training-Free):
   - 새 환경에 즉시 배포 가능
   - 도메인 격차(sim-to-real) 문제 없음
   - 소규모 팀도 즉시 활용 가능

2. 진정한 3D 내비게이션:
   - 계단, 층계참, 수직 공간 처리
   - 실제 건물 구조에 적합
   - 기존 2D ZSON과 차별화된 유일한 접근

3. 실세계 검증 충실:
   - 50회 실험, 4개 다양한 환경
   - Unitree Go2로 사족보행 이동 포함
   - 구체적 실패 모드 분석 제공

4. 모듈형 설계:
   - 각 모듈을 독립적으로 개선 가능
   - SAM3 → 더 나은 모델로 교체 가능

단점 (Disadvantages):

1. 오탐 비율 22-26%:
   - 성공률의 주요 병목
   - 오픈-보캐뷸러리 세그멘테이션 한계
   - 세밀한 인스턴스 식별 부재

2. 분산 컴퓨팅 의존:
   - RTX 4090 마스터 서버 필요
   - 완전 자율(fully autonomous) 배포 불가
   - Wi-Fi 단절 시 동작 불가

3. 대규모 환경 비효율:
   - 300 m² 환경에서 평균 203초
   - 프런티어 폭발 → ATSP 풀이 지연
   - 실용적 배포를 위한 최적화 필요

4. 계단 이동 성능 한계:
   - 크로스 플로어 성공률 48.7% (단층 74.6% 대비 낮음)
   - 계단 스텝 초과 실패 다층에서 3배 증가

9.3 실적용 가능성 평가

단기 적용 가능 시나리오:

  • 실내 건물 탐색 로봇 (사무실 청소, 물건 배달)
  • 재난 구조 로봇 (다층 건물 생존자 탐색)
  • 보안 순찰 로봇 (다층 상업 건물)

적용 제한 요소:

  • RTX 4090급 외부 서버 필요 → 온보드 컴퓨팅으로 경량화 필요
  • 비정형 계단(나선형, 경사로)에서 성능 미검증
  • 목표 물체가 숨겨진/폐색된 경우 처리 미흡

경쟁 대비 실용성:

실내 단층 배달 로봇:  기존 2D ZSON 방법이 더 성숙, 충분
실내 다층 탐색:       TravExplorer가 현재 최적 (경쟁자 없음)
실외 구조 임무:       아직 실외 확장 미검증, 주의 필요

9.4 연구 방향성 평가

TravExplorer는 기존 ZSON 연구의 자연스러운 다음 단계를 구현한다. 기존 연구들이 단층 내비게이션을 고도화하는 데 집중한 반면, TravExplorer는 "실제 건물은 여러 층으로 이루어졌다"는 간단하지만 중요한 현실을 수용하고 이를 해결한다는 점에서 연구 방향이 옳다.

그러나 학습 기반 접근(SAGE, NavOL 등)이 더 도전적인 환경(비정형 구조물, 동적 장애물)에 대한 적응성에서 장기적으로 유리할 수 있다. TravExplorer의 모듈형 구조가 학습 기반 컴포넌트와 통합되는 방향이 이상적이다.

11. 결론 (Conclusion)

혁신성 평가

TravExplorer는 ZSON 문제를 다층 환경으로 확장하는 실질적이고 실용적인 혁신을 달성했다. 기존 연구들이 단층 환경의 성능을 소수점 단위로 개선하는 데 집중하는 동안, TravExplorer는 실제 건물에서의 내비게이션이라는 더 중요한 문제를 정면으로 다루었다.

기술적 혁신의 핵심은 통과 가능성 개념의 3D 확장이다. 이는 단순한 구현 변경이 아니라, 내비게이션 맵의 기본 표현을 "점유/비점유"에서 "점유/비점유/통과가능"으로 재정의하는 개념적 전환이다.

실용적 의의

50회 실세계 실험과 64% SR은 실제 배포 가능성을 보여주는 의미 있는 결과다. 특히 Unitree Go2를 사용한 다층 건물 실험은 사족보행 로봇의 새로운 응용 가능성을 시사한다.

향후 연구 방향

  1. 온보드 컴퓨팅 경량화: 현재의 RTX 4090 의존성을 줄여 완전 자율 배포 실현
  2. LLM 통합: 대형 VLM으로 오탐 감소 및 고수준 계획 향상
  3. 멀티-로봇 확장: 층별 분담 탐색으로 대규모 건물 효율화
  4. 동적 환경: 사람이나 움직이는 물체가 있는 실제 운영 환경 대응

TravExplorer는 ZSON 연구의 다음 장을 여는 연구로 평가할 수 있으며, 다층 내비게이션이 향후 이 분야의 표준 과제가 될 것임을 시사한다.
