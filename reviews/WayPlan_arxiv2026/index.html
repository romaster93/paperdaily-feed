1.2 연구 목표 (Research Objective)

WayPlan은 밀집 장애물이 있는 환경에서 다중 로봇 시스템의 태스크-모션 계획을 공동 최적화하는 문제를 해결한다.

핵심 연구 질문: 다중 로봇 시스템에서 태스크 계획(어떤 로봇이 어떤 물체를 어디로 이동시킬 것인가)과 모션 계획(실제 경로 생성 및 충돌 회피)을 어떻게 공동 최적화할 것인가?

기존 접근법의 한계:

  1. Classical 방법 (PDDL, LTL 기반): 태스크 수준 계획은 우수하지만, 고정 모션 플래너(RRT 등)를 쌍으로 사용하여 태스크-모션 불일치 문제 발생
  2. VLA 모델 기반: 단일 로봇에서도 고차원 출력으로 RL 학습 불안정, 다중 로봇 확장 곤란
  3. LLM 단독 태스크 플래너: 모션 실현 가능성(motion feasibility) 인식 없이 계획 생성 → 실행 불가능한 계획 다수 생성

WayPlan은 이 문제를 두 LLM 기반 플래너(태스크 + 모션)의 계층적 공동 최적화로 해결한다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. 태스크-모션 불일치 (Task-Motion Mismatch)

다중 로봇 계획에서 발생하는 두 가지 유형의 실패 모드:

[실패 유형 분류]

태스크 수준 실패 (Task-Level Failure):
┌────────────────────────────────────────┐
│ 원인: 고수준 계획 자체가 내부적으로 불가능 │
│ 예시:                                  │
│  - 두 로봇에게 같은 위치 할당           │
│  - 이미 점유된 공간으로 이동 명령        │
│  - 로봇 B의 이동 완료 전에 로봇 A 사용  │
│                                        │
│ 결과: 모션 플래너가 아무리 좋아도 해결 불가 │
└────────────────────────────────────────┘

모션 수준 실패 (Motion-Level Failure):
┌────────────────────────────────────────┐
│ 원인: 태스크 계획은 유효하지만 경로 생성 실패 │
│ 예시:                                  │
│  - 장애물로 둘러싸인 경로에 RRT 막힘    │
│  - 로봇 간 충돌로 인한 이동 불가         │
│  - 키노다이나믹 제약 위반               │
│                                        │
│ 결과: 고정 모션 플래너로는 해결 불가     │
└────────────────────────────────────────┘

이 두 유형은 상호의존적이다. 태스크 계획이 실행되면서 모션 실패가 발생하면 새로운 태스크 계획이 필요하고, 태스크 계획의 품질은 모션 플래너의 능력에 따라 달라진다.

B. 모션 계획의 학습 표현 문제

로봇 모션 궤적은 고차원적이며 복잡한 제약 조건을 갖는다:

VLA 방식의 문제점:
────────────────────────────────────────

VLA 모션 플래너:
  입력: 환경 관찰 (이미지/상태)
  출력: 밀집 조인트 구성(joint configuration) 시퀀스
         예) [q1, q2, ..., q_n]^T for each time step
  
  문제:
  - 출력 차원 수 = timesteps × joints
    (예: 100 스텝 × 7 DOF = 700차원 출력)
  - RL 학습 시 고차원 출력으로 그래디언트 신호 희박
  - 단일 로봇에서도 불안정, 다중 로봇은 불가

Waypoint 방식의 이점:
────────────────────────────────────────
  입력: 로봇 로컬 환경 상태 τ_i
  출력: 웨이포인트 시퀀스 W_i = {w_1, ..., w_K}
         (K개의 3D 좌표, K << timesteps)
  
  이점:
  - 출력 차원 수 = K × 3 (예: 5 × 3 = 15차원)
  - 운동학적 실현 가능성은 RRT에 위임
  - 학습 샘플 효율 대폭 향상

C. 학습 시 크레딧 할당 모호성

태스크와 모션을 공동 최적화할 때, 실행 실패의 책임을 두 수준 중 어디에 귀속시킬 것인지가 불분명하다:

크레딧 할당 모호성:

시나리오: 로봇 A가 이동 중 장애물과 충돌
  원인 분석:
  │
  ├── 태스크 플래너 책임?
  │   └─ A에게 불가능한 경로를 요구하는 목표 할당
  │
  └── 모션 플래너 책임?
      └─ 가능한 경로가 있었지만 발견하지 못함

두 수준을 동시에 학습하면 스파스 보상 신호가
어느 플래너를 업데이트해야 할지 불명확 → 학습 불안정

2.2 핵심 해결책

WayPlan의 세 가지 핵심 해결책:

해결책 1: 웨이포인트 모션 표현
─ LLM 모션 플래너가 중간 3D 좌표(웨이포인트)만 출력
─ RRT가 웨이포인트 간 충돌 없는 실제 경로 생성 담당

해결책 2: 양방향 계층적 플래닝
─ 태스크 플래너: 멀티-스텝 고수준 조율 계획
─ 모션 플래너: 각 태스크 스텝의 로컬 이동 실현

해결책 3: 커리큘럼 3단계 훈련
─ Stage 1: SFT 워밍업 (태스크/모션 독립 초기화)
─ Stage 2: 분리 RLVR (태스크-모션 크레딧 명확화)
─ Stage 3: 결합 RLVR (태스크-모션 피드백 전파)

3.2 양방향 태스크-모션 계획 (Bi-Level Task-Motion Planning)

3.2.1 태스크 플래너 (Task Planner M_θ)

태스크 플래너는 전체 미션을 T개의 순차 스텝으로 분해한다:

태스크 계획 s = {s_1, s_2, ..., s_T}

각 스텝 s_t 형식:
  {로봇 ID → (목표위치 (x,y,z), carry_bool)}

예시 (창고 자동화 시나리오):
  s_1: {Robot3: (0.5, 1.2, 0.0), False}
       Robot3이 (0.5, 1.2, 0.0)으로 이동 (물체 없음)
  
  s_2: {Robot1: (1.73, 0.34, 0.17), True}
       Robot1이 물체를 (1.73, 0.34, 0.17)로 운반
  
  s_3: {Robot2: (2.1, 0.8, 0.0), False}
  s_3: {Robot4: (0.3, 2.5, 0.0), True}
       두 로봇 동시 실행

선택되지 않은 로봇: no-op (정지)

태스크 플래너의 역할: 글로벌 조율

  • 어떤 로봇이 어떤 물체를 담당할지 결정
  • 스텝 간 의존성 관리 (로봇 A가 먼저 경로를 비워야 로봇 B 이동 가능)
  • 장거리 로봇-로봇 충돌 회피 (global 수준)

3.2.2 모션 플래너 (Motion Planner M_φ)

모션 플래너는 각 태스크 스텝을 실제 이동으로 구현한다:

입력: (s_t, τ_i)

s_t: 태스크 스텝 (목표 위치, carry 상태)
τ_i: 로봇 i의 로컬 환경 인식
     - 주변 반경 r 내의 장애물 위치
     - 다른 로봇 위치
     - 현재 carrying 물체 정보

출력: W_i = {w_{i,1}, w_{i,2}, ..., w_{i,K}}
각 w_{i,k}: 3D 좌표 (x_k, y_k, z_k)

웨이포인트 특성:
  K = 3~8 (실험값)
  각 웨이포인트: 로봇이 경유해야 할 중간 위치
  역할: 장애물을 우회하는 경로 가이던스 제공

웨이포인트의 직관적 이해:

장애물 우회 시나리오:

시작(S) ─────── 직선경로 ─────── 목표(G)
                  │ (장애물)
                  │
웨이포인트 계획:
S → W1(장애물 왼쪽) → W2(장애물 통과 후) → G

실제 실행: RRT가 S→W1, W1→W2, W2→G 각 구간의
충돌 없는 연속 궤적 생성

3.2.3 웨이포인트와 RRT의 역할 분담

[LLM 모션 플래너의 역할]
  - 글로벌 경로 형태 결정 (어느 방향으로 우회할지)
  - 대략적인 중간 위치 지정
  - 운동학적 세부사항 불필요

[RRT의 역할]
  - 웨이포인트 간 충돌 없는 실제 경로 생성
  - 운동학적 실현 가능성 보장
  - 세밀한 충돌 검사

이 분업의 장점:
  LLM: 고차원 공간 추론 (강점) 활용
  RRT: 물리 제약 처리 (특기) 활용
  → 두 방법의 장점을 결합

3.3 BoxNet3D-OBS 벤치마크

논문은 새로운 다중 로봇 벤치마크를 제시한다:

[BoxNet3D-OBS 구성]

기반: BoxNet 스타일 환경 (Chen et al., 2024a 확장)
추가 요소: 밀집 장애물 + 도전적 모션 제약

환경 설정:
  맵 크기: 2×2 ~ 4×4 (그리드 기반)
  물체 수: 1 ~ 6개
  로봇 수: 1 ~ 9대
  장애물 수: 1 ~ 8개
  
데이터셋:
  훈련: 3,400 환경
  테스트: 480 환경
  
특징:
  - 솔버블(Solvable) 환경만 포함 (A* 검증)
  - 장애물 배치: Critical-path-aware 전략
    → 중요 경로 주변에 장애물 배치
    → 단순한 무작위 배치보다 도전적

평가 지표:
  1. Success: pass@1 (4번 시도 중 성공 비율)
  2. StepDiff: 모델 계획 스텝 수 - A* 최적 스텝 수
               (음수: 더 짧음, 양수: 더 긺)

Critical-path-aware 장애물 배치의 중요성:

무작위 배치: 장애물이 경로와 무관하게 배치 → 모션 도전 최소
Critical-path-aware:
  1. A*로 최적 태스크 계획 및 모션 경로 계산
  2. 해당 경로 주변에 우선 배치
  3. 모션-태스크 상호작용 최대화 → 더 현실적 도전

3.4 커리큘럼 3단계 훈련 전략 (Curriculum Training)

3.4.1 Stage 1: SFT 워밍업

목표: 두 플래너의 기본 능력 초기화

[태스크 플래너 SFT]
데이터 생성:
  1. A* 탐색으로 최적 태스크 계획 s* 생성
  2. GPT-5-mini로 추론 트레이스(reasoning trace) 생성
     ├── 실패-불가지론적(failure-agnostic) 방식 vs.
     └── 반성-인식(reflection-aware) 방식 [본 논문 채택]

반성-인식 프롬프팅:
  - A*가 역추적(backtrack)할 때마다 실패 정보 기록
  - [실패 액션] + [실패 이유] + [수정된 대안] → LLM 프롬프트
  - 결과: 오류를 단순 회피가 아니라 이해하는 추론 학습

예시 반성 트레이스:
  "Robot1에게 (2.3, 1.5, 0.0) 할당 시도 → 실패
   이유: Robot2가 해당 위치 점유 중
   수정: Robot1을 (2.3, 1.5, 0.0) 대신 (2.1, 1.7, 0.0)으로 재할당
   이후 Robot2가 이동한 다음 (2.3, 1.5, 0.0)으로 이동 가능"

[모션 플래너 SFT]
데이터 생성:
  1. 단일 로봇 + 랜덤 장애물 환경 샘플링
  2. BFS(너비 우선 탐색)로 웨이포인트 시퀀스 생성
  3. RRT로 실행 가능성 검증
  4. 검증된 쌍 (로컬 상태 τ_i, 웨이포인트 W_i) 수집

주의: 태스크 플래너와 달리 텍스트 추론 없음
      → 모션은 로컬, 단기, 순수 기하학적 문제

학습률:
  태스크 플래너: lr = 3×10⁻⁶
  모션 플래너: lr = 1×10⁻⁵ (더 빠른 수렴)
  옵티마이저: AdamW

3.4.2 Stage 2: 분리 RLVR

목표: 각 플래너를 독립적으로 강화학습으로 개선
      (태스크-모션 크레딧 모호성 방지)

[태스크 플래너 보상 함수]
r_task^stage-2(s) = r_success(s) + r_format(s) + r_efficiency(s, s*)

r_success(s) = 1: 충돌 없이 태스크 완료
               0: 실패
               (모션 페널티 의도적 제외!)

r_format(s) = 0.1: 요구된 출력 형식 준수

r_efficiency(s, s*) = max(0.05 × (|s*| - |s|), -0.2)
  → 최적 계획보다 짧으면 보상, 너무 길면 페널티
  → -0.2 하한으로 효율성 과도 보상 방지

핵심: 이 단계에서 모션 실현 가능성 페널티 없음
→ 태스크 플래너는 순수 태스크 수준 성능만 학습

[모션 플래너 보상 함수]
r_motion(W) = r_success(W) + r_format(W)

r_success(W) = 1: 목표 위치 도달 (거리 임계값 내)
               0: 실패

훈련: 태스크 플래너 없이 독립적 단일 로봇 환경에서만 학습

알고리즘:
  태스크 플래너: GSPO (Generalized SPPO)
  모션 플래너: GRPO (Group Relative Policy Optimization)
  배치 크기: 64 (그룹 크기 8)
  검증 주기: 10 스텝
  최종 체크포인트: 모션 ~200 스텝, 태스크 ~160 스텝

3.4.3 Stage 3: 결합 RLVR

목표: 태스크-모션 커플링 해결
      태스크 플래너가 모션 실현 가능성을 고려하도록 학습

[수정된 RLVR 알고리즘]

반복 k마다:
1. 이전 태스크 플래너 M_θ^(k-1)가 태스크 계획 s 생성
2. 현재 모션 플래너 M_φ^(k-1)로 실제 실행
3. 실행 결과 기반 태스크 플래너 업데이트:

r_task^stage-3(s) = r_success(s) + r_format(s) + r_efficiency(s, s*)
                    + r_motion_penalty(s)  ← 신규 추가

r_motion_penalty(s): 모션 실패를 유발하는 태스크 계획에 페널티
  예) 장애물로 막혀 모션 불가능한 목표 위치를 할당하면 페널티

4. 모션 플래너도 태스크 플래너가 생성한 계획의
   모션 쿼리로 학습 (실제 태스크-모션 커플링 반영)

오프-폴리시 RL:
  태스크 플래너: 2-step off-policy RL (훈련 효율 향상)
  → 1번의 태스크 계획 생성으로 2 RL 업데이트 가능

컴퓨팅: 8× NVIDIA H100 GPUs
프레임워크: VeRL (Versatile RL)

4.2 FullPlan vs. Replan 모드

[FullPlan 모드]
  초기 상태에서 전체 계획 s를 한 번에 생성
  → 장거리 의존성 추론 필요
  → 4B 모델에게 도전적인 태스크

[IC-Replan (In-Context Replanning)]
  실패 발생 시 전체 실행 히스토리를 컨텍스트에 유지하여 재계획
  → 오류 반성 가능
  → 4B 모델의 긴 컨텍스트 처리 능력 한계로 성능 제약

[NC-Replan (New-Context Replanning)]
  실패 발생 시 컨텍스트 초기화, 업데이트된 환경 상태만으로 재계획
  → 4B 모델에게 더 적합 (짧은 입력)
  → 최고 성능 달성: NC-Replan-S3 = 0.62 SR

6. 핵심 기여점 (Key Contributions)

6.1 BoxNet3D-OBS 벤치마크

기여 내용: 밀집 장애물과 최대 9대 로봇이 있는 다중 로봇 태스크-모션 계획 벤치마크

왜 중요한가: 기존 BoxNet 계열 벤치마크는 장애물 없이 로봇-로봇 충돌만 고려했다. BoxNet3D-OBS는 장애물 + 로봇-로봇 상호작용을 동시에 고려하여 더 현실적이다. Critical-path-aware 배치로 임의적 난이도 조절이 아닌 체계적 도전 환경 생성.

6.2 웨이포인트 표현

기여 내용: LLM 모션 플래너가 고차원 조인트 궤적 대신 3D 웨이포인트를 출력하는 표현 방식 제안

왜 중요한가: VLA 모션 플래너의 고차원 출력으로 인한 RL 학습 불안정 문제를 웨이포인트 추상화로 해결. 웨이포인트(15~24차원) vs VLA(700+차원)의 차원 감소 효과.

기술적 혁신: 운동학적 실현 가능성을 LLM이 아닌 RRT에 위임하는 역할 분담 설계. "글로벌 경로 추론(LLM의 강점) + 물리 제약 처리(RRT의 강점)"

6.3 커리큘럼 3단계 훈련

기여 내용: SFT 워밍업 → 분리 RLVR → 결합 RLVR의 점진적 훈련 전략

왜 중요한가: 태스크-모션 공동 최적화의 크레딧 할당 모호성 문제를 단계적으로 해결. Stage 2에서 각 플래너를 독립 훈련하여 명확한 신호를 먼저 학습한 후, Stage 3에서 피드백 전파 가능.

6.4 반성-인식 SFT 데이터 생성

기여 내용: A*의 역추적 과정에서 실패 정보를 기록하여 LLM 추론 훈련 데이터 생성

왜 중요한가: 성공 경로만 모방하는 기존 SFT 대비 실패-반성 패턴을 학습하여 일반화 능력 향상. 오류를 회피하는 것이 아닌 이해하는 추론 방식 학습.

8. 고급 주제 (Advanced Topics)

8.1 LLM 기반 로봇 계획의 이론적 고찰

WayPlan은 LLM을 로봇 계획 도구로 사용하는 새로운 패러다임을 탐구한다. 전통적 TAMP(Task and Motion Planning)와의 비교:

전통 TAMP:
  - 심볼릭 태스크 계획 (PDDL, PDDLStream)
  - 수치적 모션 계획 (RRT, PRM, CHOMP)
  - 장점: 완전성(Completeness) 이론적 보장
  - 단점: 대규모 환경, 복잡한 언어 지시에 취약

WayPlan의 위치:
  - LLM 태스크 플래너: 유연한 언어 추론, 확장 가능
  - 웨이포인트 모션: LLM의 공간 추론 + RRT의 안전성
  - 장점: 자연어 태스크 지시 처리, 이전 경험 활용 가능
  - 단점: 완전성 이론 보장 없음, 훈련 데이터 의존

RLVR의 역할:
  LLM의 언어 사전 지식 + 로봇 피드백 신호
  → 로봇 제어에 특화된 추론 능력 강화

8.2 웨이포인트 표현의 정보 이론적 분석

VLA 방식:
  출력 공간 크기: |R^(T × n_joints)|
  T = 100 timesteps, n_joints = 7
  → 700차원 연속 출력

Waypoint 방식:
  출력 공간 크기: |R^(K × 3)|
  K ≤ 8 웨이포인트, 3D 좌표
  → 최대 24차원 연속 출력

차원 감소 비율: 700/24 ≈ 29배
→ RL 샘플 효율 대폭 향상 이론적 근거
→ 실험: Waypoint(92% SR) >> VLA(35% SR) 입증

단점:
  K 웨이포인트로 표현 불가능한 복잡한 궤적 존재
  → 긴밀한 공간에서 K 개수 부족 가능성
  → K를 너무 크게 하면 학습 어려움 재발

8.3 한계점 (Limitations)

  1. 시뮬레이션 전용: BoxNet3D-OBS는 2D/3D 그리드 기반 가상 환경 → 실세계 로봇 검증 없음

  2. 단순화된 물리 모델: RRT 기반 경로 실행은 실제 로봇의 다이나믹스, 마찰, 관성 등 무시

  3. 폐쇄 환경 가정: 환경이 완전히 관찰 가능(fully observable) → 부분 관찰(partial observability) 미처리

  4. 모션 플래너 확장성: 9대 로봇에서 각 로봇이 독립적 모션 쿼리 → 로봇 수 증가 시 연산 비용 선형 증가

  5. 학습 데이터 의존성: BoxNet3D-OBS에 특화 → 다른 환경(창고, 병원 등)에 대한 일반화 검증 필요

  6. NC-Replan의 반성 부재: 새 컨텍스트로 재계획하므로 이전 실패에서 학습 불가 (IC-Replan의 장점)

8.4 향후 연구 방향

  • 실세계 검증: 실제 창고 로봇(AMR 등)에서의 WayPlan 적용
  • 부분 관찰 확장: POMDP 기반 태스크 플래닝과 통합
  • 계층적 웨이포인트: 거친 웨이포인트 → 세밀한 웨이포인트 계층 도입
  • 연속 환경: 이산 그리드에서 연속 공간으로 확장
  • 안전 보장: 형식 검증(formal verification)과 LLM 계획 결합

SANDO와의 상세 비교:

SANDO는 UAV 단일 로봇의 안전한 궤적 계획 문제를 MIQP + STSFC로 해결한다. WayPlan과 근본적으로 다른 문제 설정:

  • SANDO: 동적 장애물 있는 미지 환경, 안전 보장 핵심 → 충돌 없음 수학적 증명
  • WayPlan: 정적 장애물 있는 알려진 환경, 태스크-모션 협조 핵심 → 다중 로봇 협동 최적화

PRoID와의 상세 비교:

PRoID는 다중 로봇 탐색 릴레이 문제를 정보 전달률 예측으로 해결한다. WayPlan과의 차이:

  • PRoID: 탐색 + 통신 릴레이 최적화, 물체 이동 없음
  • WayPlan: 물체 운반 + 충돌 회피, LLM 기반 태스크 플래닝

BTIT*와의 상세 비교:

BTIT*는 MM-최적 키노다이나믹 계획으로 단일 로봇의 최적 경로를 보장한다. WayPlan과의 차이:

  • BTIT*: 최적성 보장 (이론적 증명), 단일 로봇
  • WayPlan: 최적성 보장 없음, 다중 로봇 협동 (더 복잡한 문제)

9.2 장단점 분석 (Pros and Cons)

장점:

  1. LLM 기반 언어 추론 활용: 자연어로 기술된 복잡한 태스크 목표 처리 가능. 기존 PDDL 기반 방법과 달리 사전 도메인 지식 없이도 유연한 적용

  2. 모션 인식 태스크 플래닝: 태스크와 모션을 공동 최적화하여 기존 분리된 방법 대비 일관된 성능 향상. 단 4B 모델이 100B+ 모델을 능가

  3. 웨이포인트 추상화: VLA 대비 29배 낮은 출력 차원으로 학습 안정성 확보. 92% 단일 로봇 모션 성공률

  4. 코드 공개 + 재현 가능성: CC BY 4.0 라이선스, GitHub 공개로 후속 연구 가능

  5. 확장 가능한 다중 로봇 지원: 1~9대 로봇을 단일 프레임워크로 처리

단점:

  1. 실세계 검증 부재: 시뮬레이션 전용. 실제 AMR(자율이동로봇) 창고 적용 검증 없음

  2. 낮은 절대 성공률: 최고 성능 NC-Replan-S3 = 0.62 → 여전히 38% 실패. 실용화 어려움

  3. 단순화된 물리 모델: RRT 실행 가정. 실제 로봇의 다이나믹스, 센서 노이즈 미반영

  4. 훈련 비용: 8× H100 GPUs 필요 → 소규모 연구팀 재현 어려움

  5. BoxNet3D-OBS 특화: 특정 벤치마크에 과적합 가능성

11. 결론 (Conclusion)

WayPlan은 다중 로봇 태스크-모션 계획을 LLM 기반 계층적 최적화로 해결하는 탐구적 연구이다.

혁신성 평가:

  • 웨이포인트 표현으로 VLA의 고차원 출력 문제 극복 → 구체적이고 검증된 아이디어
  • 커리큘럼 3단계 훈련으로 태스크-모션 크레딧 모호성 체계적 해결
  • BoxNet3D-OBS 벤치마크로 다중 로봇 TAMP 연구 기반 제공

실용적 의의:

  • 4B 모델 + 모션 인식 훈련이 GPT-5(추정 100B+) 능가 → 모델 크기보다 태스크 특화 훈련이 중요함 입증
  • LLM-RRT 하이브리드로 두 방법의 강점 결합 가능성 제시
  • 코드 공개로 후속 연구 기반 제공

향후 연구 방향:

  • 실세계 AMR 창고 로봇에서 검증 필요
  • 부분 관찰 및 동적 환경으로의 확장
  • 안전 보장(Safety Guarantee) 통합 (현재 없음)
  • 대규모 로봇 수(50+)로의 확장성 검증
  • 연속 공간 환경으로의 일반화

현재 Planner 연구에서 실세계 안전 보장(SANDO, BTIT*)과 대조적으로, WayPlan은 복잡한 다중 로봇 태스크 협조 문제에 LLM 추론 능력을 도입하는 새로운 방향을 제시한다. 실용화까지는 추가 연구가 필요하지만, 3세대 LLM 기반 로봇 계획의 중요한 초석으로서 의의가 있다.

부록 A: RLVR 수학적 상세 분석 (Appendix A: RLVR Mathematical Details)

A.1 GRPO 알고리즘의 완전 전개

WayPlan에서 사용된 Group Relative Policy Optimization (GRPO)의 수학적 전개:

[GRPO 목적함수 완전 전개]

PPO 기준 목적함수:
  L_PPO(θ) = E[min(r_t(θ) * A_t, clip(r_t(θ), 1-ε, 1+ε) * A_t)]
  
  where:
    r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)  (확률비)
    A_t: 어드밴티지 함수

GRPO 변형 (그룹 상대 보상):
  그룹 G = {(a_1, r_1), (a_2, r_2), ..., (a_k, r_k)} 생성
  → 동일 입력에 대해 k개 샘플 생성 (k=8)
  
  표준화 보상:
    r̂_i = (r_i - μ_G) / σ_G
    μ_G = (1/k) Σ_i r_i
    σ_G = sqrt((1/k) Σ_i (r_i - μ_G)²)
  
  GRPO 목적함수:
    L_GRPO(θ) = (1/k) Σ_i [min(ρ_i * r̂_i, clip(ρ_i, 1-ε, 1+ε) * r̂_i) - β * KL(π_θ || π_ref)]
    
    where:
      ρ_i = π_θ(a_i|s) / π_θ_old(a_i|s)
      β: KL 패널티 계수 (WayPlan: β=0.001)
      π_ref: SFT 초기화 참조 정책

GRPO의 장점:
  - Value function 불필요 (메모리/계산 효율)
  - 그룹 내 상대 비교로 보상 스케일 무관
  - 장기 언어 생성에 적합

A.2 WayPlan 보상 함수 설계 상세

[3단계 훈련에서의 보상 함수 진화]

Stage 1: SFT Warmup
  - 보상: 교사 강제 학습 (순수 모방)
  - 손실: L_CE = -Σ log π_θ(a_t^* | s, a_{<t}^*)
  - 목적: 기본 형식 학습 (JSON 형식 출력, 웨이포인트 파싱)

Stage 2a: Task Planner RLVR
  보상 R_task:
  
    (a) 형식 보상 (Format Reward):
        r_format = 1 if JSON 파싱 성공 else 0
        → 올바른 출력 형식 강제
    
    (b) 태스크 완료 보상 (Task Completion):
        r_task = SR × (1 + bonus_efficient)
        SR: 로봇들이 모든 목표 도달 성공 여부
        bonus_efficient = Σ_i 1/t_i (빠른 완료 보너스)
    
    (c) 충돌 패널티 (Collision Penalty):
        r_collision = -λ × N_collide
        λ = 0.5, N_collide: 로봇 간 충돌 수

  최종 보상: R_task = r_format × (r_task + r_collision)

Stage 2b: Motion Planner RLVR  
  보상 R_motion:
  
    (a) 웨이포인트 유효성:
        r_valid = Σ_i 1(wp_i ∈ free space) / N_wp
    
    (b) 경로 효율성:
        r_eff = d_optimal / d_actual  (이상적 경로 대비)
    
    (c) 로봇 간 분리:
        r_sep = min_ij ||wp_i - wp_j||₂ / threshold
    
  최종 보상: R_motion = α*r_valid + β*r_eff + γ*r_sep
  (α=0.5, β=0.3, γ=0.2)

Stage 3: Joint RLVR
  공동 보상: R_joint = R_task + w_motion × R_motion
  w_motion = 0.3 (모션 보상 가중치)
  → 태스크 수준 협조와 모션 수준 안전의 균형

A.3 BoxNet3D-OBS 환경 상세 사양

[BoxNet3D-OBS 벤치마크 환경 구성]

환경 타입:
  - 직육면체 박스 네트워크 구조
  - 3D 공간: 20×20×10 격자
  - 장애물: 랜덤 배치 큐보이드 (밀도 15-35%)
  
  OBS (Obstacle-dense) 변형:
    - 기본 OBS: 15% 장애물 밀도
    - OBS-Dense: 25% 장애물 밀도
    - OBS-Complex: 35% 장애물 밀도

로봇 설정:
  - 로봇 수: N=3, 5, 8 (설정별)
  - 각 로봇 반지름: 0.5 격자 단위
  - 최대 속도: 2 격자/타임스텝
  - 가시 범위: 5 격자 반경 (부분 관찰)

태스크 구성:
  - 목표 수: N (로봇당 1개 고유 목표)
  - 목표 유형: 좌표 지정, 객체 라벨, 구역 도달
  - 태스크 완료 기준: 모든 로봇이 목표 도달

평가 설정:
  Train: 3,400 환경 (랜덤 시드 1-3400)
  Test:  480 환경  (시드 3401-3880)
  → Train/Test 간 환경 완전 분리 (공정한 평가)

평가 지표 정의:
  SR (Success Rate): 모든 로봇 목표 도달 비율
  NC (Navigation Cost): 총 이동 거리 (낮을수록 우수)
  CT (Collision Count): 로봇 간 충돌 횟수
  
  NC-Replan-S3: 연속 재계획 포함한 Navigation Cost
    → 실제 사용 시나리오에 가장 가까운 지표

상세 구현 사항은 공식 코드 저장소 참조: https://github.com/UCSB-NLP-Chang/navigate-cluster
