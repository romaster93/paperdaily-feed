1.2 연구 목표 (Research Objective)

문제의식: 기존 open-vocabulary robot mapping 방법들은 RGB-D 데이터로부터 CLIP과 같은 vision-language feature를 결합해 dense geometric map을 생성하지만, 다음 두 가지 근본적인 한계가 있다:

  1. 추상적 계층 쿼리 불가: "second floor의 bedroom에 있는 chair"와 같이 object 수준을 넘어서는 계층적(hierarchical) 쿼리를 처리할 수 없다. 기존 방법들은 object-level semantics만 제공한다.

  2. 대규모 multi-floor 환경의 메모리 폭발: 모든 3D 포인트에 대해 개별적으로 open-vocabulary feature를 저장하는 방식은 large-scale, multi-story building에서 메모리 효율성이 극히 낮아 실용성이 없다. VLMaps는 HM3DSem 8개 씬에서 총 6068 MB를 소비한다.

HOV-SG의 핵심 기여: 이를 해결하기 위해 building → floor → room → object의 4단계 계층 구조를 가진 3D scene graph를 구성하며, 각 노드에 open-vocabulary CLIP feature를 부여한다. 결과적으로:

  • 복합 쿼리("find the toilet in the bathroom on floor 2") 처리 가능
  • ConceptGraphs 대비 75% 메모리 절감
  • Real-world Boston Dynamics Spot 로봇으로 대규모 multi-floor navigation 실증

2. 문제 정의: 선행 연구의 한계 (Problem Definition)

2.1 Point-wise Open-Vocabulary Map 계열의 문제점

방법 핵심 아이디어 한계
VLMaps [10] 각 3D voxel에 CLIP feature 저장 메모리 과다 (6068 MB); object 수준 쿼리만 가능
OpenScene [17] 3D point cloud에 CLIP feature 투영 Flat representation; 계층 구조 없음
ConceptFusion [13] SAM mask + multi-scale CLIP fusion Flat; object-level만 지원; 메모리 비효율
OpenMask3D Instance segmentation + CLIP Closed-set 기반; open-vocabulary 미지원

공통 병목: 모든 방법이 flat point-wise 또는 object-level representation으로 제한되어, "2층 사무실의 의자" 같은 복합 쿼리(floor + room + object)를 처리하지 못한다.

2.2 3D Scene Graph 계열의 한계

  • ConceptGraphs [14]: Open-vocabulary를 scene graph와 결합한 첫 시도이나, 소규모 씬(single-floor)에만 평가되었고, segment feature를 mean pooling으로 계산하여 semantics 희석
  • Hydra [19]: Real-time 3D scene graph 구성이 강점이나 closed-set semantics만 사용; open-vocabulary 미지원
  • SceneGraphFusion [37]: Incremental 3D SG이나 closed-set에 제한됨

HOV-SG의 포지셔닝: ConceptGraphs(open-vocabulary) + Hydra(hierarchical + multi-floor) + actionable navigation의 세 가지를 모두 결합한 유일한 방법.

2.3 VLN 패러다임과의 관계

논문의 접근 방식은 map-based navigation(offline mapping + query-time retrieval)으로, end-to-end VLN(instruction following from scratch, map 사전 구성 없음)과는 다른 paradigm이다. VLN 커뮤니티 관점에서는 HOV-SG가 "hierarchical navigation을 위한 구조화된 map representation"을 제공하는 기초 기술이며, 상위 VLN 모듈이 이를 활용해 multi-floor에서 자연어 지시를 수행하는 방향으로 확장될 수 있다.

3.2 Multi-View CLIP Feature Fusion (다중 관점 CLIP 특징 융합)

동기: 단일 2D SAM mask에 대해 CLIP embedding을 추출할 때, 배경과 전경의 문맥(context)이 최종 특징을 크게 영향한다. 기존 ConceptFusion은 masked image(배경 제거)만 사용하여 맥락 정보를 잃고, ConceptGraphs는 전체 이미지와 crop만 사용한다. HOV-SG는 세 가지를 모두 활용한다.

알고리즘 (Equation 2):

각 RGB-D 프레임의 2D SAM mask m_t에 대해:

f_i = w_g f_g + w_l f_l + w_m f_m

여기서:

  • f_g: 전체 프레임의 CLIP feature (global context, 물건이 놓인 room/space의 맥락)
  • f_l: 2D mask의 bounding box crop의 CLIP feature (local context, 배경 포함)
  • f_m: Background-removed masked image crop의 CLIP feature (mask-only, 순수 물체)
  • w_g, w_l, w_m: 학습 가능하거나 고정 가중치 (합=1)

구현 세부사항 (code_analysis.md 참조):

# /tmp/hovsg-repo/hovsg/models/sam_clip_feats_extractor.py:122-128
# Weighted sum fusion with softmax normalization
similarity = F.cosine_similarity(f_g.unsqueeze(0), f_l.unsqueeze(0))
weight_g = softmax(similarity)  # 글로벌 가중치
weight_l = 1 - weight_g        # 로컬 가중치
f_fused = weight_g * f_g + weight_l * f_l  # 적응형 융합

  • DBSCAN 없음 + M-CLIP만: mIoU 0.215
  • 모두 포함: mIoU 0.231 (최고 성능)

DBSCAN 필터링 (Equation implicit):

각 3D segment 내의 point-wise CLIP feature들에 대해 cosine distance 기반 DBSCAN clustering 적용:

\text{DBSCAN}(\{f_p : p \in \text{segment}\}, \text{metric='cosine'})

  • 목적:

    1. CLIP의 mode collapse 방지 (이상치 feature 제거)
    2. SAM의 노이즈 마스크로 인한 오류 정리
    3. Majority voting을 통한 가장 대표적 semantic 추출

  • 구현 (/tmp/hovsg-repo/hovsg/utils/graph_utils.py:386):

    def feats_denoise_dbscan(feats, eps=0.02, min_points=2):
    # feats: (N, 1024) CLIP ViT-H features
    clustering = DBSCAN(eps=eps, min_samples=min_points, 
                        metric='cosine').fit(feats)
    largest_cluster_idx = np.bincount(clustering.labels_[clustering.labels_ >= 0]).argmax()
    return feats[clustering.labels_ == largest_cluster_idx].mean(axis=0)

결과: Feature 중복 제거로 동일한 label 집합을 예측하는 overlapping segment들을 병합.

3.4 Floor Segmentation (높이 히스토그램 분석)

입력: 전체 환경의 3D point cloud \mathcal{P} = \{p_i\}

알고리즘 (Figure 3 좌측):

  1. 높이 히스토그램 생성 (Y축):

    • bin size = 0.01 m (1cm)
    • 모든 점의 Y 좌표 분포 계산

  2. 피크 탐지 (local maxima):

    • scipy.signal.find_peaks() 적용
    • 최고 intensity peak의 90% 이상인 peak만 선택
    • 최소 거리: 0.2 m

  3. DBSCAN 클러스터링 (eps=1.0):

    • 탐지된 모든 피크를 clustering
    • 각 cluster에서 가장 높은 ranked peak 선택 → floor boundary candidate

  4. Floor 범위 결정:

    • 정렬된 높이 벡터에서 연속한 두 피크 쌍이 하나의 floor (바닥 + 천장)를 표현
    Height distribution:
▲
│  ┌─ Floor 1 ceiling
│  │
├─ Floor 1 floor
│
├─ Floor 0 ceiling
│
└─ Floor 0 floor

  5. Floor 포인트 클라우드 추출: 각 floor l에 대해 y_{min}^l \leq y < y_{max}^l 범위의 점들 추출 → \mathcal{P}_l

특성:

  • 정확도 100% (HM3DSem 8개 씬 모두 floor 수 정확 예측)
  • 한계: 경사진 환경, 불균일한 바닥 높이, 다락방 같은 특수 구조에서 실패 가능

3.5 Room Segmentation (Voronoi-based Skeleton + Watershed)

입력: 각 floor의 point cloud \mathcal{P}_l

알고리즘 (Figure 3 우측, step-by-step):

Step 1: 2D Bird's-Eye View Histogram 생성
        P_l을 xz 평면(수평면)에 투영
        ↓
Step 2: Wall Skeleton Mask 추출
        BEV histogram threshold → 벽 영역만 추출
        ↓
Step 3: Euclidean Distance Field (EDF) 계산
        벽 mask를 dilate한 후 distance_transform
        ↓
Step 4: Region Seed 추출
        EDF를 threshold → isolated region seeds 획득
        ↓
Step 5: Watershed Algorithm 적용
        seeds 기반으로 2D region mask 생성
        ↓
Step 6: 3D 매핑
        2D region mask를 floor height interval 내
        3D point에 적용 → room point cloud 생성

구현 세부사항 (/tmp/hovsg-repo/hovsg/graph/graph.py:378-450):

def segment_rooms(self, floor_pcd, floor_id):
    # 1. BEV 투영 + 히스토그램
    bev_hist = self.project_to_2d_histogram(floor_pcd, grid_res=0.05)
    
    # 2. Wall skeleton 추출
    walls_skeleton = cv2.threshold(bev_hist, threshold_val, 255, 
                                   cv2.THRESH_BINARY)[1]
    
    # 3. EDF 계산
    walls_dilated = cv2.dilate(walls_skeleton, kernel, iterations=3)
    edf = cv2.distanceTransform(walls_dilated, cv2.DIST_L2, 
                                cv2.DIST_MASK_PRECISE)
    
    # 4. Watershed 적용
    region_labels = cv2.watershed(bev_hist_3channel, seeds=edf_seeds)
    
    # 5. 3D 매핑: region_labels를 floor height 내 포인트에 할당
    for region_id in range(1, max(region_labels)+1):
        room_pcd = self.extract_3d_points_for_region(floor_pcd, region_labels, region_id)
        rooms.append(Room(room_id=..., pcd=room_pcd, floor_id=floor_id))

Room Embedding 계산 (k-means + majority voting):

각 room에 associated된 RGB-D observation (카메라 포즈가 해당 room segment 내 있는 프레임들)의 CLIP feature를 추출.

# /tmp/hovsg-repo/hovsg/utils/graph_utils.py:52-100
def compute_room_embeddings(room_observations, num_views=5):
    # 1. 모든 관찰의 CLIP feature 수집
    all_features = [extract_clip_from_image(img) for img in room_observations]
    all_features = np.array(all_features)  # (N_obs, 1024)
    
    # 2. K-means clustering (num_views=5)
    kmeans = KMeans(n_clusters=num_views, random_state=0)
    kmeans.fit(all_features)
    representative_features = kmeans.cluster_centers_  # (5, 1024)
    
    # 3. 추론 시 (inference)
    # 40개 room category embedding과의 cosine similarity
    category_embeddings = get_room_category_embeddings()  # (40, 1024)
    similarity_matrix = cosine_similarity(representative_features, 
                                         category_embeddings)  # (10, 40)
    
    # 4. Majority voting
    predicted_categories = np.argmax(similarity_matrix, axis=1)  # (10,)
    room_category = np.bincount(predicted_categories).argmax()
    return room_category

  • HOV-SG (view embeddings): Acc= 73.93%, Acc≈ 84.10%

3.6 Hierarchical Scene Graph Construction (계층적 씬 그래프 구성)

그래프 형식 정의:

\mathcal{G} = (\mathcal{N}, \mathcal{E})

노드: \mathcal{N} = \mathcal{N}_S \cup \mathcal{N}_F \cup \mathcal{N}_R \cup \mathcal{N}_O

  • \mathcal{N}_S = \{N_S\}: root node (building)
  • \mathcal{N}_F = \{N_{f_0}, N_{f_1}, \ldots, N_{f_k}\}: floor nodes (k개 층)
  • \mathcal{N}_R = \{N_{f,r}\}: room nodes (각 floor 내 room)
  • \mathcal{N}_O = \{N_{f,r,o}\}: object nodes (각 room 내 object)

엣지: \mathcal{E} = \mathcal{E}_{SF} \cup \mathcal{E}_{FR} \cup \mathcal{E}_{RO}

  • \mathcal{E}_{SF}: root ↔ floor edges
  • \mathcal{E}_{FR}: floor ↔ room edges
  • \mathcal{E}_{RO}: room ↔ object edges

각 노드의 속성:

            self.floor_id = None
            self.rooms = []
        elif node_type == "room":
            self.room_id = None
            self.floor_id = None
            self.objects = []
            self.embeddings = []  # k개 representative features
        elif node_type == "object":
            self.object_id = None
            self.room_id = None
            self.name = None  # Open-vocabulary label

def parse_hier_query(query_text, openai_api_key):
    """
    GPT-3.5-turbo로 자연어 쿼리를 [floor, room, object] 토큰으로 파싱
    """
    system_prompt = """You are a query parser for robotic navigation.
Extract floor number, room name, and object name from the query.
Return as: [floor_X, room_name, object_name]
If a level is not specified, return "any".
"""
    
    few_shot_examples = [
        {
            "role": "user",
            "content": "chair in living room on floor 0"
        },
        {
            "role": "assistant",
            "content": "[floor_0, living room, chair]"
        },
        {
            "role": "user",
            "content": "Find the laptop in the office"
        },
        {
            "role": "assistant",
            "content": "[any, office, laptop]"
        },
    ]
    
    response = openai.ChatCompletion.create(
        model="gpt-3.5-turbo",
        messages=few_shot_examples + [{"role": "user", "content": query_text}],
        temperature=0.0
    )
    
    parsed_tokens = parse_response(response["choices"][0]["message"]["content"])
    return parsed_tokens  # e.g., ("floor 2", "bathroom", "toilet")

    # 2. Floor 검색
    if floor_token != "any":
        target_floor = self.query_floor(floor_token)  # cosine similarity
    else:
        target_floor = self.floors[0]  # 기본값: 첫 번째 층
    
    # 3. Room 검색 (target floor 내)
    room_candidates = self.query_room(target_floor, room_token, top_k=top_k)
    
    # 4. Object 검색 (각 room 내)
    object_results = []
    for room in room_candidates:
        objects_in_room = self.query_object(room, object_token, top_k=top_k)
        object_results.extend(objects_in_room)
    
    # 5. 상위 k개 객체 반환 (confidence 기준 정렬)
    return sorted(object_results, 
                  key=lambda x: x['confidence'], 
                  reverse=True)[:top_k]

Text embedding (CLIP template) (/tmp/hovsg-repo/hovsg/utils/clip_utils.py:251-280):

def get_text_feats_multiple_templates(text, model):
    """
    여러 템플릿으로 텍스트를 인코딩하고 평균화
    """
    templates = [
        "{}",
        "There is the {} in the scene.",
    ]
    
    features = []
    for template in templates:
        prompt = template.format(text)
        with torch.no_grad():
            tokens = model.tokenizer(prompt)
            text_features = model.encode_text(tokens)
            text_features = text_features / text_features.norm(dim=-1, keepdim=True)
        features.append(text_features)
    
    # 평균화
    text_features = torch.mean(torch.stack(features), dim=0)
    return text_features

def extract_feats_per_pixel(rgb_image, depth_image, mask):
    """
    각 SAM mask에 대해 3-way CLIP feature fusion 수행
    """
    # 1. 전체 이미지 CLIP 인코딩
    f_g = clip_model.encode_image(rgb_image)  # (1024,)
    
    # 2. Mask BBox 기반 local crop
    bbox = get_bbox_from_mask(mask)
    local_crop = rgb_image[bbox[0]:bbox[2], bbox[1]:bbox[3]]
    f_l = clip_model.encode_image(local_crop)  # (1024,)
    
    # 3. Mask 적용된 crop (배경 제거)
    masked_crop = rgb_image.copy()
    masked_crop[~mask] = 0
    f_m = clip_model.encode_image(masked_crop)  # (1024,)
    
    # 4. Weighted sum fusion
    f_p = 0.4418 * f_m + 0.3272 * f_l + 0.2310 * f_g  # float16으로 저장
    return f_p

def create_voronoi_nav_graph(floor_pcd, floor_points_bev, camera_poses):
    """
    Single-floor Voronoi navigation graph 구성
    """
    # 1. Obstacle map 생성 (BEV)
    camera_poses_2d = project_to_2d(camera_poses)
    inflated_camera_map = inflate_camera_poses(camera_poses_2d)
    floor_bev = project_to_2d(floor_pcd)
    obstacle_region = inflated_camera_map | floor_bev
    
    # 2. Free space map
    free_space = full_space - obstacle_region
    
    # 3. Voronoi diagram
    voronoi_graph = scipy.spatial.Voronoi(camera_poses_2d)
    
    # 4. Cross-floor 연결 (stairs)
    stair_subgraph = extract_stair_camera_poses()
    connect_floors(voronoi_graph, stair_subgraph)
    
    return voronoi_graph

6. 한계와 시사점 (Limitations & Insights for VLN)

6.1 저자 명시 한계점

  1. 하이퍼파라미터 수 다수: floor segmentation (histogram bin size, peak threshold), room segmentation (EDF threshold, watershed seed extraction), DBSCAN clustering 등 tuning해야 할 parameter 많음
  2. 처리 속도: Scene graph construction이 time-consuming (RGB-D 시퀀스 처리 수시간) → real-time mapping 부적합
  3. 정적 환경 가정: dynamic object (사람, 움직이는 물건) 처리 불가
  4. Room segmentation 취약성: 복잡하고 semantically ambiguous layout (combined kitchen-living room, open floor plan)에서 성능 저하; morphological heuristic 사용

6.2 추가 기술적 한계 (리뷰어 관점)

  1. Floor segmentation의 경계 케이스:

    • 경사진 환경 (sloped floors)에서 height histogram이 실패
    • 다락방 (attic), 반지하(basement) 같은 특수 구조 미지원
    • 연속적인 경사로(ramp)가 있는 경우 floor 경계 모호

  2. SAM 의존성:

    • 전체 파이프라인의 bottleneck
    • SAM의 over-segmentation/under-segmentation이 cascade error 유발
    • 배경과 전경 구분이 모호한 object에서 실패 (예: 반투명 가구)

  3. LLM 파싱 취약성:

    • GPT-3.5-turbo의 hallucination risk
    • Floor/room 이름을 정확히 모르는 경우 decomposition 실패
    • Few-shot prompt 품질에 민감 (example 추가/변경 시 성능 변동)

  4. Odometry 의존성:

    • SLAM odometry drift에 취약
    • Odometry 없이는 3D segment merging 무너짐
    • 루프 폐쇄(loop closure) 오류 시 전체 구조 왜곡

  5. VLN 패러다임과의 정렬:

    • HOV-SG는 map-based navigation (offline pre-mapping)
    • 한계: 사전에 전체 환경을 매핑해야 함 (비실용적인 경우 많음)
    • 기회: multi-floor hierarchical structure는 VLN instruction following을 위한 강력한 prior로 활용 가능

  6. Room Classification 일반화:

    • 14개 room category (MATTERPORT_LABELS_40 subset)로 제한
    • 실제 환경의 다양한 room type에 대한 일반화 검증 부족
    • 일관되지 않은 room naming (예: "living area" vs "lounge")에 취약

6.3 VLN 연구 관점에서의 시사점

기여:

  1. Hierarchical representation의 효율성: multi-floor scene을 O(floor + room + object)로 표현 → 메모리 75% 절감, 복합 쿼리 지원
  2. Feature clustering의 효과: DBSCAN 기반 dominant feature 추출로 outlier noise 제거 → mIoU 68% 향상
  3. Actionable navigation graph: Voronoi diagram + cross-floor stair 연결로 실제 로봇 내비게이션 실현

향후 연구 방향:

  1. 온라인 mapping: 사전 mapping 없이 incremental하게 scene graph 구축 → 보다 동적 환경에서 활용 가능
  2. Dynamic object 지원: temporal tracking으로 움직이는 객체 처리 (예: 사람, 애완동물)
  3. Semantic uncertainty modeling: 쿼리 "find a red chair"에서 여러 빨간 의자가 있을 경우 확률 기반 disambiguation
  4. Cross-floor instruction decomposition: VLM을 이용한 natural language instruction을 hierarchical subtasks로 자동 분해
  5. 강화 학습과의 결합: HOV-SG의 scene graph를 state representation으로 사용하는 RL-based VLN policy

6.4 SFACW + LGDP 통합 관점 (Co-main bet 연결)

이 절은 우리 연구의 co-main bets — P4 SFACW (Sparse-Frame Action-Conditioned World Model) 와 LGDP — 관점에서 HOV-SG를 어떻게 흡수/거부할지 정리한다. §6.3의 일반 시사점과 달리, 여기서는 무엇을 가져오고 무엇을 안 가져올지를 명시한다.

6.4.1 HOV-SG → SFACW에 줄 수 있는 것 / 못 줄 것

가져올 수 있는 신호:

  1. 4-tier hierarchy를 z_t의 graph slice prior로

    • SFACW의 latent state z_t는 [geom, graph, video-slow, video-fast]의 slice 조합으로 가정됨
    • HOV-SG의 building → floor → room → object 트리는 graph slice의 inductive bias로 사용 가능
    • 구체적으로: room embedding(K-means num_views=5) 같은 압축 표현이 latent 차원 절약에 직접 차용 가능

  2. DBSCAN-based dominant feature aggregation 패턴

    • 한 segment 내 outlier feature 제거 + majority cluster mean → noise-robust grounding
    • SFACW가 sparse frame에서 객체 feature를 누적할 때 동일 트릭 적용 가능 (mean pooling이 아닌 majority pooling)
    • 코드: graph_utils.py:386의 단 10줄짜리 wrapper. 이식 비용 매우 낮음

  3. 계층적 grounding signal as auxiliary loss

    • "object가 어느 room/floor에 속하는가"의 consistency를 SFACW 학습 시 auxiliary supervision으로
    • HOV-SG를 offline oracle로 두고 latent space에 distill하는 방향

가져오면 안 되는 것 (핵심 mismatch):

  1. Offline pre-mapping 의존성

    • HOV-SG는 RGB-D 비디오 전체 sweep을 가정. SFACW는 sparse-frame online setting이 motivation
    • HOV-SG의 scene graph를 SFACW의 입력으로 받아쓰는 순간 sparse-frame 가설이 깨짐
    • 따라서 HOV-SG는 eval-time oracle 또는 prior distillation source로만 써야 함. inference time 입력 X

  2. Explicit graph 표현 그 자체

    • SFACW의 철학은 implicit world state. explicit graph node를 latent로 끌고 오면 두 패러다임 충돌
    • inductive bias로만 차용하고, latent space는 SFACW 자체 학습 결과로 유지

6.4.2 HOV-SG → LGDP 관점

LGDP가 co-main bet으로 escalated된 상황에서 HOV-SG가 줄 수 있는 신호:

  1. Hierarchical relational structure as graph kernel

    • LGDP가 graph-based policy를 다루는 경우, HOV-SG의 contains-edge 위계는 graph kernel의 strong prior로 작용 가능
    • 단, ConceptGraphs 같은 relation-rich graph가 LGDP에 더 직접적일 수도 있음 (relation diversity > containment depth)

  2. Cross-floor traversability를 LGDP graph node로

    • HOV-SG의 Voronoi navigation graph (계단 연결 포함)는 LGDP의 long-horizon graph 표현에 직접 차용 가능
    • 단, 이 부분은 HOV-SG의 classical CV 부분이라 modern learned graph로 대체하는 게 합리적

주의: LGDP 디테일은 research/research_plan/LGDP_DESIGN.md 참조. 본 절은 HOV-SG 관점에서의 외부 접점만 다룸.

6.4.3 두 패러다임 공통의 거절 사유

SFACW든 LGDP든 HOV-SG 시스템 자체를 가져올 ROI는 낮다. 이유:

  1. 1,446줄 God Class (hovsg/graph/graph.py): 모듈 분리가 어려워 부분 차용도 비용 높음
  2. closed OpenAI API 의존 (GPT-3.5 query parser): 오픈소스 환경에서 재현 어려움
  3. 24GB+ VRAM 요구 (SAM ViT-H + CLIP ViT-H 동시 로드): 학습 클러스터 부담
  4. Pre-mapping latency (분~수십분 per scene): online VLN rollout과 부적합

6.4.4 한 줄 요약

HOV-SG는 코드가 아니라 신호로 가져와야 한다. 4-tier hierarchy, DBSCAN dominant feature, hierarchical consistency signal — 이 셋만 inductive bias / auxiliary loss로 추출해 SFACW · LGDP 둘 다에 흘려보내고, explicit graph 시스템 자체는 baseline 비교군 외엔 import 금지.
