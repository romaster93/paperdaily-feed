1.2 연구 목표 (Research Objective)

본 논문은 실내 이동 로봇이 자연어 지시를 수신하여 자율적으로 목적지까지 내비게이션하는 시맨틱 자율성 문제를 다룬다. 핵심 문제는 두 가지다:

  1. VLM 추론 지연(Latency): 일반 소비자 하드웨어에서 VLM 추론은 결정당 2~9초가 소요되는데, "연구실로 가줘"처럼 단순한 명령에도 매번 VLM을 호출하는 것은 불필요하고 실용적이지 않다.

  2. 세션 기억상실(Session Amnesia): 현재 VLM 기반 내비게이션 시스템은 각 운용 세션을 독립적으로 처리한다. 운용 중 획득한 지식은 종료 시 폐기된다. 기존 시스템 중 VLM-해결 지시사항을 결정론적 규칙으로 승격(promotion)하고, 여러 로봇 간에 학습된 선호도를 전이한 시스템이 없다.

이 논문이 제안하는 해결책은 Semantic Autonomy Stack(SAS): 자연어 지시→실내 내비게이션 파이프라인을 6개 계층(Layer)으로 분리하고, 7단계 결정론적 리졸버(Resolver)로 88%의 명령을 VLM 없이 0.1ms 내에 처리하며, 나머지 12%만 VLM에 에스컬레이션한다. 또한 5범주 시맨틱 메모리 프레임워크를 통해 크로스-로봇 지식 전이를 가능하게 한다.

이 논문의 핵심 통찰: VLM은 언제나 필요하지 않다. 대부분의 자연어 내비게이션 지시는 매개변수적 계단식 리졸버로 결정론적으로 처리 가능하며, VLM이 한 번 해결한 지시는 학습되어 이후 호출 없이 동일 결론을 즉시 반환할 수 있다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

A. VLM 추론 지연과 실용 배포의 딜레마

현존하는 VLM 기반 로봇 내비게이션 시스템들은 다음과 같은 근본적 딜레마에 직면한다:

[VLM 기반 내비게이션의 지연 문제]

매 결정마다 VLM 호출:
  입력: "go to a place to take a short break for personal needs"
  VLM 처리: ~6,733ms (평균)
  → 매 지시마다 6~9초 대기 = 실용적 배포 불가

이상적 시스템:
  동일 입력 → <0.1ms 처리
  → 103,000× 속도 향상 필요

기존 접근 방식들:

  • IROS 이중 프로세스 프레임워크 [6]: RL 분류기를 학습하여 빠른/느린 경로를 결정 → 53.6% 빠른 경로 달성, 단 훈련 데이터와 GPU 필요
  • Hydra-Nav [19]: 단일 VLM에 적응형 Chain-of-Thought 내장 → 통합되었으나 여전히 모든 결정에 VLM 개입
  • CausalNav [22]: 인과 그래프 기반 RAG 메모리 → 크로스-세션은 가능하나 크로스-로봇 전이 미검증

본 논문이 제안하는 7단계 매개변수적 캐스케이드(L3a)는 훈련 데이터, GPU, 네트워크 접근 없이 <0.1ms에 작동한다.

B. 세션 기억상실과 크로스-로봇 지식 고립

기존 시스템의 메모리 한계:

Robot A (세션 1): "화장실 가줘" → VLM이 6.7초 처리 → node 0
Robot A (세션 2): "화장실 가줘" → VLM이 다시 6.7초 처리 → node 0 (반복)
Robot B (세션 1): "화장실 가줘" → VLM이 다시 6.7초 처리 → node 0 (재중복)

메모리 전이 없이는 동일한 VLM 추론이 세션마다, 로봇마다 반복된다. 이는 컴퓨팅 낭비이자 지식 고립(Knowledge Isolation) 문제다.

C. 안전성과 감사 가능성(Auditability) 부재

기존 VLM 기반 시스템은 블랙박스처럼 작동하여:

  • 왜 특정 결정이 내려졌는지 추적 불가
  • 잘못된 결정의 재발 방지 곤란
  • 여러 로봇이 공유 환경에서 작동 시 일관성 보장 불가

2.2 핵심 해결책

SAS의 3가지 핵심 해결 전략:

해결책 1: 6계층 Semantic Autonomy Stack (SAS)
→ 하드웨어(L0)부터 운용 지능(L5)까지 명확한 계층 분리
→ 각 계층의 책임과 인터페이스 명확화

해결책 2: 하이브리드 결정론적-VLM 추론 (L3a + L3b)
→ 7단계 매개변수적 리졸버로 88% 처리 (<0.1ms)
→ 진짜 모호한 명령만 VLM 에스컬레이션

해결책 3: 5범주 시맨틱 메모리 (M1-M5)
→ M3 오퍼레이터 선호도: VLM 결정 → 결정론적 규칙으로 승격
→ 컴파일 다이제스트 공유를 통한 크로스-로봇 전이

3. 핵심 방법론 (Core Methods)

3.1 Semantic Autonomy Stack (SAS): 6계층 참조 프레임워크

SAS는 실내 이동 로봇의 시맨틱 자율성을 위한 6계층(L0~L5) 참조 프레임워크다:

┌─────────────────────────────────────────────────────┐
│  L5: 운용 지능 및 시맨틱 메모리                      │
│      (Operational Intelligence & Semantic Memory)    │
│      M1~M5 메모리, 크로스-세션/크로스-로봇 학습      │
├─────────────────────────────────────────────────────┤
│  L4: 미션 인터페이스                                  │
│      (Mission Interface)                             │
│      자연어, 구조화 명령, VDA 5050 프로토콜          │
├─────────────────────────────────────────────────────┤
│  L3: 시맨틱 추론 (Semantic Reasoning)               │
│      L3a: 결정론적 고속 리졸버 (7단계 캐스케이드)    │
│      L3b: VLM 시각-시맨틱 추론 (에스컬레이션 시만)   │
├─────────────────────────────────────────────────────┤
│  L2: 지각 (Perception)                              │
│      YOLO 객체 탐지, 센서 퓨전, 시맨틱 맵            │
├─────────────────────────────────────────────────────┤
│  L1: 내비게이션 실행 (Navigation Execution)          │
│      ROS 2 Nav2, AMCL, 경로 계획, 장애물 회피        │
├─────────────────────────────────────────────────────┤
│  L0: 이동 플랫폼 (Mobile Platform)                   │
│      구동계, 센서, 전원, 컴퓨팅 하드웨어              │
└─────────────────────────────────────────────────────┘

각 계층의 상세 역할:

계층 역할 구현
L0 하드웨어 기반 4WD 차동 구동, STL-19P LiDAR, C920 카메라
L1 메트릭 내비게이션 ROS 2 Jazzy, Nav2, AMCL, MPPI 컨트롤러
L2 지각/환경 이해 YOLO26n (5.5Hz), Angular Sector Fusion, 18개 정적 POI
L3 시맨틱 추론 7단계 L3a + Qwen 3.5:4b L3b
L4 지시 수신 ROS 2 토픽, OpenClaw 터미널 UI
L5 적응 메모리 5범주 M1~M5, 컴파일 다이제스트

3.2 L3a: 7단계 결정론적 리졸버

핵심 알고리즘. 입력:

  • I: 자연어 지시
  • G: 내비게이션 그래프(24개 노드, 60개 엣지)
  • S: 정적 POI 목록(18개 객체)
  • P: 로봇 현재 포즈 (AMCL x, y, yaw)
  • D: M3 선호도 컴파일 다이제스트

출력: (node_id, resolution_method) 또는 ESCALATE_TO_L3B

전처리: 언어 정규화(소문자화, 언더스코어→공백, 발음 부호 제거, 루마니아어 지원)

[7단계 결정론적 캐스케이드]

Step 0 — M3 선호도 매칭 (Jaccard 유사도 기반):
  tokens ← tokenize(normalize(I)) \ STOPWORDS
  for each preference p in D.promotions:
    for each example e in p.examples:
      j ← jaccard(tokens, tokenize(e))
      if j ≥ 0.6:
        candidates ← candidates ∪ {(j, p.node_id)}
  if 단일 명확한 매칭:
    return (node_id, "L3a_m3_preference")
    // 예상 처리시간: 0.063ms

Step 1 — 명시적 노드 ID:
  정규식 "node N" 또는 "nodul N" (EN/RO 이중 언어) 매칭
  // 예: "go to node 5" → node 5

Step 2 — 노드 이름 매칭:
  정규화된 지시와 각 노드 이름의 부분문자열 포함 관계 테스트
  // 예: "go to lab cb204" → lab_cb204 (노드 5)

Step 3 — 객체 ID 매칭:
  정적 POI의 obj_id 필드와 부분문자열 매칭
  // 예: "go to plant_3" → plant_3

Step 4 — 속성 점수화:
  각 POI의 명시적 속성값(type, department, seating, use 등)이
  지시에 등장하는 횟수 계산 (임베딩/동의어 확장 없음)
  // 예: "실험실 cb202" → room_number: cb202 매칭

Step 5 — 단일 클래스 매칭:
  지시에서 객체 클래스명("plant", "radiator", "laboratory") 탐색
  해당 클래스 인스턴스가 정확히 1개면 해당 노드 반환

Step 6 — 근접성 + 클래스 (최종):
  근접 키워드("closest", "nearest", "cel mai apropiat") 검출 AND
  Step 5에서 다중 인스턴스인 경우만 활성화
  AMCL 포즈에서 각 인스턴스까지 유클리드 거리 계산 → 최근접 반환
  // 예: "Take me to the closest plant" → 현재 위치 기준 최근접 plant
  // 처리시간: ~0.400ms (거리 계산 비용)

단계 실패 시: ESCALATE_TO_L3B

핵심 특성:

  • 결정론적: 동일 입력 → 항상 동일 출력
  • 훈련 데이터 불필요: 규칙 기반, 학습 없음
  • GPU 불필요: CPU 전용, Raspberry Pi 5에서 작동
  • 명시적 에스컬레이션: 최선 부분 매칭 없이 실패 → L3b

3.3 L3b: VLM 시각-시맨틱 추론

L3a가 실패한 진짜 모호한 지시만 처리.

VLM 설정:

  • 모델: Qwen 3.5:4b (Ollama, 포트 11434)
  • 오퍼레이터 워크스테이션: Intel Core Ultra 7 255H, NVIDIA RTX 5050
  • 파라미터: temperature=0.3, num_predict=500, num_ctx=16384, think=false

6섹션 구조화 프롬프트:

[L3b 프롬프트 구조]

섹션 1: 메모리 접두사 (0~500 토큰)
         컴파일 다이제스트의 top 엔티티 + 공간 패턴

섹션 2: 현재 상태
         로봇 포즈 (x, y, yaw) from AMCL

섹션 3: 내비게이션 그래프
         모든 노드 ID + 이름 + 좌표

섹션 4: 구역별 시맨틱 객체
         최근접 그래프 노드 기준 그룹화, 속성, 소스, 거리

섹션 5: 지정 착석/휴식 위치
         seating=true 또는 use=resting spot 객체

섹션 6: 태스크 및 규칙
         오퍼레이터 지시 + 명시적 규칙
         (그래프 노드 선택, 정적 > 동적 선호, 착석 위치 선호)

응답 형식: {"node_id": 정수, "reason": "문자열"}

실험 결과 (S3new: "Take me somewhere I can sit and relax"):

결정 대상 노드 정확성 VLM 시간(ms)
1 9 (radiator_main) ✓ 8,552
2 9 (radiator_main) ✓ 8,203
3 9 (radiator_main) ✓ 8,935
4 9 (radiator_main) ✓ 2,566
5 15 (lab_chair) ✗ 7,921

이 어포던스 추론 능력("앉아서 쉬다" → seating=true인 객체)이 L3a가 처리할 수 없는 종류의 추론이다.

3.4 Executive Contract ⟨A, O, V, L⟩

VLM이 임의의 ROS 명령을 생성하는 것을 방지하는 안전 래퍼:

Executive Contract C = ⟨A, O, V, L⟩

[A] Affordance Manifest (어포던스 매니페스트):
    허용된 행동: {ComputeRoute, FollowPath, NavigateToPose, Spin}
    허용된 대상: 내비게이션 그래프 노드만
    병합된 시맨틱 객체 목록

[O] Observation Normalizer (관찰 정규화):
    AMCL 포즈 (x, y, yaw)
    시맨틱 객체 인벤토리
    카메라 이미지 (L3b 경로에서만, base64 JPEG)

[V] Action Validator (행동 검증기, 3단계 순차 검증):
    1. 행동 유형이 허용 목록에 있는가?
    2. 대상 노드가 현재 그래프에 존재하는가?
    3. 목표 거리가 최대값(기본: 50m) 이내인가?
    → 어떤 단계든 실패 시 차단 + 로깅

[L] Audit Logger (감사 로거):
    결정마다 JSONL 구조화 로그:
    타임스탬프, 지시, 해결 방법, 대상 노드,
    검증 결과, 내비게이션 결과, 타이밍 분해,
    확인 데이터, 이미지, 플랫폼별 메트릭

실험 중 0건의 차단된 행동(zero blocked actions) 발생.

3.5 5범주 시맨틱 메모리 프레임워크 (M1~M5)

[메모리 범주 계층 구조]

M1: 환경 지식 (Environment Knowledge)
    ├─ 스코프: 글로벌 (맵별)
    ├─ 내용: POI 방문 통계 (방문 횟수, 성공률, 평균 내비게이션 시간, 위치 분포)
    └─ 공유: 동일 맵의 모든 로봇

M2: 시간 패턴 (Temporal Patterns)
    ├─ 스코프: 글로벌 (맵별)
    ├─ 내용: 키워드 중복 기반 클러스터링된 반복 시각 관찰 (Jaccard ≥ 0.5)
    └─ 공유: 동일 맵의 모든 로봇

M3: 오퍼레이터 선호도 (Operator Preferences) ★핵심★
    ├─ 스코프: 글로벌 (오퍼레이터별)
    ├─ 내용: 지시→노드ID 매핑, 빈도, 일관성, 방법 분포
    ├─ 공유: 동일 오퍼레이터의 모든 로봇
    └─ 승격 조건: frequency≥3 AND consistency≥0.80 AND VLM결정≥1회

M4: 플랫폼 역량 (Platform Capabilities)
    ├─ 스코프: 로봇별
    ├─ 내용: 하드웨어 설정, 소프트웨어 버전, 센서, 컴퓨팅
    └─ 공유: 해당 플랫폼만

M5: 태스크 이력 (Task History)
    ├─ 스코프: 로봇별 (집계 가능)
    ├─ 내용: 결정별 요약 (지시, 해결, 결과, 타이밍, 이상)
    └─ 공유: platform_id로 속성 부여

M3 승격 기준 (3가지 모두 충족 필요):

조건 1: frequency ≥ 3  (최소 3회 이상 동일 지시)
조건 2: consistency ≥ 0.80  (80% 이상이 동일 노드로 수렴)
조건 3: method_counts['L3b_vlm'] ≥ 1  (최소 1회 VLM이 해결)
         → 조건 3이 필수인 이유: 결정론적으로 처리 가능한 지시를
           실수로 승격시키지 않기 위해

{

크로스-로봇 전이 9단계 파이프라인:

1. 오퍼레이터가 Robot C에서 지시
2. L3b VLM이 해결
3. 감사 로그에 platform_id=xplorer-c로 기록
4. memory_extractor.py 실행 (오프라인, 멱등적)
5. M3 승격 기준 충족
6. 다이제스트의 l3a_promotions_ready에 선호도 등재
7. Robot B 시작 시 동일 다이제스트 로드
8. Robot B의 동일 지시가 Step 0에서 Jaccard 매칭
9. <0.1ms 결정론적 해결, VLM 없음

6. 핵심 기여점 (Key Contributions)

6.1 C1: Semantic Autonomy Stack (SAS) 참조 프레임워크

6계층 구조(L0~L5)를 통해 실내 시맨틱 자율 내비게이션의 계층적 책임을 명확히 정의한다. 각 계층은 독립적으로 교체 가능하며(예: L0의 차동 구동 → 사족보행), 물리적 로봇에서 완전히 검증되었다.

6.2 C2: 하이브리드 결정론적-VLM 추론 (88% 빠른 경로)

7단계 매개변수적 리졸버가 훈련 데이터, GPU, 네트워크 없이 VLM 지연의 103,000배 빠르게 88%의 지시를 처리한다. 이는 기존 최고 수준인 IROS 이중 프로세스 프레임워크의 53.6%를 크게 상회한다.

6.3 C3: 크로스-로봇 적응형 메모리 (100% 전이 정확도)

5범주 메모리 프레임워크(M1~M5)와 M3 승격 메커니즘으로 VLM 학습 지식이 다른 로봇으로 전이된다. 재훈련 없이, 엔지니어링 없이, 33/33(100%)의 정확도를 달성했다.

6.4 C4: GPU 없는 물리적 다중-로봇 검증

Raspberry Pi 5(GPU 없음)에서 2대의 물리적 로봇에 대해 82개 결정, 3세션에 걸친 완전한 검증. 제로 훈련 데이터. 소비자 엣지 하드웨어에서의 실용적 배포 가능성 실증.

8. 고급 주제 (Advanced Topics)

8.1 확장성 한계

현재 한계:

  1. 단일 환경: FIIR 2층 복도(24노드)만 검증. 대규모 환경 미검증.
  2. 어휘적 M3 매칭: Jaccard 기반 토큰 집합 비교. 낮은 어휘 중복의 패러프레이즈("화장실 가줘" vs "go to a place to take a short break for personal needs")는 매칭 실패.
  3. VLM 비결정론: 86% 일관성. 결정 5번(5/7)에서 동일 지시에 대해 다른 노드(lab_chair vs radiator) 선택.
  4. 카메라 시야각 한계: 16cm 마운팅 높이에서 1.5m 높이 소화전 확인 불가 → confirmed=false 10/10 (물리적 도착은 정확).
  5. 동시 VLM 직렬화 미검증: 여러 로봇이 동시에 L3b 에스컬레이션 시 대기열 지연 발생 가능.

8.2 향후 연구 방향

  1. 시맨틱 임베딩 도입: Jaccard 대신 all-MiniLM-L6-v2(22M 파라미터, CPU <10ms)로 M3 매칭 개선
  2. VLM 다양성 벤치마크: Qwen 2.5-VL-7B, Gemma 4 E4B 등 4B/7B/14B 비교
  3. Unitree Go2 사족보행 로봇 이식: 3D LiDAR, 뎁스 센서 환경
  4. 엣지 GPU 배포: Jetson Orin으로 L3 마이그레이션, HTTP → localhost
  5. 대규모 그래프: 전체 층 50노드(200m 경로), 엘리베이터 통합 다층 내비게이션
  6. 공유 메모리 서버: REST API 기반 Fleet 배포, 주기적 추출

8.3 학습 주기의 의의

S3new("앉아서 쉬다") 실험은 SAS 학습 루프의 완전한 사이클을 보여준다:

초기: L3a 실패 → L3b 활성화 (7회, 평균 6,733ms)
      일관성 0.86 달성 → M3 승격
이후: 동일 지시 → L3a Step 0 Jaccard 매칭 (3회, 평균 0.060ms)
      VLM 한 번도 호출되지 않음
효과: 103,000× 지연 감소, 100% 전이 정확도

이는 단순 캐싱을 넘어 진화하는 결정론적 규칙 기반으로의 전환을 의미한다.

9.2 장단점 분석

장점:

  1. 근본적 지연 해결: 기존 시스템들이 VLM 지연을 "비동기화"로 숨기는 방법을 취한 것과 달리, SAS는 대부분의 지시에서 VLM 자체를 불필요하게 만든다. 103,000× 지연 감소는 VLN 분야에서 유례없는 수치다.

  2. 크로스-로봇 지식 전이: 검토된 모든 기존 VLN 시스템 중 크로스-로봇 시맨틱 전이를 물리적 로봇에서 검증한 최초 사례다. 100% 정확도(33/33)는 통계적으로 유의미하다(95% CI [0.894, 1.000]).

  3. 훈련 데이터 제로: HiCoNav, LiveVLN, NavDP 등 대부분의 현대 VLN 시스템이 수천~수십만 에피소드의 시뮬레이션 훈련 데이터를 요구하는 것과 달리, SAS는 완전히 training-free다.

  4. 엣지 하드웨어 배포: Raspberry Pi 5(GPU 없음)에서의 실용적 배포는 연구 실험실 수준을 넘어 실제 산업/상업 배포를 위한 중요한 단계다.

  5. 감사 가능성(Auditability): 모든 결정이 JSONL로 로깅되어 실패 원인 추적, 시스템 디버깅, 규정 준수 검토가 가능하다. 이는 의료/산업 환경에서의 배포에 특히 중요하다.

단점:

  1. VLN 벤치마크 미비: R2R, REVERIE, CVDN 등 표준 VLN 벤치마크에서의 평가가 없다. 단일 복도 환경(24노드, 18 POI)에서의 82개 결정만으로는 일반화 가능성을 주장하기 어렵다.

  2. 어휘적 매칭의 취약성: M3의 Jaccard 기반 매칭은 의미적 동의어에 취약하다. "I need to use the restroom"이 "go to a place to take a short break for personal needs"로 승격된 선호도와 매칭되지 않을 수 있다.

  3. 단일 환경의 한계: 모든 실험이 FIIR 2층 복도 하나에서만 진행되었다. 다층 건물, 개방 공간, 동적 객체가 많은 환경에서의 성능은 미지수다.

  4. 단순한 명령 구조: 실험 시나리오들이 상대적으로 단순하다. "화장실을 찾아줘" 수준이 아닌, "미팅룸을 찾되 CB204 근처에서 시작하고 복도 끝 식물 옆을 지나서" 같은 복합 지시는 테스트되지 않았다.

  5. 학회 게재 없음: 현재 arXiv 프리프린트만 존재. 동료 평가(peer review)를 거치지 않았다.

9.3 실적용 가능성 평가

높음 (High):

  • 병원, 호텔, 공장 등 반구조화된 실내 환경에서 안내 로봇 배포
  • 물류 센터의 다중 로봇 플리트 관리 (공유 메모리를 통한 경험 공유)
  • 엣지 컴퓨팅 제약 환경 (GPU 없는 Raspberry Pi 급 하드웨어)
  • 규정 준수 요구 환경 (완전한 감사 로그)

낮음 (Low):

  • 개방 공간 / 실외 환경: 24노드 그래프 + 18 정적 POI 구조가 실외 규모 확장에 도전
  • 동적 객체 다수 환경: L2 지각이 YOLO 탐지에 의존하므로 동적 대상 혼동 위험
  • 다국어 지원: 영어/루마니아어만 지원. 다른 언어군에서의 언어 정규화 검증 없음

9.4 연구 방향성 평가

SAS는 VLN 연구의 주류(시뮬레이션 벤치마크 성능 경쟁)와는 다른 방향을 취한다. 대신 실용적 배포 가능성(practical deployability)에 집중한다:

  • 기존 VLN 연구가 "R2R에서 SPL 0.01 향상"을 목표로 한다면, SAS는 "실제 로봇에서 지금 당장 작동"을 목표로 한다.
  • 이 방향은 상업화 관점에서 매우 중요하지만, 학술 인정(conference/journal 게재)을 위해서는 표준 벤치마크 평가가 필요하다.
  • 시사점: VLN 커뮤니티가 실용적 배포 지표(배포 지연, 크로스-로봇 일반화, 훈련 비용)를 공식 벤치마크에 포함시키는 방향으로 발전해야 한다는 주장을 지지한다.

11. 결론 (Conclusion)

11.1 혁신성

SAS의 혁신은 기술적 새로움보다 패러다임 전환에 있다. VLM이 "매번 추론해야 하는 블랙박스"에서 "학습하고 잊히지 않는 보조 도구"로 전환된다. 7단계 결정론적 리졸버의 단순성(어휘 매칭, 거리 계산)이 오히려 강점이다 — 투명하고, 감사 가능하고, 결정론적이다.

11.2 실용적 의의

  • 첫 번째 물리적 크로스-로봇 시맨틱 전이 검증: VLN 분야에서 이를 물리적 로봇에서 보인 최초 작업
  • GPU-free 실용 배포: 소비자 엣지 하드웨어(RPi5)에서의 실증은 학술 연구와 현장 배포 간의 간극을 좁힌다
  • 103,000× 지연 감소: 이 숫자 자체가 VLN 시스템 설계 철학에 시사하는 바가 크다 — "VLM이 필요없는 상황이 대부분"

11.3 향후 연구 방향

  1. 표준 VLN 벤치마크(R2R, REVERIE)에서의 평가로 일반화 가능성 검증
  2. 시맨틱 임베딩(MiniLM) 도입으로 어휘적 매칭의 취약점 보완
  3. Unitree Go2 등 고급 플랫폼으로의 이식 및 실외 환경 확장
  4. 동시 VLM 에스컬레이션 처리를 위한 분산 Ollama 서버 아키텍처
  5. 다층/다건물 통합을 위한 Federation 메모리 프로토콜 설계
