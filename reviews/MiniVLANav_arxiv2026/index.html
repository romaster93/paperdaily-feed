1.2 연구 목표 (Research Objective)

MiniVLA-Nav v1은 언어 조건부 객체 접근(Language-Conditioned Object Approach, LCOA) 내비게이션 과제를 위한 멀티씬 시뮬레이션 데이터셋이다. 기존 VLN 데이터셋들이 파노라마 이산 행동(panoramic discrete actions) 또는 단일 씬 기반으로 설계된 반면, MiniVLA-Nav v1은 다음의 격차를 해소하고자 한다:

  1. 연속 차동 구동 행동 레이블의 부재: 기존 대규모 객체 목표 내비게이션 벤치마크는 이산 파노라마 행동을 사용하며, 실제 차륜 로봇에 직접 적용 불가
  2. 멀티씬 다양성의 부재: 단일 씬 또는 고정된 환경 유형만 다루는 기존 데이터셋의 한계
  3. 멀티모달 관찰의 부재: RGB, 깊이, 인스턴스 세그멘테이션이 동기화된 다중 모달 관찰 데이터의 필요성
  4. 언어 지시 다양성 부재: OOD(Out-Of-Distribution) 언어 패러프레이즈 및 미노출 객체 카테고리 평가를 위한 체계적 분할 설계

이 데이터셋은 NVIDIA Isaac Sim 기반 4개의 포토리얼리스틱 실내 씬(사무실, 병원, 전체 창고, 다중 선반 창고)에서 수집된 1,174개 에피소드로 구성되며, NVIDIA Nova Carter 차동 구동 로봇이 자연어 지시에 따라 지정된 객체에서 1m 이내에 정지하는 과제를 수행한다. 각 에피소드는 지시문과 동기화된 640×640 RGB, 미터 단위 float32 깊이 맵, 인스턴스 세그멘테이션 마스크, 그리고 연속 (v, ω) 및 7×7 토큰화 전문가 행동을 60Hz로 함께 제공한다.

이 논문의 위치를 한 문장으로 요약하면: 기존 VLN/ObjNav가 다루지 못한 "자연어 지시 + 실제 차동 구동 속도 레이블 + 멀티씬 + 멀티모달 + OOD 평가"의 다섯 가지 축을 한 데이터셋 안에서 동시에 제공하는 작지만(이름 그대로 "Mini") 정밀하게 큐레이션된 데이터 자원이다.

2. 문제 정의 (Problem Definition)

2.1 도전과제 (Challenges)

도전과제 1: 연속 행동 레이블의 희소성

기존 VLN 연구의 핵심 데이터 격차는 실세계 차동 구동 로봇에서 직접 사용 가능한 연속 속도 명령(continuous velocity commands) 레이블을 제공하는 데이터셋의 부재이다. R2R, RxR, HM3D-ObjNav 등 주류 벤치마크는 파노라마 그래프 위의 이산 노드 점프 또는 [forward 0.25m / turn-left / turn-right / stop] 같은 토큰을 행동으로 사용한다. 이는 토폴로지 그래프 위의 계획에는 적합하지만, 실제 차륜 로봇이 받는 입력인 (선속도 v, 각속도 ω) 명령과는 표현 자체가 다르다.

기존 R2R / ObjNav 데이터셋의 행동 공간:
  [앞으로 0.25m 이동] [왼쪽 회전] [오른쪽 회전] [정지]
  → 이산 파노라마/그래프 행동 (discrete panoramic actions)
  → 실제 차동 구동 로봇에 직접 적용 불가 (속도 레이블 없음)

MiniVLA-Nav의 행동 공간:
  (v, ω) ∈ [0, 1] m/s × [−1.5, 1.5] rad/s   — 연속 선속도 + 각속도
  7×7 = 49 토큰화 이산 버전도 동시 제공 (VLA 분류 헤드 호환)
  → 연속 회귀 제어와 토큰 기반 VLA 모델 모두 지원 (이중 레이블)

도전과제 2: 씬 다양성 부족

기존 로봇 내비게이션 데이터셋들은 주로 단일 환경 유형(예: 가정 환경, 실험실 환경)에 집중하여 다양한 실내 도메인에 대한 일반화 능력을 평가하기 어렵다. 실제 배포 환경에서 로봇은 사무실의 좁은 책상 통로, 병원의 위생 복도, 창고의 넓은 적재 공간과 밀집 선반 영역 같은 이질적인 기하·외관 분포를 동시에 다뤄야 한다. MiniVLA-Nav는 이 네 도메인을 한 포맷 안에 묶어 도메인 간 일반화를 검증 가능하게 한다.

도전과제 3: OOD 언어/객체 지시 평가 체계

자연어 기반 내비게이션 모델의 실용적 배포를 위해서는 훈련 시 보지 못한 언어 표현(paraphrases)과 새로운 객체 카테고리에 대한 강건성 평가가 필요하다. 기존 데이터셋들은 이러한 두 축(언어 축·객체 축)을 분리한 체계적 OOD 분할을 제공하지 않았다. MiniVLA-Nav는 ID 평가에 더해 언어 패러프레이즈 OOD와 객체 카테고리 OOD를 별도 분할로 제공한다.

도전과제 4: 전문가 제어기 설계의 딜레마

수동 텔레오퍼레이션 데이터 수집은 비용이 크고 일관성이 낮다. 자동화된 전문가 제어기는 특정 씬에서 편향된 경로를 생성할 수 있으며, 협소한 복도·밀집 선반 영역에서 전문가 성공률이 낮아 데이터 품질 저하가 우려된다. 실제로 본 데이터셋의 전문가는 개방 공간에서는 80–90% 성공률을 보이지만 일부 어려운 씬에서는 40–60%로 떨어진다 — 이 편향을 인지하고 보고하는 것 자체가 데이터셋의 정직성 측면에서 중요한 설계 결정이다.

3. 핵심 방법론 (Core Methods)

3.1 LCOA 과제 정의

Language-Conditioned Object Approach (LCOA)는 기존 VLN과 ObjNav의 중간 지점에 위치하는 과제로 정의된다:

입력: 자연어 지시 l ∈ L, 현재 관찰 oₜ = (RGB_t, D_t, Seg_t)
목표: 지정된 객체 인스턴스 o* 로부터 1m 이내에 정지
       d(robot, o*) ≤ 1.0m (유클리드 거리)

제약:
  - 비전 기반 제어 (전역 지도/GPS 없이 RGB-D + Seg만 사용)
  - 60Hz 실시간 제어 주기
  - 연속 (v,ω) 명령 출력 (또는 49-토큰 분류)

기존 과제와의 차이점:

  • R2R/RxR: 다단계 방 이동 지시 + 파노라마 이산 행동 → LCOA는 연속 단일 객체 접근으로 단순화
  • ObjNav (Gibson/HM3D): 객체 카테고리만 주어짐(find a chair) → LCOA는 풍부한 자연어 지시 + 인스턴스 특이성
  • LCOA: 단일 객체 접근 + 연속 속도 + 다중 언어 표현 + 1m 정밀 정지의 조합

전문가 제어기 상세 설계 (논문의 실제 수식):

전문가는 타깃 세그멘테이션 마스크가 32픽셀 이상 보일 때(가시 모드)와 보이지 않을 때(비가시 탐색 모드)를 구분하는 비례 제어기다. 핵심 수식은 다음과 같다.

[가시 모드] — 타깃 마스크가 ≥ 32 px 보일 때
  cx     : 타깃 마스크의 수평 중심 (픽셀)
  W      : 이미지 폭 (640)
  d̂_t    : 타깃 마스크 영역의 중앙값(median) 깊이

  각속도:  ω_t = clamp( -k_ω · (cx - W/2) / (W/2),  ω_min, ω_max )
  선속도:  v_t = clamp(  k_v · (d̂_t - r_success),    0,     v_max )

[비가시 모드] — 타깃이 시야에 없을 때 (휴리스틱 헤딩 정렬)
  Δψ_t   : 타깃 방향까지의 헤딩 오차 (특권 정보)
  d_t    : 타깃까지의 유클리드 거리

  각속도:  ω_t = clamp(  k_ω · Δψ_t,  ω_min, ω_max )
  선속도:  v_t = clamp(  k_v · d_t,    0,     v_max )

[장애물 회피] — 전방 깊이 크롭(rows 55–95%, cols 25–75%)의 최소 깊이가
  0.25 m 미만이면 선속도/각속도를 클램프하여 충돌 회피

게인 (논문 보고값):
  k_ω = 1.4  rad⁻¹     (중심 정렬 게인)
  k_v = 0.7  s⁻¹       (깊이 오차 → 선속도 게인)
  r_success = 1.0 m    (목표 정지 거리)
  v ∈ [0, 1] m/s,  ω ∈ [-1.5, 1.5] rad/s
  장애물 임계 = 0.25 m

가시 모드의 각속도 항 -k_ω·(cx - W/2)/(W/2)는 타깃을 이미지 중앙으로 끌어오는 시각 서보잉(visual servoing) 항이며, 정규화 /(W/2)로 인해 입력이 [-1, 1] 범위로 스케일된다. 선속도 항 k_v·(d̂_t - r_success)는 타깃이 멀수록 빠르게 전진하다가 1m에 가까워질수록 0으로 수렴해 부드러운 정지를 만든다. 비가시 모드는 마스크가 없으므로 특권 정보인 헤딩 오차 Δψ로 회전하여 타깃을 시야에 다시 들이는 탐색 휴리스틱이다.

행동 토큰화 (7×7 = 49 토큰):

연속 행동 범위:
  v ∈ [0, 1] m/s        →  7단계 등간격 분할
  ω ∈ [-1.5, 1.5] rad/s →  7단계 등간격 분할

토큰 인덱스 = 7 × v_bin + ω_bin ∈ {0, 1, ..., 48}
  → 49개 joint action vocabulary
  → VLA 모델(분류 헤드)과 직접 호환
  → 연속 (v,ω)와 동시 저장 (회귀/분류 모델 모두 학습 가능)

3.3 언어 지시 생성 시스템

언어 다양성은 두 가지 레이어로 설계된다:

레이어 1: 훈련 템플릿 (18개)

"Go to the {object}"
"Drive to the {object} and stop"
"Navigate to the {object}"
"Approach the {object}"
"Head to the {object}"
... (총 18개 기본 훈련 템플릿)

레이어 2: 패러프레이즈 OOD 템플릿 (12개)

"Make your way to the {object}"
"Proceed to the {object}"
"Find the {object} and come to a stop"
... (훈련 분포 외 표현 12개)

색상 슬롯 비활성화: v1에서는 모든 타깃이 color = 'unknown'으로 어노테이션되어 색상 조건부 템플릿("the red chair" 등)이 의도적으로 억제되었다. 이는 v1 한계이자 향후 확장 포인트로 명시된다.

훈련-OOD 분리 전략:

  • 패러프레이즈 OOD: 동일 객체, 다른 언어 표현 → 언어 강건성 평가 (언어 축)
  • 카테고리 OOD: 훈련 시 미노출 객체 + 훈련 언어 표현 → 객체 일반화 평가 (객체 축)

3.4 티어 기반 스폰 샘플링

궤적 다양성을 위한 3단계 거리 티어와 실제 수집된 분포:

                 스폰 거리 분포 (의도 비율 vs 실제 수집)
            ┌──────────┬───────────────┬───────────────┐
            │  Near    │      Mid      │     Far       │
            │ 의도 30% │   의도 40%    │   의도 30%    │
            │ 실제 640 │   실제 520    │   실제 14     │
            │ (54.5%)  │   (44.3%)     │   (1.2%)      │
            ├──────────┼───────────────┼───────────────┤
            │U(1.5,3.5)│  U(3.5,7.0) m │ 전역 큐레이션  │
            │   m      │               │ 유효 바닥 포인트│
            └──────────┴───────────────┴───────────────┘

상관: 스폰 거리 ↔ 궤적 길이
  Pearson r = 0.94, 95% CI [0.93, 0.95], p < 0.001

주목할 점은 의도한 30/40/30 비율과 실제 수집 분포(54.5/44.3/1.2%)가 크게 어긋난다는 것이다. Far 티어는 전역 큐레이션 유효 포인트에서 샘플링하는데, 그런 포인트가 드물어 14개(1.2%)만 수집되었다. 이는 장거리 일반화 평가의 명백한 한계로, 논문도 이를 솔직히 보고한다. Near 티어가 절반 이상을 차지하는 편중은 모델 학습 시 단거리 접근에 과적합될 위험을 시사한다.

5.4 리얼월드 실험

MiniVLA-Nav v1은 순수 시뮬레이션 데이터셋으로 실세계 실험을 포함하지 않는다. 저자들은 이를 향후 연구 과제로 명시하며 Sim-to-Real 격차를 한계점으로 인정한다:

실세계 격차 요인:
  1. 시각적 외관 차이: 합성 RTX 렌더링 vs. 실제 조명/텍스처
  2. 깊이 센서 아티팩트: 반사 표면, 측정 노이즈 (시뮬 깊이는 완벽)
  3. 바닥 동역학 가변성: 카펫, 불균일 표면, 슬립
  4. 로봇 하드웨어 지연: 제어 루프 지연, 모터 응답 특성

단, 플랫폼이 실제 판매되는 NVIDIA Nova Carter(동일 차동 구동 인터페이스)이고 연속 (v,ω) 레이블을 제공하므로, 실세계 동일 로봇으로의 전이 경로 자체는 비교적 직접적이라는 점이 강점이다.

  새로운 표현 + 새로운 객체 (극단적 일반화)

8. 고급 주제 (Advanced Topics)

8.1 데이터 편향이 학습에 미치는 영향 분석

이 데이터셋은 네 종류의 구조적 편향을 동시에 갖는다. 각 편향이 다운스트림 모델 학습에 어떻게 작용하는지 분석한다:

편향 1) 씬 불균형 (Office 59.6% vs Hospital 4.4%)
  → 모델이 사무실 외관/레이아웃에 과적합
  → 완화책: 씬별 역빈도 가중 샘플링, 또는 씬 균형 미니배치

편향 2) 카테고리 롱테일 (Monitor/Rack/Crate 62%)
  → 다수 카테고리의 시각 특징에 분류 헤드 편향
  → 완화책: focal loss, 카테고리 재균형, OOD 분할로 일반화 검증

편향 3) 스폰 거리 편중 (Near 54.5%, Far 1.2%)
  → 단거리 직선 접근에 정책 편향, 장거리 탐색 미숙
  → 완화책: 티어 가중 학습, Far 에피소드 오버샘플

편향 4) 전문가 차선성 (협소 씬 40–60% 성공)
  → 모방 학습 시 전문가 실패 궤적까지 모방할 위험
  → 완화책: 성공 에피소드만 필터링, DAgger 보정, 보상 가중 BC

8.2 Sim-to-Real 전이 가능성

MiniVLA-Nav v1은 시뮬레이션 전용이지만, 실세계 전이를 위한 잠재적 경로가 존재한다:

경로 1: Domain Randomization
  - Isaac Sim의 RTX 렌더링 파라미터 랜덤화 (조명/텍스처)
  - 깊이 센서 노이즈 모델 주입 (시뮬 깊이는 완벽 → 노이즈 추가 필요)

경로 2: Domain Adaptation
  - Sim 데이터로 사전 훈련 + 소량 실세계 파인튜닝
  - CycleGAN 등 이미지 변환으로 외관 격차 축소

경로 3: 실세계 확장 데이터셋 구축
  - 동일 에피소드 포맷으로 실세계 Nova Carter 텔레오퍼레이션 수집
  - RealSense 깊이를 640×640 float32로 동일 저장 → Sim+Real 혼합

플랫폼이 실제 Nova Carter이고 (v,ω) 인터페이스가 동일하므로, R2R 같은 그래프 기반 데이터셋보다 전이 경로가 직접적이라는 점은 분명한 장점이다.

8.3 VLA 모델과의 통합

49-토큰 행동 설계는 현대 VLA 모델과의 통합을 목표로 한다:

지원 가능한 모델 아키텍처:
  - OpenVLA: 7B LLM + 행동 토큰 생성 헤드
  - RT-2: VLM + 로봇 행동 토큰
  - 경량 BC: ViT/ConvNet + BERT + 49-way 분류 헤드

통합 방법:
  1. 언어 지시 → 텍스트 인코더
  2. RGB/Depth/Seg → 비전 인코더
  3. 49-way 분류 헤드 출력 (또는 연속 회귀 헤드)
  4. token → (v, ω) 역양자화로 실제 제어 명령 생성

8.4 한계점 (Limitations)

데이터 규모:

  • 1,174 에피소드는 대규모 VLA 훈련에 상대적으로 소규모 (이름 그대로 "Mini")
  • 향후 버전에서 규모 확장 필요

전문가 차선성/편향:

  • 비례 제어기 전문가가 협소 공간에서 40–60% 성공률 → 최적 경로 보장 안 됨
  • 씬·카테고리·티어 불균형 (앞 절 참조)

색상 어트리뷰트 부재:

  • 모든 객체가 color = 'unknown' → 색상 기반 지시("빨간 의자") 불가

Far 티어 희소:

  • Far 14편(1.2%)뿐 → 장거리 탐색 능력 평가에 통계적 한계

훈련 베이스라인 미포함:

  • 본 논문은 데이터셋만 제공, 실측 모델 성능 수치 없음

Sim-only:

  • 실세계 검증 없음, Sim-to-Real 격차 미해소

9.2 장단점 분석

장점:

  1. 데이터 자원의 공백 해소: 멀티씬 연속 행동 + 자연어 인스턴스 접근 + 멀티모달이라는 조합은 기존에 없던 자원
  2. OOD 평가 체계 (2축 5분할): 언어/객체 일반화를 분리 측정 가능 → 공정한 벤치마크
  3. VLA 통합 설계: 49-토큰화로 OpenVLA/RT-2 계열 연구와 직접 연결
  4. 실제 로봇 플랫폼 + 연속 레이블: Nova Carter (v,ω)는 실세계 동일 인터페이스
  5. 투명한 편향 보고: 씬·카테고리·티어·전문가 성공률을 모두 정량 공개

단점:

  1. 시뮬레이션 전용: Sim-to-Real 격차 미해소, 실세계 검증 없음
  2. 소규모: 1,174편은 대규모 VLA 학습에 부족 ("Mini")
  3. 단순/차선 전문가: 비례 제어기 전문가는 최적 경로 미보장 (협소 씬 40–60%)
  4. 심한 불균형: 씬(Office 59.6%)·카테고리(상위 3종 62%)·티어(Far 1.2%) 모두 편중
  5. 훈련 베이스라인 부재: 모델 성능 수치 없이 데이터만 제공

NavDP 대비 핵심 차이: NavDP는 자체 비공개 시뮬 데이터(좌표 기반 PointNav)로 강력한 Zero-Shot 실세계 전이를 달성했다. MiniVLA-Nav는 공개 데이터 + 자연어 조건 + OOD 평가를 제공하지만 실세계 검증이 없다. 둘을 결합하면(NavDP의 diffusion 정책 + MiniVLA-Nav의 언어 조건 데이터) "언어 조건부 Sim-to-Real diffusion navigation"이라는 유망한 방향이 열린다.

AwareVLN 대비 핵심 차이: AwareVLN은 단안 RGB에서 자기인식 추론으로 다단계 지시를 따르는 모델이다. MiniVLA-Nav는 그런 모델을 학습/평가할 데이터다. AwareVLN의 추론 모듈을 MiniVLA-Nav의 LCOA 과제에 적용해, "왜 이 객체로 접근하는가"를 설명하는 추론 증강 LCOA 모델을 만드는 것이 자연스러운 후속 연구다.

9.3 실적용 가능성 평가

MiniVLA-Nav v1의 실적용 가능성: 중간 (★★★☆☆)

장점:
  ✅ NVIDIA Nova Carter → 실세계 차동 구동 로봇과 동일 제어 인터페이스
  ✅ 60Hz 제어 주기 → 실시간 제어 가능
  ✅ 연속 (v,ω) 레이블 → 직접 제어 명령으로 사용 가능

단점:
  ❌ 실세계 검증 없음 → 전이 성능 미지
  ❌ 정적 씬 + 균일 조명 → 실세계 복잡도 부족
  ❌ 시뮬 렌더링 vs 실세계 이미지 도메인 격차
  ❌ 데이터 규모 소규모 → 단독 학습으로는 강건성 부족

실용적 활용 방향:

  • 사전 훈련 데이터: NavDP처럼 시뮬 사전 훈련 후 실세계 파인튜닝
  • 표준 벤치마크: 새 VLN 모델의 언어/객체 OOD 일반화를 공정 비교
  • 데이터 증강: 실세계 데이터와 혼합 훈련으로 도메인 적응 연구

9.4 연구 방향성 평가

연구 방향성: 유망하나 스케일/실세계 필요 (★★★★☆)

MiniVLA-Nav v1은 VLN 연구의 실용적 공백을 채우는 데이터셋이다. 기존 VLN 연구가 R2R/RxR의 파노라마 이산 행동 공간에 집중된 반면, 실제 차동 구동 로봇 제어에 필요한 연속 (v,ω) 행동 레이블을 자연어 조건과 함께 제공하는 멀티씬·멀티모달 데이터셋이다.

다만 현재 규모(1,174편)와 시뮬 전용성, 네 종류의 불균형은 명백한 제약이다. 그러나 편향을 숨기지 않고 표로 공개한 점과 확장 가능한 표준 포맷은, 커뮤니티가 이 데이터 위에서 재균형·증강·실세계 확장을 점진적으로 쌓아 올릴 수 있게 한다. NavDP·AwareVLN 같은 모델 중심 연구가 공정한 비교 기준 위에서 발전하도록 돕는 데이터 인프라로서의 가치가 핵심이며, v2에서의 규모 확장과 실세계 통합이 이뤄지면 LCOA 과제의 표준 벤치마크로 자리잡을 잠재력이 있다.

11. 결론 (Conclusion)

MiniVLA-Nav v1은 Vision-Language Navigation 연구의 실용화를 위한 데이터 기반을 제공한다. 핵심 혁신은 세 가지이다:

  1. 연속 + 토큰 이중 행동 레이블: 기존 이산 행동 데이터셋에서 벗어나 실제 차동 구동 로봇에 직접 적용 가능한 (v,ω) 레이블과, VLA 호환 49-토큰을 함께 제공
  2. 2축 5분할 OOD 평가 프로토콜: 언어 패러프레이즈와 객체 카테고리 두 축의 OOD 평가로 모델의 실용적 일반화 능력 측정
  3. 멀티씬·멀티모달 + 투명한 편향 보고: 4개 도메인 × RGB/Depth/Seg를 표준 포맷으로 제공하고, 씬·카테고리·티어·전문가 성공률의 편향을 모두 정량 공개

실용적 의의: NavDP 등 실세계 배포를 목표로 하는 VLN 연구에서, MiniVLA-Nav는 시뮬레이션 사전 훈련을 위한 공개 표준 데이터셋으로 활용될 수 있다. 특히 연속 행동 레이블과 VLA 호환 토큰화의 조합은 OpenVLA, RT-2 등 최신 VLA 모델을 내비게이션 과제에 파인튜닝하는 연구를 직접 지원한다.

향후 연구 방향: (1) 데이터 규모 확장 및 씬·카테고리·티어 재균형, (2) 동적 장애물·색상 어트리뷰트 도입, (3) 실세계 Nova Carter 데이터 통합을 통한 Sim-to-Real 검증, (4) 훈련 베이스라인 공개. 이들이 이뤄지면 LCOA(언어 조건부 객체 접근)는 VLN과 ObjNav 사이의 실용적 과제로 자리매김할 수 있다.

12.1 기존 VLN 데이터셋 계보 분석

Vision-Language Navigation 연구는 지난 8년간 여러 데이터셋 세대를 거쳐 발전해왔다:

1세대 (2018–2020): 파노라마 이산 행동
  R2R (Anderson et al., 2018):
    - 환경: Matterport3D 스캔 90개 씬
    - 행동: 파노라마 그래프 위 이산 이동
    - 지시: 다단계 자연어 (평균 ~29 토큰)
    - 한계: 실제 로봇 적용 불가 (이산 그래프 행동)

  RxR (Ku et al., 2020):
    - R2R의 다국어 확장 (11개 언어)
    - 세밀한 궤적-발화 정렬 추가
    - 동일한 이산 행동 공간 유지

2세대 (2020–2023): 연속 환경 + 특수 과제
  VLN-CE (Krantz et al., 2020):
    - R2R를 Habitat에서 연속 환경으로 재구현
    - 연속 환경이지만 행동은 여전히 이산화 토큰
    - 실제 로봇 속도 레이블은 없음

  ObjNav (HM3D/Gibson):
    - 카테고리만 주어지는 객체 탐색 ("find a chair")
    - 자연어 지시 풍부성 부족

3세대 (2023–2026): 실세계 전이 + 연속 제어
  NavDP (ICRA 2026):
    - 확산 정책 기반 연속 내비게이션
    - 시뮬 전용 학습 → Zero-Shot 실세계 전이
    - PointNav(좌표) 목적, 언어 조건 아님

  MiniVLA-Nav v1 (2026):
    - 연속 (v,ω) 레이블 + 49-토큰화 이중 제공
    - 언어 조건부 객체 접근(LCOA) 특화
    - 2축 OOD 평가 분할 체계화
    - "Mini": 소규모지만 멀티씬 + 멀티모달

12.2 LCOA vs 기존 ObjNav 과제 심층 비교

Object Goal Navigation (ObjNav)과의 비교:

전통 ObjNav (HM3D, Gibson 기반):
  입력: "find a chair" (카테고리만)
  목표: 임의의 의자 인스턴스 발견
  행동: [앞 0.25m] [왼 10°] [오 10°] [정지]
  성공: 해당 카테고리 객체가 시야에 들어오면

LCOA (MiniVLA-Nav):
  입력: "Drive to the {object} and stop" 등 (자연어 문장 + 인스턴스)
  목표: 특정 객체 인스턴스에서 1m 이내 정지
  행동: (v, ω) 연속 + 7×7(49) 토큰
  성공: 지정 인스턴스로부터 유클리드 거리 ≤ 1.0m

핵심 차이:
  1. 인스턴스 특이성: LCOA는 지정된 특정 객체로 접근
  2. 실제 제어: LCOA는 실제 차동 구동 속도 레이블 제공
  3. 정밀도: ObjNav의 "시야 내" vs LCOA의 "1m 이내 정지"
  4. 언어 풍부성: ObjNav 단어 vs LCOA 문장 + 패러프레이즈 OOD

12.4 베이스라인 모델 설계 방향 (예고된 컴패니언 연구)

논문은 데이터셋만 제공하므로, 이 데이터 위에서 동작할 베이스라인 후보를 정리한다:

베이스라인 1: 순수 모방 학습 (Behavior Cloning)

class BCNavModel(nn.Module):
    def __init__(self):
        self.vision_encoder = ViT_B16()   # 640×640 RGB
        self.depth_encoder  = ConvNet()    # 깊이 맵
        self.lang_encoder   = BERT()       # 언어 지시
        self.action_head    = MLP()        # → 49-way 분류 또는 (v,ω) 회귀

    def forward(self, rgb, depth, instruction):
        f = concat(self.vision_encoder(rgb),
                   self.depth_encoder(depth),
                   self.lang_encoder(instruction))
        return self.action_head(f)         # token ∈ {0..48}

베이스라인 2: VLA 기반 (OpenVLA 파인튜닝)

model = OpenVLA.from_pretrained("openvla-7b")
model.finetune(
    dataset=miniVLANav_train,                 # train_id 716

12.6 MiniVLA-Nav와 NavDP의 시너지 가능성

NavDP의 데이터 전략:
  - 자체 시뮬 데이터 (비공개, 다수 씬)
  - 연속 궤적 생성 (Diffusion Policy)
  - PointNav 목적 (좌표 기반)

MiniVLA-Nav의 보완점:

  - 2축 5분할 OOD 평가 체계

  NavDP 아키텍처 + MiniVLA-Nav 데이터
  → 언어 조건부 Diffusion Policy for LCOA
  → NavDP의 강력한 Sim-to-Real 전이 능력을
     자연어 기반 객체 접근에 적용
